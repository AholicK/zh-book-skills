# 输入与输出（input 接收键盘输入、print 输出结果）

## R — 原文 (Reading)

> 在 Python 中，使用内置函数 inputO可以接收用户的键盘输入。inputO函数的基本用法如下:
> variable = input(”提示文字"）
> 其中，variable为保存输入结果的变量，双引号内的文字用于提示要输入的内容。
>
> — 第 2 章 · Python 语言基础「必背必记 4．input()函数与 print()函数」L289-301（p04）

## I — 方法论骨架 (Interpretation)

让程序「跟人对话」只需两个内置函数各占一行：`input` 把键盘上的东西收进来存进变量，`print` 把结果显示出去。本节的全部内容就是这两行的写法，没有可选项要挑。

`input` 是一行赋值：等号左边是**保存输入结果的变量**，小括号里是**双引号内的提示文字**，用于提示要输入的内容。角色分工只有这两项。提示语不是装饰——它是这个界面上唯一的说明，用户看不到别的字，所以必须写清「要输什么」。

`print` 的输出内容书中分三类：数字、字符串（需用引号括起来，直接输出）、含运算符的表达式（输出计算结果）；三类之外本书没给别的写法。

判据是一条最小闭环：**能收进来 → 存进变量 → 打出去**。需要外部数据处铺一行 `输入变量 = input("提示")`，需要展示结果处铺一行 `print(输出内容)`，输出内容落在三类之一。

本节给得极薄：收进来的东西是什么类型、能不能直接做算术、怎样与别的值拼在一起，都不在本节范围内（见 B 段）。

### 与相邻能力的区分（阶段 3 定稿）
- 与 `control-flow-and-loops` 的区别: 本卡只负责「收进来」「打出去」两行语句，不写按输入分流、反复询问、满足条件才停这些控制结构；它是那边的**前置步骤**——先能收数据，再谈怎么处理。
- 与 `string-formatting` 的区别: 本卡只用 print 输出**内容**（数字 / 字符串 / 含运算符的表达式），不做排版；要控制宽度、小数位、填充与对齐时用 `string-formatting`。

## E — 可执行步骤 (Execution)

1. **列出交互点**
   - 完成标准: 写出程序需要用户提供的每一项信息，并为每一项配一句写清「输什么」的提示文字（如「请输入姓名：」）
   - 判停条件: 程序不需要外部输入（数据全写在代码里）时，本卡不适用

2. **写输入行**
   - 完成标准: 每项输入写成一行 `变量名 = input("提示文字")`——等号左边是变量、提示写在双引号内，变量名与第 1 步清单一一对应
   - 输入契约: 必需信息 = 要问什么（提示文字）+ 存到哪里（变量名）；缺项先问用户，不替用户杜撰提示语

3. **写输出行**
   - 完成标准: 每个输出点写一行 `print(输出内容)`，内容属于书中三类之一；字符串与变量相拼时只用书中认可的运算符（`+`）
   - 判停条件: 需要排版（对齐、小数位、填充）时停下，转 `string-formatting`

4. **通读检查**
   - 完成标准: 逐行能说清「这一行问什么 → 存进哪个变量 → 哪一行用它输出」；出现被赋值却从未使用的变量、或问了却从不使用的输入时回到第 2 / 3 步
   - 判停条件: 需要把输入当数字用（做算术、比大小）时先停下——本卡**不声称** `input` 收到的是什么类型（见 B 段）

- **输入契约**: 必需信息 = 交互点清单（问什么、存进哪个变量）+ 输出点清单（输出什么内容）。要判断「输入能不能直接参与运算」时书中无依据，必须先说明「本书未覆盖」，不得默认按字符串或数字处理。
- **输出契约**: 交付 ① 每个交互点的提示语 ② 保存输入结果的变量名 ③ 每个输出点的 `print` 语句。完成标准 = 每条提示语都有对应变量、每个变量最终被输出或说明用途、输出内容全部落在书中三类之内，且不出现书中没有的函数或参数。

## B — 边界 (Boundary) ★

### 不要在以下情况使用这张卡
- 需要对输入做格式校验、类型转换或错误兜底时（本卡不含这些规则）
- 需要按输入分流、反复询问时（用 `control-flow-and-loops`）
- 需要排版输出时（用 `string-formatting`）

### 作者在书中警告的失败模式
- 本节全文只有两段说明，作者**没有给出任何错误写法或失败示例**，也没讲输入不合法时会发生什么；可用的负面口径只有「双引号内的文字用于提示要输入的内容」这一句角色说明——提示语写不清就失去了它唯一的作用（p04）

### 作者盲点与底本缺口
- **`input()` 的返回值类型书中未说明**（unit_note / NR-07，v10 / task-14）：书中只说「接收用户的键盘输入」并给出赋值写法。本卡**不声称**收进来的是字符串，也不说是数字；要把输入当数值用，**本书未覆盖**。
- **`print()` 的分隔符等参数书中未说明**（unit_note）：书中只给「输出内容」一项，sep / end 之类的参数口径**本书未覆盖**。
- 本单元只有 1 条候选（p04），是 20 个单元里证据最薄的一个；这两行之外的写法**本书未覆盖**。
- OCR 现象（NR-15）：引文中的 `inputO` 是圆括号 `()` 被误识成字母 O，`(”提示文字"）` 的配对引号同样照抄原文，均未更正；源文 print 相关文字有同类混排（`printO`）。

### 容易混淆的邻近方法论
- `string-formatting`: 两者都落在「输出」这一步；本卡只管输出**什么内容**，格式化管**怎么排**。
