# 文件及目录操作（open/close/write、os.remove/rename、stat 属性）

## R — 原文 (Reading)

> mode：可选参数，用于指定文件的打开模式。默认的打开模式为只读（即
> r)。
> buffering：可选参数，用于指定读写文件的缓冲模式，值为0表达式不
> 缓存；值为1表示缓存；如果大于1，则表示缓冲区的大小。默认为缓
> 存模式。

## I — 方法论骨架 (Interpretation)

这张卡把「操作一个文件」拆成固定顺序：先用内置 `open()` 创建或打开文件、得到**文件对象**，再用文件对象的方法操作（write 写、close 关），删文件或改名时改走内置 os 模块。它防两个直觉错误——以为打开就能写（默认只读）、以为有内置的删文件函数（没有）。

打开的口径全落在参数上：filename（要创建或打开的文件名，需用单引号或双引号括起；和当前文件在同一目录下就直接写文件名，否则要指定完整路径）、mode（可选，**默认只读 r**）、buffering（可选，0 不缓存 / 1 缓存 / 大于 1 表示缓冲区大小，默认缓存模式）；返回值书中写作 file。用完必须 `file.close()`。

有一处底本缺口必须说清：`open()` 的**函数签名行在源文中丢失**（L1843 之后直接是「参数说明：」），本卡只按参数逐项交代参数名与默认值，不给签名写法（NR-09）。

写入用 `file.write(string)`；因默认模式只读，写之前必须显式给出可写模式，书中没列全部模式取值（ce14）。

删除与改名走 os 模块，判据是书里明写的前提：**Python 没有内置删除文件的函数**。`os.remove(path)`，path 可用相对或绝对路径；同章给出 `os.rename(src,dst)`。元数据用 `os.stat()` 返回对象的属性：st_size 是文件大小（**单位为字节**）、st_mtime 是最后修改时间。

## A1 — 应用示例 (Application Example)

### 示例 1: 打开当前目录下的 status.txt
- **类型**: 原书示例（残片）
- **问题**: 要打开当前路径下一个名为 status.txt 的文件，路径该怎么写
- **怎么用**: 按 filename 的口径——文件名需用单引号或双引号括起来；与当前文件同目录就直接写文件名，否则指定完整路径。书中给的例子是「要打开当前路径下的名称为 status.txt 的文件，可以使用“status.txt”」。
- **结果**: 书中未说明打开之后的行为。这是残片——同节的 `open()` 签名行已丢失（NR-09）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这张卡?
1. 要把程序里的内容存到文件，或从文件读回来
2. 打开文件后写不进去，报「不可写」一类的错
3. 要删掉一个文件或给它改名，找不到函数
4. 要报告文件大小、修改时间这类元数据

### 语言信号
- 「文件写不进去 / 打不开」
- 「怎么删文件 / 怎么改文件名」「open 怎么写」
- 「怎么看文件大小 / 修改时间」
- 英文: "write to a file", "delete a file", "file size", "open mode"

### 与相邻能力的区分（阶段 3 定稿）
- 与 `exception-handling` 的区别: 本卡给文件动作本身的参数口径；文件不存在、输入输出错误**怎么办**属于那条卡（composes-with）。
- 与 `string-encoding-split-join` 的区别: 本卡操作的是**文件对象**（打开之后才存在；文件名只是字符串），那条卡处理字符串内容与编解码本身（depends-on：要做编码转换、拆分合并时走那条卡；本卡不给 `open()` 的编码参数——底本只提取到 filename / mode / buffering，NR-09）。

## E — 可执行步骤 (Execution)

1. **写清文件身份（filename）**
   - 完成标准: 给出文件名并确认写法——引号括起；与当前文件同目录就直接写文件名，否则写完整路径

2. **选模式（写操作必须）**
   - 完成标准: 写操作显式给出可写模式，并说明「默认的打开模式为只读（即 r)」才是写不进去的原因（ce14）
   - 判停条件: 书中没有列出全部模式取值，不要凭记忆补出模式字母表，只能说明「需要可写模式」

3. **打开—操作—关闭**
   - 完成标准: 给出 `open(...)`（只按 filename / mode / buffering 逐项交代，**不写签名行**）+ `file.write(string)` + `file.close()` 三步
   - 判停条件: 用户要求「自动关闭」「with 写法」或逐行读取时，如实说明本书未覆盖（单元 v15 note）

4. **删除或改名走 os**
   - 完成标准: 删除写成 `os.remove(path)` 并说明前提「没有内置删除文件的函数」（ce15）；改名写成 `os.rename(src,dst)`

5. **元数据与自检（可选）**
   - 完成标准: 大小用 st_size（单位字节）、时间用 st_mtime；交付物没有 with、逐行读取、open 签名行与书中未列的 mode 取值，出现任一即删除

**输入契约**: 必需 = ①文件名或路径；②要做哪件事（打开 / 写入 / 删除 / 改名 / 看属性）；③是读还是写（决定要不要给可写模式——默认只读会让写操作失败，缺 ③ 必须先问）。目录级需求本书未覆盖，本卡不承接。

**输出契约**: 「打开—操作—关闭」的调用序列（或删除 / 改名的一行调用）+ 参数依据说明（filename / mode / buffering 逐项，或 os.remove 的 path 口径）。完成标准：每个调用与参数都能回指 f26 / f27 / f28 / p28。

## B — 边界 (Boundary) ★

### 不要在以下情况使用这张卡
- 需要 with 上下文管理器、自动关闭语义或逐行读取——本书未覆盖（单元 v15 note）
- 需要目录级操作（建目录、列目录、遍历）——本书未覆盖
- 需要字符集 / 编码参数——底本只提取到 filename、mode、buffering 三个参数（NR-09）

### 作者在书中警告的失败模式
- 用默认模式打开却要写: ce14 明写「默认的打开模式为只读（即 r)」——把「可选」误读成「可以随便写」是典型翻车点
- 凭直觉找内置删除函数: ce15 明写「Python 没有内置删除文件的函数，但是在内置的os 模块中提供了删除文件的函数remove()」
- 一律写绝对路径或只写文件名: c10 的口径是「和当前文件在同一个目录下…直接写文件名即可，否则需要指定完整路径」

### 作者盲点与底本缺口
- **底本缺口 NR-09**: `open()` 的签名行在源文中丢失（L1843 之后直接是「参数说明：」），本卡因此只给参数口径
- **本书未覆盖** with 上下文管理器与逐行读取（单元 v15 note）
- **本书未覆盖** mode 的全部取值（只写了默认值 r）、write 的覆盖/追加语义（f27）与目录级操作
- 底本缺陷（p28）: stat 属性表被压成单列（引文里的「属性」「说明 st_mode」即为原样），对应关系需按语义核对；引用照抄（NR-15）

### 容易混淆的邻近方法论
- `exception-handling`: 给「出错时怎么办」的三段式，本卡给「文件动作怎么写」
