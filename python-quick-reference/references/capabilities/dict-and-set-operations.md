## I — 方法论骨架 (Interpretation)

字典是「键→值」的对照表，集合是「只问在不在」的容器。本单元把两者的**合法性约束**与**基本动作**固定下来。

字典的三条约束来自参数说明：键**必须唯一且不可变**（可以是字符串、数字或元组）；值**可以是任何数据类型，且不要求唯一**；写法是键值之间用冒号、元素之间用逗号、整体用大括号。这是正向声明——它说什么合法，不说违规报什么错。

遍历有一条固定路径：`items()` 是入口，返回「可遍历的（键-值对）的元组列表」；要拿到具体的键值对必须再用 `for` 走一遍。把 items() 当成可直接取用的结果是最常见的误读。

集合有两种创建方式：大括号字面量，或 `set(iteration)` 把列表、元组、range、字符串转过来——字符串进去得到「全部不重复字符」的集合，顺带完成去重。成员资格受一条限制：`add(element)` 的 element 只能用字符串、数字、布尔值 True/False，不能是列表、元组等可迭代对象；它与字典键的不可变要求同源（书中未点明这层原因）。

删除四种方式的分工：`del` 删**整个集合**、`pop()` 删一个元素、`remove()` 删指定元素、`clear()` 清空成空集合。判据是「要整个删掉 / 去掉某个值 / 随机弹一个 / 只清空留着」。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这张卡?
1. 要按「名字→电话」这类对应关系存数据或查表，而不是按下标取
2. 想知道字典的键能放什么、某个写法为什么不合法
3. 想把一串数据去重，只问「出现过没有」
4. 遍历字典时拿不到键值对，或不确定 `items()` 返回什么

### 语言信号
- 「键值对」「查表」「字典怎么建」「键能不能放列表」
- 「去重」「重复的挑出来」「items()」「遍历字典」
- 英文: "dict", "key-value", "set", "deduplicate", "items()"

### 与相邻能力的区分（阶段 3 定稿）
- 与 `list-and-tuple-operations` 的区别: 那条处理有序序列（append/extend、count/index/sum）；本卡处理按键取值的字典与用于去重的集合，两者常互转：问「列表怎么加元素、怎么统计」走那条，问「怎么按键取值、怎么去重、键能放什么」走本卡

## E — 可执行步骤 (Execution)

1. **定结构**
   - 完成标准: 判定需求是「按键取值」（字典）还是「只问存在性/去重」（集合），并写明依据

2. **建对象**
   - 完成标准: 字典用字面量创建，每个键都是字符串/数字/元组之一；集合用大括号字面量或 `set(iteration)`，元素只用字符串/数字/布尔值
   - 判停条件: 用户给的键或集合元素是列表、字典这类对象时，停下按 p15/p18 的限制改类型，不要先试运行

3. **遍历 / 增删**
   - 完成标准: 字典遍历写成「先用 `items()` 拿元组列表、再用 `for` 逐个取」两步；删除按「整个删 `del`、删指定值 `remove`、删一个 `pop`、只清空 `clear`」选定一种并说明理由

4. **核验**
   - 完成标准: 键无重复、无列表型键或元素；`items()` 的结果确实经过一层 `for` 才取值；输出中没有本卡未覆盖的写法

- **输入契约**: 必需——键的类型、集合成员的类型、要做的动作（创建/遍历/增删）。缺类型先问用户，不要替他挑；「按键取值 + 缺失键怎么办」不在本卡范围（NR-01，本书未覆盖）。
- **输出契约**: 交付①结构选型②创建写法③遍历或增删写法④约束检查结论。完成标准是约束检查可逐条对照原文参数说明，且不含本卡未覆盖的写法。

## B — 边界 (Boundary) ★

### 不要在以下情况使用这张卡
- 需要「按键取值」与缺失键处理——本书未覆盖（NR-01），本卡不给这类写法
- 集合的交并差运算与嵌套结构示例——本书未覆盖（unit_note）
- 有序序列的增删与统计——走 `list-and-tuple-operations`

### 作者在书中警告的失败模式
- 键必须唯一且不可变（ce03）：用可变对象当键、或以为键能重复，字典不成立；书中只给正向约束，未给反例与报错名
- 集合元素不能是列表、元组等可迭代对象（ce04）：与上一条同源，书中未点明「可哈希/不可变」这层原因
- 把 `items()` 当成可直接取用的结果（ce06）：「想要获取到具体的"键-值对"，可以通过 for 循环遍历该元组列表」

### 作者盲点与底本缺口
- NR-01：字典按键取值与 KeyError 无示例——本书未覆盖，本卡不写。
- NR-03：集合示例区（L1071-1077）是 OCR 残片，变量创建行缺失——本书该处不可复原。
- 集合运算（交、并、差）书中未讲；字典与集合的区别书中未展开（g06）——本书未覆盖。
- NR-04（相关）：列表元素的 remove/pop 只出现在集合章节，不要外推到列表。

### 容易混淆的邻近方法论
- `list-and-tuple-operations`: 序列只有 `del`（删整个列表），集合有 del/pop/remove/clear 四种；套用会出界。
