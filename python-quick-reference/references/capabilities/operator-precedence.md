# 运算符与优先级（求值顺序、复合赋值展开、布尔值口径）

## I — 方法论骨架 (Interpretation)

一个表达式里挤了几个运算符时，「先算哪个」由一张**从高到低**排好的表决定：`**` → 取反、正号和负号 → 算术 `* / % //` → 算术 `+ -` → 位移 → 位与 → 位异或 → 位或 → 比较运算符（表尾行的符号列在底本中被截断）。同一行内优先级相同，此时由**结合方向**定先后（`and` / `or` 从左到右，`not` 从右到左）。

复合赋值不是新运算，而是「先算、再存回原变量」的简写：`x += y` 即 `x = x + y`，一路到 `x //= y` 即 `x = x // y`。判断 `x op= y` 在做什么，只需把它展开。

结果口径有两条：比较运算符**为真返回 True、为假返回 False**，通常用在条件语句中作为判断依据；逻辑运算符对真假布尔值运算，**结果仍是布尔值**。合起来意味着条件位置上写的必须是能算出 True / False 的东西。

用法固定三步：展开复合赋值 → 按优先级表逐层定顺序 → 确认每步结果是数值（算术）还是布尔值（条件）。书中没教何时该加括号，括号取舍只能靠「与表算出的顺序是否一致」来判。本卡只固定**优先级顺序 / 展开形式 / 布尔值口径**三条，不据底本重建运算符表（见 B 段）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这张卡?
1. 心算结果和程序输出对不上，怀疑是「谁先算」的问题
2. 读别人写的表达式，要判断该不该加括号才符合预期
3. 看到 `x += 1` / `x //= 2`，想确认它到底改了什么
4. 条件里混了算术、比较、逻辑，想知道求值顺序与每步结果

### 语言信号
- 「这个表达式先算哪一步？」「为什么结果是 50 不是 20？」
- 「`x += 1` 和 `x = x + 1` 一样吗？」
- 英文: "which operator runs first", "operator precedence", "what does += do"

### 与相邻能力的区分（阶段 3 定稿）
- 与 `control-flow-and-loops` 的区别: 本卡只处理**表达式内部怎么算**（求值顺序、复合赋值展开、结果是布尔还是数值），不写 `if` / `while` 的语法与循环控制；条件已写对、只想确认某一步先算谁时用本卡。

## E — 可执行步骤 (Execution)

1. **展开复合赋值**
   - 完成标准: 每处 `+=` / `-=` / `*=` / `/=` / `%=` / `**=` / `//=` 都改写成「左 = 左 op 右」，等号两侧变量名一致
   - 判停条件: 书中七个展开式之外的复合写法标注「本书未覆盖」，不代为展开

2. **按优先级定顺序**
   - 完成标准: 从 `**` 起步逐层指出每步运算对象（`**` → 取反/正负号 → 算术 `* / % //` → 算术 `+ -` → 位移 → 位运算 → 比较），写出每步中间结果；同优先级按结合方向定先后
   - 输入契约: 一条完整表达式 + 其中变量的初值；缺初值先问，不静默假设

3. **判定结果口径**
   - 完成标准: 说明最终结果是数值还是布尔值；比较与逻辑运算的结果是 `True` / `False`，用作条件时指出能否直接放进 `if` / `while`

4. **复核**
   - 完成标准: 把第 2 步顺序写成加括号的等价式（如 `2 + (3 * (4 ** 2))`），与原式逐项对照一致
   - 判停条件: 涉及底本损毁的算术运算符表或逻辑符号列（NR-05）时停止推断，只标注「底本损毁，本书未覆盖」

- **输入契约**: 一条待判断的表达式 + 其中变量的初值；缺初值先问，不猜。
- **输出契约**: 交付 ① 展开后的表达式 ② 逐步求值序列（每步写「上一步结果 + 本次运算 → 本步结果」）③ 最终结果及其类型（数值 / 布尔）。完成标准 = 每步可独立复核，且不引入书中没有的运算符或内置函数。

## B — 边界 (Boundary) ★

### 不要在以下情况使用这张卡
- 要写 `if` / `while` 的判断逻辑本体时（用 `control-flow-and-loops`）
- 要把一个值转换成另一种类型时（类型转换不在本卡范围）
- 只想要一张运算符符号表——底本损毁，本卡给不出符号列

### 作者在书中警告的失败模式
- 书中把优先级解释为「哪一个运算符先计算，哪一个后计算」，与数学「先乘除、后加减」同理，同行由结合方向定顺序——不按这张表读，顺序只能靠猜（p08）
- 比较运算符的用途被限定为「通常用在条件语句中作为判断的依据」，离开该口径讨论它的返回值没有原文支持（p06）

### 作者盲点与底本缺口
- **算术运算符表与逻辑运算符符号列在底本中损毁**（unit_note / NR-05，v09 / task-13）：算术表只剩「实例 / 结果」交错行（`7%2` 与 `71/2` 连排、`2**4` 的结果写作「16，即24」），逻辑运算符被识别成「。（非）o（）（与）中o」、位运算符符号被识别成 `ΛΛ，VV`；故本卡**只给优先级顺序与展开形式，不重建这两张表的符号与实例值**。
- 比较与逻辑运算符的相对优先级只能按表尾行序说明（该行符号列被截断为「= 」），完整符号对照**本书未覆盖**；何时该加括号**本书未覆盖**。

### 容易混淆的邻近方法论
- `control-flow-and-loops`: 本卡检查表达式内部的求值顺序与结果类型，不检查分支结构是否正确。
