# 列表推导式三形态（range 生成 / 列表映射 / 条件筛选）

## R — 原文 (Reading)

> （1）生成指定范围的数值列表，语法格式如下： list = [Expression for var in range] 参数说明：
>
> ……
>
> （3）从列表中选择符合条件的元素组成新的列表，语法格式如下：
> newlist = [Expression for var in list if condition] 参数说明：
>
> — 第 5 章 · 列表与元组「必背必记 8．列表推导式」L905-939

## I — 方法论骨架 (Interpretation)

任何「要一批数据」的需求都能拆成三个空位：**从哪儿取值**、**每个元素怎么算**、**要不要筛**。三形态就是往同一句语法里填这三个空位：`[Expression for var in range]` 从范围生成数值列表；`[Expression for var in list]` 把已有列表逐项映射成新列表；`[Expression for var in list if condition]` 在映射之上加一道筛选，只留符合条件的元素。书中对三个参数只说一件事——Expression 是「表达式，用于计算新列表的元素」，var 是「循环变量」，第三形态多一个 condition。

判据是可数的：产出的是**新列表**，来源（range 或原列表）不被改动；形态①②的结果长度等于来源长度，形态③的结果长度等于满足条件的元素个数。先按长度核对，再逐项复算内容。

选型只问两个问题：取值来源是**范围**还是**已有列表**（决定 `in range` 还是 `in list`）、**要不要条件**（决定有没有 `if condition`）。三形态彼此不冲突，可以连着用——先按范围生成平方数，再对生成结果做筛选。

安全写法：先写出等价的 `for` 循环，循环体里只有一条「把新元素放进新列表」的语句，再把它压成一行。压不出来，说明循环体里其实做了不止一件事——那就不要用推导式，回到 `control-flow-and-loops` 的普通循环。

书中只给语法格式与逐参数说明，没有变量命名规范、没有反例、也没有与生成器的对比，这些不在本卡的知识范围内。

## A1 — 应用示例 (Application Example)

### 示例 1: 1 到 10 的平方列表，再筛出偶数
- **类型**: 合成演练（按原书规则构造，非作者案例）
- **问题**: 从 1 到 10 生成平方数列表，再从该列表中筛出偶数
- **怎么用**: 第一步用形态① `[x * x for x in range(1, 11)]`；第二步用形态③ `[x for x in 平方数列表 if x % 2 == 0]`。变量名 `x`、表达式与条件由本项目选取（书中只给 Expression / var / condition 占位符），形态本身完全照书
- **结果**: 第一步得 `[1, 4, 9, 16, 25, 36, 49, 64, 81, 100]`，第二步得 `[4, 16, 36, 64, 100]`（本项目纸面推演，书中未给结果）

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这张卡?
1. 要把一批数据一次算成新列表，手边却是一堆 `for` + `append`
2. 只要某个范围内的数（或这些数的平方、换算结果）
3. 要从已有列表里挑出符合条件的元素
4. 读不懂一段写成一行的高斯式写法，想还原成普通循环
5. 想确认推导式会不会改到原列表

### 语言信号
- 「一行搞定」「有没有更简洁的写法」「别写 for 循环了」
- 「挑出…」「只保留满足…的元素」「筛一下」
- 英文: "list comprehension", "one-liner to build a list", "filter into a new list"

### 与相邻能力的区分（阶段 3 定稿）
- 与 `list-and-tuple-operations` 的区别: 同一个「生成新列表」需求的两条路。那条给的是循环 + 方法（append/extend）的写法，也负责增删遍历统计；本卡只负责「一次算成新列表」的三种句式。要改原列表或做统计走那条，要一行生成/筛出新列表走本卡
- 与 `control-flow-and-loops` 的区别: 推导式的映射与筛选语义建立在 for 与 if 之上，但本卡不含 break/continue、不做多步循环体。流程控制与多步循环体走那条；推导式写不对时按 depends-on 回那条对一遍循环写法

## E — 可执行步骤 (Execution)

1. **定形态**
   - 完成标准: 明确两个问题——取值来源是范围还是已有列表、是否需要 if 条件——并落到形态①/②/③之一
   - 判停条件: 需要嵌套多层 for 或生成器表达式时，本书未覆盖，停下来向用户说明，改按标准库口径另议

2. **先写循环版**
   - 完成标准: 写出等价的 `for` 循环，循环体内只有一条「把新元素放进新列表」的语句

3. **压成一行**
   - 完成标准: 最终行形如 `[Expression for var in range]` 或 `[Expression for var in list if condition]`；Expression 中只出现循环变量与常量；不沿用书中占位符 `list` / `newlist` 当变量名

4. **验证**
   - 完成标准: 形态①②结果长度等于来源长度、形态③结果长度等于满足条件的元素个数；原列表与 range 未被改动
   - 判停条件: 长度对不上或原列表被改，回到 step 1 重新定形态

- **输入契约**: 必需「数据来源」（range 的起止，或原列表的当前内容）与「每个元素怎么算」（Expression 规则）；筛选场景另需 condition。缺任一项先问用户，不要替他挑变量名或猜数据。
- **输出契约**: 交付①选定的形态②一行推导式③等价 for 循环版④预期结果列表与长度。完成标准是长度校验通过、且每个元素都能按 Expression 手算复现。

## B — 边界 (Boundary) ★

### 不要在以下情况使用这张卡
- 循环体里要做多件事（打印、累加多个变量、改外部状态）——用 `control-flow-and-loops` 的普通循环
- 要原地修改原列表或做增删统计——用 `list-and-tuple-operations`
- 需要嵌套推导式或生成器表达式——本书未覆盖，不要凭本卡外推

### 作者在书中警告的失败模式
- 本单元没有失败侧证据（2 条候选都是正向语法格式与术语卡），书中未给反例代码与报错示例。
