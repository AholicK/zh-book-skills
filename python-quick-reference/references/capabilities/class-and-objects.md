## I — 方法论骨架 (Interpretation)

类是把「数据 + 行为」打成一个包，闭环三步：**定义类 → 创建实例 → 用点操作符调用方法**。

定义是 `class ClassName:` 后接类文档字符串与类体；类体**不能空着**，未定功能用 `pass` 占位。类名按书中惯例大写字母开头、两个单词时第二个首字母也大写（「驼峰式命名法」）。

实例方法就是「在类中定义的函数」：**第一个参数必须是 `self`**（位置强制），名字只是惯例。调用：`classname(parameterlist)` 创建实例，再 `instanceName.functionName(parametervalue)` 调用。

**计算属性**：`@property` 修饰 `def methodname(self):`——方法名小写开头且**最后作为创建的属性名**、方法体以 `return` 结束，对外按属性读、不加括号。**继承**写 `class ClassName(baseclasslist):`（多基类逗号分隔，不指定则用根类 `object`）；**重写**是在派生类里重定义同名方法。

判据：出现「数据成组反复传递」「一组函数共享同一批数据」「按种类分支不同行为」时用类。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这张卡?
1. 一批数据跟着几个函数到处传，想打包成一个「东西」
2. 想按种类（不同水果、不同角色）给出不同行为，而非到处写 `if`
3. 写 `class` 时不确定方法第一个参数要不要写 `self`

### 语言信号
- 「怎么定义一个类？」「实例方法为什么要写 self？」「@property 是什么？」
- 英文: "define a class in python", "self in python", "inherit from a class"

### 与相邻能力的区分（阶段 3 定稿）
- 与 `function-definition-and-call` 的区别: 本卡只多两条约束——**第一个参数必须是 `self`**（位置强制）与**类体不能空**；代码里出现 `self` / `class` / `@property` / 继承时用本卡。
- 与 `gui-window-construction` 的区别: 窗口与控件都是类的实例，那边的方法用点操作符调用、parent 逐层传递；本卡只管类与实例的写法。

## E — 可执行步骤 (Execution)

1. **判断该不该用类**
   - 完成标准: 说出至少两项会一起出现的「数据」与一个操作它们的行为；三项迹象（成组传递的数据 / 一组函数共享同一批数据 / 按种类分支不同行为）至少命中一条；只是「一段逻辑复用一次」时改用 `function-definition-and-call`

2. **定义类并写实例方法**
   - 完成标准: `class 类名:` + 类文档字符串 + 非空类体（未定功能用 `pass` 占位）；每个方法写成 `def 方法名(self, 其他参数):`，第一个参数位置必须是 `self`

3. **按需要添计算属性 / 继承 / 重写**
   - 完成标准: 现算的值写成 `@property` + `def 方法名(self):`（属性名取自方法名、以 `return` 结束、调用处不加括号）；复用写 `class 子类名(基类名):`，只在派生类里重定义同名方法
   - 判停条件: 要给属性赋值 / 删除，或需要 `__init__` 写法、`super()`、类方法时停下，标注**本书未覆盖**

4. **实例化与调用**
   - 完成标准: `实例名 = 类名(实参)` 创建实例，`实例名.方法名(实参)` 调用（实参个数对得上 parameterlist），计算属性用 `实例名.属性名` 读

- **输入契约**: 数据清单 + 操作清单 + 是否有「种类不同行为不同」的分支 + 创建实例是否需要初始数据；缺清单先问用户；要求 `__init__` 写法 / `super()` 时先说明本书未覆盖。
- **输出契约**: 交付 ① 类定义 ② 实例方法（含 `self`）③ 计算属性（如有）④ 派生类与重写（如有）⑤ 实例化与调用示例。完成标准 = 每个方法第一个参数都是 `self`、类体非空、计算属性以 `return` 结束。

## B — 边界 (Boundary) ★

### 不要在以下情况使用这张卡
- 只需要一段可复用逻辑时（用 `function-definition-and-call`）；要写界面时（用 `gui-window-construction`）
- 需要 `__init__` 的参数写法、`super()`、类方法 / 静态方法、多继承 MRO 时——**本书未覆盖**，不得据残片外推

### 作者在书中警告的失败模式
- 实例方法漏写第一个参数：书中明写「实例方法的第一个参数必须是 self，并且必须包含一个 self参数」（ce10 / f17，引文见 R 段）——漏的是**位置**，不是名字
- 类体空着：规避办法是「如果在定义类时，没想好类的具体功能，也可以在类体中直接使用pass语句代替」（ce11）
- 在基类动手改行为：要按种类区分就得在派生类中重写同名方法（f20），改基类会波及全部子类

### 作者盲点与底本缺口
- **`__init__` 的参数写法未覆盖**（unit_note / NR-04，v12 / task-17）：示例里下划线丢失，构造函数本流水线不外推；**`super()`、类方法 / 静态方法、多继承 MRO（g13）均未覆盖**；**`@property` 只讲读**（g12），setter / deleter 未覆盖。
- 命名规范只在**类名**上讲（驼峰式，g10），函数 / 变量命名风格**本书未覆盖**。
- 示例（c06）是本书唯一一段面向对象的完整示例，缩进与下划线在 OCR 中丢失，**不得据残片复原可运行代码**（NR-15）。

### 容易混淆的邻近方法论
- `function-definition-and-call`: 两卡共用 `def` 写法，差别只在第一条参数与类体约束。
