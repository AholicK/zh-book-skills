## I — 方法论骨架 (Interpretation)

切片回答一个问题：**"我要这个序列里从哪儿到哪儿的那一段"**。作者把它写成一套三参数语法，并强调列表、元组、字符串同形——所以只需要记一次口径，不必按类型记三遍。

三个默认值决定绝大多数用法：**start 默认 0 且含该位置**；**end 默认序列长度且不含该位置**；**step 默认 1，省略步长时最后一个冒号也可以省略**（于是可以写成 `[start:end]`）。"含起点、不含终点"最反直觉，也最容易出 off-by-one——`[0:3]` 拿到的是前三个元素，不是前四个。

第二条关键性质是副作用：切片**生成一个新的序列**，原序列不动。要一份"摘出来的副本"就用切片，要改动原序列本身属于另一类操作（`list-and-tuple-operations`）。这也解释了为什么元组与字符串同样能切片：它不修改任何东西。

判据压成三句：要"取一段"而不是"改一处"→ 用切片；区间是"从第 i 个到第 j 个之前"→ 写 `[i:j]`；要隔几个取一个 → 用 step。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这张卡?
1. 要把字符串/列表里的一段取出来（前几位、中间一段、每隔几个取一个）
2. 切片结果"少一个/多一个"，怀疑下标写错
3. 想确认切片会不会把原来的列表或字符串改掉
4. 看到别人写的 `x[1:5:2]`，要读懂它到底取了哪几个元素

### 语言信号
- 「取前几个字符」「从第几个到第几个」「每隔一个取一个」「截取字符串」
- 「切片怎么少了一个」「为什么没包含最后那个」「这样切会不会把原列表改掉」
- 英文: "slice this", "take the first N characters", "substring", "is the end index exclusive?", "does slicing copy the list?"

### 与相邻能力的区分（阶段 3 定稿）
- 与 `list-and-tuple-operations` 的区别: 同一句"处理这个列表"里可能有两种诉求——本卡只管"取出一段"（只读、不改原序列），增删改与统计（追加、计数、求和、带序号遍历）归 `list-and-tuple-operations`；出现"往里加/减/数一数"就转过去
- 与 `string-encoding-split-join` 的区别: 拆分/合并是"按分隔符切碎或拼起来"，本卡是"按位置区间取一段"；实际任务常连用——先按分隔符拆出字段，再对字段用切片截取需要的范围

## E — 可执行步骤 (Execution)

1. **确认对象与区间**
   - 完成标准: 写下①序列名与类型（列表/元组/字符串）②用自然语言说清要哪一段（"从第几个到第几个之前""每隔几个"）
   - 判停条件: 若诉求是"改这个序列"（增删改元素）而非"取一段"，转 `list-and-tuple-operations`，本卡不再往下走
2. **把区间翻成三参数**
   - 完成标准: 写出 `名字[start : end : step]`，逐参数说明取值理由——start = 要取的第一项的位置（含）、end = 取到哪一项**之前**（不含）、step = 每隔几项取一个；用默认值的参数显式标"省略"
3. **校验边界（防 off-by-one）**
   - 完成标准: 按"含起点不含终点"复算——结果第一项等于 start 位置的元素；若 end 指向第 j 项，结果最后一项必须是第 j 项**之前**那个；元素个数与区间长度一致
4. **声明副作用**
   - 完成标准: 明确写出"原序列未被修改"（切片生成新的序列）；若后续代码依赖原序列的顺序或长度，此处再确认一次无就地改动
5. **交付**
   - 完成标准: 按下方输出契约给出表达式、三参数表与复算结果，且复算结果与表达式取值一致

**输入契约**：①序列变量名与类型；②要取的范围（自然语言；用户说"前 N 个/取到第 N 个"时必须澄清 N 是否含在结果内）；③原序列后续是否还要用（本卡默认不改动它）。缺失时先问，不要默认 start=0、end=末尾。

**输出契约**：①一行切片表达式；②三参数取值表（参数 / 取值 / 是否用默认值 / 理由）；③复算结果（元素个数 + 首尾元素）；④"原序列是否改变"的声明。完成标准：复算的首尾元素与表达式取值一致，"含起点、不含终点"被显式写出。

## B — 边界 (Boundary) ★

### 不要在以下情况使用这张卡
- 要修改序列本身（追加、删除、替换元素）——切片只能得到副本，改内容用 `list-and-tuple-operations`
- 要"按条件筛选或逐元素变换出另一个序列"——优先 `list-comprehension`
- 要按分隔符把字符串切碎、或把多段拼起来——转 `string-encoding-split-join`

### 作者在书中警告的失败模式
- 作者没把切片写成失败模式清单，但对性质有两处明确交代：**「通过切片操作可以生成一个新的序列。」**与三参数边界口径（start 含、end 不含）。据此两种最常见错法都不成立：①以为切片改动了原序列；②以为 end 是"取到该位置"（结果会多一个元素）

### 作者盲点与底本缺口
- 负索引与逆序切片书中未讲——**本书未覆盖**（unit_note）；本卡不含 `[-1]`、`[::-1]` 一类写法
- step 取负值、start 大于 end、end 超出序列长度等边界情形书中未讲——**本书未覆盖**，不要据本卡推断
- 第 5 章 L741-757 与第 7 章 L1139-1153 的参数说明逐字同构，按一处证据计（NR-16）
- 底本为 OCR：参数说明被折行切开、引文末尾是断句（NR-15），引用时照抄、不要据断句推断缺失内容

### 容易混淆的邻近方法论
- `list-and-tuple-operations`: 都在列表/元组上操作，分界线是"只读取一段（不改）" vs "改变内容或做统计"
