## I — 方法论骨架 (Interpretation)

列表排序只有一个真问题：**排完之后，原来那个列表还能不能用**。书里把两条路分开写清，判据就一条——

- `listname.sort(key=None, reverse=False)`：对**原列表**排序，排序后原列表中的元素顺序发生改变。
- `sorted(iterable, key=None, reverse=False)`：**原列表的元素顺序不变**，返回排序后的结果。

两个参数的口径两处同构：`key` 表示"从每个元素中提取一个用于比较的键"（书中例子 `key=str.lower`，表示排序时不区分字母大小写）；`reverse` 为 True 表示降序、False 表示升序，**默认为升序**。

选型可以固定成一句话："这份原顺序后面还要用吗？"——要，就用 `sorted` 拿一份新结果；不要（或就是要就地排），才用 `sort`。ce05 记的失败模式正是跳过这一问的后果：本想排副本，却调了 `listname.sort()`，原列表被改掉。

另有一处来自书中写法的边界：作者把 `sort` 写成**列表对象**的方法，而 `sorted` 的参数写成 `iterable`——对元组、字符串这类对象，书中只给了 `sorted` 的口径。

## A1 — 应用示例 (Application Example)

原书未提供案例：本单元 3 条候选（f09 两条路对比、p13 参数口径、ce05 失败模式）都是规则，没有带编号的原书示例；书中唯一的"例子"是规则内嵌的 `key=str.lower`。下面两条都明确标记为合成演练。

### 示例 1: 要降序、但原顺序不能动 / 就地升序
- **类型**: 合成演练（按原书规则构造，非作者案例）
- **问题**: 给定 `nums = [3, 1, 2]`，①要一份降序结果但 `nums` 原顺序不能变；②要把 `nums` 本身排成升序
- **怎么用**: ①走 `sorted`（原列表元素顺序不变），要降序加 `reverse=True` → `sorted(nums, reverse=True)`；②走 `nums.sort()`（明确允许改原列表），`reverse` 用默认升序
- **结果**: 书中未提供该任务的输出；按书中口径复算为 ①`[3, 2, 1]`，且 `nums` 仍为 `[3, 1, 2]` ②`nums` 变为 `[1, 2, 3]`。纸面推演，未在解释器执行

### 示例 2: 不区分大小写的升序（用书中给出的那个键）
- **类型**: 合成演练（按原书规则构造，非作者案例）
- **问题**: 对 `['Apple', 'banana', 'Cherry']` 做**不区分字母大小写**的升序
- **怎么用**: 键取书中例子 `key=str.lower`；只要结果、不改原列表，所以用 `sorted` → `sorted(['Apple', 'banana', 'Cherry'], key=str.lower)`
- **结果**: 书中只说明 `key=str.lower` 的语义、未给输出；按该语义复算为 `['Apple', 'banana', 'Cherry']`——转小写后按 apple / banana / cherry 比较，恰好与原顺序相同，原列表未变（纸面推演）

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这张卡?
1. 要把列表排成升序/降序，不确定会不会改掉原列表
2. 排完后还要用原来的顺序（做对比、做展示），结果发现原列表被改了
3. 要对一组字符串做不区分大小写的排序，或按元素的"某个键"排序
4. 拿到别人写的 `x.sort()` 或 `sorted(x)`，要判断哪个合适

### 语言信号
- 「排个序」「升序/降序」「从大到小」「排序之后原来的列表怎么变了」
- 「不想改原列表」「保留原顺序」「按字母排序不区分大小写」
- 英文: "sort this list", "ascending / descending", "in-place sort", "sort without modifying the original", "case-insensitive sort"

### 与相邻能力的区分（阶段 3 定稿）
- 与 `list-and-tuple-operations` 的区别: 两者都作用在列表上，但本卡只回答"做不做就地改动"这一个选型问题；追加、计数、求和、带序号遍历都归 `list-and-tuple-operations`。实际任务里排序常是列表处理链上紧接着统计/追加的一步，先按本卡定方法、再回到那条链上
- 与 `function-definition-and-call` 的区别: 本卡的 `key` 需要一个"从元素提取比较键"的函数；传什么函数（书中例子 `key=str.lower`，或一个临时小函数）属于 `function-definition-and-call`，本卡只把这个参数的语义与取值口径说清

## E — 可执行步骤 (Execution)

1. **确认对象与"原顺序还要不要用"**
   - 完成标准: 写下被排序对象的变量名与类型（列表/元组/字符串），并用"是/否"明确回答"原顺序后面还要不要用"。这一项缺失时必须先问，不能默认
2. **定方法**
   - 完成标准: 允许改原对象且对象是列表 → 写 `listname.sort(...)`；需要保住原顺序、或对象不是列表 → 写 `sorted(iterable, ...)`；并写出理由就是第 1 步的那个答案
3. **定参数**
   - 完成标准: 只有需要降序才写 `reverse=True`（不写即默认升序）；需要"不按元素本身比较"时写出键，并说明这个键从每个元素里提取什么（书中口径的键例是 `key=str.lower`），同时标注键函数本身的写法属于 `function-definition-and-call`
4. **校验**
   - 完成标准: 选了 `sort`——确认后续代码不再依赖原来的顺序，或已明确接受被改；选了 `sorted`——逐项确认原对象在调用前后相同
5. **交付**
   - 完成标准: 按下方输出契约给出调用、选型理由、参数表与复算结果，"是否修改原对象"的声明与所选方法一致

**输入契约**：①被排序对象的变量名与类型；②元素样例（至少 3 个，供复算）；③排序依据（元素本身，还是其某个属性/大小写处理）；④升序还是降序；⑤**原顺序是否还要用**（关键项，缺失必须先问）。不要默认升序，也不要默认就地排序。

**输出契约**：①一行调用；②选型理由（原顺序是否保留）；③参数表（key / reverse / 取值理由）；④复算结果（排序后的元素顺序）；⑤"原对象是否被修改"的声明。完成标准：声明与实际选用的方法一致（`sort` 改、`sorted` 不改），复算结果符合参数口径（不写 `reverse` 即升序，`reverse=True` 才降序）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用这张卡
- 要按多个关键字、或按自定义规则做复杂排序——**书中没有这些内容**（见缺口），本卡不提供
- 只是要取出列表里的一段连续元素——用 `sequence-slicing`
- 要统计次数、求和、追加、带序号遍历——用 `list-and-tuple-operations`，排序只是那条链上的邻居步骤

### 作者在书中警告的失败模式
- **本想排副本，结果改掉了原列表**：书中对 sort 明写「排序后原列表中的元素顺序将发生改变。列表对象的 sortO方法的语法格式如下：」，对 sorted 明写「使用该函数进行排序后，原列表的元素顺序不变。stortedO函数的语法格式如下： sorted(iterable,key-None,reverse=False) 参数说明：」——这正是判据的两半。需要保留原顺序时用 `sorted`；用 `sort` 就得接受原列表被改

### 作者盲点与底本缺口
- 排序稳定性与多键排序书中未讲——**本书未覆盖**（unit_note）；本卡不推演任何关于"稳定""多关键字"的说法
- `key` 参数书中只给了 `key=str.lower` 一个例子，其它键函数写法（含自定义键）**本书未覆盖**，本卡不扩展
- `sort`/`sorted` 的返回值细节（就地排序返回什么、返回结果的对象类型）书中未说明——**本书未覆盖**
- 元素为非 ASCII 字符（如中文）时排序结果如何，书中未涉及——**本书未覆盖**
- 底本为 OCR：`sortO`/`sortedO`/`stortedO` 与 `key-None` 是括号被识成 `O`、等号被识成连字符的现象（NR-15），引用时照抄

### 容易混淆的邻近方法论
- `list-and-tuple-operations`: 都作用在列表上；本卡只管"改不改原列表"的选型，内容增删与统计归那张卡
- `function-definition-and-call`: `key` 常要一个函数（如 `str.lower` 或临时小函数），函数怎么定义与传参归那张卡
