## I — 方法论骨架 (Interpretation)

这套东西解决日常最常做的五类列表动作：**造一个表、遍历它、往里加东西、从里面查东西、算它的统计量**。作者不讲原理，而是把方法名、参数与口径一次列清。

- **创建**：赋值创建 `listname = [element1, element2, …]`；空列表 `emptylist = []`；数值列表把 range() 的结果用 `list()` 转过来（`list(data)` 的 data 可以是 range 对象、字符串、元组或其他可迭代类型）。删除用 `del listname`——删的是**整个列表**，不是元素。
- **遍历**：只要元素值就写 `for item in listname:`（作者明说这种方式"只能输出元素的值"）；循环体里要用下标（打印序号、按下标回写）就写 `for index, item in enumerate(listname):`，它一次给出索引与值。
- **追加**：加"一个对象"用 `append(obj)`；要把另一个列表里的**全部元素**逐个接上去用 `extend(seq)`。这是本单元最容易记反的一处。
- **查询与统计**：`count(obj)` 数出现次数；`index(obj)` 取**首次出现**的位置。两者都只能**精确匹配**——书中明写 obj「这里只能进行精确匹配」，所以拿元素的一部分去查更长的元素不会命中。
- **求和**：`sum(iterable[,start])`，start 表示"统计结果是从哪个数开始（即把统计结果加上 start 所指定的数）"，未指定时默认为 0。
- **术语与选型**：`list()`/`str()`/`sum()`/`reversed()`/`enumerate()`/`sorted()` 六个内置函数的用途要先认得；元组用与列表几乎同形的两套方式创建（赋值 `(element1, element2, …)`、数值元组 `tuple(data)`），删除同样是 `del`。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这张卡?
1. 要统计某元素出现几次、或它在第几位
2. 要把一批数据逐个加到已有列表里，不知道用哪个方法拼
3. 遍历时要同时拿到序号和元素
4. 要按范围生成一串数字（列表或元组），或求和后还要加一个基数

### 语言信号
- 「这个元素出现了几次」「它在第几个位置」「下标是多少」
- 「怎么把另一个列表接到后面」「append 和 extend 有什么区别」「遍历的时候要序号」
- 英文: "how many times does X appear", "index of this element", "append vs extend", "enumerate with index", "list(range(n))", "sum with a starting value"

### 与相邻能力的区分（阶段 3 定稿）
- 与 `sequence-slicing` 的区别: 都在列表/元组上操作，但诉求不同——本卡是"改变内容或做统计"（追加、计数、求和、带序号遍历），`sequence-slicing` 是"只读取一段、不改原序列"；出现"取第几个到第几个"就归切片
- 与 `sort-vs-sorted` 的区别: 排序是列表处理链上紧接着统计/追加的一步，但"改不改原列表"的选型单独成卡；本卡只负责把数据准备好、把结果数出来，不提排序口径
- 与 `list-comprehension` 的区别: 同一个"生成新列表"需求有两条路——循环里逐次追加（本卡的 append/extend）与推导式；元素多、规则简单用 `list-comprehension`，循环体里要做多件事用本卡的循环+追加
- 与 `dict-and-set-operations` 的区别: 序列与字典/集合常互转（去重、按键取值、items 遍历）；本卡只处理列表与元组本身，转换后按字典/集合的规则操作

## E — 可执行步骤 (Execution)

1. **把需求归类**
   - 完成标准: 归入 创建 / 遍历 / 追加 / 查询统计 / 求和 中的一类或多类，并写出目标列表名与元素样例（至少 3 个）
2. **选方法名与参数**
   - 完成标准: 追加类必须回答"加的是一个对象还是一整个列表"（一个 → `append`，一整个 → `extend`）；查询类必须确认查询值与元素是**精确相等**关系，不能按"元素的一部分"查；求和类必须确认有无基数（无 → start 用默认 0，有 → 写进 `sum(nums, 基数)`）
3. **选遍历方式**
   - 完成标准: 检查循环体是否用到下标——用到 → `enumerate` 版（索引、值两个变量）；只取值 → `for item in listname:`，并说明"直接遍历只能拿到值"
4. **创建与删除**
   - 完成标准: 空列表写 `[]`、按范围生成写 `list(range(...))`（元组同理 `tuple(...)`）；删除整个列表写 `del listname`，并声明"删的是列表不是元素"
5. **交付**
   - 完成标准: 按下方输出契约给出代码与表单，每个动作都对得上书中的参数口径，统计类结果可用样例数据复算

**输入契约**：①目标列表的变量名与元素样例（决定能否精确匹配、是否都是数值）；②要做的动作类型；③追加时给的是一个对象还是一个列表；④是否需要下标；⑤求和是否有基数。缺失时先问，不要默认用 `append`、不要默认 start=0。

**输出契约**：一段可读代码 + 一张表单（数据：列表名 + 元素样例 → 方法名与参数 → 结果）。完成标准：追加类已声明"一次加一个还是一批"；查询类已声明精确匹配；统计类结果能在样例数据上复算复现；`del` 的语义（删整个列表）被写明。

## B — 边界 (Boundary) ★

### 不要在以下情况使用这张卡
- 要取出序列中一段连续元素——用 `sequence-slicing`
- 要排序、或纠结"改不改原列表"——用 `sort-vs-sorted`
- 要按键取值、去重、集合运算——转 `dict-and-set-operations`

### 作者在书中警告的失败模式
- **用 append 拼整个列表**：书中对 extend 的用途明写「将一个列表中的全部元素添加到另一个列表中」，拼整表是 `extend` 的活；用 `append` 会把整个列表当成一个元素塞进去
- **拿元素的一部分去 index 查**：书中对 index 的参数口径明写 obj「这里只能进行精确匹配」（原句后半跨 OCR 折行断开，完整引文见 R 段）
- **以为 `del listname` 删的是元素**：书中「列表的创建和删除」给的是列表级删除，删掉的是整个列表

### 作者盲点与底本缺口
- 元组的不可变性与"单元素元组必须带逗号"书中未讲——**本书未覆盖**（unit_note、NR-04）；本卡只覆盖元组的创建与删除
- 列表元素级的删除写法（按值或按位置删除单个元素）在本书列表章节没有出现——**本书未覆盖**（NR-04 同节）
- `append`/`extend` 的返回值书中未说明——**本书未覆盖**
- 内置函数表在底本中被 OCR 压成单列、函数名与作用交错（如"作用 listO"），逐项对应需按语义核对（NR-15）
- 数据类型的转换只覆盖本节提到的几个函数；本书的类型转换表因列错位整体降级为 reference（NR-02），**本卡不引用该表**

### 容易混淆的邻近方法论
- `sequence-slicing`: 分界线是"只读取一段" vs "改变内容或做统计"
- `sort-vs-sorted`: 都作用于列表，但分属"处理"与"排序选型"两件事
