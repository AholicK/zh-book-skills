## I — 方法论骨架 (Interpretation)

本书把正则拆成三层材料，写模式串就是按顺序把三层拼起来：

1. **匹配什么（元字符）**：`.` 匹配除换行符以外的任意字符；`\w` 匹配字母或数字或下划线或汉字；`\s` 匹配任意的空白符；`\d` 匹配数字；`\b` 匹配单词的开始或结束；`^` 匹配字符串的开始；`$` 匹配字符串的结束。（符号与说明的对应是本项目按语义核对；底本此列已丢失。）
2. **重复几次（限定符）**：`?` 零次或一次（示例 `colou?r`）、`+` 一次或多次（示例 `go+gle`）、`*` 零次或多次；另有按次数限定的三类——恰好 n 次、最少 n 次、最少 n 次最多 m 次，书中以 `go(2)gle` 形式出现（OCR 把成对大括号识别成圆括号，本项目只作原样标注）。
3. **什么行为（标志）**：`A`/`ASCII`（书中注"仅适用于Python3.x"）、`I`/`IGNORECASE` 不区分大小写、`L`/`LOCALE`、`M`/`MULTILINE`（让 `^`/`$` 匹配每行的开始与结尾）、`S`/`DOTALL`、`U`/`UNICODE`、`X`/`VERBOSE`。

判据与读法：先问"要匹配什么字符"，再问"重复几次"，最后才加行为开关——反过来先加标志最容易写错。

**提醒**：本单元覆盖"模式串 + 标志"的构造，不覆盖调用（书中无 `re` 模块的调用函数）；花括号限定符只能照抄 OCR 的圆括号形态（`go(2)gle`），不重建。

## A1 — 应用示例 (Application Example)

### 示例 1: 同一词根的几种拼写，用限定符一次覆盖
- **类型**: 原书示例（残片）
- **问题**: 想让一个模式同时匹配 colour 与 color
- **怎么用**: 用 `?` 表示前面的字符零次或一次——书中给的 `colou?r` 就是"u 可有可无"；同一节的 `+` 示例是 `go+gle`，匹配范围从 gogle 到 goo...gle
- **结果**: 书中给出的就是匹配范围（colour 和 color；gogle 到 goo...gle），非运行输出

### 示例 2: 数字开头的字母数字串（忽略大小写）
- **类型**: 合成演练（按原书规则构造，非作者案例）
- **问题**: 匹配"由一个数字开头的、长度不定的字母数字串"，并要求忽略大小写
- **怎么用**: 起点用 `^`（匹配字符串的开始）；数字用 `\d`；再接 `\w`（匹配字母或数字或下划线或汉字）；数量用 `+`；最后附 `I` 或 `IGNORECASE` 标志
- **结果**: 书中未说明（纸面推演）。演练**未写** `re.match`/`search` 调用（书中未给函数），也未用按次数限定的那一类

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这张卡?
1. 要写一条正则，但记不清 `\d`/`\w`/`\s`/`\b` 各匹配什么
2. 要限制重复次数：恰好 n 次、至少 n 次、n 到 m 次该用哪个限定符
3. 大小写、单行/多行、`.` 是否跨行，该挑哪个标志
4. 模式里有 `^` 与 `$`，想知道是按整串还是按行匹配
5. 抄来的正则跑不通，想确认底本这几行是否可读

### 语言信号
- 「\d 和 \w 有什么区别」「正则怎么表示重复 n 次」
- 「忽略大小写用哪个标志」「^ 和 $ 是不是按行匹配」
- 英文: "regex metacharacters list", "how to repeat n times in regex", "IGNORECASE flag"

### 与相邻能力的区分（阶段 3 定稿）
- 与 `string-encoding-split-join` 的区别: 两卡都会出现"字符串"。本卡产出**模式串与标志**；那条能力负责待匹配文本本身的编解码与拆分合并。相接处是转义：模式串里的反斜杠与普通字符串同规则，写模式时要共用那套口径

## E — 可执行步骤 (Execution)

**输入契约**：①目标文本长什么样（举 2–3 个应匹配与不应匹配的例子）②是否区分大小写 ③是否跨行。缺①时先要例子——没有例子就无法判定元字符选得对不对。

1. **定"匹配什么"** — 完成标准: 为每个字符位置写出对应元字符（`.`/`\w`/`\s`/`\d`/`\b`/`^`/`$`）
2. **定"重复几次"** — 完成标准: 为每个可变长度位置选一个限定符（`?`/`+`/`*`，或按次数限定的那一类），并像书中那样给出"它能匹配到的范围"（如 `go+gle` → gogle 到 goo...gle）
3. **定"什么行为"** — 完成标准: 列出所加标志（`I`/`M`/`S`/`X` 等），每个说明解决了哪个具体问题；用 `A` 时一并标注它仅适用于 Python3.x
4. **回读一遍模式串** — 完成标准: 用第 1–3 步的分层读法与第 2 步的范围逐一比对，确认没有把限定符当元字符用
5. **声明边界** — 完成标准: 交付物中不出现 `re.match`/`search`/`sub` 等调用（书中未给，NR-13）；若用了按次数限定的那一类，标注"底本中该处为圆括号形态（OCR）"

**输出契约**：交付物 = ①模式串（+ 所用标志）②三层分解说明（元字符/限定符/标志各一行）③匹配范围或应匹配样例。完成标准：任举 2 个应匹配、2 个不应匹配的例子，都能用第 2 步的范围说明解释得通。

## B — 边界 (Boundary) ★

### 不要在以下情况使用这张卡
- 要"跑一次匹配/替换"（`re.match`/`search`/`sub`）：书中未给 `re` 模块的调用函数（NR-13），**本书未覆盖**，不能凭本卡写出可执行代码
- 要分组捕获、贪婪/懒惰、lookahead、Unicode 属性：书中未讲
- 要精确次数限定符：底本里花括号被误识成圆括号（`go(2)gle`），只可原样标注，不得重建
- 只是切分/拼接文本 → `string-encoding-split-join`

### 作者在书中警告的失败模式
- 本节没有写成警告句的失败模式；可复算的只有限定符的匹配范围口径（`colou?r` → colour/color；`go+gle` → gogle 到 goo...gle）

### 作者盲点与底本缺口
- 元字符表的「代码」列整体丢失（只剩说明列，NR-13）——**底本此列不可读**，I 段的符号↔说明对应由本项目按语义核对
- 花括号 `{}` 被 OCR 识别成圆括号（NR-13）：引用时只作原样标注，不重建
- `re` 模块的调用函数缺失（`match`/`search`/`sub` 只出现在英语词汇栏，NR-13）——**本书未覆盖**
- 标志列与说明列同行交错、表格压成单列（NR-15），对应需按语义核对

### 容易混淆的邻近方法论
- `string-encoding-split-join`: 两者都处理字符串；本卡产出模式串与标志，那条负责文本的编解码与拆分合并
