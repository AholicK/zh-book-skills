## I — 方法论骨架 (Interpretation)

这套写法解决两件事：**让程序按条件走不同的路**、**让同一段语句重复执行**。它给的是一组"照着写就不会错"的形式与判序，不是原理。

**分支判序**：`if` 只判一次，真则执行、假则跳过；`if…else` 二选一；`if…elif…else` 从第一个表达式起逐个判真，全假才走 else。条件不必是字面量 True/False——只要是"表达式返回真还是假"，布尔值、变量、比较表达式或逻辑表达式都行。

**硬约束**：else 不可以单独成句，必须与保留字 if 一起使用。这是语法层面的边界，不是风格建议。

**循环选型**：条件已知（重复几次取决于条件何时变假）用 while——先判条件，真则执行循环体，**执行完重新判断**，为假才退出，因此循环体里必须有能改变条件的动作；对象已知（要遍历的东西是现成的序列）用 for——三要素是迭代变量（保存读出的值）、对象（任何有序的序列对象，如字符串、列表和元组）、循环体。

**跳出循环**：`break` 中断整个循环，`continue` 结束本轮、回到条件判断或取下一个元素；两者都写成"循环体里放一个 if，条件成立就调用"，while 与 for 各有一份写法。

**命名**：保留字不能用作变量、函数、类、模块和其他对象的名称，且区分字母大小写（True 是保留字，true 不是）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这张卡?
1. 要从头写"满足条件就做某事、否则做另一件事"的逻辑
2. 要重复处理一批数据，卡在"该用 while 还是 for""循环怎么停下来"
3. 循环里要提前收工或跳过某一项，分不清 break 与 continue
4. 写了 `else:` 报语法错，或想用 `class`/`if` 这类词当变量名

### 语言信号
- 「写个循环遍历一下这个列表」「满足条件就退出」「这一类跳过不处理」
- 「while 和 for 什么时候用哪个」「break 和 continue 有什么区别」「else 报错了」
- 英文: "loop over this list", "while vs for", "break out of the loop", "skip this item", "is this a reserved word?"

### 与相邻能力的区分（阶段 3 定稿）
- 与 `operator-precedence` 的区别: 条件只要"返回真或假"就能用；多个运算符混在一起时谁先算归 `operator-precedence`，本卡只管结构形状与跳出时机
- 与 `input-and-print` 的区别: 本卡产出控制结构本身，`input-and-print` 负责"人怎么把数据给程序、程序怎么把结果说出去"；能对话的小程序 = 两者相加
- 与 `list-comprehension` 的区别: 要"逐元素生成一个新列表"优先 `list-comprehension`；本卡的 for 是通用循环（循环体里可放任意副作用操作），推导式写错时要回看本卡的 for/if 语义
- 与 `exception-handling` 的区别: 同样是"处理意外"——if 判的是可预期的条件，`exception-handling` 捕的是运行期才可能发生的错误；不要用 if 去挡不可知的异常

## E — 可执行步骤 (Execution)

1. **定结构**
   - 完成标准: 用一句话回答"要重复吗？重复几次由什么决定？"——答"次数由条件何时变假决定"选 while；答"要遍历现成的序列"选 for；不重复则只写分支
2. **写分支**
   - 完成标准: 三种形态中选定一种并写全每个语句块；每个 else 上方都能找到配对的 if/elif；全文无单独成句的 else
   - 判停条件: 出现两种以上互斥情况时改用 `if…elif…else`，不要写成并列的多个独立 if
3. **写循环**
   - 完成标准: while 版——循环体内存在能改变条件表达式的动作；for 版——`for 迭代变量 in 对象:` 三要素齐全且对象可迭代。缺项时回第 1 步重新选型
4. **放 break / continue**
   - 完成标准: 每个 break/continue 都在循环体内、且位于某个 if 之下，该 if 的条件可判真假；调用点旁注明语义（break 中断整个循环、continue 结束本轮）
5. **命名与形式审查**
   - 完成标准: 逐个标识符对照书中保留字清单（第 2 章 L185-235）检查，无保留字被用作变量/函数/类/模块/对象名；大小写敏感已考虑（True 是保留字、true 不是）；OCR 全角写法没有进真实代码

**输入契约**：①要判断的条件（须能判真/假）；②要处理的对象的类型与内容（序列则给样例元素）；③是否要提前退出或跳过部分元素。缺任一项先问，不要默认"就是要遍历"或"循环一次就够"。

**输出契约**：一段可读的控制结构代码 + 一张"结构 → 判据"表单（字段：结构、进入条件、循环体是否改变条件、break/continue 位置与语义）。完成标准：能按书中判序逐句复述执行顺序，且第 5 步命名审查通过。

## B — 边界 (Boundary) ★

### 不要在以下情况使用这张卡
- 运行期才可能出现的错误（文件不存在、网络失败、类型不匹配）——那属于 `exception-handling`；用 if 去挡只会把问题推迟
- 目标是"逐元素生成一个新列表"——优先 `list-comprehension`
- 只想知道"表达式为什么这样算"（运算符先后）——转 `operator-precedence`

### 作者在书中警告的失败模式
- **else 单独使用**：书中原话「在使用else 语句时，else一定不可以单独使用，它必须和保留字 if一起使用。」——让 else 独立成句是语法级错误
- **保留字当标识符**：书中明写「不可以把这些保留字作为变量、函数、类、模块和其他对象的名称来使用」，且「Python中所有保留字是区分字母大小写的，如下表所示」——`class`/`if`/`None` 不能当名字；`True` 是保留字而 `true` 不是（用什么报错，书中未给报错名）

### 作者盲点与底本缺口
- for-else、死循环（恒真条件）、嵌套控制流（含嵌套 break/continue 的作用范围）书中未讲——**本书未覆盖**（unit_note）
- 保留字清单未标注与 Python 版本的对应关系（async/await 是否在列无法核验）、使用保留字或单独 else 报什么错——**本书未覆盖**
- 第 1 章「必背必记 1-8」与第 4 章 L597-695 是同文重出（NR-16），本卡按一处证据计
- 底本为 OCR：折行与符号误识（`a>band a！=c`、全角冒号、`printO`）使引用保真度受限（NR-15）

### 容易混淆的邻近方法论
- `operator-precedence`: 都出现在"条件为什么这样判"的场景；本卡给结构与判序，它给运算符先后
- `exception-handling`: 都叫"意外处理"，分界线是可预期 vs 不可预期，混用会让异常被静默吞掉

## 相关能力（阶段 3 定稿）

- composes-with: `operator-precedence`（条件的判序要先看运算符优先级）
