# 系统思维：商业模式是利益相关者的交易结构

## R — 原文 (Reading)

> 什么是商业模式？就是利益相关者的交易结构。…要素，是系统中你看得见的东西；关系，是系统中你看不见的、要素之间相互作用的规律。我们要看到要素，看到要素之间的关系，更要看到这些关系背后的规律。……
>
> 在上述商业模式中，写字楼餐厅与顾客的交易结构是：用租金买流量。……
>
> 但是，方向不对，努力白费，在错误的赛道上一路狂奔，越努力，毁灭的速度越快。
>

## I — 方法论骨架 (Interpretation)

系统观的第一句话：**要素是看得见的，关系是看不见的，而关系背后的规律才是要看的**。把这条眼光落到生意上，作者给出商业模式的还原式定义——商业模式 = 利益相关者的交易结构。

- 洞察顺序：先列利益相关者（顾客、供应商、房东、平台、员工……谁参与），再看他们之间交换什么（书中案例里的交换物是「流量」），最后看这组关系形成什么规律（「旺铺」的本质是人流）。
- 一个骨架案例：写字楼餐厅的传统交易结构是「用租金买流量」——用高租金换写字楼人流；外卖平台出现后结构变了，顾客不再下楼，还把力气全押在临街旺铺上就会「方向不对，努力白费」。看懂结构的人会改在方圆 3 千米内租便宜的地方（甚至做成大厨房、砍掉前厅省 80% 租金），把省下的成本放进优惠与产能。
- 规律可以推演新载体：看透「旺铺=人流」后，就能顺着载体的变化往下推演（PC 电商 → 移动电商 → 直播……），从未来倒推今天的布局——「所有的战略，都是站在未来看今天」。

一句话：产品思维与用户思维解决「做得对不对」，系统思维解决「在哪做、和谁交易」。

## A1 — 书中的应用 (Past Application)

### 案例 1: 写字楼餐厅——从「用租金买流量」到外卖改写结构
- **类型**: 书中演练（第2章）
- **问题**: 外卖平台出现后，写字楼餐厅的生意为什么越来越差？
- **方法论的使用**: 作者作结构分析——租临街旺铺的旧结构是「用租金买流量」；外卖 App 出现后交易结构改变，顾客不再下楼，继续在产品与用户思维上加码也止不住客流减少
- **结论**: 懂系统思维的人改为在方圆 3 千米内租便宜的地方（甚至做成大厨房、砍掉前厅省 80% 租金）放大优惠与产能；不懂的人在错误的赛道上越努力越糟
- **结果**: 作者推演的结果（教学分析；「省 80% 租金」等数字未注明出处）

### 案例 2: 做人力资源外包的老友错失转型
- **类型**: 书中转述（第2章）
- **问题**: 一位在 IT 鼎盛期做人力资源外包成功的老友，因大量雇人早已体察到中国人力成本上升，却没有把体察转成对时代的判断
- **方法论的使用**: 他习惯从「个位」（管理）找原因，用提高管理效率对冲成本上升——作者评价：像用汤勺给下沉的船外舀水
- **结论**: 在「个位」上的努力对抗不了「千位」上的变化；等微观体察变成所有人的共识时才醒悟，已错失最好的转型机遇
- **结果**: 后来他把人力资源团队迁到印度，整体成本下降三分之一；仍与很多新机会擦肩而过

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 生意/业务增长停滞，越努力越差，怀疑「是不是我做得不够好」
2. 要设计或复盘一块业务的赚钱方式（谁付钱、谁履约、钱怎么流）
3. 行业出现新平台或新渠道（外卖、直播、AI 工具），判断要不要换打法
4. 听懂了一个「趋势」，想把趋势翻译成自己生意里的动作
5. 想给「为什么输了」找原因：是执行不行，还是这件事本身错了

### 语言信号

- 「我做得更努力了，顾客反而更少了」
- 「产品没问题、用户也满意，但就是不赚钱」
- 「是不是这个行业的玩法变了」
- 「看不出来问题出在哪」
- 英文: "we work harder but do worse", "the game has changed", "where's the disconnect"

### 与相邻 skill 的区分

- 与 `system-five-blocks` 的区别: 两种系统视角——那条拆系统内部的连接关系（变量、因果链、回路、滞后），回答「系统为什么这样运转」；本 skill 画利益相关者的交易结构，回答「这门生意的钱与人怎么连」
- 与 `life-business-model` 的区别: 两个「商业模式」含义不同——本 skill 指利益相关者的交易结构（生意层）；`life-business-model` 指个人能力×效率×杠杆（个人层），不要互串

## E — 可执行步骤 (Execution)

1. **列利益相关者**
   - 完成标准: 写出这笔生意/业务的所有参与方（顾客、供应链、房东、平台、员工、渠道……），先列全再分析
   - 输入契约: 一块具体业务（在做的或要做的）

2. **列交易内容**
   - 完成标准: 逐对参与方写清「谁给谁什么、换回什么」；交换物清单由使用者按业务自定（书中案例涉及的是「流量」，其余维度原书未给定）
   - 输出契约: 一张「参与方 × 交易内容」的清单

3. **找结构性断点**
   - 完成标准: 检查各条交易关系是否还成立——有没有新载体（平台/渠道/技术）已经改写了某条关系（如「人流不再来自临街旺铺」）；标出被改写的关系
   - 判停条件: 若所有关系完好、问题只出在执行细节，转常规执行复盘（本卡不适用）

4. **给改造点**
   - 完成标准: 针对断点给出结构改造动作（换位置、换渠道、换交易对象、换分成方式），并说明预期省下/增加的资源流向哪里
   - 输出契约: 改造点清单 + 一句方向判断（这件事本身是否已错——「有时候不是你不努力，而是这件事本身就错了」）

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 结构性证据不足时硬下结论：本单元证据偏薄（9 条候选），结论强度低于高证据单元，宜作视角而非定论
- 用交易结构替代执行与人：结构对了也要靠执行落地；案例中的老友也说明「人的判断与决心」同样是变量
- 与 `system-five-blocks` 混用：两边都叫「系统思维」，但一个拆连接关系、一个画交易结构，混讲会让问题失焦

### 作者在书中警告的失败模式

- 有产品思维、用户思维，缺系统思维——结构变了还在原路加码（更真诚的微笑、更好吃的饭菜、更豪华的装修），顾客依然越来越少（ce117）
- 「方向不对，努力白费，在错误的赛道上一路狂奔，越努力，毁灭的速度越快」
- 「我不知道我们做错了什么，但是我们输了」——不是你不努力，而是这件事本身就错了

### 作者的盲点 / 时代局限

- 证据偏薄：单元仅 9 条候选（framework 1 条、规则/格言 5 条、案例 2 条、反例 1 条），结构判断缺乏数据与失败对照
- 案例语境锚定在 2020 年前的平台经济（外卖、流量、旺铺租金）；「省 80% 租金」「成本下降三分之一」等数字未注明出处，使用时须自行核验
- 只讨论「结构对不对」，不讨论「谁有权力改结构」——利益相关者中的弱势方（如小餐厅面对平台）在书中未展开
- 「先改结构」不等于「不必管人」：与 `system-five-blocks` 的连接关系视角（系统=要素×连接关系）不矛盾，两者应并用；作者未讨论两套视角的优先级

### 容易混淆的邻近方法论

- `system-five-blocks`: 连接关系（内部机制）与交易结构（外部利益相关者）是两把透镜；先画交易结构定方向，再用五块积木拆机制
- `life-business-model`: 「商业模式」一词两层含义的边界所在——生意层 vs 个人层，引用时必须说明是哪一层
