# 假设—验证—结论—调整（反经验主义四步法）

## R — 原文 (Reading)

> 什么是“假设—验证—结论—调整”？就是在遇到问题时，先大胆假设，然后去验证，得出结论，最后根据结论做出调整。…在使用这套方法论时，我建议你要注意一点：就事论事，不要被立场左右。……
>
> 一是抛弃经验，放弃想当然，不要轻易下结论，要怀着空杯心态去看问题。
>
> — 第2章 思考问题的底层逻辑 · 普通和优秀的差距，在于解决问题的方式不同（L857-950、L937-949）

## I — 方法论骨架 (Interpretation)

经验失效的地方，正是这套四步法上场的地方。先看清经验不可信的三类情形：**幸存者偏见**（只看得见飞回来的飞机）、**成功者光环**（微软厉害，连员工用什么牙膏都值得研究）、**成败反转评价**（同一个做法，随企业兴衰被反向评价）。经验不靠谱，不是因为经验总是错的，而是因为在样本不全、光环加持之下，经验从未被检验。

四步是：**① 大胆假设 → ② 去验证 → ③ 得出结论 → ④ 根据结论做出调整**。二战飞机的标准走法：假设「应该给机翼加钢甲」→ 去看被击落飞机的中弹位置 → 结论「机头机尾中弹多，给机翼加甲作用不大」→ 调整「增加飞机头部和尾部的钢甲」。

两个纪律不可省：其一，**抛弃经验、放弃想当然、不要轻易下结论，怀着空杯心态看问题**；其二，**就事论事——从事实出发、对事不对人**，不被自己和他人的利益、立场所左右，「因为事实更可靠」。

这套方法论的本质，是「为了印证假设，而不辞辛苦、不嫌麻烦地去验证假设」。假设要写成能被事实推翻的句子，验证要覆盖「回不来的那一侧」样本——否则又掉回幸存者偏见。

## A1 — 书中的应用 (Past Application)

### 案例 1: 二战轰炸机弹孔与统计学家顾问
- **类型**: 书中转述（第2章）
- **问题**: 盟军轰炸机损失大，少部分返航的飞机机翼上布满弹孔；司令凭经验决定，用钢甲加强机翼
- **方法论的使用**: 担任盟军顾问的统计学家说：「司令，你看到机翼中弹还能飞回来，也许正是因为它很坚固。机头和机尾没有中弹，也许正是因为这些部分一旦中弹，飞机就飞不回来了。」司令大惊，赶紧派军队去战地检查飞机残骸
- **结论**: 被击落的飞机都是机头、机尾中弹——该加强的是机头和机尾；书中随即用这个案例走完四步：假设→验证→结论→调整
- **结果**: 战地检查证实了统计学家的判断（「被击落的飞机，已经永远无法开口了」——这正是只统计返航样本会错的证据）

### 案例 2: 微软「一个开发配备两个测试」与「用什么牌子牙膏」
- **类型**: 作者亲历（第2章）
- **问题**: 10 多年前，作者作为微软员工常被邀分享开发经验，其中很重要的一点是「一个开发配备两个测试」，许多人听完表示醍醐灌顶
- **方法论的使用**: 一次有人问「你们微软的员工都用什么牌子的牙膏？」作者答自己用黑人牙膏，提问者露出恍然大悟的表情，就好像在说「怪不得这么厉害」；大约 10 年后，作者再分享同一方法，很多人已经开始鄙夷微软：「太浪费资源，太不敏捷，太没有效率」
- **结论**: 牙膏和成功没有因果关系；「别人的成功经验当然重要，但是他给你分享的方法真的是让他成功的经验吗？适合不适合我们呢？」——不一定
- **结果**: 同一做法随企业成败被反向评价（10 年前被追捧、10 年后被鄙夷）

### 案例 3: 分析会开成追责大会（反例）
- **类型**: 书中反例（第2章）
- **问题**: 产品卖不出去，各部门开会讨论原因：产品部门说是销售、营销没做好；销售部门说是广告不够响；市场部门说预算不够、产品有瑕疵；质量部门说是生产没按作业指导书操作……扯皮、踢皮球
- **方法论的使用**: 书中判定：这样的扯皮会无论开多久都达不成共识、找不出解决方法。正确姿势是「对事不对人」——假设销售没卖好，就去验证「是所有销售人员都卖得不好，还是只有一部分卖得不好」，逐一验证假设
- **结论**: 「为了能真正解决问题，所有人都要秉持着对事不对人的态度来分析问题」；从事实出发，不被利益、立场所左右
- **结果**: 未说明（反例警示，无事件性结果）

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 业绩骤降、次品率上升、投诉变多这类「遭遇战」，团队急着找原因和办法
2. 手上只有成功者的经验、别家公司的方法论，想照抄又心里没底
3. 分析会上各部门开始互相甩锅，讨论跑偏成追责
4. 自己复盘时发现，手头的结论全靠「当时觉得」和「以往都这样」
5. 拍板前想先验证一个判断，而不是直接下注

### 语言信号

- 「以前都是这么干的，上次就没事」
- 「行业头部就是这么做的，照着学就行」
- 「先别急着定责，我们先看事实」
- 「这个结论是拍出来的，还是验出来的？」
- 英文: "that's how we've always done it", "let's validate the assumption first", "sounds like survivorship bias"

### 与相邻 skill 的区分

- 与 `axiomless-learning` 的区别: 那条「给每个模型找反例、先复述前提」是验证循环的输入端纪律；本 skill 处理「遇到具体问题」时的完整四步展开
- 与 `system-five-blocks` 的区别: 本 skill 是解题流程（假设→验证）；`system-five-blocks` 是问题结构分析（五块积木）——先立结构，再验证假设
- 与 `result-cause-model` 的区别: 本 skill 决定「怎么验证」；`result-cause-model` 决定「在哪一层动手」（结果/原因/模型）
- 与 `what-why-how` 的区别: 先重定义问题（那条），再立假设验证（本卡），避免解错题

## E — 可执行步骤 (Execution)

1. **立假设**
   - 完成标准: 把候选解释写成可证伪的一两句话（「应该给机翼加钢甲」式）；一个假设一句话，不写复合解释
   - 输入契约: 一个突然发生的问题 + 至少一个可检验的假设；用户给不出假设时，先请其列出「大家觉得可能的解释」

2. **设计验证**
   - 完成标准: 明确「去看什么样本、找什么证据、什么结果算推翻」；样本须覆盖「回不来的那一侧」（对抗幸存者偏见）
   - 判停条件: 常识即可判断、且验证成本高于收益的低风险场景 → 停用本卡

3. **执行验证**
   - 完成标准: 拿到第一手事实（「去战地检查飞机残骸」式），而不是转述与印象；原样记录实际看到的数据与事实
   - 判停条件: 验证过程中出现追责/扯皮迹象 → 先执行「就事论事」纪律（对事不对人），再继续

4. **下结论**
   - 完成标准: 结论只写被证据支持的版本；证据不足时写「未得出结论」，不用立场补空
   - 输出契约: ①假设 ②证据 ③结论；三者对齐，不允许结论超出证据

5. **调整 + 记录**
   - 完成标准: 给出调整动作（「增加机头机尾钢甲」式）并留档：假设、证据、结论、动作四件套，供同类问题复用
   - 输出契约: 一个明确的调整动作 + 一份复盘记录（含「下次怎么更快验证」）

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 常识即可判断、验证成本高于收益的低风险场景：四步法有成本，别用大炮打蚊子
- 纯创意发散/头脑风暴阶段：先发散后验证，别在生成假设的阶段就砍掉想法
- 没有可验证条件的问题（无法观测、无法取证）：本卡的前提是「不辞辛苦去验证」——验证无门时先改造问题，或明说局限，不要硬套

### 作者在书中警告的失败模式

- 幸存者偏见：只检查飞回来的飞机——「只有被击落的飞机才知道。但是，被击落的飞机，已经永远无法开口了」（ce18）
- 迷信成功企业经验：因为企业成功就认为它做什么都对（连牙膏都值得研究），把成功者分享的方法当成让其成功的原因照抄（ce19）
- 成败反转评价：同一做法随企业成败被追捧或鄙夷——反馈的是跟随成败的情绪，而不是做法本身是否成立（ce20）
- 把分析会开成追责大会：被利益和立场左右互相甩锅，「无论开多久都达不成什么共识」（ce21）

### 作者的盲点 / 时代局限

- 自反性：本书批判「经验不可信」，自身却是一部成功者经验的总结集——案例同样是幸存者样本（BOOK_OVERVIEW 批判节所指出的最有力反驳）
- 验证的成本与条件是隐含假设：派人去战地检查残骸、用 10 年跨度观察同一方法的遭遇，都需要资源与时间；对无法验证的环境（信息封闭、样本太小），书中未给替代方案
- 「就事论事」假设组织有心理安全：在追责文化里，第一个说出事实的人要承担真实风险，作者未讨论发言者如何自保

### 容易混淆的邻近方法论

- `system-five-blocks` / `result-cause-model`：都是解题工具，但一个给你「结构画面」、一个给你「动手层级」；本卡只保证一件事——结论是验出来的
- 「先收数据再找解释」的纯数据分析：本卡是假设先行——先立可证伪的假设，再去验证，避免在数据里挑故事
