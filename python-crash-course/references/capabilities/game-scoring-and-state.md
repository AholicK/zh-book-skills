# 记分、升级与游戏状态管理（第14章）

## R — 原文 (Reading)

> 为在屏幕上实时地显示得分，每当有外星人被击中时，我们都更新stats.score的值，再调用prep_score()更新得分图像。但在此之前，我们需要指定玩家每击落一个外星人都将得到多少个点：
>
> — 第14章 14.3.3 在外星人被消灭时更新得分（L19262-L19262）

## I — 方法论骨架 (Interpretation)

三条主线：**记分**（把战果换算成可显示的分数）、**升级**（节奏与点数随等级提高）、**状态**（哪些量每局重置、哪些跨局保留、结束后如何完整重开）。

状态先分归属：每局开始要复位的统计（命数 ships_left、得分 score、等级 level）初始化在 reset_stats()；跨局保留的量（最高分 high_score）放在 __init__()——「在任何情况下都不应重置最高得分」。会随游戏变化、重开又要归零的设置（三个速度因子、fleet_direction、alien_points）集中放进 initialize_dynamic_settings()，由 __init__() 先调用一次、开始新游戏时再调用一次。

重开是一份清单，不是一个开关：单击 Play 后按序执行——重置统计 → 进入活动状态 → 清空外星人与子弹 → 建新群 → 飞船居中 → 复位动态设置 → 刷新记分牌 → 隐藏光标。点击判定用「命中按钮 **且** 游戏非活动」双条件，避免游戏进行中误触重开。

计分公式：groupcollide 的返回值是字典，值为被同一颗子弹击中的外星人列表——遍历 collisions.values()，把「单个点数 × len(aliens)」累加进得分，才不漏掉一帧多杀。升级时节奏与奖励分开调：三个速度因子乘 speedup_scale，点数乘 score_scale 并取整。

显示：记分牌按「每种信息一对 prep_xxx() / show_score()」扩展；位置用锚点（当前得分在右上、最高分在顶部中央、等级在得分下方 10 像素）；显示口径 = 圆整到 10 的整数倍 + 千位逗号；剩余命数用图标编组绘制（Ship 需继承 Sprite 才能进编组）。

判据与纪律：重开后所有每局状态回初值、场上无残留、进行中点击无效；临时 print 确认后删除；最高分不落盘属已知缺口，如实标注、不假装已解决。

## A1 — 书中的应用 (Past Application)

### 案例 1: 单击 Play 开始游戏与误触防护
- **类型**: 原书例题（可运行示范）（第14章 14.1.3-14.1.6）
- **问题**: 游戏开始时要先把状态重置到可玩；按钮不可见时原区域被点会误触发重开。
- **方法论的使用**: MOUSEBUTTONDOWN 事件 → pygame.mouse.get_pos() → collidepoint 命中测试；把重置逻辑并入 check_play_button()（重置统计、清场、建新群、飞船居中），消除「只能玩一次」的问题；再改成「命中按钮 且 游戏非活动」双条件；开始游戏隐藏光标、结束时恢复。
- **结论**: 重置逻辑复用给「首次开始」与「结束后重开」两条路径；点击判定必须带上游戏状态条件。
- **结果**: 能开始游戏，游戏结束时重新显示 Play 按钮（L18672）；游戏进行中单击原按钮区域无影响（L18796）。

### 案例 2: 等级提升——速度与点数同步提高
- **类型**: 原书例题（可运行示范）（第14章 14.2）
- **问题**: 每清空一群外星人后，节奏与奖励如何递增，且不能把上一局的难度带进新局。
- **方法论的使用**: Settings 重组为静态（__init__）与动态（initialize_dynamic_settings）两组；新增 speedup_scale = 1.1；整群清空后调用 increase_speed()，把三个速度因子乘 speedup_scale；单击 Play 时调用 initialize_dynamic_settings() 复位速度。
- **结论**: 动态设置必须集中初始化、集中复位——否则新游戏会带着上一局加速后的值继续。
- **结果**: 每当玩家把屏幕上的外星人消灭干净后，游戏都将加快节奏、难度更大（L19030）。

### 案例 3: 击落外星人时更新得分（每个都计点）
- **类型**: 原书例题（可运行示范）（第14章 14.3.3-14.3.4）
- **问题**: 初版每轮只加一次分：一次循环里两颗子弹射中、或宽子弹同时击中多个外星人时，玩家只能得到一个外星人的点数。
- **方法论的使用**: 计分改为遍历 collisions.values()——每遍历到一个列表，就把 alien_points × len(aliens) 累加进 stats.score；随后重建得分图像；测试时把 bullet_width 临时设为 300 验证多目标计分，测完恢复。
- **结论**: groupcollide 字典的「值 = 被同一颗子弹击中的所有外星人列表」——只判断字典非空会丢掉数量信息。
- **结果**: 得分将不断增加（L19346）；宽子弹命中多个外星人时，将得到每个外星人的点数（L19390）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 要给游戏加得分、最高分、等级、剩余命数这类屏幕信息。
2. 游戏结束后无法重开，或重开后状态残缺（命数不满、得分与速度延续上一局）。
3. 游戏进行中误点按钮区域导致整局意外重开。
4. 清空一波后希望节奏加快、点数提高，但难度不能带到下一局。
5. 分数增长与击杀数对不上，需要核对「一帧多杀」是否都计了分。

### 语言信号

- 「怎么记分、怎么显示最高分」
- 「重开一局之后命数不是满的」
- 「第二局一开始速度就好快」
- 「点一下就把我的进度给重置了」
- 英文: "add a scoreboard / high score", "restart the game resets everything", "score doesn't count every kill"

### 与相邻能力的区分

- 与 `pygame-aliens-and-collisions` 的区别: 那张卡负责敌人群体与碰撞击杀、损失响应的机制；本卡在其上把「击杀 → 分数」「损失 → 命数」「结束 → 重开」的状态流接完。
- 与 `pygame-project-setup` 的区别: 骨架与设置容器由它搭好；本卡只处理「哪些统计/设置要分组与复位」以及界面信息的呈现方式。

## E — 可执行步骤 (Execution)

1. **状态盘点：给每个量分归属**
   - 完成标准: 逐项过一遍现有状态——每局重置的（命数、得分、等级）进 reset_stats()；跨局保留的（最高分）进 __init__()；动态设置（三个速度因子、方向、点数）进 initialize_dynamic_settings()。每个字段有唯一初始化处与唯一重置处，找不到归属的列入清单补齐。
2. **重开清单：单击 Play 的完整动作序列**
   - 完成标准: 点击判定 = collidepoint 命中 且 stats.game_active 为 False；命中后按序执行「stats.reset_stats() → game_active = True → 清空外星人与子弹 → create_fleet() → ship.center_ship() → initialize_dynamic_settings() → 刷新记分牌（得分/最高分/等级/命数图标）→ 隐藏光标」。
   - 判停条件: 连续开两局做核对——命数、得分、等级、速度都回到初值，场上无残留；游戏进行中点击按钮区域无任何影响。
3. **难度升级：速度与点数**
   - 完成标准: 整群清空后调用升级函数——三个速度因子乘 speedup_scale（默认 1.1）、alien_points 乘 score_scale（默认 1.5）并取整；重置点固定在 initialize_dynamic_settings()。
   - 输出契约: 每清空一群节奏加快、点数上升；重开一局从初值开始（不带上一局的加速）。
4. **计分：遍历碰撞字典逐个累加**
   - 完成标准: 遍历 collisions.values()，对每个列表按「alien_points × 列表长度」累加进得分；计分后立即重建得分图像，并与最高分比较（高于则更新最高分并重建其图像）。
   - 判停条件: 用宽子弹（或一帧多杀）验证每个被击中的外星人都计分；测试用参数测完恢复。
5. **显示层：记分牌结构与布局锚点**
   - 完成标准: 每种信息一对 prep_xxx()（生成并摆位）+ show_score()（统一 blit）；当前得分 right = 屏幕右边 − 20、top = 20；最高分 centerx 居中、top 与得分对齐；等级 right 与得分对齐、top = 得分 bottom + 10；显示口径 int(round(score, −1)) 加 "{:,}" 千位逗号；剩余命数用图标编组（Ship 继承 Sprite；x = 10 + 序号×宽、y = 10），损失后与重开时都重建。
6. **收尾：清理验证输出、核对难度曲线、标注缺口**
   - 完成标准: 临时 print 核实后全部删除；难度曲线符合「前几群容易清完、中段有难度但可完成、更靠后几乎不可能」的验收描述；未实现的项（最高分不落盘、按钮素材等）列入已知缺口，与实际功能一致。

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- 游戏不需要跨局状态（一次性演示、无重开需求）——分组与重置清单的复杂度可以省掉。
- 计分需要服务端校验、排行榜反作弊等场景——本书是本地单机口径，不能直接外推。
- 只有静态文字、没有状态变化的界面——用不上 prep_xxx 图像族与重置时机这套结构。

### 作者在书中警告的失败模式

- ce125: 只处理第一次单击 Play——第二局飞船数不是满的、场上残留上一局的外星人与子弹、得分与等级继续累加，「重开一次就坏一点」；每次开始都必须执行完整的重置清单。
- ce127: 新游戏沿用上一局被加速过的设置——动态设置只增不减，新手越玩越不可能赢；必须在开始新游戏时复位动态设置。
- ce131: 最高分只存在内存里，退出即归零——书中实现的最高分不落盘（练习 14-4 才要求写入文件并在初始化时读回，题面未给参考实现）。
- ce134: 难度与点数系数（1.1 / 1.5）没有客观标准，只能反复试玩调参；换一台帧率不同的机器手感还会不一样。

### 作者的盲点 / 时代局限

- 最高分持久化是原书自认缺口——本卡按内存版口径执行，并把「不落盘」如实标注为已知缺口，不假装已解决。
- round() 的返回类型随 Python 版本变化（ce130）：书中为兼容 2.7 与 3 保留了 int() 包裹，跨版本照抄会得到多余转换或小数显示。
- 全书是 2016 年技术栈快照（Python 3.5 / Pygame 1.9.2a0，Pygame 从 Bitbucket 源安装），安装、版本与平台流程须按现环境替换（2016 年快照）。
- 转档稿中图14-2~14-6 截图全丢、行内标记悬空（如「。处的代」），界面位置以文字与代码口径为准，不要向读者承诺截图内容。
