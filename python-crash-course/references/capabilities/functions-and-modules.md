# 函数与模块化（第8章）

## R — 原文 (Reading)

> 向函数传递实参的方式很多，可使用位置实参，这要求实参的顺序与形参的顺序相同；也可使用关键字实参，其中每个实参都由变量名和值组成；还可使用列表和字典。
>
> — 第8章 8.2 传递实参（L8785-L8785）

## I — 方法论骨架 (Interpretation)

函数是带名字的代码块：把一项工作写一次，之后用「函数名 + 括号」反复调用。定义由四要素构成——`def` 与函数名、结尾冒号、缩进的函数体、紧跟定义的三引号文档字符串；**形参**是定义括号里的变量，**实参**是调用时传入的信息，两者不能混用。

传参方式要按场景选择：位置实参最简，但顺序即语义，写反不报错、结果荒谬；关键字实参是「名称=值」对，顺序无关、意图清楚，代价是必须写准定义中的形参名；默认值让实参可省略、也标出函数的典型用法。两条排列硬规则：**没有默认值的形参排在前面**，**收集任意数量实参的形参（`*args` 收成元组、`**kwargs` 收成字典）放在最后**。

返回值不是打印：处理型函数用 `return` 把结果交回调用行、由变量接住，显示型函数才直接 print；返回值可以是简单值，也可以是字典、列表这类结构。让实参变成可选的标准做法是给默认值加「空字符串 + if 判断」。

列表以引用方式进函数：**函数内对它的修改是永久性的**；要保留原件就传副本 `list_name[:]`，但没有充分理由不要传副本——创建副本有时间和内存成本。设计上每个函数只负责一项具体的工作，发现任务太多就拆成两个函数，函数之间可以互相调用。

模块化再往前一步：把函数存进独立的 `.py` 文件（模块），主程序用 import 取用。导入写法有多种，作者的取舍是**要么只导入需要的函数，要么导入整个模块并用句点表示法**——星号导入可能让同名函数被静默覆盖。

## A1 — 书中的应用 (Past Application)

### 案例 1: describe_pet()——位置实参顺序写反后的排查
- **类型**: 原书例题（可运行示范，含有意写错）（第8章 8.2.1–8.2.2）
- **问题**: 顺序错乱时函数不报错、只是输出把两个字段的角色对调（得到「名为 Hamster 的 harry」）
- **方法论的使用**: ① 核对调用中实参的顺序与定义中形参的顺序；② 改用关键字实参 describe_pet(animal_type='hamster', pet_name='harry')，两个顺序不同的调用等效
- **结论**: 位置实参靠顺序对号入座，Python 无法分辨「这个值原本属于谁」；改用关键字实参则必须准确指定定义中的形参名
- **结果**: 正常调用输出 I have a hamster. / My hamster's name is Harry.；顺序写反时输出 I have a harry. / My harry's name is Hamster.；关键字实参两版调用均恢复正常输出

### 案例 2: get_formatted_name()——把繁重工作移进函数
- **类型**: 原书例题（可运行示范）（第8章 8.3.1）
- **问题**: 拼装整洁姓名这类工作散在主程序里，主程序被细节淹没
- **方法论的使用**: 函数内部拼 full_name 并 return full_name.title()；调用行写成 musician = get_formatted_name('jimi', 'hendrix')，再用变量打印
- **结论**: 返回值让程序的大部分繁重工作移到函数中去完成，从而简化主程序；作者以「直接打印 Jimi Hendrix」对照说明该函数在大型程序中的价值
- **结果**: 输出 Jimi Hendrix

### 案例 3: pizza.py 与 making_pizzas.py——五种导入写法
- **类型**: 原书例题（可运行示范）（第8章 8.6）
- **问题**: 把 make_pizza() 存进模块后，主程序如何取用
- **方法论的使用**: 依次演示 import pizza + 句点调用、from pizza import make_pizza、给函数起别名、给模块起别名、from pizza import *
- **结论**: 作者给出最佳做法——只导入需要的函数，或导入整个模块并使用句点表示法；并提醒星号导入可能造成同名覆盖
- **结果**: 各导入版本的运行输出相同（Making a 16-inch pizza with the following toppings: 与 - pepperoni 等）

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 同一段代码在程序里重复出现两三遍，想把它抽成一个函数、写一次反复调用
2. 函数调用后结果不对劲：输出把两个字段对调、数字对不上、缺参报错
3. 主程序文件越来越长，想把一批函数搬进独立文件，由主程序导入
4. 函数处理完列表，回到主程序发现原列表被清空或被改「花了」
5. 想给函数加可选信息（中间名、年龄、偏好项），又不希望每次调用都填全

### 语言信号

- 「这段代码重复了三遍，怎么抽成函数」
- 「参数好像传反了，输出驴唇不对马嘴」
- 「函数里 print 了，但我想把结果接着用」
- 「我把列表传进函数，出来就空了」
- 英文: "how do I define a function", "function returns None", "import from my own module doesn't work", "why is my list empty after the function call"

### 与相邻能力的区分

- 与 `classes-and-inheritance` 的区别: 本卡管无状态的过程封装（名字 + 参数 + 返回值）；一旦要把数据和操作绑成一体、要靠继承复用，转入类与继承
- 与 `files-and-exceptions` 的区别: 「把已有代码拆成函数」的单一职责动作属于本卡；那张卡负责文件读写与用异常兜住外部因素，重构只是它的落点之一
- 与 `unit-testing` 的区别: 本卡保证函数接口与行为正确（传参、返回值口径）；把「函数在各种输入下的行为」固化成测试用例、在改动时守住行为，属于那张卡

## E — 可执行步骤 (Execution)

1. **定义函数四要素**
   - 完成标准: `def` + 小写加下划线的描述性名称 + 括号（无参数也要写）+ 结尾冒号；函数体缩进；定义后紧跟三引号文档字符串，一句话说清它做什么
   - 输入契约: 先说清这个函数「只做哪一件事」，说不清就先拆

2. **确定形参表与排列规则**
   - 完成标准: 调用方必须提供的写成无默认值形参；可省略的给默认值并排在其后；收集形参（*args/**kwargs）放在最后；默认值等号两边无空格
   - 判停条件: 形参列表中一旦出现「先有默认、后无默认」的顺序，立即调整（ce54）

3. **选择传参方式并核对调用**
   - 完成标准: 位置实参按顺序、关键字实参写准形参名，每个调用点与定义逐项对得上；结果荒谬或报 missing N required positional arguments 时，按 traceback 清点实参个数与名字
   - 输入契约: 每个调用点的实参清单；输出契约: 调用行为与定义语义一致

4. **接住返回值，做好可选实参**
   - 完成标准: 处理数据的函数用 return 交回结果、调用行用变量接住，不用 print 冒充返回值；可选实参用「默认空字符串 + if 判断」；返回字典/列表时键名、字段写清
   - 判停条件: 调用方拿到 None 时，先查函数里是否真的执行了 return

5. **列表传参与副本决策**
   - 完成标准: 明确这个函数是「就地修改」还是「只读取」；要保留原件的调用改用 `[:]` 副本；为「是否传副本」写一句理由（原书口径：无充分理由就不传副本，避免时间与内存成本）
   - 输出契约: 调用后原列表的去留符合预期，且理由有记录

6. **拆模块并自检**
   - 完成标准: 模块 `.py` 只留要共享的函数（其余代码删掉）；主程序与模块同目录；导入取「只导入所用函数」或「import 模块 + 句点」，全文件无 `from … import *`；收尾按编写指南逐条核对——描述性命名、文档字符串、79 字符行长、函数间两空行、import 语句置顶
   - 判停条件: 两种导入写法调用结果不一致时，先查模块中是否有同名函数互相覆盖

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- 一次性的十几行流水账：不必强拆函数——作者的建议是「发现任务太多」再拆，而不是逢三行必成函数
- 数据与行为必须绑定成体系、还要层层复用：那已经不是函数问题，转入类与继承
- 需要跨项目安装、分发的库：原书只到「.py 模块」层级，包结构与分发流程超出本卡范围

### 作者在书中警告的失败模式

- ce53: 位置实参顺序错乱——不报错、不崩溃，只是结果荒谬（「名为 Hamster 的 harry」），错值被当成正常数据继续流动
- ce56: 函数内修改列表是永久性的——调用后调用方的 unprinted_designs 被清空，想留档的原件没了；要保留就传 `[:]` 副本
- ce58: `from module import *` 可能造成同名覆盖——多个模块的同名函数相遇时静默顶替，调用会执行「不是你写的那个函数」
- ce54/ce55/ce57 同批高频点：默认值形参前置会让位置实参无法正确对号入座；实参多于或少于形参都会触发 TypeError；收集形参（*args）一旦前置，后面的普通形参就永远收不到自己的实参

### 作者的盲点 / 时代局限

- 2016 年快照，按现环境替换：书中模块与导入按当年 Python 3.5 的默认行为写作——没有虚拟环境、没有包安装与依赖管理的工程口径；现代工程实践中的项目结构与运行方式请按现环境替换
- 「编写、阅读、测试和修复都将更容易」是作者的价值断言，书中未给对照证据
- 原书未给「函数多长、几个形参算合理」的量化标准，只给「发现任务太多就拆」这一个触发条件；也未讨论类型注解等现代写法
- 转档提醒：本卡依据的电子文本中，代码缩进被压平、页码行切断句子、行内标记 ❶❷❸ 丢失造成「见 处」悬空指代——回引示例代码请以原书排版为准
