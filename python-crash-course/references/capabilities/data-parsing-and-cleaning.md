# CSV/JSON 解析与清洗（第16章）

## R — 原文 (Reading)

> 原始数据的格式常常不统一，因此经常会出现错误。导致上述错误的原因是，Python不能直接将包含小数点的字符串'1127437398.85751'转换为整数（这个小数值可能是人口数据缺失时通过插值得到的）。为消除这种错误，我们先将字符串转换为浮点数，再将浮点数转换为整数：

## I — 方法论骨架 (Interpretation)

这条能力处理的是「别人生成的数据文件」——CSV 导出的气温记录、JSON 导出的统计——把它们变成程序能用的列表与字典。核心前提：**外部数据不保证完整、不保证格式统一**，所以每一步都要有核对与兜底。

**CSV 管线**：`csv.reader` 顺序读取（读掉表头后，循环从第二行实际数据开始）→ 用 `enumerate` 打印表头定位「要的字段在第几列」（不硬编码列名，因为表头里可能有空格和怪单位）→ 逐行取值并显式转换类型 → 日期用 `datetime.strptime(字符串, '%Y-%m-%d')` 解析成对象喂给图表。

**JSON 管线**：`json.load()` 把文件变成 Python 结构（本书是「列表套四键字典」）→ 先打印核对结构再筛选（值都带引号，年份比较用字符串 `'2010'`）→ 数值转换要分层：可能含小数点的字符串用 `int(float(x))` → 需要对照码表时用查表函数映射（命中即返回、循环后 `return None`），调用侧对查不到的显式登记。

**三个固定判据**：① **先打印核对、再进可视化**——进入图表之前必须亲眼确认捕获的数据形状正确；② **缺测数据逐行兜底**——打印缺失的日期/主键后继续下一行，而不是让整个程序停摆；③ **转换分层、映射兜底**——`str → float → int` 两步走，查表失败走 None 分支并打印 ERROR 清单。

数据质量问题分两类：**口径不对应**（有的记录不是国家，而是地区与经济类群）与**名称不一致**（Yemen, Rep. vs Yemen）；两者都要显式归因，再决定忽略、修补还是分档重画。

## A1 — 书中的应用 (Past Application)

### 案例 1: 缺失数据的错误检查——死亡谷天气数据
- **类型**: 原书例题（可运行示范）（第16章 16.1.10）
- **问题**: 同一程序换到死亡谷数据集立即崩溃：traceback 指出某天最高气温为空字符串，`int()` 无法转换，整张图一张也画不出来
- **方法论的使用**: 回查数据文件定位坏行（2014-2-16 一行除一个值外全为空）；把逐行循环改为 `try:` 解析日期与两个温度 / `except ValueError: print(current_date, 'missing data')` / `else:` 才追加到三个列表
- **结论**: 缺失数据是常态而非例外（「有些气象站会偶尔出现故障」），逐行兜底后循环继续处理下一行；必要时也可用 continue 跳过、用 remove()/del 删除已提取数据
- **结果**: 运行后只打印一行「2014-02-16 missing data」，并正常画出图16-6

### 案例 2: JSON 人口数据——结构探查与 int(float()) 两步转换
- **类型**: 原书例题（可运行示范）（第16章 16.2.1–16.2.3）
- **问题**: 加载 population_data.json 后，直接 `int(pop_dict['Value'])` 报 ValueError（值里混着带小数的字符串 '1127437398.85751'）；直接看文件也说不清结构
- **方法论的使用**: 先打印核对——文件是「列表，每个元素是四个键的字典」（国家名/国别码/年份/值），年份用字符串比较筛选 2010；把转换改为 `population = int(float(pop_dict['Value']))`——先转浮点、再由 int 丢弃小数部分
- **结论**: 「原始数据的格式常常不统一」；进入可视化前先用打印确认捕获的数据形状正确
- **结果**: 修复后完整打印 2010 年各国人口清单（Arab World: 357868000 … Zimbabwe: 12571000）

### 案例 3: 世界人口地图——映射失败归因与分档着色
- **类型**: 原书例题（可运行示范）（第16章 16.2.4–16.2.9）
- **问题**: 用国家名查两字母国别码后，一批记录永远匹配不上（ERROR - Arab World、ERROR - Yemen, Rep. ……）；按数值线性着色时「很多国家都是浅色的，只有两个国家是深色的」，差别看不出来
- **方法论的使用**: ① 映射——遍历对照表的「代码—名字」对，命中即返回、循环后 `return None`，调用侧 `if code: … else: print('ERROR - ' + 名称)`；失败归为两类（地区/经济类群不是国家；统计用名与标准名不同），先忽略错误数据、用成功恢复的数据出图；② 分档——按人口阈值分三组（<1000 万、1000 万~10 亿、>10 亿）分别着色，`print(len(...))` 核对各组规模
- **结论**: 映射失败要显式登记、分类归因，而不是静默丢弃；极端值会压缩线性色阶，分档才能让差别可见
- **结果**: 打印「85 69 2」（85 国 / 69 国 / 2 国）；图16-10 用三种颜色显示人口差别

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 拿到一份陌生 CSV/JSON（导出的报表、监测站数据、开放数据），要读进程序分析或作图
2. 同一段代码在别的文件上跑得通，换一份数据就崩（空字段、异常字符）
3. 数值列里混着字符串与小数的写法，`int()` 转换总是报错
4. 按名称对照码表做映射（国家名→国别码、城市→区号），一批记录对不上
5. 数据画成图后「看不出差别」，需要重新组织（分档、筛选）再画

### 语言信号

- 「CSV 文件怎么读？第几列是哪一列？」
- 「invalid literal for int() 怎么解决」
- 「JSON 转成 Python 之后是什么结构？」
- 「数据里有空值/缺测，程序直接崩了」
- 英文: "parse this CSV file with Python", "ValueError: invalid literal for int()", "my script crashes on missing data"

### 与相邻能力的区分

- 与 `data-visualization` 的区别: 那条从「已有干净列表」开始画图与定制；本 skill 负责把外部文件变成这些列表（解析、转换、清洗），出图仍走前者
- 与 `web-api` 的区别: 那条的数据来自在线接口（先核验响应再解析）；本 skill 处理已经落盘的文件（CSV/JSON），是另一条取数线
- 与 `files-and-exceptions` 的区别: 那条讲文件读写与异常语法本身；本 skill 是它们在真实数据集上的固定组合动作（表头定位、缺测跳过、分层转换）

## E — 可执行步骤 (Execution)

1. **先看清结构，再写取数代码**
   - 完成标准: CSV 打印出文件头并用 enumerate 标出列号（如第 0 列日期、第 1 列最高气温），JSON 先 json.load 再打印类型与键名；能书面写出「所需字段在第几列/哪个键」的结论
   - 输入契约: 一个待解析的文件（CSV 或 JSON）

2. **逐行提取并分层转换类型**
   - 完成标准: 数值显式转换——可能含小数点的字符串用 int(float(x)) 两步转换；日期用 datetime.strptime(字符串, '%Y-%m-%d') 转成日期对象；提取循环从表头下一行开始（reader 从停留处继续读）
   - 判停条件: 转换抛错时先按第 3 步兜底，不要注释掉坏值或跳过整个文件

3. **缺失与坏数据逐行兜底**
   - 完成标准: 逐行 `try:` 提取 → `except ValueError:` 打印缺失数据的日期/主键 → `else:` 才追加到列表；程序在含缺测的数据集上完整跑完并输出缺失清单，不中断
   - 判停条件: 缺测过多以致图表不可读或结论不可靠时，停下来核对数据来源与口径再做
   - 口径: 处置手段不限（跳过、删除、修补均可），验收标准是能做出「精确而有意义的可视化」

4. **对照表映射与失败归因（涉及名称→编码时）**
   - 完成标准: 映射函数遍历对照表、命中返回编码、循环后 return None；调用侧对 None 显式输出（如 ERROR - 名称）；失败清单按「口径不对应（地区/经济类群）」与「名称不一致（别名）」两类归因，并决定忽略或修补
   - 输出契约: 成功映射的「编码→数值」字典 + 失败清单

5. **先核对分布，再交给可视化**
   - 完成标准: 清洗后的数据先打印抽样核对（条数、极值、分组规模，如分组后 print 各组长度）；数值差别被色阶压缩时按量级分档重画；分档阈值是人口数据的示例口径，换数据须按量级自定
   - 判停条件: 核对不通过（条数/极值异常）时回到第 3 步，不带着疑问出图

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- 数据文件本身还没到位或来源不可复现时——先解决数据获取（书中数据依赖配套资源与外部站点，须自备或替换）
- 数据是流式/超大规模、需要数据库或专用 ETL 时——本 skill 口径来自中小型文件示例
- 数据格式完全受控且每行都完整时——兜底按风险加，不是仪式

### 作者在书中警告的失败模式

- ce146: 一条空数据就能让整个程序崩溃——气象站故障致某天字段为空，int('') 抛 ValueError，一张图也画不出来
- ce147: 带小数点的数字字符串不能直接 int()——程序打印到一半才中断，前面「正常」的输出掩盖了后面的失败
- ce148: 数据集里不只有国家，还有地区与别名（Yemen, Rep.）——按名称精确匹配永远对不上，这些记录在地图上直接缺失
- ce156: 数据质量问题远超书中示范的类型——格式错、数值本身错不一定会抛异常，只包一层 try 不够，坏数据会被当正常值画进图里

### 作者的盲点 / 时代局限

- 2016 年快照：`from pygal.i18n import COUNTRIES` 与 `pygal.Worldmap()` 的导入路径与模块组织在后续版本已变更（原书未讨论），须按现环境替换；天气数据来源与配套资源下载链接同样按现环境核对
- 数据质量处置只给了原则、没有单一标准（跳过/删除/修补皆可）；书中只示范了 ValueError 一类，不能当完整清洗清单
- 分组阈值（1000 万 / 10 亿）是人口数据的示例口径，其他量级的数据须自定阈值（原书未给通用换算）
- 函数正确性靠 print 验证、自动化测试留作练习——验证环节不完整
- 转档缺陷：图16-1~16-11 图形内容全丢、只剩图注；格式码表被页内数字序列切碎，按缺口处理

### 容易混淆的邻近方法论

- `data-visualization`: 图表选型、定制与输出归它；本 skill 到「干净的数据列表/字典」为止
- `web-api`: 数据来自在线接口、要先核验响应，属另一条取数线
- `files-and-exceptions`: 文件读写与异常的语法底座；本 skill 是其在真实数据集上的固定动作
