# 列表操作与 IndexError 排障（第3章）

## R — 原文 (Reading)

> 索引错误意味着Python无法理解你指定的索引。程序发生索引错误时，请尝试将你指定的索引减1，然后再次运行程序，看看结果是否正确。
>
> — 第3章 3.4 使用列表时避免索引错误（L3661-L3661）

## I — 方法论骨架 (Interpretation)

列表的纪律只有两条线：**访问靠换算，改动用选型**。

访问线：列表是有序集合，索引从 0 计——「第 n 个」一律换算成索引 n-1；末元素用 -1（不知道长度时尤其有用，-2、-3 依次倒数）。每次索引访问前先问一句「这个索引合法吗」——n 个元素的合法索引是 0 到 n-1。

改动线：所有修改都是就地生效，**选型先于记方法名**。增——append 追加到末尾（「空列表 + 一连串 append」是动态建表的固定模式），insert(索引, 值) 插到指定位置并把既有元素右移；两者都只改列表本身、不动其他元素。

删除要按两步判据选：先问按位置还是按值，再问删完还要不要用它——按位置且不再用：del；删后还要用它的值：pop()（可带索引弹任意位置）；只知道值不知道位置：remove()，且它只删第一个匹配。

排序分永久与临时两个家族：永久重排用 sort()（不可恢复，可传 reverse=True 反向）；只按序展示、保留原顺序用 sorted()（是函数，要接住返回值或直接用于显示）；只想把顺序倒过来用 reverse()（再调一次即恢复）；数个数用 len()。

排障线：IndexError 意味着索引不存在。排查两步——**先把指定的索引减 1 再运行**；仍找不到原因就把列表或其长度打印出来核对，被动态增删过的列表尤其如此。边界：-1 取末元素「在任何情况下都行之有效」，唯列表为空时同样报错。

## A1 — 书中的应用 (Past Application)

### 案例 1: pop() 弹出并继续使用元素值
- **类型**: 原书例题（可运行示范）（第3章 3.2.3）
- **问题**: 要删除列表里的一辆摩托车，还要在消息里用到它的品牌
- **方法论的使用**: 用 popped_motorcycle = motorcycles.pop() 接住被删的值，再拼进消息；对照 del 的判据——删后不再用就 del、还要用就 pop()；pop(0) 可弹指定位置
- **结论**: 删除方式按「删后是否复用该值」选型，而不是随手挑一个
- **结果**: 书中给出的输出：['honda', 'yamaha']；The last motorcycle I owned was a Suzuki.；The first motorcycle I owned was a Honda.

### 案例 2: sorted() 保留原顺序的临时展示
- **类型**: 原书例题（可运行示范）（第3章 3.3.2）
- **问题**: 要按字母序展示一份列表，但之后还要按原始排列顺序继续处理
- **方法论的使用**: 用函数 sorted(cars) 临时排序显示，并把原列表再打印一次核对顺序未变
- **结论**: sorted() 产生显示用的新顺序、不动原列表；原顺序要保留时不能落到 sort()
- **结果**: 书中给出的输出：原始列表两次均为 ['bmw', 'audi', 'toyota', 'subaru']，中间一次为 ['audi', 'bmw', 'subaru', 'toyota']

### 案例 3: 三元素列表取 [3] 的 IndexError
- **类型**: 原书例题（可运行示范，含空列表对照）（第3章 3.4）
- **问题**: 想取「第四个元素」却写成 print(motorcycles[3])
- **方法论的使用**: 按排查动作把指定的索引减 1 再运行；再对空列表演示 [-1] 的报错情况，确认 -1 的边界
- **结论**: 差一错误所致——索引从 0 起、n 个元素合法索引到 n-1 为止；-1 仅在列表为空时才会报错
- **结果**: 书中给出的输出：IndexError: list index out of range（取 [3] 与空列表取 [-1] 两次）；正常访问 [-1] 时返回 'suzuki'

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 要从列表里删东西，del、pop、remove 分不清该用哪个，或删完还要用那个值
2. 只想按顺序展示一次，却把原始顺序弄丢了、找不回来
3. 报 IndexError: list index out of range，把索引改来改去还是不对
4. 列表被程序动态增删过，写代码时凭记忆假设它的内容和长度
5. 要把陆续到来的数据先收集进一个列表、之后再统一处理

### 语言信号

- 「IndexError: list index out of range 怎么解决」
- 「我明明要取第 4 个，为什么报错」
- 「排序之后原来顺序全没了」
- 「del 和 pop 有什么区别」
- 英文: "list index out of range", "does sorted() change my list", "how to remove an item from a list"

### 与相邻能力的区分

- 与 `loops-slices-and-formatting` 的区别: 切片、range 与遍历里的差一（「加 1」核对法）归它；本卡只管单表索引访问与增删改排的选型。
- 与 `dicts-and-nesting` 的区别: 键值建模、嵌套结构与列表与字典之间的转换归它；本卡处理一维列表自身。

## E — 可执行步骤 (Execution)

1. **先定意图，再选操作**
   - 完成标准: 每个动作先回答两个问题——「按位置还是按值」「删除后是否还要用该值」，并据此选定写法（append / insert；del / pop / remove；sort / sorted / reverse / len）
   - 输出契约: 每个动作附一句选择理由
2. **索引访问先过换算与边界**
   - 完成标准: 所有「第 n 个」写成索引 n-1；末元素用 -1；核对列表当前长度，确认索引落在 0 到 n-1 之间
   - 判停条件: 列表可能被动态改过、拿不准内容与长度时，先打印列表或其长度核对，再进入下一步
3. **报错即进 IndexError 排查链**
   - 完成标准: ① 把指定的索引减 1 再运行看结果；② 仍找不到原因，打印列表或其长度核对内容与个数；③ 顺带检查空列表这一边界（-1 也会报错）
4. **核对「永久 vs 临时」的后果**
   - 完成标准: 需要保留原顺序时用 sorted() 并确保结果被接住或直接用于显示；使用 sort() / reverse() 前确认原顺序不再需要（sort 无法恢复）
5. **收尾复验**
   - 完成标准: 打印最终列表，核对内容、顺序、长度三项与预期一致；若不一致，回到第 1 步重新选型

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- 数据需要按键取值或表示层级关系时——转字典与嵌套结构类能力
- 任务本质是遍历、过滤、变换整表或处理切片与 range 边界时——转遍历与格式类能力

### 作者在书中警告的失败模式

- 点名反例 ce18：sort() 是永久排序——「再也无法恢复到原来的排列顺序」；想「只是排一下看看」或之后还要原顺序时，务必先复制或改用 sorted()。
- 点名反例 ce21：列表为空时索引 -1 同样报 IndexError——「-1 总取末元素」的安心感会掩盖空列表这一边界，删空或过滤之后仍用 [-1] 就会出事。
- ce17：remove() 只删除第一个指定的值，重复值要靠循环才能删净；按「已删净」继续处理会产生残留元素。

### 作者的盲点 / 时代局限

- 2016 年快照：示例围绕 Python 3.5 写作，按现环境替换；各章对 Python 2 差异的说明也属历史资料。
- 排序细则留缺口：并非所有值都是小写时，大小写混排的字母顺序有多种解读方式，书中未给细则——涉及混合大小写排序时应另行核对当前行为。
- 转档缺陷：部分代码清单与正文粘连（代码被压进一行）、行内指向标记丢失形成悬空指代；复现时须按语法补换行与缩进，照原文留空处不得补造。
- 「-1 在任何情况下都行之有效」的表述自带一个例外（空列表），引用时须连带这条例外。
