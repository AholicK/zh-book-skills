# 环境搭建与运行排障（第1章 起步）

## R — 原文 (Reading)

> 如果没有看到这样的输出，请检查你输入的每个字符。你是不是将print的首字母大写了？是不是遗漏了引号或括号？编程语言对语法的要求非常严格，只要你没有严格遵守语法，就会出错。如果代码都正确，这个程序也不能正确地运行，请参阅1.3节。
>
> — 第1章 1.2.1 在Linux系统中搭建Python编程环境（L1289-L1289）

## I — 方法论骨架 (Interpretation)

环境这件事按一条固定流水线处理：**先检查是否已装并确定版本 → 未装则安装 → 配置编辑器 → 运行最小程序验收 → 不通过才按排障链升级**。顺序本身就是方法——不检查就开装、不验收就继续写代码，只会把问题推迟到更难定位的地方。

第一个锚点是 **Hello World 作为环境验收测试**：最小程序能正确运行，则此后任何程序都能运行；最小程序都跑不通时，问题几乎必然在环境或输入，而不在业务代码。

第二个锚点是 **版本决定命令口径**：两个版本并存用较新的 Python 3；默认版本是 2.x 时全部命令改用 python3；命令不可用时先找出解释器的完整路径做测试，再决定是补配置还是直接用完整路径。

失败归因遵循同一纪律：**先逐字符核对，再怀疑环境**——print 首字母大小写、引号、括号这类输入错误与「环境坏了」的外在表现完全相同；代码确认无误仍不能运行，才升级到排障链。

排障链是分级的：读 traceback 找线索、离开休息后重读、推倒重来、请旁人照步骤复做并旁观、请懂 Python 的人帮忙、查在线安装说明、到网上求助。求助前先组织好三要素：要做什么、试过哪些方法、结果如何。

## A1 — 书中的应用 (Past Application)

### 案例 1: hello_world.py 首次运行（编辑器路径）
- **类型**: 原书例题（可运行示范）（第1章 1.2.1）
- **问题**: 第一个程序要在编辑器里跑起来，并用它的输出判断环境是否搭好
- **方法论的使用**: 把空文件保存为 hello_world.py → 写入一行 print("Hello Python world!") → 用编辑器的 Build/Execute（或 F5）运行
- **结论**: 出现预期输出即环境验收通过；输出不对先逐字符检查拼写、引号与括号，而不是重装
- **结果**: 书中给出的输出：Hello Python world!，随后是分隔线与 (program exited with code: 0)

### 案例 2: Windows 命令不可用，改走完整路径
- **类型**: 原书例题（可运行示范）（第1章 1.2.3）
- **问题**: 命令窗口执行 python 报「is not recognized」一类的不可用提示
- **方法论的使用**: 到 C 盘寻找以 Python 打头的文件夹，先确定解释器完整路径（如 C:\Python35\python），再用完整路径做测试
- **结论**: 完整路径能进入解释器，说明已经知道如何访问 Python，再补简单命令或路径配置
- **结果**: 书中给出的输出：输入完整路径后出现 Python 3.5.0 提示符（>>>）

### 案例 3: 从终端运行既有程序
- **类型**: 原书例题（可运行示范）（第1章 1.4.1，Windows 版 1.4.2）
- **问题**: 想直接从终端运行已保存的 hello_world.py
- **方法论的使用**: cd 进入程序所在目录 → ls 确认文件在其中（Windows 用 dir）→ 用已确定的命令运行该文件
- **结论**: 从终端运行程序只需命令加上文件名；未配置简单命令时改用完整路径
- **结果**: 书中给出的输出：Hello Python world!

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 新机器或重装系统后第一次装 Python，命令敲进去提示「不是内部或外部命令」
2. 系统里同时有 Python 2 和 3，不知道书里的 python 命令该换成 python3 还是直接用完整路径
3. 编辑器里点运行没有输出（或窗口一闪而过），分不清是环境问题还是自己打错了
4. 按教程装完却始终跑不起来 hello_world.py，需要一条逐级升级的排查路径
5. 换电脑要重搭一遍环境，想照一份可验收的流程走完

### 语言信号

- 「python 命令用不了」「'python' 不是内部或外部命令」
- 「我装好 Python 了，为什么还是运行不了／没有输出」
- 「明明照书敲的，怎么跑不出来」
- 英文: "python is not recognized", "command not found: python", "I installed Python but the script won't run"

## E — 可执行步骤 (Execution)

1. **检查已装版本，确定命令口径**
   - 完成标准: 得到明确结论——用 python、用 python3 还是用完整路径；默认版本为 2.x 且 python3 可用时，所有命令按 python3 口径替换
   - 判停条件: 两个版本都不可用时不进入下一步，先补装解释器
2. **跑通最小程序（Hello World 验收）**
   - 完成标准: 在编辑器中运行 hello_world.py，看到 Hello Python world! 与退出码 0
   - 输入契约: 一行 print("Hello Python world!") 的 .py 文件
   - 判停条件: 输出不对先做逐字符检查（print 大小写、引号、括号）；命令找不到或编辑器用错版本时转第 3 步
3. **处理命令与路径问题**
   - 完成标准: 报「不是内部或外部命令」时，用完整路径（如 C:\Python35\python）成功测试；编辑器构建命令与要求逐字一致（含空格与大小写）
4. **补走终端运行三步**
   - 完成标准: cd → ls（Windows 用 dir）→ 命令加文件名 依次执行，终端中出现正确输出
5. **失败升级链**
   - 完成标准: 逐字符检查无问题且代码与范例一致的前提下，按七步路径（读 traceback、离开休息再重读、推倒重来、请旁人照步骤复做并旁观、请懂 Python 的人帮忙、查在线安装说明、网上求助）依次尝试并记录每步结果；求助信息含「做什么、试过什么、结果如何」三要素
   - 判停条件: 任一步解决问题即停止升级

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- 环境已验证正确、错误出在代码逻辑或第三方库内部时——应转调试与求助类能力
- 只需要某个安装界面或菜单项的对照说明时——那属于参考类内容，不必走本卡全流程

### 作者在书中警告的失败模式

- 点名反例 ce01：程序没有输出或直接报语法错误时，初学者容易误判为「Python 没装好、编辑器有问题」，把时间花在重装上；真正的原因可能只是 print 首字母大写、引号或括号漏了一个字符——两类问题的外在表现完全相同。
- 编辑器构建命令不逐字一致（空格、大小写不同）就不会按预期生效——配置须以给出的命令文本为准，逐字照抄。
- Windows 安装时不勾选 Add Python to PATH，终端里命令 python 直接不可用，需要手工补路径。

### 作者的盲点 / 时代局限

- 2016 年快照：写作环境为 Python 3.5、Geany 1.25、Sublime Text 3，安装界面与编辑器菜单可能随版本变化，按现环境替换；Python 2 分支仅作历史语境。
- 各平台安装细节被推给附录，正文流程不覆盖（书中明确指向附录A/B）；按平台安装遇到差异时以现版本说明为准。
