# 安装与编辑器参考（附录A–B）

## R — 原文 (Reading)

> 输出表明默认版本是2.7.6，但系统可能还安装了一个Python 3版本。为核实这一点，请执行如下命令： $ python3 --version Python 3.5.0 输出表明也安装了Python 3.5.0。安装新版本前，有必要执行上述两个命令。
>
> — 附录A A.1 在Linux系统中安装Python（L29904-L29910）

## I — 方法论骨架 (Interpretation)

这张卡是环境搭建的**补充参考**：当标准路径不通、或要安装非系统自带的版本时使用。它把三件事收在一处——安装口径、编辑器配置、命名禁区。

安装的核心是**先诊断、再动手**：先跑 python --version 与 python3 --version 两条命令，按「有输出=已装、报错=需安装或需配路径」判读，再按平台选择安装方式（Linux 用 deadsnakes 包、OS X 用 Homebrew、Windows 从官网下载安装程序并勾选 Add Python to PATH），最后**开新终端复验**——路径改动只在关闭旧终端、重开新终端后生效。

Path 的纪律只有一条：**只追加、不覆盖**。在变量值末尾先加分号、再追加 python.exe 的路径；一旦覆盖原值，系统里其他软件的查找也会受波及，误操作应立刻「取消」重来。

编辑器配置看三件套：**制表符转空格**（宽度 4）、**行长标志**（Geany 列值 79；Sublime 与 IDLE 在 80 字符处）、**一键运行**（Geany 按 F5、Sublime 按 Ctrl+B）。改构建命令时，空格与大小写必须与规范完全一致。

命名有两道禁区：**关键字**用作变量名会引发错误；**内置函数名**用作变量名不报错，但会覆盖同名函数的行为。正方向是「长短合适并描述了变量的作用」。

一句话判据：版本信息决定之后所有命令的形态（python / python3 / 完整路径）；配置的每一步都在把难诊断的问题尽量前置拦截。

## A1 — 书中的应用 (Past Application)

### 案例 1: Windows 上让命令 python 可用，并核对命名禁区
- **类型**: 原书例题（配置示范）（附录A A.3–A.4）
- **问题**: 每次启动 Python 终端都要输入完整路径；同时给变量起名要避开关键字与内置函数名两张清单
- **方法论的使用**: 用「python（全部小写）文件属性」找到解释器路径，先用完整路径验证版本；再到「系统变量→Path」末尾加分号、追加 python.exe 路径（不覆盖原值，改错点「取消」重来），关掉旧终端重开；命名对照 A.4 清单——关键字用了会报错、内置函数名用了会覆盖行为
- **结论**: 路径配好后只需命令 python 即可启动会话；Python 2.7 中 print 是关键字、Python 3 没有内置函数 unicode()，这两个词都不应用作变量名
- **结果**: 书中给出的结果：执行 python --version 显示所设版本，可直接输入 python 启动会话（L30120）

### 案例 2: 把 Geany / Sublime 配成「一键运行 + 规范内置」
- **类型**: 原书例题（编辑器配置示范）（附录B B.1–B.2）
- **问题**: 默认构建命令是 python；多版本机器上要让编辑器用 python3 运行当前文件，并防止制表符与空格混用
- **方法论的使用**: Geany 在 Build→Set Build Commands 把编译命令改为 python3 -m py_compile "%f"、执行命令改为 python3 "%f"（空格与大小写完全一致）；Indentation 设制表符宽度 4、Type=Spaces；Display 启用长行标志、列值 79；Sublime 用 Ctrl+B 运行，View→Ruler→80 放行长线，多版本时另存 Python3.sublime-build 指定解释器路径
- **结论**: 合格编辑器应突出代码结构、自动缩进、行长标志与快捷键；新手先用简单编辑器，把时间花在学编程上
- **结果**: 书中给出的结果：Geany 运行 hello_world.py 弹出终端输出 Hello Python world! 与 (program exited with code: 0)；Sublime 输出 [Finished in 0.1s]（L30460-L30476、L30572-L30576）

## A2 — 触发场景 (Future Trigger) ★

## E — 可执行步骤 (Execution)

1. **先查版本**
   - 完成标准: 依次执行 python --version 与 python3 --version，记录每条的输出或报错原文；两条都执行过才算完成
   - 判停条件: 版本可用且满足需求时，跳过安装与 Path 步骤，直接进入第 4 步
2. **按平台安装（仅在需要时）**
   - 完成标准: 按平台选定路径——Linux 用 deadsnakes、OS X 先 xcode-select --install 再用 Homebrew、Windows 从官网下载并勾选 Add Python to PATH；装完在**新终端**里 python --version 输出与预期一致
   - 输入契约: 平台类型 + 第 1 步的版本记录
   - 输出契约: 一行版本输出
3. **Path 处置（仅在没勾选复选框时）**
   - 完成标准: 在系统变量 Path 的值末尾先加分号、再追加 python.exe 路径，原值一字不动；误操作立即「取消」重来；关旧终端、开新终端复验命令可用
   - 判停条件: 第 2 步已勾选 Add Python to PATH 时，跳过本步
4. **编辑器配置核验**
   - 完成标准: 逐条核对三项——制表符转空格（宽度 4、Type=Spaces）、行长标志（Geany 列值 79；Sublime 与 IDLE 为 80）、运行方式（Geany F5、Sublime Ctrl+B）；多版本时构建命令用 python3，且空格与大小写完全一致
5. **命名禁区检查**
   - 完成标准: 产出两栏清单——硬禁区（关键字）与软禁区（内置函数名）各至少 3 例，并注明后果差异（报错 vs 静默覆盖）；对照当前代码逐名核对
   - 输出契约: 一份命名核对清单

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- 环境已装好且满足需求时，不要为「更新一下」而重装或改系统 Path——先核版本，很可能什么都不用做
- 多版本隔离与依赖管理（虚拟环境、包管理器）不在本卡范围；本卡只处理「命令能不能叫应」这一层
- 不要为运行一个脚本先把编辑器折腾成高级配置——简单编辑器先行，熟悉代码编辑后再考虑升级

### 作者在书中警告的失败模式

- ce192：编辑 Path 时覆盖原值——系统命令（含其他软件）会找不到可执行文件，故障范围远超 Python 本身；纪律是「末尾追加、误操作取消重来」，且这类修改没有自动撤销兜底
- 内置函数名作变量名是**静默失败**：不报错，但之后调用该函数会变成调用你的变量（f191/p196）
- 构建命令的空格与大小写必须完全一致——「你必须完全按这里显示的这样输出这个命令」（f192），否则编辑器与终端行为不一致
- 制表符与空格混用会给 Python 程序带来「极难诊断的问题」（p197/f192），应在编辑器里一次性转为空格

### 作者的盲点 / 时代局限

- **2016 年快照，按现环境替换**：deadsnakes PPA、Homebrew、python3.5、Geany 1.25、Sublime Text 3 与全部界面路径都随时可能失效
- Homebrew 的 ruby -e 安装命令会执行下载的代码，书中只提示「除非来源是你信任的，否则不要运行这样的命令」（L30004），没有展开安全判据
- 未给版本更新后的替代路径；三平台流程与工具版本均为 2016 年口径，新版系统的界面差异（如 Windows 菜单名）没有覆盖
- 转档说明：安装界面截图与图全部丢失（只剩图注）；A.4 清单在转档中呈逐行词条流并混入孤立数字，两栏版式关系丢失；引用命令与菜单路径时须逐字核对空格与大小写
