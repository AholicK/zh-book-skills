## I — 方法论骨架 (Interpretation)

数据可视化的目的是**通过可视化表示来探索数据**，而不是「把图做好看」：先把数据变成图看见形状，再让图具备可交付的质量。

两条工具链各占一段：**matplotlib** 负责静态图（折线、散点，输出 PNG），骨架是「画布 + 绘图调用 + 展示/保存」；**Pygal** 负责矢量图（SVG），自动缩放、自带交互（悬停看数值），适合在线发布与同图多数据集。

核心机制是把数据喂成**坐标序列**：`plt.plot(x_values, y_values)`、`plt.scatter(x, y, s=…)`、`hist.add('系列名', 数值列表)`。绘图函数对缺省参数有自己的假设——只传一个列表时会被假定从 x=0 开始——所以**把参数给全比依赖默认安全**。

节奏是**先跑通最简版，再逐项定制**：先让图显示出来，再依次调线宽、标题与轴标签字号、刻度字号、点尺寸与轮廓、颜色映射、坐标轴范围；数据点多时把数值生成交给循环/列表解析，把点调小、去掉黑色轮廓。

输出分三档：即时查看（`plt.show()`）、落盘交付（`plt.savefig('名字.png', bbox_inches='tight')`）、在线发布（`render_to_file('名字.svg')`，用浏览器打开）。**数据与图形的一致性优先于样式**——错位的图比难看的图危险得多。

## A1 — 书中的应用 (Past Application)

### 案例 1: mpl_squares.py——折线图的最小集、定制与校正
- **类型**: 原书例题（可运行示范）（第15章 15.2.1–15.2.2）
- **问题**: 把平方数序列 [1, 4, 9, 16, 25] 画成折线图：第一版能显示但标签太小、线条太细；放大后发现数据根本没画对——「折线图的终点指出 4.0 的平方为 25」
- **方法论的使用**: 先跑最小集 `plt.plot(squares)` + `plt.show()`；再逐项定制 `linewidth=5`、`plt.title("Square Numbers", fontsize=24)`、`plt.xlabel/ylabel(..., fontsize=14)`、`plt.tick_params(axis='both', labelsize=14)`；最后补出输入列表 `input_values = [1, 2, 3, 4, 5]`，改为 `plt.plot(input_values, squares, linewidth=5)` 同时提供 x/y
- **结论**: 「图形更容易阅读后」才暴露出错位——数据正确性的核对要放进出图流程，不能默认绘图函数会替你对齐；同时提供输入值与输出值后，绘图不再需要对生成方式做假设
- **结果**: 图15-1 为最简图；定制后的图阅读起来容易得多（图15-2）；校正后得到正确绘制的图15-3

### 案例 2: 散点图——自动计算 1000 个点、样式与自动保存
- **类型**: 原书例题（可运行示范）（第15章 15.2.3–15.2.9）
- **问题**: 散点图从单点演示扩到 1000 个点后：手工算坐标不现实、点尺寸沿用单点取值会糊、只留在查看器里的图无法交付
- **方法论的使用**: ① 造数——`x_values = list(range(1, 1001))`、`y_values = [x**2 for x in x_values]`，把计算交给 Python；② 定轴——`plt.axis([0, 1100, 0, 1100000])` 显式给出两轴范围；③ 样式——`s=40` 调小点尺寸、`edgecolor='none'` 删除黑色轮廓、`c=y_values` + `cmap=plt.cm.Blues` 按 y 值深浅着色；④ 保存——把 `plt.show()` 替换为 `plt.savefig('squares_plot.png', bbox_inches='tight')`
- **结论**: 数据量大时「不该手工计算坐标列表」；点越多、点尺寸越小并去掉轮廓；颜色映射用来表达第三维（值的大小，小值浅色、大值深色）
- **结果**: 图15-6（1000 个点）、图15-7（由浅蓝渐变到深蓝）；生成 squares_plot.png 文件

### 案例 3: 掷骰子——Die 类造数 + Pygal 直方图与 SVG 输出
- **类型**: 原书例题（可运行示范）（第15章 15.4）
- **问题**: 把 1000 次掷 D6 的点数分布画成图表，并让图表适合在线查看
- **方法论的使用**: ① 先验证数据源——掷 100 次打印快速扫描（见到 1 和 6、没有 0 或 7、1~6 都出现），确认 Die 类正常；② 统计——对 `range(1, die.num_sides+1)` 逐个 `results.count(value)` 得到频率列表；③ 建图——`hist = pygal.Bar()`，设 `title` / `x_labels` / `x_title` / `y_title`；④ 加数据与输出——`hist.add('D6', frequencies)`、`hist.render_to_file('die_visual.svg')`
- **结论**: 随机/生成类数据先做「边界值 + 范围外值 + 覆盖性」三项抽查再进图表；输出文件扩展名必须为 .svg，用浏览器打开查看
- **结果**: 1000 次频率 [155, 167, 168, 170, 159, 181]「看起来合理」；图15-11 为可交互的条形图（书中注明为印刷稍作修改，默认背景更暗）

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 手里有一组数字（销量、气温、模拟结果），要画成折线图/散点图/直方图交付
2. 图能出来但「能看不好看」：标签挤、线条细、点糊成一团，想把它调到可读
3. 图表要放进报告或网页，发现 `plt.show()` 之后什么都没留下
4. 想用模拟数据看分布或路径（掷骰子、随机漫步），不知道数据怎么造、图怎么搭
5. 需要在线发布、可缩放、鼠标悬停能看数值的图表

### 语言信号

- 「matplotlib 怎么画折线图 / 散点图」
- 「散点图点太多，糊成一团了」
- 「plt.show() 之后图去哪了，怎么保存成文件」
- 「Pygal 和 matplotlib 该用哪个」
- 英文: "how do I save a matplotlib figure", "my scatter plot looks like a blob", "matplotlib chart doesn't show up"

### 与相邻能力的区分

- 与 `data-parsing-and-cleaning` 的区别: 那条负责把 CSV/JSON 等外部数据读进来、清洗成列表；本 skill 从「手里已有一组数据」开始，负责把它变成图表并落盘
- 与 `web-api` 的区别: 那条负责联网取数（拼 URL、核验响应、配额）；本 skill 是其后端的呈现环节——数据无论来自哪里，出图都走这里

## E — 可执行步骤 (Execution)

1. **选型并跑通最小可运行图**
   - 完成标准: 选型明确（静态交付用 matplotlib；在线可缩放/可交互用 Pygal）；脚本先只做「数据 → 一张能显示的图」，折线用 `plt.plot`、散点用 `plt.scatter`、直方图/地图用 `pygal.Bar()` 等
   - 输入契约: 一组数值（x/y 两个等长列表，或「系列标签 + 数值列表」）

2. **核对数据与坐标对齐（含合理性抽查）**
   - 完成标准: 只传一个列表时，补齐 x 值列表后再出图（对照 plot() 默认把首点 x 当 0 的假定）；抽查 2–3 个点与手算值一致（如 x=4 处的 y 应为 16）；随机/生成类数据先过「边界值出现、无范围外值、取值全覆盖」三项扫描
   - 判停条件: 若错位的观感来自点太密而非坐标映射，转步骤 3、4 处理

3. **大数据集：程序化造数 + 参数化 + 规模控制**
   - 完成标准: 坐标列表由循环/列表解析生成（不手工计算）；取值范围与标签的边界不写死只适配一种输入的字面量，用参数推导（如两个骰子的最大点数 = 面数之和）；点数与点尺寸调整到「能辨认」的区间（点变多则点尺寸变小）
   - 判停条件: 图形明显卡顿或点密到无法辨认时，先减点或缩小点尺寸，再考虑换工具

4. **逐项定制与轴范围**
   - 完成标准: 按清单逐项过——线宽（linewidth）、标题与轴标签字号（fontsize）、刻度字号（tick_params(axis='both')）、点尺寸（s）与轮廓（点多时 edgecolor='none'）、颜色映射（c=值列表 + cmap）、坐标轴范围（axis 四值：x/y 的最小值与最大值）；每项改动后图仍与数据一致
   - 输出契约: 一份「数据未动、样式已调」的定制图

5. **输出、保存与查看方式**
   - 完成标准: 需要交付时文件已落盘且格式正确——静态图 `plt.savefig('名字.png', bbox_inches='tight')`；Pygal 用 `render_to_file('名字.svg')`（扩展名必须为 .svg）；写明查看方式（PNG 直接看，SVG 用浏览器打开）；只在只需即时查看时保留 `plt.show()`
   - 判停条件: 批量化出图时不要保留「关闭窗口才继续」的交互写法

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- 数据还没读进来或没清洗干净时——先把外部文件处理成列表（走 `data-parsing-and-cleaning`）
- 只要数字结论、不要图形时——画图不是数据核对与统计的替代品
- 需要交互式仪表盘、超大规模数据集渲染时——书中的静态工具链口径不够用，须评估专用可视化方案

### 作者在书中警告的失败模式

- ce136: 只给 plot() 传一个系列——横坐标由库自行假定（首点 x=0），图形「看起来正常」却把数据画错位置，误差不报错、只在读图时被发现
- ce137: 点多时默认黑色轮廓粘连成块——数据的疏密规律被样式掩盖
- ce138: 只用 plt.show() 不落盘——关掉窗口或程序结束后图表就不存在了，无法交付
- ce139: 查看器窗口与程序流程耦合——不关窗口程序不走下一步，批量出图会被卡住
- ce140 / ce141: 点数的性能与可读性上限、dpi 与尺寸的换算关系，原书未给口径（留作读者自测）

### 作者的盲点 / 时代局限

- 全书工具链为 2016 年快照：matplotlib 1.4.3 与当时版 Pygal 的写法（如 `plt.axes().get_xaxis().set_visible(False)`、pip/pip3/--user 安装口径）须按现版本 API 与现环境替换
- 书中的插图是作者为印刷调亮的样张，代码默认输出（尤其 Pygal 的深色背景）与插图不一致，不能拿插图当验收基准
- 安装方式按平台分段给命令、未给判定表：照抄属于自己平台的命令也可能失败，除错线索分散在若干「注意」里
- 转档缺陷：图15-1~15-13 的图形内容全部丢失、只剩图注，行内指向标记也有缺失，涉及图形外观的判断按缺口处理

### 容易混淆的邻近方法论

- `data-parsing-and-cleaning`: 取数、解析、清洗归它；本 skill 只处理「已有数据 → 图表与输出」，两者常前后串联
- `web-api`: 联网请求与响应核验归它；数据到手后的出图仍走本 skill 的流程
