# 用户输入与 while 循环（第7章）

## R — 原文 (Reading)

> 在要求很多条件都满足才继续运行的程序中，可定义一个变量，用于判断整个程序是否处于活动状态。这个变量被称为标志，充当了程序的交通信号灯。你可让程序在标志为True时继续运行，并在任何事件导致标志的值为False时让程序停止运行。
>
> — 第7章 7.2.3 使用标志（L8099-L8099）

## I — 方法论骨架 (Interpretation)

交互程序＝一个能被用户反复驱动、又始终能停下来的循环。三件套缺一不可：**进入循环前先给状态变量初值**（`message = ""`、`responses = {}`、`active = True`），**循环条件可被终止**（输入值等于退出值、标志变 False），**循环体内有推进或退出路径**（更新计数、更新待检变量、置标志、break）。条件里出现的名字在首次求值前就必须已经存在——它没有「还没轮到赋值」这种中间态。

`input()` 的语义只有两点：让程序暂停、显示提示并等待输入；把用户输入**一律**解读为字符串。因此在任何比较、计算、求模之前，数值输入都要先 `int()`（或 `float()`）转换——只打印不转换时看不出问题，到比较环节才爆雷。

结束手段分三层选择：单个退出值直接写进 while 条件最直白；结束事件多（游戏中飞船耗尽、城市被毁）用一个标志统一管理，while 只检查一个条件；循环中部发现要立即停下用 `break`；只跳过本轮余下代码、回到循环开头用 `continue`。遍历列表又要改动它（搬移元素、删净某个值）时不要用 for，改用 while 配合 `pop()`／`remove()`。

一条硬规则贯穿全章：**每个 while 循环都必须有停止运行的途径**。写完不能靠祈祷，要对每个循环做终止测试——输入那个应当结束循环的值，看程序是否真的结束。

## A1 — 书中的应用 (Past Application)

### 案例 1: 数值输入忘记转换——TypeError 与 rollercoaster.py
- **类型**: 原书例题（可运行示范）（第7章 7.1.2）
- **问题**: 用 input() 拿到年龄/身高后直接参与比较，程序报错中断
- **方法论的使用**: 先看到值是带引号的 '21'（字符串），再做 age = int(age)、height = int(height)，然后才做 age >= 18、height >= 36 的比较
- **结论**: 数值输入用于计算和比较前必须转换为数值表示；不转换时只打印不报错、到比较才爆雷
- **结果**: 书中给出报错 TypeError: unorderable types: str() >= int()；转换后比较通过并输出 You're tall enough to ride!

### 案例 2: counting.py 漏掉 x += 1——无限循环的成因与处置
- **类型**: 原书例题（含有意写错示范）（第7章 7.2.6）
- **问题**: while 循环从 1 数到 5；若把推进语句 x += 1 漏掉，条件恒为 True
- **方法论的使用**: 对照正确版（x <= 5 配合 x += 1）找出缺失的推进动作；书中给出处置动作与预防动作——对每个 while 循环进行测试、确保它按预期结束
- **结论**: 每个 while 循环都必须有停止运行的途径；退出条件「微妙」时肉眼审查更难发现
- **结果**: 正确版打印 1 2 3 4 5；漏掉推进后没完没了地打印 1；陷入无限循环时按 Ctrl + C 或关闭显示程序输出的终端窗口

### 案例 3: 在 while 循环中搬移元素与删净特定值
- **类型**: 原书例题（可运行示范）（第7章 7.3.1–7.3.2）
- **问题**: 把未验证用户逐个迁入已验证名单；以及把列表中全部 'cat' 删掉（remove() 只删第一个匹配值）
- **方法论的使用**: ① while unconfirmed_users: 中 current_user = unconfirmed_users.pop() 再 append 到目标列表，源列表变空即结束；② while 'cat' in pets: pets.remove('cat') 每轮删一个、回到条件重新检查
- **结论**: 要在遍历列表的同时修改它，应使用 while 而不是 for
- **结果**: 确认过程输出三行 Verifying user（Candace/Brian/Alice）与最终名单；pets 由含三个 'cat' 变为 ['dog', 'dog', 'goldfish', 'rabbit']

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 要写一个反复询问用户输入的程序（前台登记、问卷收集、菜单式小工具），不知道用户会输入几轮、何时停下
2. 程序跑起来停不下来：同一行无限刷屏、出现「卡在提示里」的状态
3. 把 input() 拿到的数字直接做比较或计算，报错或结果明显不对
4. 想「删除列表里所有某个值」「把元素逐个搬到另一个列表」，用 for 写总是漏掉或删不干净
5. 需要不间断地采集任意条数的输入（姓名、柜号、偏好），最后统一打印成清单

### 语言信号

- 「程序一直刷屏停不下来，怎么打断它」
- 「input 拿到的东西怎么不能比大小」
- 「我输入 quit 之后，它把 quit 也打印出来了」
- 「列表里同一个值删了好几次还在」
- 英文: "how do I stop this infinite loop", "input returns a string", "while True with no break", "'q' to quit doesn't work"

### 与相邻能力的区分

- 与 `conditionals-and-if` 的区别: 那张卡解决单次判定的分支选型（if/elif/else 怎么排）；本卡解决「重复执行直到某条件不成立」的循环骨架与退出途径，循环条件里的比较规则沿用其口径
- 与 `functions-and-modules` 的区别: 输入循环要被反复使用时，应把循环封装进函数（第8章 8.3.4 的函数+while 交界）；本卡只负责循环与输入本身，两张卡在「每次提示都提供退出途径」上同口径
- 与 `variables-strings-and-numbers` 的区别: 类型转换的机理属于那张卡；本卡只固定一条硬规则——数值输入做比较、计算、求模前先 int()

## E — 可执行步骤 (Execution)

1. **写清提示与退出方式**
   - 完成标准: 提示语准确说明要输入什么、末尾（冒号后）留一个空格把提示与输入分开；提示里写明退出方式（如 "(enter 'done' at any time to quit)"）
   - 输入契约: 一句给用户看的提示文本

2. **初始化状态变量**
   - 完成标准: while 条件里出现的每个名字，在进入循环前都已赋初值（`message = ""`、`lockers = {}`、`active = True`）；容器与退出值都写在这段里
   - 判停条件: 首次执行 while 行出现 NameError 时回到本步

3. **搭循环骨架并接上退出途径**
   - 完成标准: 循环条件可终止，且体内至少有一处推进或退出路径（更新计数、更新待检变量、置标志 False、break）；按枚举选择——单个退出值用条件测试、多事件用标志、循环中部立即终止用 break、跳过本轮用 continue
   - 输入契约: 明确每轮的「读入什么、推进什么」

4. **数值输入先转换再比较**
   - 完成标准: 凡参与比较、计算、求模的输入，都在使用前完成 int()（或 float()）转换；转换与比较分成两步写（先赋值、再判断）
   - 判停条件: 出现 unorderable types 一类比较报错时回到本步

5. **处理退出值与结束输出**
   - 完成标准: 退出值不写入容器、也不回显（入库/打印前先 if 判断）；循环结束后遍历 items() 输出结果清单与统计（如总人数）
   - 输出契约: 一份不含哨兵值的登记清单

6. **终止自检**
   - 完成标准: 对每个 while 逐一验证——输入那个应当结束循环的值，程序确实结束；确认体内能看到对条件变量的修改或 break 通道
   - 判停条件: 若体内没有推进，回到第 3 步补上；已经停不下来时按 Ctrl + C 或关闭输出终端窗口中断，再回查

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- 遍历次数或对象已知且固定：直接用 for（本卡不替代 for 的场景）
- 无人值守的批处理脚本：交互式 input 循环需要有人在场，自动化流程应改从命令行参数或文件取数
- 只需要单次一问一答：直接一次 input() 加打印即可，硬套 while 反而引入终止风险

### 作者在书中警告的失败模式

- ce42: input() 一律返回字符串——用户输入的是数字 21，拿到的却是 '21'（数值的字符串表示）；直接做 age >= 18 会报 TypeError: unorderable types: str() >= int()，而且只打印时无异常，掩盖了隐患
- ce49: 无限循环——遗漏推进语句或没有退出途径时条件恒真，同一输出被无限打印、程序失去响应；作者提醒退出条件微妙时尤易发生，处置按 Ctrl + C 或关闭输出终端窗口
- ce45: 循环条件里的变量必须先初始化（如 message = ""）——「如果没有可供比较的东西，Python将无法继续运行程序」
- ce46: 退出值被当成普通消息处理——'quit' 也被打印出来，需在循环体内加 if 判断，仅在不是退出值时才处理

### 作者的盲点 / 时代局限

- 2016 年快照，按现环境替换：书中按当时 Python 3.5 与 Sublime Text 环境写作——「Sublime Text不能运行提示用户输入的程序」是当年的编辑器结论，现代编辑器多已内置终端可跑交互程序；Python 2.7 的 raw_input() 段落已完全过时，现环境一律用 input()
- 原书未覆盖输入校验细则：空输入、非数字输入走 int() 会引发 ValueError、退出值的大小写容错（done/Done/DONE）等，书中均未给出
- 终止手段只有 Ctrl + C 与关闭终端窗口两条，没有程序内超时、看门狗或非交互回退的口径
- 转档提醒：本卡依据的电子文本中，页码行与页内孤立数字会把句子切断、行内标记 ❶❷❸ 丢失导致「见 」式悬空指代、代码缩进被压平——回引示例代码请以原书排版为准

### 容易混淆的邻近方法论

- `conditionals-and-if`: 判断「走哪条分支」；本卡把 if 放进循环体里，解决的是「何时停止重复」——两者常在同一个程序里先后出现，不要互相代替
- `functions-and-modules`: 当输入循环要被复用或作为程序块交付时，把它包成函数、用形参控制退出值；第8章 8.3.4 的「函数 + while」仍遵守本卡的退出途径要求
