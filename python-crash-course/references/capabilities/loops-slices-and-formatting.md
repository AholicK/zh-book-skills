# 遍历、切片与代码格式（第4章）

## R — 原文 (Reading)

> 要复制列表，可创建一个包含整个列表的切片，方法是同时省略起始索引和终止索引（[:]）。这让Python创建一个始于第一个元素，终止于最后一个元素的切片，即复制整个列表。
>
> — 第4章 4.4.3 复制列表（L4605-L4605）

## I — 方法论骨架 (Interpretation)

处理一个列表，这件事被拆成三层：**逐元素遍历**、**取或复制子集**、**把代码写整齐**，每层都有一套可以逐条核对的规则。

遍历的心智模型是「取出一个值、执行一遍缩进的行」：for 语句后面每个缩进的代码行都属于循环体，列表有多长就重复多少次；循环后面没有缩进的代码只执行一次，用来放总结性输出。临时变量用单数式、列表用复数式，读代码时一眼分清处理的是单个元素还是整个列表。

数字与子集两条边界规则同源：range(1, 5) 到 5 之前就停（不打 5），切片 [0:3] 同样不包含第二个索引处的元素——输出比预期「少一个」时，先把指定的值加 1 核对。取尾部的 [-3:] 与取前部的 [0:3] 对称，列表长度变化也不失效。

复制是这一章代价最高的知识点：new = old[:] 得到新列表；new = old 只是给同一个列表再加一个名字，任何一边修改、两边同步。

容器选型还有一条判据：一组值在程序整个生命周期内都不变时用元组（圆括号）——元素级赋值会被拒绝（TypeError: 'tuple' object does not support item assignment），但给存储元组的变量整体换一个新元组是合法的。

最后是格式：代码被阅读的次数比编写的次数多——每级缩进四个空格、每行不超过 80 字符、用空行分隔不同部分但别滥用；这套规范是通用建议而非不可逾越的红线。

## A1 — 书中的应用 (Past Application)

### 案例 1: magicians.py 用 for 循环遍历列表
- **类型**: 原书例题（可运行示范）（第4章 4.1）
- **问题**: 把魔术师名单里每位名字打印出来，并在循环内对每人做多行操作。
- **方法论的使用**: 写 for magician in magicians:，循环体内先 print(magician)，再打印含 .title() 的个性化消息；循环变量用单数式描述性名称。
- **结论**: 循环体里每个缩进行对列表中每个值各执行一次；作者强调命名约定——单数接临时变量、复数接列表，帮助判断处理对象。
- **结果**: 输出 alice、david、carolina，以及 Alice, that was a great trick! 一类的消息。

### 案例 2: 忘记缩进的两种后果
- **类型**: 原书例题（有意写错的反例示范）（第4章 4.2.1–4.2.2）
- **问题**: 演示两类缩进失误：循环体完全没缩进；只漏缩进循环体里的第二条 print。
- **方法论的使用**: 按 4.2 的检查顺序核对——for 后紧跟的代码块必须缩进；只应执行一次的操作不要缩进。
- **结论**: 前者报 IndentationError: expected an indented block；后者语法合法但属于逻辑错误——第二条消息只打印一次，且因变量终值为 'carolina'，只有她收到消息。
- **结果**: 书中给出的输出：第一种报错为 IndentationError；第二种在三条技巧消息后只有 I can't wait to see your next trick, Carolina. 一行。

### 案例 3: foods.py 引用陷阱——直接赋值得到同一个列表
- **类型**: 原书例题（有意写错的反例示范）（第4章 4.4.3）
- **问题**: 想为朋友单独建一份「喜爱的食物」列表，实现时写成了 friend_foods = my_foods。
- **方法论的使用**: 对照 4.4.3 的复制口径——复制列表要用省略起止索引的切片 [:]；直接赋值只是让两个变量指向同一个列表。
- **结论**: 因为是同一个列表，任一边 append，两个变量看到的内容都变；作者给出排查口径：使用副本而结果出乎意料时，先确认是否用了切片复制。
- **结果**: 两个列表内容完全相同，均为 ['pizza', 'falafel', 'carrot cake', 'cannoli', 'ice cream']。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 有一份名单或数据清单，要求「对每一条都做同一件事」，且长度还会变
2. 做了「复制」以后，改动副本却发现原数据也跟着变了
3. 生成数字序列或取一段数据，输出总是少一个/多一个，需要核对边界
4. 程序报 IndentationError，或没报错但某条消息只出现一次、不知道错在哪
5. 提交代码前想按格式规范做一次缩进/行长/空行自检

### 语言信号

- 「怎么让循环对每个人执行一遍？」
- 「我复制了一份列表，为什么改一个另一个也变了？」
- 「range 打出来的数字怎么少了一个？」
- 「Python 报 IndentationError: unexpected indent」
- 英文: "my copy changed the original list too", "why is it off by one", "indentation error"

### 与相邻能力的区分

- 与 `list-operations` 的区别: 那条处理列表的增删改查与 IndexError；本卡处理遍历的执行次数、切片与复制、格式自检——列表内容变化后再回到那条。
- 与 `variables-strings-and-numbers` 的区别: 那条先给报错分型（NameError/SyntaxError/TypeError）；本卡的缩进与冒号错误是语法错误里与代码块结构相关的一支，报错文本与修法都不同。
- 与 `data-visualization` 的区别: 那条把数字序列喂给图表；序列本身的边界（差一、切片范围）先按本卡核对再交过去。

## E — 可执行步骤 (Execution)

1. **界定任务形态**
   - 完成标准: 明确属于「逐元素遍历」「取部分元素（切片）」「复制独立副本」中的哪几类，并写出涉及的原列表与新列表
   - 判停条件: 若是按位置/值增删元素或排查 IndexError，转 `list-operations`
2. **写遍历骨架**
   - 完成标准: for 单数变量 in 复数列表: 成形；循环体内至少 1 行缩进操作；循环后至少 1 行不缩进的收尾语句
3. **核对缩进与冒号**
   - 完成标准: 三项自查各给出结论——①for 后紧跟的代码块都已缩进；②只应执行一次的语句没有缩进；③for 行末冒号存在。报 IndentationError 时能对应到修法；程序能跑但消息数量不对时，按「预期执行次数 vs 实际次数」定位
   - 判停条件: 修复后输出数量仍不对，进入第 4 步核对数值边界
4. **核对数字与切片边界**
   - 完成标准: 生成 1~n 写成 range(1, n+1)；取前 n 个写 [0:n]；取末尾 n 个写 [-n:]；给出至少一组「预期输出 vs 实际输出」对照，不符则把指定的值加 1 或减 1 再核
   - 输入契约: 目标范围（起止值）与取数位置（前几个/后几个）
5. **复制列表用切片并验证独立**
   - 完成标准: 副本写法为 new = old[:]；向两个列表各追加一项后互不影响；若出现「改一个另一个也变」，改回 [:] 后复验
   - 输出契约: ①原列表 ②副本列表 ③两处修改后的独立结果
6. **格式自检三步**
   - 完成标准: ①每级缩进四个空格、全文无制表符与空格混用；②每行不超过 80 字符；③各部分之间用空行分隔且不过量——三项各给出核对结论
   - 判停条件: 行长超限处按协作约定处理；文中注明行长并非不可逾越的红线，存在 99 字符的小组例外

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- 数据是字典或嵌套结构（键值访问、遍历选型）时——转 `dicts-and-nesting`
- 只需要按位置/值增删元素，或正在排查 IndexError——转 `list-operations`
- 把「格式自检」当完整代码规范检查器：本卡只覆盖缩进/行长/空行三项，原书未给自动检查工具

### 作者在书中警告的失败模式

- ce30（引用陷阱）：`friend_foods = my_foods` 只是让两个变量指向同一个列表——给任一方 append，另一边同步变化，想维护两份数据的程序被静默错乱
- ce29（range 差一）：range(1,5) 只输出 1~4，期望 1~5 的计数/汇总结果整体偏移；作者的口径是「输出不符合预期就加 1 或减 1」
- ce25 与 ce27（缩进的两种相反逻辑错误）：该缩进而没缩进 → 本应逐元素执行的操作只执行一次；不该缩进却缩进 → 只应执行一次的操作重复多次。两者多数不报错，结果静默偏离预期
- ce28 与 ce32（最难发现的两类「隐形」错误）：for 行末漏掉冒号是单字符语法错误，作者称「并不那么容易发现」；制表符与空格混用会让看上去对齐的代码报错或行为异常，可批量把制表符转换为空格

### 作者的盲点 / 时代局限

- 2016 年快照：PEP 8 的缩进/行长口径（每级四个空格、每行不超过 80 字符）是成书时（2016）的通用建议，作者本人注明「并非不可逾越的红线」（有小组用 99 字符）；现环境若启用自动格式化工具，默认口径可能不同，按现环境替换
- 复制列表只给了 [:] 一条路径，未讨论 copy() 与浅/深拷贝概念——现代 Python 中遇到嵌套结构复制时须另行确认
- 本电子文本经转档后代码缩进丢失、图与截图内容全丢、页内孤立数字行会切断句子；回源核对与照抄示例时，须以可逐字核对的连续片段为准

### 容易混淆的邻近方法论

- `list-operations`: 那条管列表的增删改查与索引越界；本卡管遍历的执行次数、切片与复制、格式——复制出副本之后如需增删改，回到那条
- `data-visualization`: 那条把数字序列喂给图表；range 与切片的边界核对在本卡完成后再进入绘图
