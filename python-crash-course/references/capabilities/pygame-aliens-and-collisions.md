# 外星人群与碰撞检测（第13章）

## R — 原文 (Reading)

> 子弹击中外星人时，我们要马上知道，以便碰撞发生后让外星人立即消失。为此，我们将在更新子弹的位置后立即检测碰撞。方法sprite.groupcollide()将每颗子弹的rect同每个外星人的rect进行比较，并返回一个字典，其中包含发生了碰撞的子弹和外星人。
>
> — 第13章 13.5.1 检测子弹与外星人的碰撞（L17652-L17654）

## I — 方法论骨架 (Interpretation)

成组敌人系统由四件套构成：**网格铺量、整群位移、命中判定、损失响应**。每一步都有可核对的口径，而不是「看起来差不多」。

生成：数量不写死，由屏幕与自身尺寸算出——available_space_x = 屏幕宽 − 2×外星人宽，number_aliens_x = int(available_space_x / (2×外星人宽))；行数 = int((屏幕高 − 3×外星人高 − 飞船高) / (2×外星人高))，在飞船上方留出缓冲。int() 向下取整是明确口径：宁愿每行多留一点空间，不让外星人拥挤。位置 = 边距 + 2×宽/高×序号，用外层行号、内层列号的双层循环铺满。

移动：方向用**数字 1/−1** 编码（fleet_direction），位移统一写成速度 × 方向，换向只乘 −1，省掉整组 if-elif 分支；这是「状态取值恰好对应正/负方向」时的通用建模手法。触边判定看边缘：rect.right >= 屏幕右缘 或 rect.left <= 0。**一个成员触发、整群响应**——遍历中一发现触边就令全体下移固定像素并换向，随即 break。

碰撞：编组×编组用 groupcollide(bullets, aliens, True, True)，两个布尔实参分别决定被撞子弹与被击中外星人的去留（第一个改 False 即「能穿行的高能子弹」）；返回值是字典，键为子弹、值为被该子弹击中的外星人列表，后续记分直接复用。精灵×编组用 spritecollideany(ship, aliens)，没有碰撞时返回 None。碰撞按 rect 重叠的**矩形近似**，不是像素级形状。

损失与状态：撞到飞船与抵达屏幕底端共用一条响应——计数减一、清空双方编组、重建外星人群、飞船居中、短暂暂停（放在更新所有元素之后、显示到屏幕之前）。全程**只创建一个飞船实例**；游戏是否活动由 game_active 门控，事件处理与屏幕刷新在任何情况下都要运行。

验证纪律：难以自然触发的分支（空群重建、撞船）先写一条 print 确认检测可行，再写完整响应；为测试临时改参数（大子弹、加快下移）测完必须恢复。

## A1 — 书中的应用 (Past Application)

### 案例 1: 第一行外星人的数量与位置
- **类型**: 原书例题（可运行示范）（第13章 13.3.1-13.3.3）
- **问题**: 一行能容纳多少个外星人、每个应该放在哪里。
- **方法论的使用**: 先建一个临时 Alien（不入编组）取宽度；available_space_x = 屏幕宽 − 2×外星人宽；number_aliens_x = int(available_space_x / (2×外星人宽))；按 x = 外星人宽 + 2×外星人宽×序号 逐个创建并加入编组；绘制用 aliens.draw(screen)。
- **结论**: int() 向下圆整——宁愿多留空间、不让外星人拥挤；公式不必先验证正确，运行看结果再调整。
- **结果**: 运行后看到第一行外星人（图13-3），位置稍偏向左边，为后续整群移动留出空间（L17104）。

### 案例 2: 外星人群触边后下移换向
- **类型**: 原书例题（可运行示范）（第13章 13.4.4）
- **问题**: 整群外星人持续向右移动，抵达屏幕边缘后如何处理。
- **方法论的使用**: check_fleet_edges() 遍历 aliens.sprites()，任一外星人 check_edges() 为真即调用 change_fleet_direction() 并 break；后者让每个外星人 rect.y += fleet_drop_speed，再把 fleet_direction 乘以 −1；update_aliens() 在开头调用这套检测。
- **结论**: 整群行为用「一个成员触发、全体响应」实现；发现第一个触边者即可停止遍历。
- **结果**: 外星人群在屏幕上来回移动，并在抵达屏幕边缘后向下移动（L17632）。

### 案例 3: groupcollide 击落外星人与整群消灭后重建
- **类型**: 原书例题（可运行示范）（第13章 13.5.1-13.5.3）
- **问题**: 子弹击中外星人时直接穿过（还没有碰撞检测）；整群被消灭后游戏里再没有目标。
- **方法论的使用**: 更新子弹位置后立即 collisions = pygame.sprite.groupcollide(bullets, aliens, True, True)；if len(aliens) == 0 时 bullets.empty() 清空余弹并 create_fleet() 建新群；随后把碰撞与重建拆进 check_bullet_alien_collisions()。测试技巧：把 bullet_width 临时设为 300 快速清屏，测完恢复。
- **结论**: 绘制重叠不会自动产生交互，必须显式调用碰撞检测；groupcollide 的返回值是字典，为记分系统预留了数量信息。
- **结果**: 被击中的外星人将消失（L17704）；整群外星人被消灭干净后，将立刻出现一个新的外星人群（L17810）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 要生成成排成列的敌人/目标，并控制它们整体巡回移动。
2. 射出的子弹穿过敌人不生效，需要判定命中并让目标消失。
3. 敌人撞到玩家或抵达屏幕底端后的「损失一条命、场面重置」还没有接上。
4. 空群重建、撞船这类分支很难自然触发，需要一套加速验证的办法。
5. 游戏结束后停不下来，需要把「进入非活动状态」接进主循环。

### 语言信号

- 「怎么让敌人排成一排一排地出现」
- 「子弹打中了却没反应，直接穿过去」
- 「敌人整群走到边上就不见了」
- 「清完一波之后屏幕上什么都没有了」
- 英文: "bullets pass through enemies", "the fleet walks off the edge of the screen", "spawn a wave of enemies"

### 与相邻能力的区分

- 与 `pygame-control-and-bullets` 的区别: 那张卡负责我方飞船的操控与子弹的产生、回收、限数；本卡接手敌方群体的生成、整群移动与碰撞击杀。
- 与 `game-scoring-and-state` 的区别: 本卡把「撞船/到底端 → 损失一条命」的响应与 game_active 门控搭起来；记分、等级与完整重开清单在那一张。

## E — 可执行步骤 (Execution)

1. **开工前盘点：计划、既有代码与退出热键**
   - 完成标准: 本轮要做的改动列成清单（先网格生成、再整群移动、最后碰撞与损失响应）；既有代码的清理项已审核；加一个远离操作键的退出热键（Q），测试期可按 Q 关闭窗口。
2. **网格生成：先算数量，再定坐标**
   - 完成标准: available_space_x = 屏幕宽 − 2×外星人宽；number_aliens_x = int(available_space_x / (2×外星人宽))；行数 = int((屏幕高 − 3×外星人高 − 飞船高) / (2×外星人高))；单个外星人坐标 = 自身宽/高 + 2×宽/高×序号；用外层行号、内层列号的双层循环建群；外星人初始 rect.x = width、rect.y = height；编组 draw() 批量绘制。
   - 输入契约: 屏幕宽高、外星人宽高、飞船高度（像素）；输出契约: 铺满屏幕上段的外星人编组。
   - 判停条件: 行列数与截图不符时，先核对屏幕尺寸与 int() 取整口径，再检查公式变量名，不要盲目改公式。
3. **整群移动：数值方向、触边检测、整群下移换向**
   - 完成标准: fleet_direction 用 1/−1 编码；每轮位移 = alien_speed_factor × fleet_direction；check_edges() 判定 rect.right >= 屏幕右缘 或 rect.left <= 0；check_fleet_edges() 一发现触边即调用 change_fleet_direction() 并 break；后者让全体 rect.y += fleet_drop_speed、fleet_direction *= −1。群体左右巡回、触边整群下移一次并换向，不会走出屏幕。
4. **碰撞击杀与空群重建**
   - 完成标准: 更新子弹位置之后立即 groupcollide(bullets, aliens, True, True)；命中外星人双方消失；if len(aliens) == 0 时清空余弹并重建整群；需要穿行弹药时把第一个布尔实参改为 False（被击中的外星人仍消失）。
   - 判停条件: 难以自然触发的分支用临时参数加速测试（大子弹、加快下移），测完必须恢复默认值。
5. **损失响应：两条触发线共用一个函数**
   - 完成标准: 撞船线用 spritecollideany(ship, aliens)；到底端线遍历 aliens.sprites()，alien.rect.bottom >= 屏幕底缘即调用统一响应并 break；响应内按序执行「计数减一 → 清空外星人与子弹 → 重建整群 → 飞船居中 → 短暂暂停（更新后、上屏前）」；全程只保留一个飞船实例。
   - 输出契约: 每损失一次，场面回到初始可玩状态，计数正确递减。
6. **状态门控：确定主循环里哪些部分始终运行**
   - 完成标准: 事件处理与屏幕刷新在任何情况下都调用；位置更新类函数（飞船、子弹、外星人）仅在 game_active 为真时调用；飞船数用尽时在损失响应内把 game_active 置为 False；统计量用单独的统计对象承载，开局要复位的部分放进统一的重置方法。
   - 判停条件: 若主循环被整体包进活动判断导致无法退出，回到本步骤核对「始终运行 / 仅活动时运行」的划分。

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- 只有单个、静态的敌人或装饰物——网格公式与整群机制是为「成组、要整体行动」的对象准备的，单件直接摆坐标即可。
- 需要像素级或多形状精确碰撞的场合——本书口径是 rect 矩形重叠近似，精细判定要换检测方案。
- 按固定时间步（delta time）推进的引擎/框架——这里的速度因子是「像素/帧」口径，需要另行换算。

### 作者在书中警告的失败模式

- ce118: 缺少终局条件——游戏永远都不会结束，ships_left 一路减成更小的负数；损失处理必须有「用完即切换状态」的分支。
- ce126: 把主循环整体包进活动标志——游戏结束后键盘与关闭窗口都无响应，玩家被卡在死窗口里；事件处理与屏幕刷新必须始终运行。
- ce121: 误以为「飞船被撞毁」要不断创建新 Ship 实例——对象越建越多且已有引用指向旧对象，状态与显示脱节；全程只创建一个飞船实例，被撞后居中 + 计数减一。
- ce114: 把坐标公式的正确性交给「跑起来看着差不多」——取整、差一、边界误差在视觉上不可见；先手工验算一两个样例再运行。

### 作者的盲点 / 时代局限

- 两处原文自相矛盾、须以代码块为准：行数公式中 available_space_y 与 available_height_y 前后不一致（L17220，原文如此）；正文要求把新函数命名为 update_aliens() 而紧随其后的定义为 check_aliens_bottom()（L18210-L18214，原文如此）。
- 布局结果依赖屏幕尺寸（ce113）：书中截图对应 1200×800，换尺寸后行列数变化不是代码错误；素材图 alien.bmp 需自备且背景色要与屏幕一致，转档稿中相关图全丢。
- 「临时改参数加速测试」依赖人工记得恢复（ce119），书中没有测试模式与正式值的隔离机制。
- 全书是 2016 年技术栈快照（Python 3.5 / Pygame 1.9.2a0，Pygame 从 Bitbucket 源安装），安装、版本与平台流程须按现环境替换（2016 年快照）。

### 容易混淆的邻近方法论

- `pygame-control-and-bullets`: 同一项目线的上一段；子弹的产生与回收在那里，子弹与外敌的相交判定在本卡。
- `game-scoring-and-state`: 同一项目线的下一段；本卡管「命数怎么扣、状态怎么切」，那张管「分数怎么加、重开怎么复位」。
