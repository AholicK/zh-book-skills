# 条件测试与 if 结构选型（第5章）

## R — 原文 (Reading)

> 总之，如果你只想执行一个代码块，就使用if-elif-else结构；如果要运行多个代码块，就使用一系列独立的if语句。
>
> — 第5章 5.3.6 测试多个条件（L5929-L5929）

## I — 方法论骨架 (Interpretation)

分支代码的正确性由两层决定：**怎么问**（条件测试）与**用哪种结构问**（if 家族选型）。

条件测试是一切「值为 True 或 False 的表达式」的统称，记忆锚点是一个等号陈述、两个等号发问。常用写法可归成六类：相等/不等、大小写归一（先 lower() 再比较，原值不被改动）、数字比较、and/or 组合、in/not in 成员检查、把列表名直接当布尔条件（至少一个元素为 True、空列表为 False）；and 要求全部通过，or 只需一个通过。

结构选型看两件事：情形数量与是否互斥。只有一种情形 → 简单 if；两种情形必发生其一 → if-else；多个互斥情形 → if-elif-else（逐条测试，命中即跳过余下）；可能多个条件同时成立、且每个都要处理 → 一系列独立 if。

两个安全阀：分支体里只设置变量、把输出统一放到结构后一条语句（改输出只改一处）；else 慎用——它包罗万象、不校验数据，知道最终要测的条件时就写成显式 elif。

数据来自用户后，处理列表要先做两道检查：循环前先判空（列表名直接作条件），循环内对特殊值（如缺货配料）用 if 走特殊分支；两份名单核对则用 in 与供应清单比对。

格式上只有一条建议：比较运算符两边各加一个空格。

## A1 — 书中的应用 (Past Application)

### 案例 1: voting.py 从简单 if 到 if-else
- **类型**: 原书例题（可运行示范）（第5章 5.3.1–5.3.2）
- **问题**: 判断年龄是否够投票资格，并按结果给出不同消息。
- **方法论的使用**: 先用简单 if（测试通过才执行缩进块，age=19 时打印两条消息）；再改成 if-else，令 age=17 走 else 分支。
- **结论**: if-else 适合「只存在两种情形」（够/不够）的场景，总是执行两个操作中的一个。
- **结果**: 输出 You are old enough to vote!（两条消息版含 Have you registered to vote yet?）；age=17 版输出 Sorry, you are too young to vote. 与 Please register to vote as soon as you turn 18!。

### 案例 2: amusement_park.py 定价与「分支只赋值」重构
- **类型**: 原书例题（可运行示范）（第5章 5.3.3）
- **问题**: 按年龄段定价（4 岁以下免费、4~18 岁 5 美元、18 岁以上 10 美元），并让输出消息便于修改。
- **方法论的使用**: if-elif-else 逐条测试、命中即跳过余下；再重构——分支内只设置 price，结构后用一条未缩进的 print 统一打印。
- **结论**: 重构版除效率更高外还更容易修改：要调整输出消息，只改一条而不是三条 print。
- **结果**: age=12 时输出 Your admission cost is $5.（重构版输出相同）。

### 案例 3: 三个独立 if 与 if-elif-else 的对照
- **类型**: 原书例题（正确版与有意写错版对照）（第5章 5.3.6）
- **问题**: 顾客点了 mushrooms 与 extra cheese 两种配料，两种都要添加。
- **方法论的使用**: 正确版用三条独立 if 逐项检查（每条都执行）；对照版误写成 if-elif-else——第一个测试通过后跳过余下测试。
- **结论**: 只想执行一个代码块用 if-elif-else，要运行多个代码块用一系列独立 if；误用会让结果静默缺项。
- **结果**: 独立 if 版输出 Adding mushrooms. / Adding extra cheese. / Finished making your pizza!；elif 版只输出 Adding mushrooms. 与结束语。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 一个值要按区间/档位分流（票价、额度、等级），不确定该用 if-else 还是 if-elif-else
2. 几个提醒/校验条件可能同时命中，输出却只出现了第一条
3. 判断「谁在名单里/谁被禁言」，需要 in 与 not in 的写法
4. 输入来自用户，可能为空或大小写不一，比较前想先做体检
5. 兜底分支想用 else，但担心把未预期的输入也放进来

### 语言信号

- 「按年龄分档，写成 if-elif-else 就行吧？」
- 「我两个条件都满足，怎么只执行了一个分支？」
- 「这个列表可能是空的，要不要先判断一下？」
- 「用户名大小写不一样，算不算重复？」
- 英文: "only the first branch runs", "if-elif-else vs separate if", "should I check if the list is empty"

### 与相邻能力的区分

- 与 `input-and-while-loops` 的区别: 那条处理「反复询问直到满足条件」的循环与退出途径；本卡只管单次判定的条件测试与结构选型——需要重复时整段交过去。
- 与 `dicts-and-nesting` 的区别: 成员检查的对象不同——本卡用 in/not in 查列表；对字典键的成员检查（keys()）按那条的口径处理。

## E — 可执行步骤 (Execution)

1. **盘清情形**
   - 完成标准: 列出有几种情形、是否互斥、每种的判定条件，并标注是否可能多个同时成立
   - 判停条件: 若需要反复询问直至条件满足，转 `input-and-while-loops`
2. **选结构**
   - 完成标准: 按判据给出结论——单情形→简单 if；两情形必发生其一→if-else；多个互斥情形→if-elif-else；可同真且都要处理→一系列独立 if
3. **写条件测试**
   - 完成标准: 所需写法逐类落地（==/!=、lower() 归一、数字比较、and/or、in/not in、列表名作布尔条件）；每条测试能枚举 True/False 两种结果；归一化后确认原变量未被改动
   - 输入契约: 待测变量及其合法取值；来自用户的输入先按类型归一（字符串转小写、数值转换）
4. **写分支体**
   - 完成标准: 分支内只设置变量，输出/统计放在结构后一条语句；可同真的条件各占一条独立 if；知道最终条件时，else 已改写为显式 elif
5. **对照预期复检**
   - 完成标准: 每种情形各给一个代表输入，命中分支与输出条数逐一核对；空列表输入获得明确提示而非零输出；发现输出缺项先查是否把可同真条件写进了 elif 链
   - 判停条件: 全部通过后核对比较运算符两边各一个空格，收尾

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- 需要重复执行直到条件变化——那是循环的职责，转 `input-and-while-loops`
- 数据本身是字典：对键做成员检查、按数据建模再分支，先按 `dicts-and-nesting` 理顺结构，再回到分支判断
- 把 else 当作「异常输入兜底」：知道最终条件时应写成显式 elif，而不是靠分支结构吞掉未预期的数据

### 作者在书中警告的失败模式

- ce33（该用独立 if 时误用 if-elif-else）：多个条件都可能成立却写成 elif 链，第一个测试通过后跳过余下——只添加第一种配料，其余静默丢弃，程序不报错
- ce34（else 包罗万象）：只要不满足任何 if/elif 的条件就执行，可能引入无效甚至恶意的数据；知道最终要测的条件时应改用 elif
- ce35（大小写敏感）：'Audi' 与 'audi' 判为不等；用户名查重这类场景会放过本应拦截的输入，或反过来误报冲突，须先 lower() 归一
- ce36（假设列表非空）：数据来自用户后不能再假设列表有元素；空列表让循环执行零次，输出凭空少一段却不报错，循环前先判空

### 作者的盲点 / 时代局限

- 2016 年快照：术语与示例按成书时（2016）的 Python 3 语法书写（print 函数形式）；原书未涉及条件表达式（单行简写）与短路求值细节，现代写法的差异按现环境替换
- else 的风险只给出原则与一个改写示例，未给完整的输入校验流程；需要严格校验时须自行补全
- 练习 5-10 的不区分大小写比较未给完整代码；正文与总结句含印刷/转档错误（「不区分大消息」、Ture），照抄会失败，引用时须按上下文自行校正
- 把列表名当条件的用法只讲到空/非空判定，未展开其他真值语义（如 0 与空字符串），超出范围处未补

### 容易混淆的邻近方法论

- `input-and-while-loops`: 本卡的条件测试可以原样搬进 while 的循环条件；区别在于本卡做单次判定，那条管反复判定与退出途径
- `dicts-and-nesting`: in / not in 查的是列表成员；换成字典时是「查键」，用 keys() 口径
