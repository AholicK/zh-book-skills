# 变量、字符串与数字基础（第2章）

## R — 原文 (Reading)

> 语法错误是一种时不时会遇到的错误。程序中包含非法的Python代码时，就会导致语法错误。例如，在用单引号括起的字符串中，如果包含撇号，就将导致错误。
>
> — 第2章 2.3.5 使用字符串时避免语法错误（L2377-L2377）

## I — 方法论骨架 (Interpretation)

这一层的能力是把「写码前的口径」与「报错后的定位」连成一体，两头互认：写码时守口径，出错时按类型回查口径。

先立变量模型：**变量是名字到值的关联**，赋值即创建、可随时重新关联，程序始终记录最新值——这正是拼错名字会报错的来源，也是查 NameError 的出发点。

字符串有三组固定动作：大小写（title/upper/lower——**存储前先 lower() 统一口径，显示时再整形**）；拼接（`+` 只连接字符串，混入数字必须先转换）；空白（strip 系列只返回新字符串，要永久生效必须把结果**存回变量**）。

数字的口径：整数四则与 `**` 乘方、运算次序可用括号改写、除法在当前默认环境下得到小数；浮点结果的小数位数可能不确定（0.2 + 0.1 不会给出干净的结果），书中给出的处置是暂时忽略多余小数位。

报错后的定位先分型、再查各自成因。traceback 拆三项——文件与行号、出错代码行、错误类型与消息。**NameError** 只查两件事：用前是否忘记赋值、拼写是否一致（Python 不做拼写检查，两处错成同一个名字反而能跑）；**SyntaxError** 查引号与括号匹配（含撇号的句子用双引号），可用编辑器语法高亮颜色异常做辅助；**TypeError** 查字符串与数字混用，用 str() 显式声明用途——解释器拒绝替你猜「数值 23」还是「字符 2、3」。

命名与注释是同一套纪律的延伸：字母数字下划线、不以数字打头、不用关键字与函数名、慎用小写 l 与大写 O；注释只在「曾考虑过多个方案」时写。

## A1 — 书中的应用 (Past Application)

### 案例 1: 拼错的变量名与 NameError
- **类型**: 原书例题（有意示错，含修复对照）（第2章 2.2.2）
- **问题**: 定义 message = "Hello Python Crash Course reader!"，却打印 print(mesage)
- **方法论的使用**: 读 traceback 三要素（文件与行号、问题代码行、错误类型），再按 NameError 的两个成因核对——用前是否赋值、两处拼写是否一致
- **结论**: 名称错误通常只有两种成因；Python 不做拼写检查、只要求拼写一致——两处都拼错成同一个名字时程序反而能「成功运行」
- **结果**: 书中给出的输出：NameError: name 'mesage' is not defined；改名为 mesage 后输出 Hello Python Crash Course reader!

### 案例 2: 整数拼进字符串的 TypeError 与 str() 修复
- **类型**: 原书例题（可运行示范）（第2章 2.4.3）
- **问题**: message = "Happy " + age + "rd Birthday!"（age = 23）无法通过
- **方法论的使用**: 按类型错误的口径检查字符串与数字混用，用 str(age) 显式转换后再拼接
- **结论**: Python 不做隐式转换；结果出乎意料时先检查数字被解读成了数值还是字符串
- **结果**: 书中给出的输出：报错为 TypeError: Can't convert 'int' object to str implicitly；修复后输出 Happy 23rd Birthday!

### 案例 3: 撇号引发的 SyntaxError
- **类型**: 原书例题（正误对照）（第2章 2.3.5）
- **问题**: 用单引号括起含撇号的句子（message = 'One of Python's ...'）
- **方法论的使用**: 按引号匹配口径改用双引号括起含撇号的字符串，并用编辑器语法高亮颜色异常做辅助自查
- **结论**: 语法错误是最不具体的错误类型——报错位置指向第二个单引号之后，与实际事故点不一致，难以定位
- **结果**: 书中给出的输出：双引号版本输出 One of Python's strengths is its diverse community.；单引号版本报 SyntaxError: invalid syntax

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 程序一运行就出现报错，分不清 NameError / SyntaxError / TypeError 该从哪查
2. 变量「明明写了」却被报未定义，或统一改名后程序反而能跑了
3. 想用 + 号把数字和提示语拼成一句话，结果报类型错误
4. 从表单或文件取到的文本大小写、空白杂乱，想存一份干净、可比较的数据
5. 变量该怎么起名、注释要不要写，拿不准规则

### 语言信号

- 「name 'mesage' is not defined 是什么意思」
- 「字符串和数字为什么不能相加」
- 「引号里有个撇号就报错了」
- 英文: "name 'x' is not defined", "can't convert 'int' object to str implicitly", "invalid syntax"

### 与相邻能力的区分

- 与 `loops-slices-and-formatting` 的区别: 缩进、冒号、range 边界一类错误归它；本卡只管引号、括号、大小写等字符层面与运行期三类报错的分型。
- 与 `input-and-while-loops` 的区别: input() 取回的一律是字符串、比较前需转换的分界归它；本卡只管值到手之后的字符串与数字处理。
- 与 `install-and-editor-reference` 的区别: 命名禁区与关键字清单在它那边有对照参考；本卡负责把命名规则落成写码前自查动作。

## E — 可执行步骤 (Execution)

1. **读报错、分型**
   - 完成标准: 从 traceback 中拆出文件与行号、出错代码行、错误类型三项，并归入 NameError / SyntaxError / TypeError 之一
2. **按型修复**
   - 完成标准: NameError——核对赋值与两处拼写一致性；SyntaxError——核对引号与括号匹配（含撇号用双引号）；TypeError——查字符串与数字混用并用 str() 显式转换；修完复跑，不再报同一错误且输出符合预期
   - 判停条件: 若错误与缩进、冒号、range 边界有关，转遍历与格式类能力处理
3. **字符串口径自查**
   - 完成标准: 大小写按「存储前 lower()、显示时 title()」两段式处理；拼接的每一段都是字符串；strip 系列的结果全部存回变量；比较前先统一大小写并清理空白
   - 输出契约: 列出每一处「回存变量」的赋值写法
4. **命名与注释自查**
   - 完成标准: 每个变量名过五条命名规则；每处注释按「找到方案前是否考虑过多个方案」问题决定写或不写
   - 输入契约: 完稿的脚本或代码片段
5. **数字运算核对**
   - 完成标准: 除法结果按当前默认环境（3 / 2 得 1.5）核对；浮点结果出现多余小数位时按「暂时忽略」口径处置，需要格式化时另查现行做法

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- 报错来自缩进、冒号、range 边界或循环控制时——那属于遍历与输入循环类能力
- 需要区分「语法错误 vs 逻辑错误」（程序跑得起来但结果不对）时——先按调试类口径处理

### 作者在书中警告的失败模式

- 点名反例 ce05：NameError——要么用前忘记赋值、要么拼写不一致；两处都拼错成同一个名字时程序反而能运行，错误被掩盖。
- 点名反例 ce11：字符串与整数直接相加引发 TypeError（Can't convert 'int' object to str implicitly）——必须显式转换，指望解释器自行处理会让程序中断。
- ce06：一个字符的输入错误可能耗掉数小时——计算机按字面执行、不做拼写检查，不要高估肉眼扫代码的核对能力。

### 作者的盲点 / 时代局限

- 2016 年快照：以 Python 3.5 写作，按现环境替换；Python 2 的 print 语句与整数除法段落为历史资料，不得当现行口径。
- 浮点多余小数位的处理被留给后续项目内容，本单元只有「暂时忽略」口径；涉及金额与精确计算时需另行查现行做法。
- Python 之禅六条是理念断言，书中未给应用条件与反例；不能当可核查规范使用。
- 转档缺陷：终端会话被压平，提示符与换行版式已失；行内指向标记丢失处存在悬空指代，引用须照原文留空、不得补造。
