## 变量（variable）

> 出处：第二章 2.2 ｜ L1901-L1921 ｜ 标签：[term, python, basics]

**作者定义**

「我们添加了一个名为message的变量。每个变量都存储了一个值——与变量相关联的信息。」
「在程序中可随时修改变量的值，而Python将始终记录变量的最新值。」

**关键区分**

≠ 数学里的未知数（解方程的对象）
≠ 需要先声明的「容器」
= 「名字→值」的关联：赋值即创建，可随时重新关联；Python 始终记录最新值，旧值不再可访问

**为什么重要**

下游 skill 解释变量时，需用「与变量相关联的信息」和「Python 记录最新值」这两个作者口径，
而不是「盒子装东西」的比喻；这正是书中 NameError 两大成因（未赋值先用、拼写不一致）的表述基础。

## traceback

> 出处：第二章 2.2.2 ｜ L1985-L2015 ｜ 标签：[term, python, error]

**作者定义**

「解释器会提供一个traceback。」
「traceback是一条记录，指出了解释器尝试运行代码时，在什么地方…陷入了困境。」

**为什么重要**

书把「读 traceback」当作正式技能（四个组成部分逐一点出）。下游 skill 引导用户排错时必须按此拆解，
否则「看报错信息」这句话对新手没有操作面。

## 方法（method）

> 出处：第二章 2.3.1 ｜ L2117-L2125 ｜ 标签：[term, python]

**作者定义**

「方法是Python可对数据执行的操作。」
「在name.title()中，name后面的句点（.）让Python对变量name执行方法title()指定的操作。」
「每个方法后面都跟着一对括号，…这是因为方法通常需要额外的信息来完成其工作。」

**关键区分**

**为什么重要**

## 拼接（concatenation）

> 出处：第二章 2.3.2 ｜ L2187-L2193 ｜ 标签：[term, python, string]

**作者定义**

「Python使用加号（+）来合并字符串。」
「这种合并字符串的方法称为拼接。」

**关键区分**

≠ 任意数据的相加
≠ 自动类型转换

> 出处：第二章 2.3.3–2.3.4 ｜ L2223-L2373 ｜ 标签：[term, python, string]

**作者定义**

「在编程中，空白泛指任何非打印字符，如空格、制表符和换行符。」
「'python'和'python '看起来几乎没什么两样，但对程序来说，它们却是两个不同的字符串。」

## 语法错误（syntax error）

> 出处：第二章 2.3.5（另见 4.2） ｜ L2377-L2417 ｜ 标签：[term, python, error]

**作者定义**

「语法错误是一种时不时会遇到的错误。程序中包含非法的Python代码时，就会导致语法错误。」
「这种语法错误表明，在解释器看来，其中的有些内容不是有效的Python代码。」
「语法错误也是最不具体的错误类型，因此可能难以找出并修复。」

**关键区分**

≠ 逻辑错误（代码语法合法，但结果与预期不符）
≠ 运行期错误（NameError/TypeError 等发生在运行时）
= 解释器拒绝「翻译」代码：最典型成因是引号/括号不匹配、少冒号

**为什么重要**

书把「语法错误 vs 逻辑错误」当作一对课程概念（第 4 章再展开）。下游 skill 帮用户排查时需先做此分类，
否则会把「跑起来了但结果不对」当成语法错误来修。

## 浮点数（float）

> 出处：第二章 2.4.2 ｜ L2523-L2565 ｜ 标签：[term, python, number]

**作者定义**

「Python将带小数点的数字都称为浮点数。」
「但需要注意的是，结果包含的小数位数可能是不确定的：」
「所有语言都存在这种问题，没有什么可担心的。」

**为什么重要**

涉及金额与显示格式时，若按数学直觉解释浮点结果，会得出「Python 算错了」的错误结论。
下游 skill 需按「小数位数不确定是所有语言的通病」来表述，并指向后续处理多余小数位的场合。

## 列表（list）

> 出处：第三章 3.1 ｜ L2883-L2925 ｜ 标签：[term, python, list]

**作者定义**

「列表由一系列按特定顺序排列的元素组成。」
「在Python中，用方括号（[]）来表示列表，并用逗号来分隔其中的元素。」

## 差一行为（差一错误）

> 出处：第三章 3.1.2（另见 4.3.1） ｜ L2949-L4255 ｜ 标签：[term, python, pitfall]

**作者定义**

「在Python中，第一个列表元素的索引为0，而不是1。」
「第二个列表元素的索引为1。根据这种简单的计数方式，要访问列表的任何元素，都可将其位置减1，并将结果作为索引。」
「如果结果出乎意料，请看看你是否犯了简单的差一错误。」
「在这个示例中，range()只是打印数字1~4，这是你在编程语言中经常看到的差一行为的结果。」

**关键区分**

≠ Python 的缺陷
= 从 0 开始计数（索引）与「到第二个值前停止」（range）带来的常见认知落差；
  书中给出两个检查法：索引类问题把指定的索引减 1 再试；range 输出不符预期时把指定的值加 1 或减 1

**为什么重要**

索引错误修复与 range() 用法都建立在这个概念上；下游 skill 提到索引或 range 时应主动带上这两个检查法，
而不是泛泛提示「检查边界」。

## 排序：sort() / sorted() / reverse()

> 出处：第三章 3.3 ｜ L3445-L3559 ｜ 标签：[term, python, list, sort]

**作者定义**

「Python方法sort()让你能够较为轻松地对列表进行排序。」
「要保留列表元素原来的排列顺序，同时以特定的顺序呈现它们，可使用函数sorted()。」
「要反转列表元素的排列顺序，可使用方法reverse()。」
「注意，reverse()不是指按与字母顺序相反的顺序排列列表元素，而只是反转列表元素的排列顺序：」

**关键区分**

≠ 三种方式可互换
= 永久性重排用列表方法 sort()（可传 reverse=True 得到字母逆序）；只想按特定顺序展示、不改原列表用函数 sorted()；
  reverse() 只反转当前顺序（再次调用即恢复），与「按字母逆序」不是一回事

**为什么重要**

「永久 vs 临时」是本书点名的最易混点；下游 skill 必须以该对比呈现排序选型，
并区分 sort(reverse=True) 与 reverse() 两种「反」的不同含义。

## 索引错误（IndexError）

> 出处：第三章 3.4 ｜ L3641-L3661 ｜ 标签：[term, python, error]

**作者定义**

「鉴于列表索引差一的特征，这种错误很常见。」
「索引错误意味着Python无法理解你指定的索引。」
「程序发生索引错误时，请尝试将你指定的索引减1，然后再次运行程序，看看结果是否正确。」

**关键区分**

≠ 语法错误（代码非法）
= 代码合法但访问了不存在的索引（如 3 个元素的列表访问 [3]）；修复检查法：把指定的索引减 1 再试；
  索引 -1 访问最后一个元素几乎总是可行，只有列表为空时例外

**为什么重要**

复现、读数、减 1 检查、修复这条处置链是现成排查流程；-1 的边界条件（空列表）也必须一并带上，
否则会给用户「-1 永远安全」的过度承诺。

## 逻辑错误（logical error）

> 出处：第四章 4.2.2–4.2.4 ｜ L4073-L4161 ｜ 标签：[term, python, error]

**作者定义**

「这是一个逻辑错误。从语法上看，这些Python代码是合法的，但由于存在逻辑错误，结果并…不符合预期。」
「在有些情况下，这可能导致Python报告语法错误，但在大多数情况下，这只会导致逻辑错误。」
「这也是一个逻辑错误，与4.2.2节的错误类似。Python不知道你的本意，只要代码符合语法，它就会运行。」

**关键区分**

≠ 语法错误（代码非法，解释器拒绝运行）
= 语法合法但结果与预期不符（如该逐元素执行的操作只执行一次）；
  排查线索是「预期执行次数 vs 实际执行次数」，多数指向缩进问题

**为什么重要**

本书把多数缩进错误的后果归为逻辑错误；下游 skill 排查「程序能跑但结果不对」时应先按此归类，
而不是让用户去找「语法错误」或盲目加打印语句。

## 切片（slice）

> 出处：第四章 4.4 ｜ L4475-L4733 ｜ 标签：[term, python, list]

**作者定义**

「你还可以处理列表的部分元素——Python称之为切片。」
「要创建切片，可指定要使用的第一个元素和最后一个元素的索引。与函数range()一样，Python在到达你指定的第二个索引前面的元素后停止。」
「要复制列表，可创建一个包含整个列表的切片，方法是同时省略起始索引和终止索引（[:]）。这让Python创建一个始于第一个元素，终止于最后一个元素的切片，即复制整个列表。」
「这种语法实际上是让Python将新变量friend_foods关联到包含在my_foods中的列表，因此这两个变量都指向同一个列表。」

**关键区分**

≠ 只是「读取一部分元素」的语法
= 原列表的一段：切片产生新列表（[:] 就是整表复制）；
  而 friend_foods = my_foods 只是给同一个列表再加一个名字——两个变量指向同一列表，改一个即改另一个

**为什么重要**

「引用 vs 复制」是本书标注代价很大的陷阱；下游 skill 讲「复制列表」必须给出切片写法，
并警示直接赋值的别名行为，否则用户的「副本」改动会反过来污染原列表。

## 元组（tuple）与不可变

> 出处：第四章 4.5 ｜ L4769-L4905 ｜ 标签：[term, python, tuple]

**作者定义**

「Python将不能修改的值称为不可变的，而不可变的列表被称为元组。」
「元组看起来犹如列表，但使用圆括号而不是方括号来标识。」
「虽然不能修改元组的元素，但可以给存储元组的变量赋值。」
「相比于列表，元组是更简单的数据结构。如果需要存储的一组值在程序的整个生命周期内都不变，可使用元组。」

**关键区分**

≠ 完全不能变的「常量」
= 元素本身不可修改（给元素赋值会触发 TypeError），但存放元组的变量可整体换一个新元组；
  选型判据：一组值在整个生命周期内不变 → 用元组

**为什么重要**

「不可变」指元素而非变量，这是最容易讲错的地方；下游 skill 的列表/元组选型建议
应直接以原文判据（生命周期内是否变化）为准。

## PEP 8

> 出处：第四章 4.6 ｜ L4943-L5047 ｜ 标签：[term, python, style]

**作者定义**

「PEP 8是最古老的PEP之一，它向Python程序员提供了代码格式设置指南。」
「代码被阅读的次数比编写的次数多。」
「PEP 8建议每级缩进都使用四个空格，这既可提高可读性，又留下了足够的多级缩进空间。」

= 本书特指 @login_required：未登录用户请求受保护页面时，Django 重定向到 LOGIN_URL 指定的 URL
≠ 与 if 判断同效 — 装饰器写一次即对整个视图函数生效，不需要在函数体里写登录检查

**为什么重要**

视图保护是用户系统的核心动作（除 index 外每个视图都要保护）；下游 skill 若不明白「运行前改写函数行为」的机制，会在调试时困惑于「为什么页面自己跳转了」。

## 提交（commit）

> 出处：第20章 20.2.11、附录D D.5 ｜ L29090-L29094, L31154 ｜ 标签：[term, git]

**作者定义**

「如果你阅读完了第17章，就知道Git是一个版本控制程序，让你能够在每次成功实现新功能后都拍摄项目代码的快照。」
「无论出现什么问题（如实现新功能时不小心引入了bug），你都可以轻…松地恢复到最后一个可行的快照。每个快照都被称为提交。」
「提交是项目在特定时间点的快照。」

**关键区分**

≠ 推送（push）到服务器 — 提交是本地动作，拍摄的是本地项目的快照；推送到远端是随后的另一条命令
= 「项目在特定时间点的快照」；时机是「每次成功实现新功能后」，作用是随时恢复到最后一个可行的快照
≠ 自动发生的 — 要显式执行 git commit -m "message"，消息会被记录进项目历史

**为什么重要**

部署与协作流程（第20章、附录D）都从「提交」起步；下游 skill 需要按「工作完成一小步就提交」的粒度指导学生，并解释为什么提交是「回到可行状态」的安全网。

## 仓库（repository）

> 出处：附录D D.4 ｜ L31102 ｜ 标签：[term, git]

**作者定义**

「输出表明Git在git_practice中初始化了一个空仓库。仓库是程序中被Git主动跟踪的一组文件。」

**关键区分**

≠ 项目文件夹本身 — 只有被 Git 主动跟踪的文件才构成仓库；用 git add 决定哪些文件进入仓库
= 「程序中被Git主动跟踪的一组文件」；管理仓库的数据都存放在隐藏的 .git/ 目录中
≠ 可以随便删 — 删掉 .git/ 会丢弃项目的所有历史记录

**为什么重要**

下游 skill 需要区分「项目目录」与「仓库」：git init 之后才有仓库，工作成果要经 add / commit 才能真正进入仓库，而 .git/ 是不可乱动的元数据目录。

## 分支（branch）

> 出处：附录D D.5 ｜ L31150, L31154 ｜ 标签：[term, git]

**作者定义**

「在Git中，分支是项目的一个版本。」
「每次查看项目的状态时，输出都将指出你位于分支master上。」

**关键区分**

≠ 另存一份的项目副本（另一个文件夹）— 分支是同一仓库内「项目的一个版本」，可随时检出切换
= 默认分支名为 master；git status 会告诉你当前在哪个分支上
≠ 可以无视 — 检出以前的提交会离开分支进入「分离头指针」状态，此时不适合继续开发

**为什么重要**

撤销修改、检出以前的提交等操作都要先知道自己在哪个分支；下游 skill 若忽略分支状态，会把「分离头指针下的实验性查看」误当成正常开发位置。

## 橡皮鸭子调试法

> 出处：附录C C.1 ｜ L30794, L30798 ｜ 标签：[term, debugging]

**作者定义**

「程序员甚至给这种情形提供了一个名称，称之为橡皮鸭子调试法。如果你向一只橡皮鸭子（或…任何无生命的东西）清楚地阐述自己的处境，并向它提出具体的问题，你常常能够回答这个问题。」
「有些编程公司甚至在办公室放置一个橡皮鸭子，旨在鼓励程序员“与这只鸭子交流”。」

**关键区分**

≠ 上网搜现成答案 / 直接问别人 — 是把问题清楚地阐述给无生命对象（橡皮鸭子、任何无生命的东西）并「向它提出具体的问题」，再由自己回答
= 作者给「回答三个问题后自己就摆脱了困境」这一情形起的名字；要点是「清楚地阐述处境」+「具体的问题」

**为什么重要**

这是 task-67 求助方法论的核心一招；下游 skill 在用户卡住时，应先引导其把处境和具体问题复述出来（常常自己就能回答），而不是跳过复述直接给答案。
