- **作者**: [美] Eric Matthes 著 / 袁国忠 译（人民邮电出版社·图灵社区电子书，中文版 2016 年 7 月第 1 版）

## 一句话主旨

Python 入门的最短路径是「**先掌握最小语言核心，再立刻在三个完整项目里把它用起来**」——用逐行解释的可运行代码、大量常见错误示范与每节的「动手试一试」练习，把从装环境到部署上线的完整链路走一遍，让读者在真实项目里建立「写—跑—报错—读 traceback—修—重构」的开发习惯。

## 骨架（七个一级论点）

1. **环境先行，且把环境问题当第一等公民对待。** 第1章用整章铺开三平台安装、编辑器配置、终端运行与七步排障，并承认「前期的问题可能令人沮丧」，把求助路径写进附录C。
2. **语言核心是一条严格递进的能力链。** 变量与命名 → 列表 → 条件 → 字典 → 输入与 while → 函数 → 类 → 文件与异常 → 测试；每一步都建立在前一步的数据结构之上。
3. **报错即教学：把 traceback 与常见错误当作课程内容而不是噪音。** 书中系统示范 NameError、SyntaxError、五类缩进/冒号错误、IndexError、TypeError、逻辑错误，以及测试未通过时「不要修改测试，而应修复代码」的纪律。
4. **规范与可读性优先于炫技。** PEP 8、注释判断准则、Python 之禅、函数编写指南、类编码风格；贯穿全书的理由是「代码被阅读的次数比编写的次数多」。
5. **重构与模块化是项目变大的必然动作。** 「在大型项目中，经常需要在添加新代码前重构既有代码」——先让最简版跑通，再加功能，每一阶段完成后验证。
6. **三个项目覆盖三种典型场景，并共享同一套工程流程。** 游戏（事件循环/精灵/碰撞/记分）、数据可视化（取数 → 清洗 → 图形 → 定制）、Web 应用（模型/迁移/视图/模板/表单/用户/部署）；作者强调数据与 API 调用的流程「都与此类似」，可迁移到任意数据源。
7. **发布与协作是学习的一部分。** 部署到 Heroku 并做安全加固、Git 版本控制全流程、向社区求助的方法（含橡皮鸭子调试法）。

**论点之间的关系**: 环境 → 语言核心 → 工程习惯 → 项目实战 → 发布/协作；每一层都以「可运行 + 可验证」收口。

## 作者要解决的核心问题

零基础读者如何**不从环境与报错环节掉队**地走完「从第一个 print 到发布自己的项目」这条链？作者的解法：把门槛最高的环境配置显式教掉、把最常见的失败逐类示范、把抽象语法立刻放进可玩的成品、并用 300+ 道练习题把「看懂」逼成「做过」。

## 核心命题（选摘）

1. 入门的第一道坎不是语法而是环境：把安装、编辑器配置、终端运行与排障当作独立技能教掉，后续一切示例才可复现。
2. 数据结构决定程序形态：列表（有序可改）、元组（不可变）、字典（键值关联）、集合（去重）各对应一类建模需求，选用依据被写成可判定的标准。
3. 缩进在 Python 里是语法本身：五类缩进/冒号错误各有独立的报错或逻辑后果，必须能据此反查代码。
4. 函数的价值在拆分与复用：「每个函数都应只负责一项具体的工作」；重构就是把能跑的长程序改写成一系列单一职责函数。
5. 文件与异常是程序「活下来」的能力：with 自动关闭文件、try-except-else 让程序在无效数据或缺少资源时继续运行——该报告还是该静默按用户视角决定。
6. 测试是分水岭技能：为函数与类写单元测试；测试未通过时先怀疑代码而不是测试。
7. 项目开发的正确节奏是「最简版先跑通，再重构、再扩展」：请先让项目尽可能简单，确定它能正确运行，再添加复杂的功能。
8. 可视化项目的核心不是画图而是数据链：获取 → 解析 → 清洗 → 呈现 → 定制；「使用任何 API 来访问和分析信息时，都与此类似」。
9. Web 应用的最小完整闭环：模型 → 迁移 → 管理网站 → URL/视图/模板 → 表单 → 用户系统（归属与保护）→ 部署，每一环都给出可执行步骤。
10. 代码质量是可检验的规范集合：PEP 8、文档字符串、命名约定、空行与分行规则都可以逐条核查。

## 关键概念速查

完整词典（59 条，含作者定义与关键区分）见 `glossary.md`。最常用于判定的六条：

| 术语 | 作者口径 |
|---|---|
| traceback | 一条可拆解的记录：出错文件、行号、该行代码、错误类型与说明——是线索，不是诊断结论 |
| 差一行为 | 「第一个列表元素的索引为0，而不是1」——索引与 range 边界两处都强调 |
| 键—值对 | 键与值配对关联、取值凭键；本书固定写法带连接号「键—值对」 |
| 形参 / 实参 | 定义中的变量是形参，调用时传入的是实参；位置实参靠顺序、关键字实参靠名字 |
| 重构 | 代码**能够正确地运行**后，把它划分为一系列单一职责函数；项目期的时机是「添加新代码前」 |
| 断言方法 | 用来核实结果与期望是否一致的 TestCase 方法（书中列出 6 个） |
