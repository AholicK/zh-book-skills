# 正则文本模式处理（四步调用、分组与量词、findall/sub、VERBOSE）

## R — 原文 (Reading)

> 1．用import re 导入正则表达式模块。
> 2．用re.compile()函数创建一个Regex 对象（记得使用原始字符串）。……3．向Regex 对象的search()方法传入想查找的字符串。它返回一个Match 对象。
> 4．调用Match 对象的group()方法，返回实际匹配文本的字符串。
>
> — 第7章 · 模式匹配与正则表达式（7.2.3 匹配复习 L4712-4724）

> Python 的正则表达式默认是“贪心”的，这表示在有二义的情况下，它们会尽可能匹配最长的字符串。花括号的“非贪心”版本匹配尽可能最短的字符串，即在结束的花括号后跟着一个问号。
>
> — 第7章 · 模式匹配与正则表达式（7.4 贪心/非贪心 L4834-4852）

## I — 方法论骨架 (Interpretation)

正则是一套「文本模式的描述方法」——描述模式，re 模块负责找出文本中匹配它的部分；`\d` 不是通配符，而是「一类字符中的某一位」的缩写。成本判据是「先写笨版本」：手工判断要 17 行、格式一变就失效；split/strip 能完成就别上正则。

固定序列：`import re` → `re.compile(模式)`（传原始字符串）→ `search()/findall()/sub()` → `Match.group()`。返回口径：`search()` 只取第一次匹配，未命中给 `None`（不判 None 直接 `.group()` 崩溃）；`findall()` 类型取决于**有无分组**——无分组字符串列表，有分组元组列表。

量词 `? * + {n} {n,} {,m} {n,m}` 作用在**前面的分组**上，默认贪心（有多解取最长），其后加 `?` 变非贪心。字符分类 `\d \D \w \W \s \S` 配方括号自建集合（方括号内符号免转义，`^` 开头取非）；`^`/`$` 锚定首尾，同用=整串匹配；点号匹配除换行外一个字符，含换行需 re.DOTALL。

## A1 — 书中的应用 (Past Application)

### 案例 1: isPhoneNumber() 的 17 行「笨版本」
- **类型**: 书中示例（第7章）
- **问题**: 在长文本里找出电话号码。
- **方法论的使用**: 先写笨版本：len() 与逐位 isdecimal() 判断 12 字符是否符合 415-555-4242 格式，再切片遍历全文；作者随即指出它只认一种模式。正则版（compile → search → group）实测「Phone number found: 415-555-4242」。
- **结论**: 正则版「短很多，并且做的事情一样」——笨版本写不动时再上正则。
- **结果**: 笨版本只支持单一格式；正则版同样结果。

### 案例 2: phoneAndEmail.py——整页提取电话与邮箱
- **类型**: 书中项目（第7章）
- **问题**: 在长文章里找出所有电话与邮件并写回剪贴板。
- **方法论的使用**: 先草拟高层次计划，再写两组正则（电话含可选区号/分隔符；E-mail 用 re.VERBOSE）与 findall。
- **结论**: 「取剪贴板 → 两组正则 → findall → 写回」一次运行完成。
- **结果**: 联系页实测输出以「Copied to clipboard: 800-420-7240」开头。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这张卡?

1. 要从半结构化文本里提取全部手机号/邮箱/日期/编号。
2. 要批量替换或脱敏（只替换命中的部分）。
3. 正则结果不符预期：多匹配（贪婪）、该给元组却给字符串（分组）、匹配不到；或要校验「整体」是否符合某格式（`^...$`）。

### 语言信号

- 「用正则提取所有邮箱」「为什么匹配多了一段」「.*? 和 .* 有什么区别」
- 英文: "extract emails with regex"

## E — 可执行步骤 (Execution)

1. **确认输入与目标字段**
   - 完成标准: ①文本从哪来；②提取/校验/替换什么（举 2–3 个真实样例）；③输出给谁用。
   - 判停条件: 描述笼统时先要样例——样例决定模式。

2. **判断是否值得上正则**
   - 完成标准: 手工版本的局限说得清；split/strip 能完成就转 `strings-and-clipboard`。

3. **写模式（复杂时升级）**
   - 完成标准: 含反斜杠的模式一律 `r'...'`；分类/量词/锚定逐项说得对应（`\d`=数字、`{3}`=恰 3 次、`^...$`=整串）；长而费解时改 `re.compile(r'''...''', re.VERBOSE)` 多行加注释，多选项用 `|` 组合。
   - 判停条件: 其实是解析 HTML → 转 `web-scraping`。

4. **按序列调用、按返回口径取值**
   - 完成标准: `import re` → `re.compile(模式)` → `search()/findall()/sub()` → `group()`；search 先判 None；findall 按「有无分组」预判；sub 保留分组用 `\1`。
   - 判停条件: 结果多了/少了先查贪婪（`.*` 改 `.*?`）。

**输入契约**: ①文本（或来源）；②目标模式（缺样例先问）；③结果形态；中文格式需自定模式（书中示例为美国格式）。

**输出契约**: 可运行正则片段（原始字符串模式 + 四步调用 + 返回类型说明 + 含 `.*` 时说明是否非贪心）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用这张卡

- 解析结构化 HTML 页面字段——作者明令用 BeautifulSoup 的选择器（见 `web-scraping`）。
- 固定分隔符能切分（按行/逗号）——用 `strings-and-clipboard` 的 split/join。
- 中文电话等本地格式：须给样例后自定模式（书中示例是美国格式）。

### 作者在书中警告的失败模式

- 贪婪陷阱（ce13）: 默认量词取最长匹配——`<.*>` 对 '<To serve man> for dinner.>' 吞下整段而非一个标签，不报错；告警信号：结果多出不属于字段的内容。修正：显式写非贪心 `.*?`。
- 未判 None（p34）: `search()` 未命中返回 None，直接 `.group()` 会崩溃。
