# 列表、元组与引用语义（下标/切片、可变与不可变、copy 与 deepcopy）

## R — 原文 (Reading)

> 变量不直接保存列表值，它们保存对列表的“引用”。
> ……
> 尽管spam 和someParameter 包含了不同的引用，但它们都指向相同的列表。这就是为什么函数内的append('Hello')方法调用在函数调用返回后，仍然会对该列表产生影响。
>
> — 第4章 · 4.7 引用 / 4.7.1 传递引用 L3507-3555

> 如果要复制的列表中包含了列表，那就使用copy.deepcopy()函数来代替。
> …
> deepcopy()函数将同时复制它们内部的列表。
>
> — 第4章 · 4.7.2 copy()和deepcopy() L3557-3569

## I — 方法论骨架 (Interpretation)

这张卡处理两类问题：容器怎么取（下标与切片口径），以及「改了副本却动了原件」——引用语义。

核心模型：列表、字典这类可变值，变量保存的是引用而不是值本身；复制变量、把列表传给函数，复制的都只是引用的拷贝——改动可能出现在远离修改点的位置，且不报错。

取数三口径：下标从 0 起、只能是整数、越界报 IndexError；负数下标 −1 是最后一个；切片起含止不含、两端可省略、求值为新的列表值。

可变/不可变分野：列表可变；字符串与元组不可变（改字符串要构造新串；单元素元组必须带尾逗号）。覆写不等于修改——`eggs = [4, 5, 6]` 换了新列表值，现场修改要用 del/append 这类就地操作；append() 当场修改、返回 None。

要真正复制：浅层用 `copy.copy()`；列表里还嵌套列表时必须 `copy.deepcopy()`。确定要共享修改时，传递引用反倒最方便；判据一句话：先问「这份数据允不允许被改」，再决定传引用还是造副本。

## A1 — 书中的应用 (Past Application)

### 案例 1: passingReference.py——传引用与 copy.copy() 的实测对照
- **类型**: 书中示例（第4章）
- **问题**: 函数内修改传入列表会不会影响调用方；想复制却改动原列表怎么办
- **方法论的使用**: 按 c50——eggs(someParameter) 在函数内对传入列表 append('Hello')，调用 eggs(spam) 后打印；再 import copy，用 cheese = copy.copy(spam) 得独立列表，改 cheese[1] = 42
- **结论**: 传引用输出 [1, 2, 3, 'Hello']——函数内 append 改到了调用方；copy 后 spam 保持 ['A', 'B', 'C', 'D']、cheese 为 ['A', 42, 'C', 'D']
- **结果**: 两组实测输出均来自书中；作者提醒忘记该行为会导致令人困惑的缺陷

### 案例 2: 神奇 8 球——用列表替掉重复的 elif
- **类型**: 书中示例（第4章）
- **问题**: 前一版用一堆几乎一样的 elif
- **方法论的使用**: 按 c07——messages 列表存 9 条答复，用 messages[random.randint(0, len(messages) - 1)] 生成随机合法下标
- **结论**: 「列表 + 随机下标」替代重复分支；下标由 len() 动态约束，增删字符串时不必改其他行
- **结果**: 书中说明运行效果与前一版一样；未给出具体输出样本

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这张卡?

1. 复制了列表，改副本却把原列表也改了
2. 列表传进函数、函数里 append/删除，调用方数据被改
3. 切片取不到想要的段（起含止不含、末尾元素）
4. 下标报 IndexError / 浮点下标报 TypeError

### 语言信号

- 「为什么复制了却改了原列表」
- 「传进函数被改掉了」
- 「切片怎么取不到最后一个」
- 英文: "copy still mutates original", "argument mutated", "slice off-by-one", "list index out of range"

### 与相邻能力的区分（阶段 3 定稿）

- 与 `language-basics` 的区别: 基本类型的转换回那条卡；本卡处理容器（列表/元组）的下标、切片与引用语义；遍历依赖的 for 口径仍来自 v01。
- 与 `dicts-and-modeling` 的区别: 两者同受引用语义支配、常互相转换；选结构与键值组织走那条卡，本卡管列表/元组自身的取数与拷贝判据。

## E — 可执行步骤 (Execution)

1. **先声明变更语义**
   - 完成标准: 明确回答「原数据应不应该被改」——要改则接受引用传递与就地操作；不改则先造副本
   - 判停条件: 用户答不上来先停下问——跳过必出台「改副本动原件」
2. **核对引用链**
   - 完成标准: 找出所有 `cheese = spam` 式赋值与「列表交给函数、函数内就地操作」的位置，标出共享引用（防 ce09）
3. **选择拷贝层级**
   - 完成标准: 无嵌套用 copy.copy()；列表里还有列表用 copy.deepcopy()；前置 import copy
4. **定下标与切片**
   - 完成标准: 下标整数、0 起、范围 0..len-1；−1 是最后一个；切片起含止不含
   - 判停条件: 需要三参数切片或负下标越界行为时说明书中未写，不代拟规则
5. **验证副本独立**
   - 完成标准: 修改副本后打印两者，原数据不变；嵌套样例用 deepcopy 再验一次

**输入契约**: 必需 = ①数据样例（列表/元组）；②期望：谁可以改、谁必须保持原样；③要取哪一段。缺 ② 必须先问。

**输出契约**: 处理代码（含 copy/切片调用）+ 「改副本不动原件」的验证输出 + 每个选择回指出处（p17–p23、ce09/ce10）。完成标准: 验证输出符合 ② 的约定。

## B — 边界 (Boundary) ★

### 不要在以下情况使用这张卡

- 需要选择数据结构或键值组织方式——走 `dicts-and-modeling`
- 需要三参数切片（步长）或负下标越界行为——书中未写，不得补造
- 简单遍历、不涉及下标与拷贝

### 作者在书中警告的失败模式

- ce09: cheese = spam 只复制引用——「底下只有一个列表，因为列表本身实际从未复制」；函数内对传入列表 append/删除会改到调用方——「因为被复制的只是列表引用，所以要注意，对该列表的所有改动都可能影响到程序中的其他变量」
- ce10: 下标越界 → IndexError；浮点下标 → TypeError；对既有数字又有字符串的列表 sort() → TypeError（Python 不知道如何比较它们）

### 作者盲点与底本缺口

- 单元 note: c07（神奇 8 球）演示用列表替掉重复 elif，是本单元的重构价值案例；g15（方法）与 g13（引用）是跨单元术语
- 负下标越界与空列表 spam[-1] 的行为书中未给
- 切片第三参数（步长）在源文中未出现
- copy 的性能、deepcopy 对自定义对象的处理书中未给
- nr_warnings: 本单元为空

### 容易混淆的邻近方法论
