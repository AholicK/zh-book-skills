# 函数、作用域与异常处理（def/return、global、try/except）

## R — 原文 (Reading)

> 如果在try 子句中的代码导致一个错误，程序执行就立即转到except 子句的代码。在运行那些代码之后，执行照常继续。
>
> — 第3章 · 3.7 异常处理 L2914-2960

> 全局作用域中的代码不能使用任何局部变量；
> 但是，局部作用域可以访问全局变量；
> 一个函数的局部作用域中的代码，不能使用其他局部作用域中的变量。
>
> — 第3章 · 3.5 局部和全局作用域 L2750-2772

## I — 方法论骨架 (Interpretation)

这张卡把「一段逻辑」变成黑盒：def 定义时不执行、调用时才执行；输入是参数（调用时传入的值）、输出是返回值；没写 return 返回 None。

黑盒要成立靠两条纪律：使用函数只看「变元→返回值」；编写函数不用全局变量。

作用域四法则自上而下、命中即停：函数外→全局；有 global 声明→全局；函数内出现在赋值语句中→局部；函数内只被读取→全局。一个变量要么总是全局、要么总是局部。

可见性三约束：全局看不见局部；局部看得见全局；兄弟局部互不可见。函数返回即销毁局部作用域——结果必须 return 传出。

两个高发坑：函数内「先赋值后读取」同名变量报 UnboundLocalError，且不会退回用全局同名变量；局部与全局同名会让判断失效。

异常处理：可能出错的语句放 try、处理放 except；错误发生即跳转且不回 try——try 块越宽，一次失败吞掉的后续语句越多；修改全局变量要在函数内先写 global。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这张卡?

1. 同一段代码复制了两三处，想抽成函数
2. 函数里读不到外面的变量，报 NameError / UnboundLocalError
3. 输入不对时程序直接 Traceback 崩溃，想要可读错误并继续
4. 想把一段逻辑封成只看输入输出的黑盒

### 语言信号

- 「这段代码重复了，想抽成函数」「return 怎么用」
- 「函数里读不到外面的变量」「赋值之后外面没变」
- 「输入错了程序就崩」「怎么让程序报错后继续跑」
- 英文: "extract a function", "variable scope error", "NameError / UnboundLocalError", "program crashes on bad input"

### 与相邻能力的区分（阶段 3 定稿）

- 与 `language-basics` 的区别: 表达式、命名、条件与循环的语法口径在那条卡；本卡把构件组织成函数，并给错误一条可恢复通道。
- 与 `debugging-toolkit` 的区别: 两者共享同一套异常机制（raise 与 try/except）；本卡给「函数怎么组织、异常怎么放」，系统性排查走那条卡。

## E — 可执行步骤 (Execution)

1. **划函数边界**
   - 完成标准: 写出函数名、变元、返回值；函数体不依赖全局变量
2. **放置 try/except**
   - 完成标准: try 只包住可能出错的最小语句；except 后跟异常类型与替代行为
   - 判停条件: try 里出现多条互不相关语句时缩小范围（防 ce08 连带跳过）
3. **定义返回路径**
   - 完成标准: 成功路径 return 结果；失败路径显式返回替代值（如 None）；没写 return 返回 None
4. **排查作用域**
   - 完成标准: 「为什么访问不到」能回指四法则与可见性约束；改全局时在函数内用 global；避免局部与全局同名
   - 判停条件: 报 UnboundLocalError 时按「该名在函数内已有赋值语句」处理，不再去查全局
5. **双路验证**
   - 完成标准: 合法输入走成功路径、非法输入（如 'puppy'）走 except 给提示；都不崩溃

**输入契约**: 必需 = ①要封装的逻辑；②何时算失败（对应哪个异常类型）；③失败时程序做什么（继续/返回缺省/提示）。缺 ③ 先问；重试循环写法书中未给，不交付。

**输出契约**: 函数定义（def + try/except + return）+ 调用示例 + 作用域说明（回指 p12/p13 或 ce05/ce06）。完成标准: 非法输入被 except 接住不崩溃。

## B — 边界 (Boundary) ★

### 不要在以下情况使用这张卡

- 一次性顺序脚本、无需复用与容错
- 未知错误的系统性排查（不知道该捕什么、需要完整堆栈）——走 `debugging-toolkit`
- 输入重试循环的写法——书中是练习要求，未给出

### 作者在书中警告的失败模式

- ce05: 局部变量在函数返回后被销毁，函数外读它报 NameError——「在程序执行从spam 返回后，该局部作用域就被销毁了，不再有名为eggs 的变量」
- ce06: 函数内既有赋值又先读取同名变量，Python 判定整段为局部，赋值前读取报错，且「Python 不会退回到使用全局eggs 变量」
- ce07: 完全不处理异常——一次除零之类错误终止整个脚本，无人值守时表现为跑了一半就没了
- ce08: try 包住整段调用——一次错误后，后面正确的语句也被跳过（print(spam(1)) 从未被执行），静默丢步骤

### 作者盲点与底本缺口

- 单元 note: ce07/ce08 是两个边界（不处理→崩溃；过度包裹→吞后续）；f05/c06 猜数字是整章综合实例
- f06 只给任务描述与目标异常（ValueError），重试循环代码未给——不得补造
- f04 缺口: 多 except 分支、finally、自定义异常类书中未讲（raise 在第10章才引出）
- nr_warnings: 本单元为空

- `language-basics`: 语法底座与类型转换走那条卡；本卡做函数级组织
