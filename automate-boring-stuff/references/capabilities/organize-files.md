## I — 方法论骨架 (Interpretation)

批量文件操作的风险不对称：跑错时损失不可逆（删除不进回收站、旧备份被覆写），很多错误还不报错。第一性原则是**先预演再执行**：把危险调用注释掉、改成 `print()` 打印「将对哪个文件做什么」，核对清单后再放开注释重跑。

删除序列：默认 `send2trash.send2trash()`（送垃圾箱、能反悔，不释放磁盘空间）；只有要释放空间才用 `os.unlink()`（文件）/`os.rmdir()`（空文件夹）/`shutil.rmtree()`（整棵树）。

三个构件：① `shutil.copy/copytree/move`——destination 是文件夹还是文件名会改变行为，且目的文件夹必须已存在；② `os.walk()` 的 for 三元组（当前文件夹名、子文件夹列表、文件列表），不改变程序工作目录；③ `zipfile`——'w' 建归档、`write(..., compress_type=ZIP_DEFLATED)` 加入、close()；追加用 'a'（'w' 清空原有内容）。输出命名用「递增编号 + `os.path.exists()`」。

## A1 — 书中的应用 (Past Application)

### 案例 1: renameDates.py——美国日期文件名改欧洲风格
- **类型**: 书中项目（第9章）
- **问题**: 上千个文件名含 MM-DD-YYYY，要改成 DD-MM-YYYY。
- **方法论的使用**: 正则识别日期（`re.VERBOSE` 加注释，年份用 `(19|20)\d\d` 防误匹配 10-10-1000）→ `os.listdir('.')` 逐个匹配、未命中 continue → 按分组拼新名 → `shutil.move()` 改名。作者安排先把 move 注释掉、只打印将改名的文件名，确认后才放开。
- **结论**: 批量改名四步法配合「先注释后放开」的验证顺序。
- **结果**: 书中未给运行输出；作者承认该正则接受 4-31-2014 等无效日期，「为了简单」可以接受。

（同章 `backupToZip.py`：`os.walk()` + 「递增编号 + os.path.exists()」把整目录备份成 delicious_1.zip、delicious_2.zip。）

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这张卡?

1. 把文件夹（含子文件夹）里的文件按类型/扩展名/日期批量归类、复制、移动、改名。
2. 做自动备份：把目录打包成带编号的 ZIP。
3. 要删一批文件——需要「能反悔」的删除方式。
4. 脚本要对很多文件动手，怕写错条件造成不可逆损失。

### 语言信号

- 「把这个文件夹按扩展名整理」「批量改名」
- 「做个自动备份 / 打包成 zip」

## E — 可执行步骤 (Execution)

1. **列清单、定范围**
   - 完成标准: ①源文件夹（含不含子文件夹）；②挑选规则（扩展名/名称模式/日期）；③动作与目标。
   - 判停条件: 涉及删除/覆盖而范围没说清先停下确认。

2. **路径与目标预检**
   - 完成标准: 源存在性检查；目的文件夹必须已存在（不存在先建）；重名/覆盖风险逐个说明；目的地是文件夹还是文件名没想清前不要调 `move()`。

3. **先预演，核对后再放开**
   - 完成标准: 首次运行把危险调用全部注释、改 `print()` 打印「将对哪个文件做什么」（遍历用 `os.walk()`）；核对无误后删 print 行、取消注释、重跑；输出命名用「递增编号 + os.path.exists()」。
   - 判停条件: 清单里出现不该动的文件先改条件；核对不上（文件名/数量不符）就停下报告。

4. **删除与打包**
   - 完成标准: 删除默认 `send2trash.send2trash()`，只有要释放空间才用永久删除（先预演）；打包 `zipfile.ZipFile(..., 'w')` + `write(..., compress_type=ZIP_DEFLATED)` + close()，追加用 'a'。

**输入契约**: ①源位置；②挑选规则；③动作与目标；④是否含子文件夹；⑤是否允许删除/覆盖；缺 ①③ 先问。

**输出契约**: 预演版（危险调用注释 + print 清单）+ 执行版 + 核对清单（文件数、示例文件名、目标、风险点）；首次运行只打印、不动文件。

## B — 边界 (Boundary) ★

### 不要在以下情况使用这张卡

- 单个文件读写转 `file-read-write`；PDF/Word/图像接口走 `pdf-and-word` / `image-batch`；增量备份、去重、压缩进度书中未覆盖。

### 作者在书中警告的失败模式

- move() 两个静默陷阱（ce16）: ①目标文件夹已有同名文件被直接覆写；②目标文件夹不存在时把源文件**改名成那个路径名**（丢失扩展名）。两者都不报错（「很开心地做一些事情，但和你所期望的完全不同」）。
- 永久删除不可恢复（ce17）: `os.unlink/os.rmdir/shutil.rmtree` 不进回收站——书中程序把 '.txt' 误写成 '.rxt' 就删掉了另一批文件；预演清单（p50）能一眼看出「你不小心告诉程序要删除 .rxt 而不是 .txt」。

### 作者盲点与底本缺口

- **unit_note**: f26/c17（日期改名）与 f27/c18（备份 ZIP）是两个完整项目；本单元是阶段 4 重点做「危险操作护栏」负例的单元。
- **nr_warnings**: 本单元无表格类警告（nr_warnings 为空）。
- **书中未覆盖**: `os.walk()` 的 topdown/onerror 与符号链接；send2trash 平台差异；增量备份与去重；压缩进度；日期正则接受 4-31-2014 等无效日期。

### 容易混淆的邻近方法论

- `file-read-write`: 本卡的危险动作护栏是那条卡没有的风险维度。
