## I — 方法论骨架 (Interpretation)

这张卡解决「把真实世界的事物变成可编程对象」：键与值构成映射，访问用键而不是位置；两件事必须先定——值怎么取（缺省路径）与结构怎么建（分层键设计）。

缺省路径防 KeyError：`d[key]` 要求键已存在；两参数 get() 在键不存在时返回备用值；setdefault() 一行完成「不存在就写入缺省、已存在就返回原值」。

setdefault() 的幂等性是计数套路的基石：键已存在时不覆写、只返回，循环里反复调用没问题；固定套路「先 setdefault(键, 0)，再 d[键] = d[键] + 1」。

建模判据：先设计表示（什么键表示什么位置/字段），写出初始字典，之后程序逻辑只在模型上读写——数据结构与呈现代码分离。

嵌套结构（字典套字典）：逐层建立时每层 setdefault 兜底，否则「第一层键还不存在就往下钻」抛 KeyError。

输出口径：屏幕展示用 pprint.pprint(值)；要字符串用 pprint.pformat(值)；前置 import pprint。

## A1 — 书中的应用 (Past Application)

### 案例 1: 井字棋盘——先设计表示，再操作模型
- **类型**: 书中示例（第5章）
- **问题**: 怎么用 Python 表示 3×3 棋盘（'X'、'O' 或空格）
- **方法论的使用**: 按 f09/c08——为每个空格分配字符串键（top-L 到 low-R 共 9 个），写出初始字典 theBoard；之后用赋值改格位（theBoard['mid-L'] = 'O'），写 printBoard(board) 把字典逐行打印
- **结论**: 先打印空白棋盘，改为 O 获胜的棋局后打印 O|O|O / -+-+- / X|X| / -+-+- /| |X
- **结果**: 空白与获胜两个状态都由书中给出

### 案例 2: 字符计数——setdefault 固定套路
- **类型**: 书中示例（第5章）
- **问题**: 统计文本里每个字符出现次数，直接累加会因键不存在抛 KeyError
- **方法论的使用**: 按 f08 四步——count = {}；for character in message 逐字符；count.setdefault(character, 0)；count[character] = count[character] + 1 累加
- **结论**: 键存在后「在执行count[character] = count[character] + 1 时，就不会抛出KeyError 错误」
- **结果**: 书中给出计数模式的交互式实测；未给出完整运行输出

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这张卡?

1. 统计「每个出现多少次」（词频、按类别累计）
2. KeyError 崩溃，想安全取值
3. 用 Python 表示一张表 / 一个棋盘 / 多层结构
4. 嵌套字典打印出来一团乱

### 语言信号

- 「统计每个出现多少次」
- 「KeyError 怎么避免」
- 「怎么用 Python 表示一张表/棋盘」
- 英文: "count occurrences", "avoid KeyError", "model nested data", "pretty-print a dict"

### 与相邻能力的区分（阶段 3 定稿）

- 与 `lists-and-references` 的区别: 列表/元组的下标、切片与拷贝判据在那条卡；本卡管「键→值」组织与键缺失时的缺省路径。两卡共享引用语义。
- 与 `csv-and-json` 的区别: JSON 解析出来的就是 dict/list 嵌套结构，建模口径直接复用本卡；文件读写与格式解析流程走那条卡。
- 与 `excel-spreadsheets` 的区别: 读表聚合的结果用字典组织；表格文件的打开、遍历与写回走那条卡。

## E — 可执行步骤 (Execution)

1. **判断要不要缺省路径**
   - 完成标准: 凡「键在循环中才生成」「嵌套多层」的场景禁止裸用 d[键]，改用 get()/setdefault()（防 ce11）
2. **套用计数/分组套路**
   - 完成标准: 先 count.setdefault(键, 初值)，再累加；能解释重复调用不会覆写已有值
3. **建模嵌套结构**
   - 完成标准: 先写出分层与键名设计，再写初始字典；之后操作只读写该模型；逐层建立时每层 setdefault 兜底
4. **选择打印口径**
   - 完成标准: 屏幕展示用 pprint.pprint(值)；要字符串用 pprint.pformat(值)；前置 import pprint
5. **验证**
   - 完成标准: 缺键样例复现 KeyError 后切到 get()/setdefault() 路径验证不崩；嵌套样例输出是排过序的干净结构

**输入契约**: 必需 = ①数据长什么样（键/值/几层嵌套）；②键不存在时返回什么缺省（决定 get() 第二参数）。缺 ② 先问；省略 get() 第二参数的返回值书中未写，不得凭常识补齐。

**输出契约**: 建模字典定义 + 操作/统计代码 + 可读打印输出 + 出处（get 两参数、setdefault 幂等、f08 四步、pprint/pformat 选择）。完成标准: 统计与手工核对一致，缺键路径不抛异常。

## B — 边界 (Boundary) ★

### 不要在以下情况使用这张卡

- 需要列表/元组的下标、切片或引用语义——走 `lists-and-references`
- 需要 JSON/CSV 的完整读写流程——走 `csv-and-json`
- 省略 get() 第二参数等书中未写口径——不承接

### 作者在书中警告的失败模式

- ce11: 访问不存在的键立即 KeyError（spam['color'] → KeyError: 'color'）；统计场景（count[character] += 1 未初始化）与三层嵌套（第一层键未建就往下钻）尤其常见——对策是 get()/setdefault() 的缺省路径

### 作者盲点与底本缺口

- 单元 note: c08 井字棋盘是「先设计表示、再操作模型」的完整演示；本单元是最小批次候选之一（8 条），证据密度中等但完整
- get() 省略第二个参数时返回什么书中未写，不得以常识补齐
- 从文件/键盘载入棋盘模型的流程书中未给
- nr_warnings: 本单元为空

### 容易混淆的邻近方法论

- `lists-and-references`: 同为容器与引用语义邻居——本卡管「键」的组织，那条卡管「位置」与拷贝
- `csv-and-json`: 结构与格式的交界——解析出的 dict 交给本卡的组织口径
- `excel-spreadsheets`: 表格聚合后的容器组织复用本卡
