## I — 方法论骨架 (Interpretation)

这张卡处理「拿到一段文本、批量改、再放回去」类任务，以及两个静默错误。一是字符串不可变：像「修改」的方法（`upper()`/`lower()`/`strip()`/`rjust()` 等）都只返回新字符串——只写 `line.strip()` 而不写 `line = line.strip()`，程序照常跑、结果却没变。二是 split/join 方向：`join()` 由**分隔符**调用、传入列表；`split()` 由**待拆文本**调用、返回列表；反用不报错，只得到错误结构。

判定要点：① 改整行先 `split()` 成列表逐项处理，再 `join()` 拼回；② 查「一部分」用 `startswith()`/`endswith()`，整体相等仍用 `==`；③ isX 族要求「只包含对应字符集并且非空」（`'12345'.islower()` 为 False）；④ `rjust()`/`ljust()`/`center()` 第一参数是目标总长度、第二参数可选填充字符；⑤ `strip()` 的参数是**字符集合**、与顺序无关，删的是两端。

剪贴板走固定三段式：`pyperclip.paste()` → 处理 → `pyperclip.copy(...)`；copy 只收字符串，列表先用 `join()` 拼回；口令类只演示原理（见 B 段）。

## A1 — 书中的应用 (Past Application)

### 案例 1: 口令保管箱 pw.py——字典 + 命令行参数 + 剪贴板
- **类型**: 书中项目（第6章）
- **问题**: 多个网站共用一个口令不安全，需要快速复制某账号口令到剪贴板。
- **方法论的使用**: ① PASSWORDS 字典保存账号→口令；② `sys.argv` 取账号名，参数不足两个时打印用法并 `sys.exit()`；③ 命中则 `pyperclip.copy()` 复制，否则提示无此账号。
- **结论**: 书中称「这就是完整的脚本」；作者明说程序「并不安全」，更新口令须改源码字典。
- **结果**: 未说明运行输出（Windows 下另建 pw.bat 用 Win-R 运行）。

### 案例 2: bulletPointAdder.py——剪贴板三段式样板
- **类型**: 书中项目（第6章）
- **问题**: 把维基百科的多行文本变成无序列表（每行前加星号）。
- **方法论的使用**: 先写第 1、3 步骨架（`pyperclip.paste()` … `pyperclip.copy(text)`）并放 TODO；`text.split('\n')` 拆行后逐行加星号前缀；join 拼回再 copy。
- **结论**: 书中判断「先 split 成列表逐项改，比在字符串里找换行再插入容易」。
- **结果**: 剪贴板文本被替换、每行以星号开始。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这张卡?

1. 剪贴板里有一段文本要清洗（去两端空白、大小写、拆分重排）后放回。
2. 写了 `line.strip()` / `.upper()`，不报错但输出没变。
3. split 和 join 分不清谁被调用、谁当参数，拼出的结果结构不对。
4. 要写「读剪贴板 → 处理 → 写回」的小工具；或判行首标记（如 `#` 标题行）。

### 语言信号

- 「把剪贴板里的文本处理一下」「字符串方法为什么没生效」
- 「split 和 join 分不清 / 参数该给谁」
- 英文: "process clipboard text", "split vs join", "string method has no effect"

### 与相邻能力的区分（阶段 3 定稿）

- 与 `regex-patterns` 的区别（composes-with）: 本卡做「已知分隔符/空白/大小写」的机械加工；按**模式**（电话、邮箱、日期）提取或替换才上正则。
- 与 `file-read-write` 的区别（composes-with）: 本卡处理内存里的字符串与剪贴板；对象在磁盘上时读写协议走 `file-read-write`——「读进来 → 清洗 → 写回去」的上下游。

## E — 可执行步骤 (Execution)

1. **确认来源与去向**
   - 完成标准: 说明文本从哪来（剪贴板/变量/待写位置）、处理后放哪去；剪贴板任务走三段式。
   - 判停条件: 来源或去向不明确先问，不要默认覆盖剪贴板。

2. **拆成可逐项处理的结构**
   - 完成标准: 多行/多项文本先 `split()` 成列表（多行用带换行符参数的 split），说明按什么拆。

3. **逐项变换（写回变量）**
   - 完成标准: 每个变换都是赋值形式 `x = x.strip()` / `x = x.upper()`；裸调用不赋值不算完成。

4. **拼回并交付**
   - 完成标准: 用被调用者=分隔符的 `join()` 拼回字符串；剪贴板任务以 `pyperclip.copy()` 写回并核对。

**输入契约**: ①待处理文本（或说明在剪贴板）；②清洗/变换类型；③结果去向——缺 ③ 先问（写回剪贴板会覆盖现有内容）。

**输出契约**: 「读入 → 处理 → 写回」调用序列（paste → 逐项变换（写回变量）→ join → copy）；完成标准：每处判断回指「方法不改原串」「join/split 方向」两条口径。

## B — 边界 (Boundary) ★

### 不要在以下情况使用这张卡

- 按模式提取或替换文本（电话/邮箱/日期）——转 `regex-patterns`。
- 对象是磁盘上的文件、要走读写协议——转 `file-read-write`。
- 中文分词、编码转换等书中未覆盖的加工——不承接。

### 作者在书中警告的失败模式

- 明文口令（ce12）: 注释直接写着 insecure，三个口令明文放在源码字典里；口令随脚本被复制/备份/上传即泄露，print/剪贴板输出明文同样是告警信号。**卡内口径：明文口令仅演示原理，凭据不得硬编码**（与 v15 的 SMTP 口令口径打通；凭据走 input()/环境变量一类不落源码的通道）。
- 只调方法不赋值（p27）: `spam.upper()` 单独一行等于白做，必须 `spam = spam.upper()`。

### 作者盲点与底本缺口

- **unit_note**: c09 含 ce12 安全边界：须写「明文口令仅演示、凭据不得硬编码」，与 v15 的 SMTP 口令口径打通。
- **nr_warnings（NR-01）**: 表6-1 转义字符表的符号↔说明配对为推定（OCR 压平）；引用转义字符只引正文逐句陈述过的两例（`\'` 单引号、`\n` 换行），不得重建 5 行完整表。
- **书中未覆盖**: `startswith()`/`endswith()` 的边界、`split()` 的 maxsplit、命名分组（属正则侧）；rjust() 样例空格被 OCR 压掉（`' Hello'`），引用照录；剪贴板依赖第三方 pyperclip，平台差异未展开。

### 容易混淆的邻近方法论

- `regex-patterns`: 本卡按固定字符/空白加工，正则按模式描述。
