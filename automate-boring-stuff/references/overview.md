## 一句话主旨

办公室职员、管理者、学术研究者等「非程序员」用 Python 把占时间的重复性计算机劳动
（改文件名、处理表格、抓网页、发邮件、填表单）交给程序自动完成——本书教的是
「用完即弃」的能工作代码，不是软件工程。

## 骨架（六个一级论点）

1. **前提：编程的门槛被高估了，而回报被低估了。** 编程只需要把问题分解成单个详细步骤，
   用的数学不超过算术（前言 L104-232；L418「对于大多数人，他们的计算机只是设备，而不是工具」）。
2. **基础层（第 1–6 章）：为「读代码」而学的最小语法集。** 表达式与数据类型 → 控制流 → 函数
   → 列表 → 字典 → 字符串；作者明说只讲「用最少工作量得到能工作的程序」，故意不碰面向对象、
   列表推导、生成器（前言 L150-153）。
3. **自动化层（第 7–18 章）：每一章 = 一类重复劳动 + 一个专用模块。** 正则 → 文件读写 →
   文件组织 → 调试 → Web 抓取 → Excel → PDF/Word → CSV/JSON → 时间与调度 → 邮件短信 →
   图像 → GUI 自动化；每章以「项目：……」给出完整可运行程序。
4. **项目驱动法：先场景、后工具、再完整程序、最后「类似程序的想法」。** 每章末尾固定
   习题与「实践项目」；每个项目结尾的「类似程序的想法」（共 30 处）教读者把成果扩展迁移。
5. **防御性编程观：让程序尽早失败、让危险操作先被看见。** 抛出异常（10.1）、断言（10.3）、
   不要用 print() 调试（10.4.2）、文件操作先注释危险代码加 print() 验证（9.6 小结）、
   GUI 自动化「在得到错误指令时快崩溃」（18.12 小结）。
6. **工程脚手架：第三方模块、运行方式与调度。** pip 安装（附录 A）、#! 行与批处理（附录 B）、
   用 subprocess.Popen() 启动其他程序、用操作系统调度器定时运行（第 15 章）。

**论点关系**: 整体两段式递进（工具 → 任务），第二部分内部并列（12 类任务可跳读）；
第 10 章（调试）与第 15 章（调度）是横切支撑。

## 作者要解决的核心问题

「我每天都在电脑上做重复劳动，但没有现成软件能替我完成；我不是程序员，学得会编程吗？」
作者的回答：把学习目标压缩到「会读、会改、会拼装别人写好的模块」，用项目驱动把语法门槛
降到最低，学完就能写出替代自己的自动化程序。

## 核心命题（八条）

1. 重复性计算机劳动可以被识别（有模式、有判据）并交给程序，人的角色退为「写一次脚本」。
2. 学编程的合理目标是「能读文档、会拼装模块、写出能工作的脚本」，不必先成为软件工程师。
3. 每个自动化任务 = 「输入数据来源（文件/网页/剪贴板/命令行）→ 处理（模块函数）→
   输出目的地」的一条管道。
4. 专用模块（os/shutil/requests/openpyxl/Pillow/pyautogui…）把管道里最难的环节
   （格式解析、网络协议、设备控制）压缩成少数函数调用。
5. 危险性随能力上升：能删文件、发邮件、控制键鼠的程序，必须配「先验证再动手」
   （注释掉 + print()）、断言、日志、failsafe 等护栏。
6. 调试是一项独立技能：早发现（断言/日志）比晚修复便宜；用工具观察「实际值」，
   而不是靠读源码推测。
7. 程序可以突破「一次运行一次任务」的局限：调度器定时间、多线程并行、subprocess
   启动别的程序，让自动化嵌入操作系统。
8. 遇到问题时「聪明地提问」是可训练技能（前言 L372-414）：说明目的、给完整错误信息、
   说明已尝试什么、给版本环境。

## 使用边界（作者的时代局限与盲点）

- **版本与平台年份**: 基于 Python 3.4（前言 L288）与 Windows 7 / OS X 时代界面；
  书中第三方模块（PyPDF2、openpyxl、pyautogui、imapclient、pyzmail、twilio）API 在后续
  版本中已有变动或改名——**本书代码不能假定在现代环境原样可用**（NR-04）。
- **交互式环境假设**: 以 IDLE 为教学界面；调试器一节（10.5）与具体 IDE 强耦合，现代读者
  常用 VS Code/Jupyter，应沿用同一判据而非照抄操作。
- **网络示例的时效**: 第 11 章 XKCD/Google 示例依赖当时网页结构；现代反爬、动态渲染下
  原样照搬会失败。全书未讨论 robots.txt 与网站条款。
- **安全观以「防自己手滑」为主**: send2trash、failsafe、先注释再运行都是防误操作；
  但 6.3 项目把口令明文写在源码、16 章 IMAP 口令入代码——与「不要硬编码凭据」的现代
  实践直接冲突，能力卡 B 段已按「演示可行、生产不可」约束。
- **面向个人的一次性脚本**: 明说不讲代码风格（前言 L152），不讲测试、版本控制、依赖固定；
  对团队协作与长期维护场景，本书方法学不合格。
