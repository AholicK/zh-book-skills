# 递归与迭代逼近

## R — 原文 (Reading)

> 所谓算法，是指有限步骤内可描述的过程。递归算法，是指将这个有限步骤的过程重复若干次，每一次的输出是下一次的输入，这里的若干次可以是无穷次。递归的精髓在于每次执行都继承了上一次的执行结果，从而形成渐进的变化，小变化积累起来形成大变化，从简单出发就可以得到复杂的结果。
>
> — 第1章·文明古国的计算（L897）

## I — 方法论骨架 (Interpretation)

这套方法把「求解」换成了「造一条能一直做下去的链」：先有一条**有限步骤内可描述的变换规则**，再给一个起点，然后把本轮输出接回下一轮输入反复执行。它的合法性来自继承——每次执行都接过上次的结果，形成渐进变化，小变化累积成大变化。

三个可独立检查的要素：

- **方向**：递推顺时间箭头（1×2→2×3→…），合人脑直觉；递归倒着来（先假定 (n-1)! 已知，再算 n!），符合机器执行逻辑。书里明确说，对物理构造的机器来说没必要顺着来，「因此递归有时候是一个更好的选择」（L6681）——选型第一判据是执行者是谁，而不是哪个写法更好看。
- **终止与精度**：有限次执行要给出更细的停止口径（精度阈值或步数上限）；无穷次执行则考察极限行为。数值解的定义就是在某一精度被截断的解，它与代数解（「包含有限次的加法、减法、乘法、除法和开方的表达式，又称为代数解」，L1827）是两条不同的口径（L1781）。
- **代价**：同一递归结构的步数可能是指数级（汉诺塔 2^n−1）。可定义 ≠ 可执行，递归形式的优雅会掩盖步数量级这一事实。

还有一条硬要求：递归是自指的一种，必须满足有穷性，才能成为良定义的自指、规避不可判定命题与不可计算函数（L3525）。终止性不是风格问题，是方法的准入条件。

## A1 — 书中的应用 (Past Application)

### 案例 1: 美索不达米亚人开平方——两次迭代到百万分位
- **类型**: 原书例题
- **问题**: 求正数 α 的正平方根近似值；书内以 α=2（即 √2）为例（L897、L903）。
- **方法论的使用**:
  1. 确定有限步骤的变换规则（原文公式区 L901-915 在 OCR 稿中残缺，只剩「输入值+」「输出值=」「输入值」等碎片，符号不可复述，只记结构：把输入值与由它算出的输出值合成下一次的输入）；
  2. 取初始猜测 1.5，代入规则做第一次计算，得 1.416（L903-909）；
  3. 把输出 1.416 作为下一次输入做第二次递归计算，得 1.414215…（L913-915）；
  4. 按需要的精度继续重复。
- **结论**: 一个逐次逼近 √2 的近似值序列。
- **结果**: 「在两次计算之后，得到的近似值已经达到了百万分位的精度」（L921）；作者并指出这与今天电子计算器上算平方根的算法「几乎与其完全一样」。

### 案例 2: 汉诺塔——结构极简、步数指数
- **类型**: 原书案例
- **问题**: n 个盘子在三根柱子 a、b、c 间移动（一次一个、大盘不压小盘），需求出达成目标的**操作步骤列表**（L6683、L6691）。
- **方法论的使用**:
  1. 把 n 的规模降到 n−1：先把上面 n−1 个盘子从 a 移到 c（这时 a 柱上只剩最大的盘子）；
  2. 处理最后一个元素：把最大的盘子从 a 移到 b；
  3. 把 n−1 个盘子从 c 移到 b 的大盘子上；
  4. 递归到 n=1 收口。原文记作 `Hab(n)=Hac(n-1)Hab()Hcb(n-1)`（下标与符号 OCR 残缺，只记结构，L6695）。
- **结论**: 一份操作步骤列表（或一条递推式），规模上限 2^n−1 步（源文作 `2"-1`，上标残缺，只记结构）。
- **结果**: 书中给出代价——每秒执行一步，n=64 时要 5845 亿年以上，而宇宙年龄「才大约138.2亿岁」，「所以直到世界的尽头我们都挪不完这些盘子」（L6691）。作者由此点出：先把最大数（从整体往下切）处理才是面向机器的递归思维，人脑天生从小数想到大数（L6695）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 手上有一个「猜起点 → 代入 → 比较 → 修正 → 重复」的数值求解任务，但停止条件与初值还没定。
2. 遇到自相似问题（分治、树的遍历、汉诺塔式分解），需要给出可执行的分解步骤。
3. 已有递推/递归公式，要决定实现方向（递归还是递推）并估算它的步数与终止性。
4. 有人拿一个「写法很优雅的递归方案」来评估，需要判断它会不会爆、能不能在预算内跑完。

### 语言信号

- 「这个能不能递归写？还是递推更合适？」
- 「迭代到什么时候停？」
- 「这个递归会不会爆？」
- 「用近似值凑到精度够用就行，可以吗？」
- 英文: "Should this be solved recursively or iteratively?" / "When do I stop the iteration?" / "Will this recursion blow up?"

### 与相邻 skill 的区分（阶段 3 定稿）

- 与 `self-reference-limits` 的区别: v08 用「编码 + 对角线 + 归谬」判自指系统的界限（可证/不可证、停机/不停机）；本卡只负责把「输出即下次输入」的逼近过程跑起来并交代终止条件，不做自指的良恶性判定。
- 与 `approximation-heuristics` 的区别: v16 评估近似算法好坏与启发式设计（误差界、启发式强度）；本卡产出逼近序列本身与方向选型（递归 vs 递推）。
- 与 `complex-system-diagnosis` 的区别: v19 把「简单规则 + 递归积累 + 微小随机 + 临界点」当作涌现的解释框架；本卡提供其中「递归积累」这一可执行机制。
- 与 `machine-intelligence-paradigms` 的区别: v24 谈机器智能的架构范式与主张；本卡是其中递归/迭代思想的机制来源（不含范式主张）。
- 与 `complexity-class-locating` 的区别: v14 做复杂度类的严格定位；本卡只做步数量级的粗筛与终止性判断。

## E — 可执行步骤 (Execution)

1. **定义有限步骤的变换规则**
   - 完成标准: 写出一条可机械执行的规则，并写明它的输入与输出各是什么类型、什么单位。
   - 输入契约: 变换规则 + 输入类型/单位 + 目标精度或目标状态；精度与停止口径缺任一项先向用户追问，不许默认可接受。
   - 判停条件: 若规则本身还描述不出来 → 转 `problem-definition-troubleshooting`。
2. **选方向：递归还是递推**
   - 完成标准: 给出选型结论与理由，理由须落到「执行者是人还是机器」以及「问题能否自相似下降」两点上。
   - 判停条件: 若选递归但问题不能随规模下降（不存在更小的同类子问题）→ 退回递推，或转 `approximation-heuristics`。
3. **取初始值／初始状态**
   - 完成标准: 初值明确，且代入一次就能算出与人工核算一致的结果。
   - 判停条件: 若起点离解太远导致序列发散或停滞 → 换起点（书内做法：先用「瞪眼法」取一个近似根，再代入修正，L1785）。
4. **执行并记录逼近序列**
   - 完成标准: 每一次执行都以上次输出为输入，逐项记录结果序列（至少 2–3 项），并显示它在向目标靠拢。
   - 判停条件: 达到预设精度或步数上限即停；若步数呈 2^n 量级（如汉诺塔）→ 转 `complexity-class-locating` 做代价评估，不要继续往下算。
5. **交代终止性与代价**
   - 输出契约: 结构化交付 = ①变换规则 ②方向选型结论与理由 ③初值与执行序列（2–3 项）④停止条件（精度阈值或步数上限）⑤步数量级与终止性判断；含完成标准：第三方按此交付能复现前两项序列，并据第 ⑤ 项判断能否在给定预算内跑完。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 需要判定自指系统的界限（可证性、停机、不可判定）时——转 `self-reference-limits`。
- 需要复杂度类的严格定位时——转 `complexity-class-locating`。
- 目标是「一次性精确解」而不是逼近时——本卡只产近似值（数值解口径见 L1781、L1827），精确路线不在本卡范围。

### 作者在书中警告的失败模式

- **优雅形式掩盖指数代价（ce243，L6691）**: 汉诺塔递归解结构极简，步数却是 2^n−1；n=64 时执行时间超过宇宙年龄。警告信号：给出清晰的递归/迭代形式就当作可行方案、步数不与执行预算对照、以「逻辑上有限」替代「工程上可完成」。
- **只求近似可用而不问原理（ce37，L923）**: 古埃及人和古巴比伦人「计算主要追求应用的价值，而并不追求精确的结果，只需取得近似计算结果即可」；古印度与古代中国同样「只是将其作为一种实用工具」。代价是虽有大量高超算法，却没有一般理论，方法停在专家技巧层面，无法继承与推广。
- **只总结经验而不验证推理（ce58，L1557、L1611）**: 「这类算法注重总结针对具体问题的一般性计算经验，而不注重推理验证其合理性与正确性」——可用但无法证明、无法推广、无法判定适用边界。

### 作者的盲点 / 时代局限（含阶段 1.5 登记的待核查项）

- **阶段 1.5 note 继承（c27 / NR-03③）**: 作者称巴比伦平方根递推「这可能是世界上最早的递归算法」（L921），并在 NR-03 中被登记为**作者强推测**。引用**必须保留「可能」这层限定语**，不得作为史实结论，不得据此声称美索不达米亚人已掌握一般递归概念。
- **NR-04 OCR 公式残缺（本单元受影响最重）**: 递推公式在本单元**全部不可复述**——巴比伦算法公式区（L901-915）只剩「输入值+」「输出值=」「输入值」等碎片；牛顿-拉夫森递推公式（L1793-1801）只剩「f(an)」「an+I =an」「I+u」等残片；汉诺塔公式（L6695）下标错乱；贾宪增乘开方法的二项系数表（L1811）图形被打散。**只记结构、不提供数值复算**。
- **NR-06 OCR 折行与上标丢失**: 汉诺塔步数在源文作 `2"-1`／`2”-1`（L6691、L6695），指数上标降级，[原文如此]，不得当准确数字；圆周率的 Chudnovsky 公式「每算一项得出14个有效数字」中「元」为 OCR 对 π 的写法（L4849），照抄。
- **NR-02 术语与 OCR 错形照抄**: 源文把「迭代」打成「选代」（L1785、L6681），「输入/输出」公式碎片亦缺字；引用照抄并可标 `[原文如此]`，不得更正。
- **依赖未证明假设**: 「在计算理论中，递归论与可计算性理论是等价的，任何可计算函数也都是一般递归函数」（L3525）及「递归步数上界可判定」这类一般性主张，书内作为结论给出而未给技术细节；引用时按作者表述，不写成已证定理。
- **候选 spillover**: 本单元含 p186（连续统假设不可判定）、p199（递归有穷性要求）、c184（用递归重读说谎者）等偏「数学基础/自指」的条目，`task_ids` 标注宽泛。本卡按主属候选（f21/f22/f214/f215/f45/f46/f47/f80）立论，不把 spillover 条目当本单元主张。

### 容易混淆的邻近方法论

- `self-reference-limits`: 两边都出现「递归」二字，但检查对象不同——v08 判「自指是否良性、命题是否可证」，本卡判「这个过程能不能跑、跑到哪停」。
- `approximation-heuristics`: v16 管「近似得好不好」，本卡管「逼近序列怎么产生、怎么停」。
