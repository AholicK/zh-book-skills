# 计算系统的先天约束清单（数学层 + 物理层）

## R — 原文 (Reading)

> 「图灵机在包含初等算术的情况下也是不完备的，也无法证明自身系统的一致性，以及不存在一个通用的判定过程。由于现代计算机建立在可计算性理论的基础之上，都是这样的通用图灵机，因此现代计算机都受到这样的理论约束。」
>
> — 导论·什么是可计算的（L525）

> 「对于无理数等有着无穷位的实数，现代计算机的处理是以精度的概念将无穷的数字截断为有穷的数字，只取前几位数字结果进行输出。」
>
> — 导论·宇宙是台计算机吗（L593）

> 「因此，图灵机受哥德尔不完备性定理约束的前提是，图灵机实现了一个包含初等算术的形式系统。若图灵机实现的形式系统没有包含初等算术，则并不受哥德尔不完备性定理的约束。」
>
> — 第8章·计算理论的诞生：图灵的可计算数（L4923）

## I — 方法论骨架 (Interpretation)

这套方法的产物是一张清单，但做法不是罗列「理论上做不到的事」，而是按四步把一个具体系统的约束逐条钉住，并给每条标注归属与业务含义。

- **先查归属，再列条目**。同一条约束可能挂在模型上，也可能挂在物理实现上。书内纠正了最常见的说法：现代计算机受哥德尔不完备性定理约束，「其关键不在于图灵机这个计算模型，而在于现代计算机在物理实现上采用了香农的逻辑电路」，以及冯·诺依曼架构中「中央处理器有一个算术逻辑单元，用来实现自然数的加法和乘法」（L4925）；因此「我们不应当说，图灵机受哥德尔不完备性定理的约束」（L4925）。
- **前提检查三步**（书内 L4923 的写法）：① 结论挂在什么条件上——哥德尔定理要求系统「包含初等算术」（蕴含皮亚诺公理，即满足自然数的加法和乘法）；② 被检查对象是否满足——图灵机本身可以模拟任一数学形式系统，也可以实现不含初等算术的系统，不必然满足；③ 真正让它满足的是物理实现（逻辑电路 + 冯·诺依曼架构的算术逻辑单元）。
- **数学层三条**：不完备、无法从系统内部证明自身的一致性、不存在一个通用的判定过程（L525）。这三条来自「计算机的能力边界，几乎就可以等同于希尔伯特形式系统的能力边界」（L513）。
- **有穷化与精度一条**：物理上没有任何证据表明无穷是一种实在，因此现代计算机在物理实现上都是有穷的、使用的图灵机都是有穷模型；无穷位实数则「以精度的概念将无穷的数字截断为有穷的数字」（L593）。
- **物理层三条封顶**：兰道尔原理（擦除信息的最小能量有下界）、布雷默曼极限（单位质量单位时间的最大计算速度）、贝肯斯坦约束（给定体积与能量的最大信息量），作者合称其为「这个宇宙中的时空栓桔[原文如此]」（L7879）。
- **能力上限一条**：图灵极限——「自然界中不存在比图灵机更强的计算模型」（L7935），作者注为丘奇-图灵论题的推论。
- **为什么有效**：清单的价值在于把「性能问题」与「原理问题」分开——原理层的约束换硬件不会消失；而**架构层**的约束是可替换的，作者因此主张「也许我们要大胆地取而代之，设计出一种新的架构」（L7851）。写清单时必须把这两类分行，否则会把可改的当不可改、把不可改的当可优化。

## A1 — 书中的应用 (Past Application)

### 案例 1: 给「现代计算机」开先天约束清单：一条推导链
- **类型**: 原书案例（书中给出的推导链，导论 L513-535）
- **问题**: 「现代计算机」这个对象的先天约束有哪些、凭什么挂在它身上
- **方法论的使用**: 逐环推导——计算机的能力边界几乎等同于希尔伯特形式系统的能力边界（L513）→ 图灵机把形式系统具象化，「之前希尔伯特形式系统中被研究透彻的理论，同样适用于图灵机」（L525）→ 现代计算机建立在可计算性理论上、都是通用图灵机（L525）→ 现代计算机选择接受古典数学、用冯·诺依曼架构实现通用图灵机模型，CPU 中有运算器与算术逻辑单元，实现了初等算术的加法和乘法（L535）→ 于是「所有基于冯·诺依曼架构的现代计算机（实际上包含运算器），都受到哥德尔不完备性定理的约束」（L535）
- **结论**: 三条数学层约束（不完备 / 无法自证一致 / 不存在通用判定过程）+ 一条实现层事实（含运算器，即包含初等算术）
- **结果**: 作者结论句「计算机的能力有先天的局限性」（L535）

### 案例 2: 克莱尼与戴维斯给图灵机加「接受 / 拒绝」状态
- **类型**: 原书案例（reported_case，第8章 L4779）
- **问题**: 理论图灵机可无限运行，工程上要它在有穷时间内输出结果——这是一条清单条目（有穷化与精度）的落地方案
- **方法论的使用**: 在「有穷模型 + 精度截断」条目下执行：「在20世纪50年代，斯蒂芬·克莱尼和马丁·戴维斯为了让图灵机更具有实用性，扩展了图灵机的概念，增加了接受（accept）状态和拒绝（reject）状态，让图灵机可以停机输出结果」（L4779）；书中紧接着给出精度形态：「对于实数的计算，可以根据所需精度只计算到小数点后的若干位，之后进入拒绝状态」
- **结论**: 无穷的计算过程被接到有穷输出上，这就是「精度」的工程形态（与 L593、L3675 的「在某一位截断」同一条线）
- **结果**: 未说明（书中未给该扩展的使用统计或后续影响数据）

### 案例 3: 「图灵机受哥德尔不完备性定理的约束」——作者点名纠正的说法
- **类型**: 原书案例（反例 ce171，第8章 L4923-4925）
- **问题**: 一句听起来专业但把模型与实现混起来的断言
- **方法论的使用**: 走前提检查三步：① 结论条件——哥德尔定理针对「包含初等算术的形式系统」；② 对象是否满足——图灵机可以模拟任一形式系统，也能实现不含初等算术的系统，故不必然满足（L4923）；③ 真正的归属——香农逻辑电路 + 冯·诺依曼架构的算术逻辑单元使它满足条件（L4925）
- **结论**: 正确说法是「现代计算机都受到哥德尔不完备性定理的约束」；「但我们不应当说，图灵机受哥德尔不完备性定理的约束」（L4925）
- **结果**: 未说明（作者给出的是一条引用纪律，不是案例结局）

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 要给某个系统/平台写「先天约束说明」：技术方案、架构评审、可行性文档里需要一节「哪些限制换硬件也不会消失」
2. 有人宣称新架构 / 专用芯片 / 量子方案能绕开某类极限，需要核查约束归属与物理前提
3. 系统出现原理性失败，团队按「性能问题」处理（加机器、换硬件、扩集群）
4. 需要在设计早期区分「可改的架构约束」与「不可改的模型约束」
5. 要评估某个计算任务在物理上是否可能有量级上的出路（能耗、速度、存储的信息量上限）

### 语言信号

- 「这个架构的天花板在哪？」
- 「上了新芯片就能解决吧？」
- 「我们这条链路有没有先天缺陷？」
- 「这个算不出来的原因是原理问题还是我们机器不行？」
- 英文: "What are the hard limits of this architecture?", "Will more hardware fix it?", "Is this a fundamental limit or an engineering problem?", "What constraints do we inherit by design?"

### 与相邻 skill 的区分（阶段 3 定稿）

- 与 `three-tier-screening`（v03）的区别: v03 是**问题级**快筛（某个问题值不值得算），本卡是**系统级**清单（某台机器/某个平台继承哪些约束）；v03 判「能不能算」，本卡判「算的东西被什么封顶」
- 与 `formal-system-checkup`（v10）的区别: v10 对一个形式系统做四性质体检（对象是数学系统、凭证是推导）；本卡给工程系统开清单并逐条标注业务含义（对象是系统实现、凭证是条件与归属）
- 与 `parallelization-speedup`（v17）的区别: v17 处理「并行能加速多少、上限由什么决定」；本卡提供其上位约束（物理层封顶、工艺极限），不给出加速比
- 与 `quantum-credibility`（v18）的区别: 判定量子方案是否绕过经典约束属 v18；本卡提供其物理依据（可逆性、不可克隆、物理极限）
- 与 `turing-completeness`（v13）的区别: v13 判模型的表达力上限；本卡判约束挂在模型还是实现上

## E — 可执行步骤 (Execution)

1. **锁定系统与实现基底**
   - 完成标准: 写清对象的四件事——是否等价于通用图灵机、是否实现初等算术（等价于「是否含算术逻辑单元/有无自然数加乘」）、是否有穷模型（有限时间停机、有限存储）、精度策略（在哪一位截断）
   - 输入契约: 必需字段 = 系统名与版本、计算模型、架构描述（是否冯·诺依曼 + 逻辑电路/运算器）、精度与中止策略；缺失项先问，**不许默认按「现代计算机」代入**
   - 判停条件: 若对象声称非图灵等价（超图灵、纯模拟连续量等）→ 停止本卡，转 `turing-completeness`（v13）/ `quantum-credibility`（v18）的口径处理
2. **归属检查：约束挂在模型还是实现（L4923/L4925 三步）**
   - 完成标准: 对每条候选约束填出三列表——「前提条件 / 本对象是否满足 / 满足它的是哪一环」；前提不满足的条目不进清单，并写明「若将来实现初等算术则需重新列入」
   - 判停条件: 若某条约束的归属无法判定 → 该条标「未定」，不得用「一般来说计算机都……」填空
3. **列数学层三条并标注业务含义**
   - 完成标准: 不完备 / 无法自证一致 / 不存在通用判定过程三条各有三格——现象（在本系统里会怎么表现）、允许的对策（如不设计「万能验证器」、不承诺「证明一切」）、禁止的说法（如「加硬件即可解决」）
   - 输入契约: 第 2 步的三列表
4. **补有穷化与精度条目**
   - 完成标准: 写明具体的截断位宽/误差口径与中止条件（依据 L593、L3675、L4779）；清单中出现「无限精度」「无限等待」「无限存储」的表述一律标为不合规并改写
5. **加物理层封顶**
   - 完成标准: 逐条写出兰道尔原理 / 布雷默曼极限 / 贝肯斯坦约束的**结构与方向**——擦除信息的最小能耗有下界、单位质量单位时间的最大计算速度、给定体积与能量的最大信息量（L7863-7879）；并列出能力上限条目「图灵极限」（L7935）
   - 判停条件: 若用户要求代入公式算数 → 停止本卡并声明「公式区 OCR 残缺、数据待外部复算」（NR-04/NR-05），**不得用残缺公式给数值**
6. **出清单并分流**
   - 输出契约: 一张系统先天约束清单表，字段固定为「约束名｜层级（数学/物理/架构）｜前提条件｜在本系统的表现｜业务含义与对策｜引用行号／标注（待核查·依赖假设）」；表末给出结论段「可改的架构约束 vs 不可改的模型约束」
   - 完成标准: 每行都有前提与依据；凡依赖未证明假设的行显式标注（如加密安全那条依赖 P≠NP，书内原文「以此为基础设计的密码协议可以被认为在人类有限的历史内是绝对安全的，除非P-NP」，L7869）；凡引用物理极限数值的行标「书内数据，待外部复算」

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 要判断的是「某个问题值不值得算」：转 `three-tier-screening`（v03）
- 要的是形式系统的性质证明（一致/完备/独立）：转 `formal-system-checkup`（v10）
- 要的是加速比、并行效率、集群规模测算：转 `parallelization-speedup`（v17）
- 想要的是「怎么把系统做出来」的工程方案：本卡只出约束清单，不出实现方案（作者亦言本卷只谈原理）

### 作者在书中警告的失败模式

- ce176 想造芯片直接解 10 万变量的 3SAT（L5597）：「人们一度希望设计一种高效的芯片，用于求解10万个变量以上的3SAT问题，但对于计算复杂性的研究证明，这样的芯片是不可能存在的」——把「电路做大」当作绕过复杂度的路径
- ce214 摩尔定律几近失效（L6153）：「若晶体管的长度进一步缩短，会接近原子核的直径长度，从而引发量子隧穿效应，使得晶体管失效」——把「芯片会一直更快」当作长期架构与成本假设
- ce193 资源挥霍（L5821）：「2009年的计算机程序员比1971年的计算机程序员更浪费资源」——以硬件性能提升为由放弃算法与资源纪律
- ce171 把「现代计算机受约束」套到「图灵机」上（L4925）：作者点名纠正；前提「包含初等算术」被忽略时，结论越界
- ce310 把兰道尔原理当定论（L7863）：作者自己写明「从非平衡统计物理学的进展表明，逻辑可逆性和热力学可能性不存在先验关系，因此兰道尔原理尚存争议」

### 作者的盲点 / 时代局限（含阶段 1.5 登记的待核查项）

- 阶段 1.5 note（本单元登记）：**物理极限（兰道尔/布雷默曼/贝肯斯坦）数据口径存在外部复算差异**，见 `needs-review.md` NR-05。本卡由此确立一条硬纪律：物理极限只写结构与方向，数值一律标「书内数据，待外部复算」，**不进入任何判定**（NR-05 复算记录：贝肯斯坦 2.59×10⁴² bit 与书内相符；布雷默曼 4×10⁷⁵ bit/s 与复算约差一个数量级；兰道尔「0.0178 eV」实为每比特而非每字节）
- **NR-04 OCR 公式残缺**：兰道尔式（L7863 的 nkBTln2）、贝肯斯坦式（L7873-7875 仅余「2元RE / hc ln 2」）、Amdahl/Gustafson 等在本底本内不可复述——**只记结构、不提供数值复算**
- **NR-06 上标丢失**：`4×1075`（L7869）、`2.6×1042`（L7871）等指数上标降级，引用含指数处一律标**待核查**，不得当准确数字
- **依赖未证明假设**：① 物理极限→密码学「绝对安全」的推论书内自带条件句「除非P-NP」（L7869），依赖 P≠NP 这一未证明假设；② 图灵极限为「丘奇-图灵论题的一个推论」（L7935），而作者自陈该论题「无法从数学上证明，它不是一个定理」（L643）
- **作者主张、不得当学科结论**：图灵极限是作者自己的命名（L7935）；作者对「为何图灵极限存在」的回答「这可能是由于物理世界是一种数学结构」（L7937）属推测；「时空栓桔[原文如此]」为作者用语（L7879）
- **候选 spillover**：本单元候选含若干主属其他单元的条目（如 ce308/ce309 属 ch13 的架构与工艺批判、g105「元体系 / 信息就是实在」属 v23 的口径），写卡时以主属条目为依据，不把 spillover 当本单元主张

### 容易混淆的邻近方法论

- 「约束清单」≠「限制条件表」：前者要求每条带前提条件与归属（模型 / 实现 / 物理），后者容易滑成「已知问题列表」；归属不清就会把可换架构的约束当成永久约束
- 架构约束 vs 模型约束：冯·诺依曼架构是一种物理实现，可以被替换（L7851）；不完备性、不可判定性挂在「包含初等算术」这一前提上，前提不变则约束不变。两者混用是本卡最常见的误用
- `three-tier-screening`（v03）: 两者都可能以「不可计算」收尾，但 v03 的结论是「这个问题不必算」，本卡的结论是「这个系统继承了哪些约束」
