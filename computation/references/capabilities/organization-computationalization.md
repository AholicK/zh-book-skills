# 组织与智能系统的计算化翻译与评估

## R — 原文 (Reading)

> 其使命愿景就是目标函数，使命是方向，愿景是对状态的描述；其价值观是行为准则，那么也就是一种计算规则。公司活动可以被视为一个计算过程，即在既定方向下，将规则作用于当前状态，以走向下一个状态的过程。
>
> — 第11章·复杂性计算（L6893）

> 当我们希望一个动作按照某个给定模式来进行时，给定模式与实际完成的动作之间的差异，被用作一个新的输入，以调整动作出现差异的地方，使之更接近给定模式。
>
> — 第11章·复杂性计算（L6637，作者引维纳语）

> 而我理想中的“智能化系统”，应该是以自动完成任务为目的，以任务作为输入，以完成的结果作为输出，中间的过程应该是由机器高度自动化完成的，以其完成任务的复杂度来评价其智能程度的高低。
>
> — 附录C·世界需要什么样的智能系统（L8507；该附录原文刊于 2019-07-04 微信公众号，属作者产业主张）

## I — 方法论骨架 (Interpretation)

这套方法分两半，前半是把「组织」当成计算对象来翻译，后半是把「智能系统」当成可判定的对象来筛。

组织那一半只认四个字段：目的（把使命读成方向、把愿景读成目标状态的描述，两者合起来充当目标函数）、规则（把价值观、制度、流程读成作用于状态的变换）、状态（组织与业务当前的实际处境）、递归（每轮输出的结果先与目的比对，差异再作为下一轮的输入）。四个字段齐了，才有资格问「这套治理算不算自修正」——判据不是有没有使命愿景的文本，而是差异有没有被测量、有没有被回注到下一轮动作里。三件事缺一件，闭环就不成立，系统只会重复既有动作。

它的有效性来自一个取舍：把治理问题压缩到极少的可检查量上（目的、差异、回注），不去追问组织内部结构与人的性质。这个取舍正是黑箱式的姿势——只研究输入与输出之间的关系，不深究内部结构，代价是放弃了内部解释力。

智能系统那一半把同一姿势换成可判定的问句：输入是任务还是表单、过程由机器还是由人完成、智能程度按什么尺度衡量、价值按什么口径结算。四问的答案必须指向同一件事——系统是不是在替人完成动作，而不是替人整理数据。

两处必须显式声明的约束：映射只到字段层，原书没有给出「价值观如何编码为可执行规则」的量化标准；判据强度取决于出处——第11章的组织判词是作者的经验解读，附录C 的智能系统判据是 2019 年的产业主张。

## A1 — 书中的应用 (Past Application)

### 案例 1: 德普罗尼的地籍表项目——把制表组织成一个计算工厂
- **类型**: 原书案例（历史案例）
- **问题**: 法国大革命后新政府要最新的法国地图、要废弃英制度量衡改用公制，需要编制一套全新的十进制地籍表（L2439）。
- **方法论的使用**: ①目的/目标函数=编制十进制地籍表（L2439）；②规则=把工作拆成工序（德普罗尼参考 1776 年亚当·斯密《国富论》，L2441），顶层由勒让德、卡诺等 6 位数学家明确公式、算法与步骤（L2443）；③执行分层=中层数学家按公式组织计算并汇总结果，基层 60～80 名专职计算员用差分法只做加减（L2443）；④递归与校验=计算员先「设计一张大表格，用于反映计算的步骤和结果校验」，再照表填算（L2445），把步骤与校验放进同一张表。翻成翻译表：目标函数=地籍表规格；计算规则=差分法+表格式流程；状态=表格中的当前数据；反馈=表内校验。
- **结论**: 得到一张「目的—规则—分层执行—表内校验」的组织翻译表，并据此判定这套组织的可靠性来自校验环节而非人的能力门槛。
- **结果**: 项目 1790 年启动并形成三层组织结构，基层计算员只需基本计算能力（德普罗尼雇用了大量失业的理发师）（L2439/L2443）。

### 案例 2: 阿里巴巴的使命愿景治理与后来的失控征兆
- **类型**: 原书案例（作者据其在阿里巴巴的内部观察作出的解读，书中以「可能原因」表述，属作者判断）
- **问题**: 一家以使命愿景为治理轴的公司，在体量膨胀后出现增长放缓与影响过大的偶然性事件。
- **方法论的使用**: ①把使命愿景当目标函数、价值观当计算规则，公司活动当「规则作用于状态」的过程（L6893）；②每次输出作为反馈，评估与目的和标准的差异，并成为下一次递归过程的输入（L6893）；③据差异修正业务与组织策略，弱化组织内部的机械式精益管理制度（L6893）；④体量判据：员工 20 万以上、裂变成上百个事业部，上百个小系统互相影响构成复杂系统，内部存在大量非线性关系，线性指令链式管理必然失控（L6895）；⑤改用重反馈与目的的治理方式，并允许犯错（L6897）；⑥对照判例：字节跳动的涌现创新被解释为模拟退火——先升温让个体活跃，再降温收敛（L6903）。
- **结论**: 一份治理评估——以使命愿景为轴的治理「暗含了控制论的思想」（L6893）；体量越过阈值后，线性指令链失效，需切换到复杂系统治理。
- **结果**: 书中判断「阿里巴巴后来遇到的一些困难的可能原因即在此」（L6895）——作者推测，未给出可验证判据与量化阈值。

### 案例 3: 「智能手机」并不智能——按附录C 判据筛掉冒名者
- **类型**: 原书案例（附录C 的作者判例，产业主张）
- **问题**: 如何判断一个号称「智能」的系统是否真是智能系统。
- **方法论的使用**: ①信息化 vs 智能化判别式——存在大量人工交互、依赖人提交表单完成业务的是信息化系统；以自动完成任务为目的、以任务为输入、以结果为输出、中间过程由机器高度自动化完成、按任务复杂度评价智能程度的才是智能化系统（L8507）；②结构判据——完整智能系统包含「感知」与「行动」，支撑行动的是决策与调度（L8557）；③价值判据——只做「感知」价值有限，所有价值创造都在「处置」环节，进入「行动」后解放的生产力才可被量化（L8553）。
- **结论**: 判定「智能手机」并不智能，依然是个「信息化系统」（L8509）。
- **结果**: 书中给出判词，并附带「未来不应该存在一个“人工智能”的产业」「互联网本身并未提供生产力」等主张（L8511 一带），均属作者产业观点，非学科共识。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 手里有一家公司的使命愿景价值观文本与组织架构，要判断「这套治理是不是自修正的」、差异有没有真的被回注。
2. 组织体量膨胀（多条业务线/多个小团队互相牵制）后出现增长放缓或偶发大事故，怀疑是「线性管理失效」，要一份诊断与行动清单。
3. 评估一个号称「智能 XX」的产品、项目或内部系统：它到底是把任务自动化了，还是只是让人填表单更快了。
4. 要为一个团队/开源项目设计目标函数、反馈回路与落地次序，并要一份可核对的翻译表。

### 语言信号

- 「帮我把公司翻译成计算系统」
- 「我们这套 OKR／价值观到底是不是一个反馈闭环」
- 「这个智能系统到底智能在哪，值不值得投」
- 「团队大了就管不动了，是不是管理方式错了」
- 英文: "translate our org into a computational system", "is this really an intelligent system or just a form-filling tool"

### 与相邻 skill 的区分（阶段 3 定稿）

- 与 `complex-system-diagnosis` 的区别: 本卡先做「目的—规则—状态—反馈」的翻译与环境耦合判断；只有当组织已由大量互相影响的小系统构成、需要按涌现/耗散/必要多样性/逻辑深度逐项体检时才转过去。
- 与 `machine-intelligence-paradigms` 的区别: 本卡只回答「是不是智能系统、价值在哪」，不回答「该用哪代 AI 架构」。
- 与 `concept-positioning` 的区别: 本卡的对象是具体组织/系统，输出是翻译表与评估结论；概念定位卡处理的是「计算」这个词本身的混淆，输出是术语口径。
- 与 `computationalism-boundary` 的区别: 本卡把「计算化翻译」当分析工具用（可不可用、怎么用），不涉及「世界是不是图灵机」这类世界观的取舍。

## E — 可执行步骤 (Execution)

1. **收齐翻译输入**
   - 完成标准: 四个字段各有来源文本，且能标明出处（哪份文档、哪次访谈）。
   - 输入契约: 使命与愿景文本、价值观/制度/流程文本、当前组织状态（人数、业务线数量、近一年异常事件）、业务与组织策略。缺使命或价值观原文时先问，不许用「大概是想做到最好」这类转述代替。
   - 判停条件: 若对象是智能系统而非组织，跳到第 5 步。
2. **写组织翻译表**
   - 完成标准: 表内每一行都给出「原文片段 → 计算字段」的对应，无空行。
   - 输出格式: 使命→方向；愿景→状态描述；（使命+愿景）→目标函数；价值观→计算规则；公司活动→「规则作用于当前状态→下一状态」；运作机制→递归+反馈。
3. **检查闭环三件套**
   - 完成标准: 对「目的」「差异测量」「差异回注」各给一条证据或明确写「无」。三件齐备才判为自修正系统。
   - 判停条件: 若「差异回注」无任何证据，直接输出「该治理不是反馈驱动」并停止接续的治理评估（可转 `complex-system-diagnosis` 做原因分析）。
4. **过体量闸门**
   - 完成标准: 给出两个数——组织由多少个互相影响的小系统构成、这些耦合里有多少条是非线性的；并判定「线性指令链是否仍可用」。
   - 判停条件: 若判定组织已成为互相影响的复杂系统 → 结论落为「切换治理方式」（重反馈与目的、允许灰度），并把细节诊断转 `complex-system-diagnosis`。
5. **做智能系统四问 + 两问**
   - 完成标准: 六个问题各有答案与证据来源；「智能程度」那一问必须写出所用尺度（按任务复杂度还是按功能数量）。
   - 判停条件: 若输入是表单、过程靠人工、行动环节无人以外的执行者 → 判定为信息化系统，输出后停止（不再进入价值量化）。
6. **算价值与定次序**
   - 完成标准: 指出价值产生在「感知」还是「行动」环节，并给出可量化的口径（解放了多少人力/多少调度动作）。
   - 判停条件: 若拿不出可量化口径，则结论写「价值不可量化」，不得使用任何形容词式结论。
7. **出交付物**
   - 完成标准: 三个产物齐备且互相引用一致（翻译表中的字段在评估结论里逐条被用到）。
   - 输出契约: ①组织/系统翻译表（字段：原文片段、计算字段、出处行号或文档）；②治理或智能度评估结论（每条附判据与证据来源）；③落地次序（先做对社会效率撬动最大的那一点）+ 一条标注「判据强度：作者经验解读／产业主张」。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 使命愿景文本是给融资或宣传写的官话、无法转成任何可测量的方向时——翻译表会被填成修辞练习。
- 需要的是组织行为学、人力资源或财务层面的实证结论时（本卡不提供抽样、统计或绩效计量方法）。
- 只想要一个「我们很智能」的结论来支撑对外宣传时。
- 把翻译表当作机制证明：映射成立不等于组织真的按这个机制运行。

### 作者在书中警告的失败模式

- f238（L6895）: 在上百个互相影响的小系统构成的组织里继续用线性指令链管理，「容易导致失控，失控的结果是增长放缓或者出现影响过大的偶然性事件」。
- f219（L6623）: 只研究输入—输出而不深究内部结构（黑箱姿势）在当时引发巨大争议——「毕竟数百年来，科学的发展都是建立在还原论思想上的」；沿用黑箱口径要接受它在解释力上的让渡。
- f301、g110（L8509）: 名称驱动的自欺——「市面上形形色色的智能系统也都只是冠上了智能的名号在鱼目混珠」；反过来，信息化系统本身有价值，别把判别式用成贬义词。
- f241（L6903）: 把模拟退火式的组织创新当常规手段，会忽略它依赖高温期的容忍度；组织不是算法，降温时机没有书中给的判据。

### 作者的盲点 / 时代局限（含阶段 1.5 登记的待核查项）

- **阶段 1.5 note（必须继承）**: 附录 C（L8489-8613）属作者产业主张——原文刊于 2019-07-04 微信公众号「道哥的黑板报」（L8493），作者时任阿里云「A组」（L8601-8611），判据强度低于学科共识；本卡对附录 C 的任何引用都只在此性质下使用。
- **NR-03④**: 附录 C 的产业主张不得作为结论（未来不存在单独的人工智能产业、机器之间协同比人机交互更重要、未来互联网中 70%-80% 是机器智能等，L8547、L8583、L8589），只能引为作者观点。
- **NR-03②**: 「推理越多…算力可用于衡量价值」（L4927）为作者强推测，不得进入本卡的判据链。
- **NR-05**: 附录 C 的云计算版摩尔定律等数据口径待外部复算（L8527-8533），不引具体常数。
- **NR-06**: 引用含指数处一律标待核查（上标丢失）。
- 组织映射无量化标准（f237 missing_conditions）：书中未给「价值观如何编码为可执行规则」的量化标准；f237 的结论基于作者在阿里巴巴的内部经验；f238 只给方向性判断（「可能原因即在此」），无阈值与可验证判据。
- 「信息化 vs 智能化」与「生产力五阶段」（L8497）是【作者命名】条目（g110），使用时必须保留作者标签，不得当作行业通行术语。
- 本卡不依赖 P≠NP、单向函数存在等未证明假设。

### 容易混淆的邻近方法论

- `complex-system-diagnosis`: 容易混，因为两者都用反馈与非线性说话。分辨：本卡输出「翻译表 + 是否自修正 / 是否智能系统」；复杂系统诊断输出涌现/耗散/必要多样性/逻辑深度四项体检结论。
- `machine-intelligence-paradigms`: 容易混，因为都谈智能系统。分辨：本卡判「是不是、值不值」，范式卡判「用哪条技术路线」。
- `computationalism-boundary`: 容易混，因为都涉及「计算化」。分辨：本卡是局部工程类比，世界观卡处理「计算主义」的采纳与否。
- `research-paradigm-criteria`: 附录 A/C 都在讨论范式与产业落地，分辨：本卡只做组织/系统的翻译与评估，不判科研范式。
