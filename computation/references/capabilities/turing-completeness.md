# 图灵机五元组与图灵完备判定

## R — 原文 (Reading)

> 计算并不重要。我假定计算是在一张一维的纸上完成的，例如在一条分成方格的纸带上。另外，假定可打印符号的数目是有限的。……需要考虑的思维状态的数量是有限的。
>
> — 第8章 计算理论的诞生：图灵的可计算数（L4689-4691、L4711；图灵原文引述，OCR 逐行折行，L4689→L4691 为同句续行，与 L4711 之间以 … 略去）

> 从可编程的角度讲，一种操作数据的规则如能模拟通用图灵机，则可被称为“图灵完备的”，比如指令集、编程语言等。对创造一门新的编程语言、指令集或其他计算方法来说，验证图灵完备性非常重要。
>
> — 第8章 计算理论的诞生：图灵的可计算数（L4897）

## I — 方法论骨架 (Interpretation)

这一步做的不是"造一台更聪明的机器"，而是把一个"看起来像计算"的过程判成"是不是通用计算"。骨架是一条逐级收紧的链条：

1. **先做减法（有穷化）**：把人类计算员身上与计算无关的维度逐项删掉，得到四条有穷化限制——纸带一维化（纸的二维性对计算不重要）、可打印符号数目有限、某一时刻可观察的方格数有上限、思维状态数量有限（L4689-4711）。有穷化是模型能被写死的前提：符号无限会产生"差异程度任意小的符号"，状态无限会出现状态"因无限地接近，而造成混淆"。
2. **把剩下的写成表**：每条限制落到一行指令，即五元组 (当前状态, 读入字符, 打印字符, 移动方向 ∈ {L,R,N}, 下一状态)（L4771）。于是"机器执行指令"＝五元组之间的切换，五元组序列即该机的"可计算序列"。
3. **对照一个基准**：把"机器"本身也变成数据（符号换数字得描述数，L4783、L4785），"能处理数据"就升级为"能接收另一台机器的描述数并运行它"；满足这一点即**图灵完备**（L4897）。

判据只有一条，且不含效率：能模拟通用图灵机 ⇔ 图灵完备 ⇔ 可编程。所以本卡只回答"能不能算"；"算得快不快"是另一级筛子（`complexity-class-locating`）。

三条关键约束：① 五元组表要覆盖全部"状态 × 读入符号"组合，未定义的组合才是停机/出错边界；② 有状态转移规则不等于有停机判据（第 8 章把它叫循环机，L4775）；③ 这套模型成立依赖"人的思维状态是离散的"这一未被证明的哲学前提（L4735）。

## A1 — 书中的应用 (Past Application)

### 案例 1: 图灵把"人类计算员"简化成一维纸带 + 有限符号 + 有限状态
- **类型**: 原书案例
- **问题**: 如何把"计算"从直觉变成可定义的模型——人真的在纸上算数时，哪些属性是本质的、哪些可以删掉
- **方法论的使用**: 按书内给出的六个动作逐项施加限制：① 把计算场景设为"在纸上书写某些符号"（L4683）；② 纸带一维化，并声明二维性对计算不重要（L4689）；③ 限制可打印符号数目为有限（L4691）；④ 设定某一时刻可观察方格数的上限 B（L4707）；⑤ 限制思维状态数量为有限（L4711）；⑥ 把机器操作分解为"简单操作"，并假定一个简单操作里最多改变一个符号（L4719）
- **结论**: 得到一个只有有限符号、有限状态、一维纸带、简单操作的机器模型（即图灵机）
- **结果**: 书中指出这套"思维状态离散"的假设是图灵认为机器计算过程可以等价于人脑思维过程的核心依据；哥德尔 1972 年针对该段写了短评，称其为"图灵分析中的一个哲学错误"，并认为人脑的思维状态是连续的、可能趋于无穷（L4735）；作者自陈他本人持图灵信念（L4735）

### 案例 2: 五元组 (A,0,X,L,B)、描述数编码与完备性判定的三步演示
- **类型**: 原书例题
- **问题**: 怎么把一台机器的行为完整写死，并让"机器"能被另一台机器读入运行
- **方法论的使用**: ① 把"状态 A 下扫描到 0 → 打印 X → 读/写头左移 → 转状态 B"记成五元组 (A,0,X,L,B)（L4771）；② 按书中对照表把符号换成数字（1=A、2=0、3=B、4=L、5=R、6=N、7=分号；N 表示格子为空，分号之后的内容一般是备注、不进入计算指令），得到一个正整数串，即该机的描述数（L4783、L4785）；③ 判完备性时用唯一判据——某种操作数据的规则能否模拟通用图灵机（L4897）
- **结论**: 五元组序列即该机的可计算序列；一串正整数即该机的描述数；可计算序列与可计算数都是可数的（L4785）
- **结果**: 书中确认描述数与可计算序列的对应是"多对一"而不是"一对一"（每个可计算序列至少对应一个描述数，不存在一个描述数对应多个可计算序列，L4785）；并指出"对创造一门新的编程语言、指令集或其他计算方法来说，验证图灵完备性非常重要"（L4897）；**原书未给出**对一门新语言做图灵完备判定的完整演示案例

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 正在设计或评审一门语言、DSL、配置语言、指令集、规则引擎、工作流引擎，要判"它的表达能力够不够"
2. 讨论里出现"某某是图灵完备的"这类断言（如表格软件、样式语言、沙箱脚本、数据库方言），需要判真假与它到底意味着什么
3. 要把一段人类流程或业务规则写成机器可读的规则表，产出"五元组表 + 完备性结论"（task-12 的交付物形态）
4. 要给某个系统下"它能算什么 / 不能算什么"的能力结论，必须避免用二手转述充当依据

### 语言信号

- 「我这个 DSL 的表达力够吗」「它能不能算所有能算的东西」
- 「这个规则引擎算是图灵完备吗」「为什么说它是图灵完备的」
- 「帮我用五元组描述一下这台机器」「把这张状态转移表写全」
- 「它只能算自然数吧？」（疑似 ce165 的混视听结论）
- 英文: "Is this language Turing complete?", "Can this DSL simulate a universal Turing machine?", "Write the quintuple table for this machine"

### 与相邻 skill 的区分（阶段 3 定稿）

- 与 `three-tier-screening` 的区别: 检查对象不同——v03 检查"一个想用计算机解决的问题"落在可计算性/代价/NP 完全哪一级；本卡检查"一台机器或一套规则"的**能力等价性**（能否模拟通用图灵机），且不产出任何代价结论
- 与 `complexity-class-locating` 的区别: 本卡判"能不能算"（能力），v14 判"要算多久、答案好不好验证"（代价）；图灵完备不承诺效率
- 与 `encoding-rule-initial-state` 的区别: v05 把现实过程改写成"编码—规则—初始状态"三步设计稿；本卡是把已经写成的规则表判成完备/不完备
- 与 `formal-system-checkup` 的区别: v10 给形式系统做四性质体检（一致性/完备性/可判定性等）；本卡只判机器模型的能力等价性，不体检公理系统

## E — 可执行步骤 (Execution)

1. **锁定判定对象与层级**
   - 完成标准: 一句话写清判定对象是"某台机器 / 某门语言 / 某套规则"（装置侧），而不是"某个业务问题"（问题侧）
   - 输入契约: 对象名称 + 其规则的可获得形式（指令表 / 语法 / 状态机描述）。缺规则形式时先索取，不许凭名称猜能力
   - 判停条件: 若用户实际问的是"这个问题能不能算 / 值不值得算"，停止本卡，转 `three-tier-screening`

2. **抽取四条有穷化限制**
   - 完成标准: 对四条逐条给出"是 / 否 + 证据"——① 存储是否可视为一维可寻址的纸带；② 可写符号集是否有限；③ 每一步可读/可观察的信息量是否有常数上限；④ 状态（或等价的内部控制量）是否有限
   - 输入契约: 装置的存储模型、符号集、状态表示；数据由用户提供，缺项记为"未说明"
   - 判停条件: 若某一条可明确判为"否"（如可写符号无限、可观察范围无界），停止并输出"不满足有穷化前提"，不得继续按图灵机模型下结论

3. **写成五元组表**
   - 完成标准: 表中每一行形如 (当前状态, 读入字符, 打印字符, 移动方向 ∈ {L,R,N}, 下一状态)；每个合法"状态 × 读入符号"组合都有唯一一行；未定义的组合单独列成"停机/出错边界"清单
   - 输出契约: 五元组表（字段固定为上述五项）+ 未定义组合清单；两者缺一不算完成
   - 判停条件: 若状态集无法给成有限集合（状态数无上界），跳到第 8 步，按"不满足有穷化前提"收口

4. **编码成描述数**
   - 完成标准: 产出"符号 → 数字"对照表与由此拼接出的正整数串；对照表的条目只能取自书中已给出的七项映射（1=A、2=0、3=B、4=L、5=R、6=N、7=分号）
   - 输入契约: 第 3 步的五元组表 + 该机的符号清单；出现对照表未覆盖的符号（如第三个状态名、字符 X）时，记录为"编码规则未给出"，不得自行编号（NR-04）
   - 判停条件: 若编码表存在缺口，输出仍可给，但必须标注缺口，不得声称已得到完整描述数

5. **判定图灵完备性**
   - 完成标准: 给出"完备 / 不完备 + 依据"。判"完备"须说明"程序即数据"这一环如何实现（能把另一台机器的描述数当输入并解释执行）；判"不完备"须点名缺失的是哪一环（存储无界性 / 条件分支 / 自解释执行）
   - 输入契约: 第 3、4 步的产物 + 该装置的执行语义说明
   - 输出契约: 完备性结论段，须写明判据出处（L4897，能模拟通用图灵机）
   - 判停条件: 结论一旦为"完备"，停止追问性能问题并转 `complexity-class-locating`（效率是本卡范围外的下一级筛子）

6. **与第 5 步并行：检查停机性**
   - 完成标准: 给出该装置是否存在"进入无意义循环而不停机"的判据（如卡住后不断打印 0、进入不存在的状态，L4775）
   - 输出契约: 停机性说明一行（有明确停机条件 / 无终止判据 / 未说明）
   - 判停条件: 若形态为"有规则但无终止判据"，按 ce164 记为循环机形态，不得把"继续算下去"当作可接受的终态收口

7. **登记未决项**
   - 完成标准: 把本卡范围外的疑问逐条列出——效率与代价、内存/存储的物理上限、模型成立所依赖的哲学前提（思维状态离散）、OCR 残缺导致的不可复述项
   - 判停条件: 出现"这个系统比图灵机更强吗"这类超图灵模型问题时，不在本卡回答，登记后转边界说明

8. **输出交付物**
   - 输出契约: 一页判定书，字段固定为：判定对象 / 四条有穷化限制逐条结论 / 五元组表 / 未定义组合清单 / 符号→数字对照表 / 完备性结论 + 判据出处 / 停机性说明 / 未决项与待核查标记
   - 完成标准: 每一栏都有内容或显式写"未说明"；所有引用均带行号；OCR 残缺处以"结构描述"占位而不复述符号

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 判断"这个业务问题值不值得用计算机做 / 要花多少机器"——那是 `three-tier-screening` 与 `parallelization-speedup` 的活，本卡不产出代价结论
- 把"图灵完备"当作"功能强大 / 性能高"的形容词使用；完备性只说明能力等价，与快慢、与好不好用无关
- 依据二手转述或科普概述给某个系统下能力上限结论（ce165 点名的失败模式）
- 需要判断"是否存在强于图灵机的计算模型"时——本卡只描述既有模型，不给超图灵模型的判定

### 作者在书中警告的失败模式

- ce165（L4883）：**误解图灵机能力边界**。如果不深入读图灵论文，容易得出"图灵机只能计算自然数或有理数"这类"混视听"[原文如此，OCR 脱字]的结论，而这些结论直接关系到机器能力边界的判断；书中随后给出正确覆盖范围：全部自然数与有理数、全部代数数、部分超越数（π、e、欧拉常数等，L4805、L4887）
- ce164（L4775）：**循环机**。规则完备、每步合法，但进入无意义循环或不存在的状态则永不停机——对现实世界而言没有结果；停机性独立于规则的正确性
- ce146（L4237）：**线索停在"说不定可以"**。贝曼已写下可用机器运行这种过程的设想却未深挖，把机会让给 15 年后的图灵；写作能力判定的交付物时，"只写猜想、不写可运行细则"会让整份判定作废
- 附带提醒（p260，L5021）：不要被"停机问题"这个名词迷惑，**不停机**才是理解计算机能力边界的关键——只看"停机"一词会读错整个边界

### 作者的盲点 / 时代局限（含阶段 1.5 登记的待核查项）

- **NR-04（本单元直接命中）**：图灵机转移表与描述数公式在 OCR 稿中残缺。本卡只复述结构——五元组的五个字段、符号→数字对照表已给出的 7 项（p248）——**不复述残缺公式、不给任何数值复算**
- **阶段 1.5 note（必须继承）**：转移表与描述数公式残缺，演练只能按结构复述；p247 另注明书中未给出五元组的完整语法（状态命名上限、书写分隔符规则），且图灵本人并未在论文中画任何具体的图（L4765），书中图示在 OCR 中未解析
- **依赖未证明的哲学前提**：模型成立依赖"图灵认为人的思维状态是离散的而不是连续的"（L4735）——哥德尔明确反对，称其为"图灵分析中的一个哲学错误"；两派分歧是**信念选择**而非事实判断（导论 L543"因为没有答案，所以不存在对错……只能依靠心中的信仰"；术语面见 g06），下游引用不得写成"已证明机器等价于人脑"
- **依赖未证明假设（全局条目）**：凡引用"宇宙是一台计算机 / 元胞自动机与图灵机等价"这类推论，须写明依赖未证明假设（宇宙是图灵机）；元胞自动机等价性见 p23、p388
- **NR-02 术语口径**：作者用"哥德尔数 / 编码"，全书 0 次"哥德尔编码"；OCR 错形（「悸论」= 悖论、「入演算」= λ演算）照抄不得更正
- **NR-03①（作者强推测，仅登记不采用）**：「推理越多，对算力的需求越大，因此算力在某种程度上可用于衡量价值」（L4927）属作者主张、无实证支撑，其主属单元为 v20；本卡不引用为结论
- **候选 spillover**：本单元 73 条候选中含跨单元条目（g102→v23、c444/c447→v17/v23、c234→v21、g57/p270→v20/v24、p32→v23、p441→v17）；本卡以主属候选（f141/f142/f143/f145、g04/g52、ce164/ce165、p247/p248/p249/p250/p253/p260）为依据，不把 spillover 条目当作本单元主张

### 容易混淆的邻近方法论

- `three-tier-screening`（v03）：都问"能不能算"。分法——v03 的检查对象是**问题**，输出三级筛选结论（可计算性 → 代价 → NP 完全）；本卡的检查对象是**装置/规则系统**，输出能力等价性（能否模拟通用图灵机），不含代价
- `godel-encoding`（v12）：都用到"把符号换成数字"。分法——v12 的编码用于让系统谈论自己（自指良恶性判定）；本卡的描述数编码用于让机器接收另一台机器作为输入，是**可编程性**的前提
- `concept-positioning`（v01）：v01 定位"计算"这一概念在讨论中的用法与混淆；本卡定位一台具体机器或语言的模型结构与能力等级
- `formal-system-checkup`（v10）：都用"形式系统 ↔ 图灵机"的桥梁（L4921）。分法——v10 体检公理系统的四性质；本卡只判机器模型的完备性，且须先满足"包含初等算术"才谈得上继承不完备性约束（L4923）
