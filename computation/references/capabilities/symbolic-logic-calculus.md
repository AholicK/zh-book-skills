# 符号化与逻辑演算：把推理变成符号变换（从莱布尼茨到布尔）

## R — 原文 (Reading)

> 「莱布尼茨的数理逻辑有两个核心思想：一是逻辑演算，二是普遍语言。」
>
> — 第3章·莱布尼茨的计算之梦·数理逻辑的创立（L2577）

> 「根据布尔代数的9条公式，在这个三段论方程组的运算过程中，先用p乘以第一个方程，得到pdm=pd，然后将pd=p代入，即可得到结论pm=p。运算过程非常简洁，结论也与三段论的推理结论相符。在这个过程中，我们非常清晰地看到了“推理即计算”。」
>
> — 第3章·莱布尼茨的计算之梦·布尔的逻辑代数（L2989）

## I — 方法论骨架 (Interpretation)

这条线回答一个问题：怎样让推理脱离人的语义理解而可被机械执行。书内给出的答案是四个动作，次序不能颠倒。

- **① 两端各备一件东西**：一套能表达全部思想的符号（普遍语言 / 作者称之为「人类思想的字母表」，L2755、L2785；作者把这一构想称为「元语言」），加一套能机械执行的演算（逻辑演算）（L2577）。缺符号，规则无处安放；缺演算，符号只是记法。
- **② 把散落的规则整理成公理 + 演绎**：莱布尼茨「证明了第四格的存在，将三段论扩展到4格24个有效式，同时从第一格的公理出发，有效地演绎出第二格和第三格的有效式，使三段论成为一种公理化演绎系统」（L2521）。动作是三步：补缺项 → 选不加证明的出发点 → 由公理演绎其余。
- **③ 把命题译成符号等式，再做代数运算**：布尔把每个前提写成类之间的等式（所有狗都是哺乳动物 → dm=d；所有卷毛狗都是狗 → pd=p），按 9 条公式做乘与代入（先用 p 乘第一个方程得 pdm=pd，再把 pd=p 代入，得结论 pm=p）（L2989）。九式见 L2929-2961，其中第八条矛盾律可由第九条指数律推出（L2955-2959）。判定标准是纯形式上的：只用声明的变换规则，不借助对符号内容的解释（皮考克「形式永久性原则」，作者引作布尔的出发点，L2887）。
- **④ 加一层取值解释，规则才落地为机器可用**：9 条公式本身只是形式演算；布尔再加一条限制「x、y 等仅取1或0为值」，于是有第十条公式「x=1或x=0」，符号获得真假含义——「二进制首先有一个重要的作用，就是可以用0和1来表示真与假，我们可以将其记为T和F。这就从形式系统迈向了语义系统」（L2995；第十条公式「（十）x=1或x=0」见 L2993）。
- **代价与判据**：取值解释一旦选定，其他解释的可能性就被放弃——「香农因选择布尔代数的二值解释放弃了数学上的其他可能性，现代电子计算机也同样失去了这些可能性」（L3001）；反例是概率解释，它不满足第十条（L3005）。
- **产出形态**：符号体系说明 + 一条可被第三方按同规则重放的示范演算；若某类命题译不出来，那就是**表达力缺口**，要补的是符号体系，不是加例子——书内以「苹果是酸的」这一三段论反例说明缺口的存在（L2871-2875）。

## A1 — 书中的应用 (Past Application)

### 案例 1: 三段论改写为布尔方程——哺乳动物、狗、卷毛狗
- **类型**: 原书例题（worked example，第3章 L2989）
- **问题**: 两个前提（所有狗都是哺乳动物；所有卷毛狗都是狗）要求推出结论，且不靠人对词义的理解
- **方法论的使用**: ① 译码：把前提写成类等式——「所有狗都是哺乳动物」记作 dm=d，「所有卷毛狗都是狗」记作 pd=p；② 演算：按布尔代数的 9 条公式做代数动作——「先用p乘以第一个方程，得到pdm=pd，然后将pd=p代入，即可得到结论pm=p」；③ 回译：得出「所有卷毛狗都是哺乳动物」（结论与三段论一致）
- **结论**: 推理被改写为对符号的代数运算，「在这个过程中，我们非常清晰地看到了『推理即计算』」，并且「连接符陈述的逻辑推论都可被转换为对符号的代数运算」（L2989）
- **结果**: 书上交代「运算过程非常简洁，结论也与三段论的推理结论相符」（L2989）

### 案例 2: 「苹果是酸的」——三段论反例暴露的表达力缺口
- **类型**: 原书例题（反例，第3章 L2871-2875）
- **问题**: 用现有形式工具检验一类推理时会出错误结论
- **方法论的使用**: 按标准三段论读解：原文三行即「苹果是酸的；／酸是一种味道；／因此，苹果是一种味道。」（L2871-2875）——形式上像三段论，结论明显错误。书内给出原因：传统三段论只量化主词（所有 X / 存在 X），不量化谓词（是 Y / 不是 Y），缺少「关系逻辑」；这一缺陷先由哈密顿指出、由德·摩根以关系逻辑应对
- **结论**: 缺口属表达力层面，要靠补齐符号体系解决——真正的改变由布尔的完整代数符号体系完成
- **结果**: 未说明（书中未交代该反例的实际化解过程，只说明改变由布尔完成）

### 案例 3: 把三段论整理成公理化演绎系统（莱布尼茨）
- **类型**: 原书案例（第3章 L2521）
- **问题**: 亚里士多德的三段论是「3个格14个有效式」的既有但不完整的规则体系
- **方法论的使用**: ① 找出缺失部分——「莱布尼茨则证明了第四格的存在」；② 补齐规模——「将三段论扩展到4格24个有效式」；③ 选起点并演绎——「从第一格的公理出发，有效地演绎出第二格和第三格的有效式」
- **结论**: 「使三段论成为一种公理化演绎系统」
- **结果**: 未说明（原文未列出这 24 个有效式本身，也未给出演绎细节）

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 想让机器/程序替人做推理或裁决，但规则散落在自然语言与口头约定里
2. 两方（不同团队、不同语言、不同定义）各说各话，需要「坐下来算一算」才能裁决
3. 手上的规则体系混乱且缺条目，需要补成「公理 + 演绎」的结构
4. 某类推理总是推出错误结论，需要判断是规则错了还是工具的表达力不够（关系层 vs 主词层）
5. 已经定义了符号和运算规则，但它还只是形式演算，需要判断「怎么才能真的被机器执行」

### 语言信号

- 「这套规则能不能机械化，不靠人去理解？」
- 「怎么把逻辑写成代码或者代数？」
- 「我们两边定义不一样，能不能算一遍看谁对？」
- 「这个符号系统好像漏了一类情况，哪里不对？」
- 英文: "Can this reasoning be mechanized?", "How do I turn these logic rules into computation?", "Is this rule set even expressively adequate?", "Can we settle this by calculation instead of argument?"

### 与相邻 skill 的区分（阶段 3 定稿）

- 与 `encoding-rule-initial-state`（v05）的区别: v05 产出机器可执行的「编码—规则—初始状态」工程设计（面向系统实现）；本卡产出符号体系与演算规则，并标出表达力缺口，不落到工程参数。要的是「怎么让机器跑起来」转 v05
- 与 `godel-encoding`（v12）的区别: v12 处理「系统谈论自身」（哥德尔式编码与自指良恶性）；本卡止于「推理即符号运算」，不涉及自指
- 与 `formal-system-checkup`（v10）的区别: v10 对已成形的形式系统做性质体检（一致/完备/独立…）；本卡是成形**之前**的构造动作（补缺项、选公理、演绎、加取值解释）
- 与 `abstraction-history`（v02）的区别: v02 是计算抽象化的通史方法；本卡限于第3章这条「符号化与逻辑演算」的线，方法是构造性的，不作史论
- 与 `foundations-infinity`（v27）的区别: 涉及无穷与数学基础严格化时转 v27；本卡不处理无穷

## E — 可执行步骤 (Execution)

1. **界定待机械化的推理域**
   - 完成标准: 写清推理域（对象集合、命题形态、需要裁决的分歧类型）与当前表达介质（自然语言条文 / 表格 / 口头约定），并抄录不少于 3 条**真实原句**作为样本
   - 输入契约: 必需字段 = 推理域对象、命题样例（原句）、要产出的结论形式（判定 / 分类 / 关系）；缺任一项先问，不许静默猜值
   - 判停条件: 若样本中出现对**谓词/关系**的量化（「大于」「属于某人」「位于……之上」）而现有工具只有主词量化，先记为表达力缺口（依据 L2871-2875 的苹果反例），不得继续用旧工具硬推
2. **整理成公理化演绎系统**
   - 完成标准: 交出三件东西——初始符号表（不可再分解的基本项）、公理集合（不加证明的出发点）、由公理演绎其余条目的最短链；体系条目数与被遗漏项已逐条核对（对照 L2521 的「补第四格 → 由第一格公理演绎第二、三格」做法）
   - 输入契约: 第 1 步的样本集；以及「哪些条目必须成立」的验收清单
   - 判停条件: 若公理（出发点）无法收敛、各方对基本前提各执一词 → 转 `formal-system-checkup`（v10）或 `paradox-assetization`（v22），本卡不裁断前提之争
3. **把命题译成符号表达式**
   - 完成标准: 每条前提译成一个符号表达式（书内范式：所有狗都是哺乳动物 → dm=d；所有卷毛狗都是狗 → pd=p，L2989），译写规则逐条写在旁注；译不出的命题计入缺口清单
   - 判停条件: 出现译不出的命题 → 回到第 2 步补符号，而不是给该命题开特例
4. **执行机械演算**
   - 完成标准: 只用已声明的变换规则做符号操作（乘、代入、消元；布尔代数九式见 L2929-2961，第八条可由第九条推出，L2955-2959），每一步标出所用规则的编号；过程中不得引入对内容的语义解释
   - 判停条件: 演算结果与语义直觉冲突时 → 停下来复核「前提译写 + 规则清单」，禁止改规则去迁就结论（书内失败模式见 B 段）
5. **补取值解释，并清点被放弃的解释**
   - 完成标准: 明确给出一层取值解释（如二值「x=1或x=0」，L2991-2993），写出在该解释下能得到什么（真值表、二进制运算）；同时写出这一选择放弃了哪些解释（书内例子：概率解释不满足第十条，L3005）
   - 判停条件: 若业务需要非二值/概率语义 → 停止本卡并说明本体系不适用，不得在九式上直接套概率解释
6. **出符号体系说明**
   - 输出契约: 一份「符号体系说明」，字段固定为「推理域｜初始符号表｜公理表｜变换规则（带编号）｜取值解释及被放弃的解释｜表达力缺口清单｜可重放示范演算（1 条）」；示范演算须从原句出发、经译码与规则编号、得到结论句
   - 完成标准: 示范演算可被第三方按相同规则逐行重放并得到同一结论；缺口清单非空时须写明「哪类命题当前无法译写」及其影响

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 要的是工程实现（把规则落成系统/编码设计）：转 `encoding-rule-initial-state`（v05）
- 涉及自指、编码与不可判定：转 `godel-encoding`（v12）/ `self-reference-limits`（v08）
- 要判断某个已成形形式系统的性质（一致性/完备性/独立性）：转 `formal-system-checkup`（v10）
- 只想听计算抽象化的通史：转 `abstraction-history`（v02）

### 作者在书中警告的失败模式

- c148「苹果是酸的」（L2871-2875）：表达力缺口不会被「再多举几个例子」补上——工具缺关系逻辑时，形式合规的推理仍会产出错误结论
- ce90 布尔之死（L3019）：「那时医学还不发达，布尔的妻子迷信土办法，选择以水克火来降温，用一盆凉水直接浇向布尔。布尔，卒，享年 49 岁」——把自洽的类比式因果模型（五行相克）外推到现实决策。**该条在书内以信史口吻叙述，外部文献版本不一，引用须标「待核查」**（候选条目 ce90 的 quote_note 已登记）
- p167 OR 定义版本（L2963-2965）：布尔最早的定义里「OR不包含既属于x又属于y的对象，这导致无法解释xORx」——沿用未修正的旧定义会使边界情形不可解释
- p172 概率解释越界（L3005）：「概率解释不满足布尔的公式（十）x=1或x=0」——把不满足取值限制的解释硬套到公式体系上，会得到无效结论

### 容易混淆的邻近方法论

- `encoding-rule-initial-state`（v05）: 两者都谈「符号」；区分在**产物**——v05 交机器可执行的编码与规则设计（含初始状态），本卡交符号体系说明与演算规则，并明确列出表达力缺口
- `formal-system-checkup`（v10）: 一个体检、一个构造；不得把「体检结论」当作「构造步骤」，也不得用本卡的构造动作替代性质证明
