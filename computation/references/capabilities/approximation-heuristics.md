# 近似算法评估与启发式设计

## R — 原文 (Reading)

> 一般来说，计算机工程师求一个问题的近似解有两种方式。第一种方式是建立一个问题的近似模型，比如线性规划模型，然后精确求解；第二种方式是建立一个精确模型，然后求得该模型的近似解，比如启发式算法的模拟退火或演化算法。
>
> — 第9章·计算复杂性·近似计算与丹齐格的线性规划（L5825）

## I — 方法论骨架 (Interpretation)

这套方法回答的是「问题已经难到拿不到精确解了，怎么办」。作者先立一条前提：两条路都得不到精确解——「要么模型是近似的，要么算法是近似的」（L5825）。所以第一步不是选算法，而是确认自己要交付的是「带边界的近似解」，而不是伪装的精确解。

骨架分四层，次序不能颠倒：

1. **先核可近似性前提**。可近似与否由问题结构决定，与「它是不是 NP 完全」无关。书内的硬门槛是三角不等式：对不满足三角不等式的旅行商问题，「不存在多项式时间的近似算法」（L5877），且除非 P=NP，否则其近似因子是 1，近似没有意义（L6015）。做近似前先把实例改写进「有近似算法存在」的子类——书内对 TSP 的三步标准化是：对称化（不对称 n 规模可化为对称 2n 规模，不改题意）、平面化并采用欧几里得距离、校验三角不等式（L5877）。
2. **再选一条路线**。① 近似模型 + 精确求解（如用线性规划模型近似 TSP）；② 精确模型 + 近似求解（模拟退火、演化算法）。两条路互斥且穷尽（L5825、p323）。
3. **建模路线的手上工具**。线性规划三件套＝目标函数（线性）+ 约束条件（线性等式或不等式）+ 变量非负，判据是所有关系都是线性关系、不出现变量相乘（L5833、L5841）；模型质量取决于不等式质量，「约束条件中不等式的质量，也决定了模型的质量」（L5841）。求值靠强对偶性（对偶最优值＝原问题最优值，可用来验算），求界靠弱对偶性（对偶问题的任意解都给出原目标函数的一个界，因此对 TSP 这类问题可算下界，L5865-5867）。约束数量爆炸时改用割平面法——「不必一次性列出所有的不等式，而是从局部开始，根据需要逐步列出不等式」（L5913）。
4. **求近似解路线的骨架是四问**：解是什么、解的邻域是什么、解的代价是什么、如何确定初始解（源文中为四个独立设问行，L5949、L5951、L5953、L5955）；作者称这套框架是「一种“面向机器的计算思维”」（L5967）。具体算法只是四问的实现：局部最优早停时随机化初始点、按概率接受更差解（模拟退火）、维持种群并用评估函数排序（遗传算法）。设计新启发式的来源是「师法自然」——找出与待解问题同构的已解决事物（爬山对地理、退火对冶炼、遗传对进化论）（L5941）。

最后是评估与交付口径：近似因子 p 是「算法产生解的费用与最优解的费用之间的比较，一般被表示为Cost≤p·OPT」（L6013）；工程阈值上作者给的是经验判据——「如果一个近似解和最优解的差距不到1%，那么在大多数情况下近似解是可以接受的」（L5823，属作者经验阈值而非定理）。还有一条上限提醒：越逼近最优解越慢，「当p接近1时，近似算法的运行时间会显著延长」（L6023）。

## A1 — 书中的应用 (Past Application)

### 案例 1: 商人用 A 元钱买 3 种商品，让总重量最大化

- **类型**: 原书例题（第9章，L5833-5841）
- **问题**: 商人手里有 A 元钱，要买 3 种商品，分别投入 x1、x2、x3，对应单位重量为 W1、W2、W3；目标是让购买商品的总重量最大化。
- **方法论的使用**: 按「近似模型 + 精确求解」路线写三件套——① 目标函数：关于三个投入量的线性函数，求最大值；② 约束条件：x1+x2+x3 ≤ A；③ 变量非负：xi ≥ 0。随后按书内两条判据自查：其一，所有关系都是线性的（没有变量相乘）；其二，不等式是否把所有可行解都圈进来了——作者以「约束条件中不等式的质量，也决定了模型的质量」为验收点（L5841）。几何侧的验收来自单纯形法的有穷性：可行域顶点有限，最优解必是其中之一（该例的几何图景在 L5853-5855 处给出 5 个顶点的例子），闵可夫斯基定理保证「我们一定能在线性规划模型中找出这样的可行域，其顶点恰好包含最优解」（L5857）。
- **结论**: 得到一个线性规划模型（目标函数 + 约束条件 + 非负），依单纯形法在有限步内输出精确最优解；书中强调建模成败在不等式质量而不在算法。
- **结果**: 未说明具体数值解（示例仅用于建模示范）；同段提示实际问题的变量「可能多达几千个、几万个」。

### 案例 2: 42 城环游美国的 TSP——钉绳法 699、割平面法 9 个不等式

- **类型**: 原书案例（第9章，L5891、L5911、L5913）
- **问题**: 求环游美国 42 个城市的最短路线（TSP），精确遍历的代价是阶乘级。
- **方法论的使用**: 分两段走——① 先按三步标准化把问题改写到可谈近似的形态：对称化、平面化（欧几里得距离）、校验三角不等式（L5877）；② 建模求解：先用度约束线性规划松弛（边界取 0/1，约束为经过每个点的边之和等于 2），解出的是下界而非解，因为松弛解「可能会包含孤立的回路，这样的可行解是合法的，但是脱离了旅行商的实际路线」（L5911）；③ 不用一次性列全所有约束，改走割平面法，逐步补不等式（L5913）；④ 用对偶核对结论的一致性（强对偶性给出验算途径，L5865）。
- **结论**: 作者记下一组相互印证的三个数字——把 42 城所有子回路消除干净需要 2199023254648 个不等式（超 2 万亿，L5911）；而丹齐格等人「仅仅通过9个不等式就完成了求解」（L5913）；结果与先前的物理模型（钉绳法）结论一致，最优解为 699 个单位长度（L5913）。
- **结果**: 得到 42 城 TSP 的最优解 699 个单位长度；1988 年 Yannakakis 另证「对于旅行商问题，没有比指数级规模小的对称线性规划」（L5911）。同章的反向经验亦被记录：书中称「出人意料的是，丹齐格等人首先取得进展的不是发现任何高深的算法，而是引入了一个用于验证和测试想法的物理模型一一钉绳」（L5889；「一一」为源文破折号 OCR 形态[原文如此]），作者由此提醒「很多时候不要把问题复杂化」（L5891）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户手上是一个 NP 难问题（路线规划、排产、装箱、选址），精确算法跑不动或代价不可接受，想知道「能不能给一个够好的答案、够到什么程度」。
2. 用户打算用线性规划建模去近似一个问题，需要检查模型是否合格（关系是否全为线性、不等式是否把可行解都圈进来、解出来的是解还是界）。
3. 用户要交付（或已经交付）一个启发式算法的结果，需要说清误差来源与误差边界——是模型近似还是算法近似、近似因子是多少、有没有下界可比。
4. 用户要从零设计一个启发式算法（退火、遗传、局部搜索），需要一套不依赖具体算法的骨架（解／邻域／代价／初始解）与早停排障手段。

### 语言信号

- 「这个问题太慢了，能不能近似一下？」
- 「差不多就行，差 1% 以内可以接受」
- 「帮我设计一个启发式算法（模拟退火／遗传算法）」
- 「这个近似结果靠得住吗？误差有多大？」
- 英文: "good enough answer", "approximation ratio", "heuristic design", "LP relaxation", "lower bound", "simulated annealing for scheduling"

### 与相邻 skill 的区分（阶段 3 定稿）

- 与 `reduction-argument` 的区别: 那张卡只管证明「这个问题很难」（产出一次归约论证）；本卡接着处理「难了之后怎么交付一个带边界的近似解」，且明确要求归约必须保持可近似性——用最坏情况的库克-莱文-卡普归约去论证近似难度是错的（ce204，L5993）。
- 与 `complexity-class-locating` 的区别: 那张卡检查的是问题的复杂度类归属；本卡检查的是「这个实例具备不具备可近似的结构（对称／度量／三角不等式）」以及近似因子的量级。
- 与 `parallelization-speedup` 的区别: 本卡换的是「精度」，那张卡换的是「时间」，两者都要求登记代价去了哪里（精度损失 vs 处理器与通信开销）。

## E — 可执行步骤 (Execution)

1. **锁定问题规模与可接受误差**
   - 完成标准: 写清问题规模参数量级、时间预算、以及「可接受的差距」口径（绝对值、百分比，还是「必须可证明不超过某个因子」）。
   - 输入契约: 必需 (a) 问题的目标函数与约束的自然语言描述；(b) 规模量级（变量数／城市数／约束数）；(c) 可接受误差口径。缺 (c) 先问，不许默认「1% 就可以」。
   - 判停条件: 若要求必须是精确解且误差不可接受（合规、结算、安全判定），退出本卡，转精确算法或 `complexity-class-locating` 重评可行性。
2. **核可近似性前提**
   - 完成标准: 逐条回答「问题是否满足所依赖的结构性前提」，至少覆盖书内点名的三条 TSP 设定：对称性、平面性／距离度量、三角不等式（L5877）；并给出「不满足时会发生什么」的结论（书内：不满足三角不等式则不存在多项式时间近似算法，L5877；除非 P=NP，近似因子为 1，L6015）。
   - 输入契约: 实例的距离／代价矩阵或依赖矩阵；若为不对称，需先做对称化变换（不对称 n 规模可化为对称 2n 规模，L5877）。
   - 判停条件: 若前提核不过且无法通过等价变换进入可近似子类，停并如实报告「该实例上近似路线无保证」，改走 `reduction-argument` 证难或换建模对象。
3. **选路线（近似模型 / 近似算法）**
   - 完成标准: 明确写下选的是哪一条及理由：① 近似模型 + 精确求解，或 ② 精确模型 + 近似求解；并写清「妥协落在哪里」（要么模型是近似的，要么算法是近似的，L5825。两条路都得不到精确解）。
   - 判停条件: 若走路线 ① 转第 4 步；走路线 ② 转第 5 步。
4. **路线 ①：建模、求界、逐步收紧**
   - 完成标准: 模型写成三件套（目标函数 + 线性约束 + 变量非负），并确认式中不出现变量相乘；用弱对偶性给出原目标的一个界（对偶问题的任意解都是原目标的一个界，L5867），用强对偶性做验算（对偶最优值＝原最优值，L5865）；约束数量爆炸时改用割平面法逐步补约束（L5913）。
   - 输入契约: 变量定义表 + 每个约束的来源说明 + 一个能判断「解是否合法」的检查器（例如检查 TSP 解里有没有孤立子回路，L5911）。
   - 判停条件: 若求解得到的只是松弛下界而非法定意义上的可行解，必须标注为「界」并回到第 6 步做合法性复核；若松弛解含非法结构，补一条割不等式后重解。
5. **路线 ②：四问定骨架，再选具体算法**
   - 完成标准: 四个问题都有答案——解是什么（目标函数与搜索空间结构）、解的邻域是什么、解的代价是什么（评估函数如何给阶段结果排序）、初始解如何确定（L5949-5967）；据此选定具体算法：早停则随机化初始点（L5945），要跳坑则按概率接受更差解并逐步降温（模拟退火，L5969），要保持多个解则用种群 + 评估函数排序（遗传算法，L5973-5975）。
   - 输入契约: 解的编码方式；评估函数（要求「能够很好地区分两个个体，并对两个解进行排序」，L5975）；初始解生成方式。
   - 判停条件: 若四问中「代价」一问答不出来（无法排序两个候选解），先补评估函数，不要进入调参；若反复早停，回到四问检查邻域定义而不是加大计算量。
6. **评估：因子、界与阈值**
   - 完成标准: 给出三件套中的至少两项——近似因子 p 及其含义（Cost ≤ p·OPT，L6013）、可比的下界（来自弱对偶或松弛）、以及与最优解的差距口径（书内经验阈值：差距不到 1% 在大多数情况下可接受，L5823，**须标注为作者经验阈值而非定理**）。
   - 判停条件: 若已知该问题族存在不可近似性结论（书内：足够好的近似算法「可能和求解NP完全问题一样难，除非P=NP」，L5999；MAX-3SAT 的近似求解也是 NP 完全的，L6013），停并登记「依赖未证明假设（P≠NP）」。
7. **交付与登记**
   - 完成标准: 交付物中「精确／近似」标签、误差来源、误差边界、依赖假设四项齐备，且写明重跑条件（随机化算法应给出多次运行的结果分布，而非单次最优值）。
   - 输出契约: 一份近似方案记录，字段为「问题与规模 ｜ 可近似性前提核查 ｜ 路线选择与理由 ｜ 模型或四问骨架 ｜ 因子 p 与界 ｜ 差距与阈值 ｜ 依赖假设与失效条件 ｜ 重跑与验收方式」，八项齐备且逐项有完成标准勾选。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 下游环节要求精确解（合规审计、财务结算、安全判定）：近似结果一旦被当精确值使用，误差会被放大成错误结论（ce194，L5825）。
- 实例不具备可近似的结构前提（例如不满足三角不等式的 TSP）：此时近似算法「是没有意义的」（L6015），先做等价变换或承认该实例上近似路线无保证（ce196，L5877）。
- 只想把问题「换一种更简单的说法」而不登记误差来源：这不是近似，是模糊。
- 拿松弛模型解出的界当可行解交付：松弛只筛选了部分必要条件，给出的是界而不是解（ce198，L5911）。

### 作者在书中警告的失败模式

- **把近似解当精确解**（ce194，L5825）：两条路线「都无法求得问题的精确解，因为要么模型是近似的，要么算法是近似的」；作者强调这个妥协「是我们需要认识到的」，即近似的代价必须显式登记在结果上。
- **给不满足三角不等式的 TSP 找多项式近似算法**（ce196，L5877）：除非 P=NP，否则近似因子退化为 1（L6015）。可近似性由问题结构决定，不由「是否 NP 完全」决定。
- **把松弛模型的下界当成可行解**（ce198，L5911）：度约束松弛解可能含孤立子回路，「这样的可行解是合法的，但是脱离了旅行商的实际路线」。
- **用最坏情况指数级否定一个实践有效的算法**（ce189，L5779）：单纯形法最坏情况是指数级，但「大多数时候我们都不会遇到最坏的情况」，因此仍「有着重要的应用」——判据必须双轨（最坏情况定风险上限，实际分布定平均性能）。
- **在求解前就堆叠复杂模型**（ce197，L5891）：42 城问题的第一份进展来自钉绳物理模型而非高深算法，「很多时候不要把问题复杂化」。
- **用线性直觉外推组合代价**（ce174，L5309）：22 城尚可一天遍历，100 城时「遍历完所有路线的计算时间会超过宇宙的寿命」。

### 作者的盲点 / 时代局限（含阶段 1.5 登记的待核查项）

- **本单元 brief 的阶段 1.5 note 为「（无）」**，即原书没有为本单元单独登记需要继承的待核查项；以下四项为本卡依据全局清单（needs-review.md）自行登记的相关边界。
- **依赖未证明假设（P≠NP）**：本单元的工程结论「很多已知的近似算法可能就是最好的算法」在第13章被作者挂在 P≠NP 上——「从计算复杂性理论可知，很多已知的近似算法可能就是最好的算法。由于我们普遍相信PNP，因此在很多情况下，人们不知道对目标的达成是否存在高效算法」（L8197，OCR 作「PNP」[原文如此]，按上下文应为 P≠NP）。同理，「求得一个足够好的近似算法，可能和求解NP完全问题一样难，除非P=NP」（L5999）。凡引用这两条，必须写明「依赖未证明假设」。
