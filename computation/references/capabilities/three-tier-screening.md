# 三级筛选：可计算性 → 代价 → NP 完全（立项前的快筛）

## R — 原文 (Reading)

> 「因此从计算的角度，如果一个问题不可计算，人们就大可不必再浪费时间用计算机来算。在电子计算机发明后，有了实际的工具，人们更关注的是，如果一个题目理论上可以计算出来，那么到底需要计算多少次才能得出结果。」
>
> — 导论·什么是可计算的（L527）

> 「由于大多数人相信P丰NP，因此对于NP难解问题，找到一个好的近似算法和找到最优解同等重要。」
>
> — 第9章·计算复杂性·近似算法（L5991；「P丰NP」为 OCR 形近错字，应为 P≠NP，[原文如此]）

## I — 方法论骨架 (Interpretation)

这套方法只做一件事：在动手写代码之前，按固定顺序连问三个问题，每个问题都有学科结论作背书，答完就分流。

- **第一问：能不能算**——问题是否落在可计算性理论（递归论）划定的边界之内。判据不是「我算不出来」，而是「不存在有穷步骤内终止的过程」；不可计算即停止投入（L527）。此层的边界学科由丘奇、图灵、哥德尔、克莱尼等人建立（L527）。
- **第二问：值不值得算**——若可算，再问代价。作者给的量级阈值是可对照的：「以超级计算机为基准要几亿年或几百亿年才能算出结果，那这样的计算对现实也没有太大意义」（L527）。判据是增长阶与规模，不是实测秒数。
- **第三问：它属于哪一类**——P（多项式时间可求解）／NP（多项式时间可判定结果）／NP 完全（所有 NP 问题中最难、任何 NP 问题都可归约到它）三选一，而 P 是否等于 NP 是未知问题（L529）。若落在 NP 完全，接受近似求解：书内明写「由于大多数人相信P丰NP，因此对于NP难解问题，找到一个好的近似算法和找到最优解同等重要」（L5991）。
- **书内的三层刻度（可与三问对照）**：增长超过一般指数级（如忙碌的海狸函数）＝可良定义但无法求解；一般的 O(2^n) 或 O(n!) 级＝可求解但无法「高效计算」；多项式时间级＝可高效求解（L5419，上标在 OCR 稿中降级，见 B 段）。
- **为什么有效**：前两问的答案由不可判定性与复杂性理论给出，与工程投入无关——加机器、换语言都不会改变答案；三问的**顺序**本身是省力路径：不可算的不必再花算力，代价过大的不必先做常数优化。
- **关键约束**：三级判定都必须落到「依据来自哪条可计算性/复杂度结论」；凭运行得很慢、跑不通、枚举不完这类观察来判断，属于工程直觉，不是本方法的判据。

## A1 — 书中的应用 (Past Application)

### 案例 1: 库克 1971 年提出 NP 完全性——第三级筛子从哪来
- **类型**: 原书案例（reported_case，导论 L529）
- **问题**: 可计算的问题里，哪些是能被高效求解的
- **方法论的使用**: 书中把它接在两级筛子之后：可计算性理论先终结「能不能算」（L527），复杂性理论再问「要算多少步」（L527），库克 1971 年提出 NP 完全性理论、建立复杂性理论的内核，于是第三级变成「它属于 P / NP / NP 完全中的哪一类」（L529）
- **结论**: 第三级给不出「存在多项式算法」的证明，只能给出「P 是否等于 NP」这一未知问题下的实用判断——若属 NP 完全，就不要追求精确最优解，转向近似（L529、L5991）
- **结果**: 书上交代：该问题被列为「千禧年七大数学问题」之一，证明者可获克雷数学研究所百万美元奖金；「但比较悲观的是，直到今天，我们依然没有一个较好的思路」（L529）

### 案例 2: 康托尔毕生冲击连续统假设，每次均失败（跳过第一级筛子的代价）
- **类型**: 原书案例（反例 ce102，第5章；引文 L3271）
- **问题**: 一个被反复冲击却始终无解的问题——连续统假设
- **方法论的使用**: 反读三级顺序。康托尔没有先做第一级筛查（该问题在他所用的公理系统内是否可判定），而是直接反复求解；书中写道「康托尔对连续统假设发起了一次次冲锋，但每次均以失败告终，这极大地打击了康托尔的精神状态。受限于当时的数学发展水平，康托尔不知道的是，这个问题在他的框架里是找不到答案的」（L3271）
- **结论**: 问题在给定公理系统内不可判定——「在他的框架里是找不到答案的」；导论同时交代「哥德尔和科恩的工作证明了连续统假设与选择公理是独立于ZFC公理系统的，属于不可证命题」（L533）
- **结果**: 未说明（书中只述其反复失败与精神状态受损，未给后续处置）

### 案例 3: 用书内 TSP 口径走一遍三级（合成演练）
- **类型**: 合成演练（原书未提供案例）
- **问题**: 书内没有端到端的三级筛选演练与判定书样例，故以下演练由本卡按书内口径合成。「给定一系列城市，试求出经过所有城市并回到出发点的最短路线」（书内题面 L5215）
- **方法论的使用**: ① 第一级——该题面有有穷的候选路线集合，枚举过程在有穷步骤内终止，属可计算（按 L5215 题面与 L5375「计算旅行商问题的所有可能路线要遍历n！种情况」的口径）；② 第二级——代价不可接受：22 个城市时「所有可能的组合路线有21！（21的阶乘）种」（L5305），「一旦城市达到100个，遍历完所有路线的计算时间会超过宇宙的寿命！」（L5309），书中据此写「即便它是可计算的，很可能我们在有生之年也看不到计算结果」（L5375）；③ 第三级——书中记其时间复杂度为 O(n!)，落在「可以求解或计算，但是无法『高效计算』」这一层（L5419）。三步只做归类与量级对照，不重算任何数值（公式区上标在 OCR 稿中丢失，见 B 段）
- **结论**: 走完三级的动作是转近似/启发式——「对于NP难解问题，找到一个好的近似算法和找到最优解同等重要」（L5991），具体解法设计不在本卡范围
- **结果**: 未说明（合成演练，由本卡按书内口径复算步骤而得出，书中无此演练的输出）

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 项目/需求立项前，要判断「这个问题能不能用程序算出来、要算多久」，还没开始写代码
2. 有人用「等算力上来就好了」「集群够大就能枚举」解释当前的算不出来
3. 排期被某个算法拖住，需要区分「这是优化问题还是复杂度问题」
4. 方案评审里需要一条先于实现的可行性结论（不是性能调优，也不是算法选型）
5. 反复冲击同一个难题却始终失败，需要判断「再试一次」是否有意义

### 语言信号

- 「这个问题到底能不能算出来？」
- 「先别写代码，先说说它是哪一类的难题」
- 「是不是算力再加几倍就行了？」
- 「这个我们跑了三天跑不完，是不是机器不够？」
- 英文: "Is this problem even computable?", "Is it just slow, or is it NP-hard?", "Will more compute fix this?", "Do we even need an exact answer here?"

### 与相邻 skill 的区分（阶段 3 定稿）

- 与 `complexity-class-locating`（v14）的区别: v14 是**完整的七步分类流程**（求解/验证不对称、归约、复杂度类归属与论证链）；本卡是**立项前的三级快筛**，只用三条闸门产出「可算 / 值不值得算 / 是否必须转近似」的五行判定书。快筛 vs 完整分类——需要类归属的论证与归约时，第三级内部转 v14
- 与 `concept-positioning`（v01）的区别: v01 诊断「你说的计算是哪一个计算」（概念混淆）；本卡假定概念已定，只判该问题的可行性与代价
- 与 `turing-completeness`（v13）的区别: v13 判某个系统/模型的表达能力是否等价于图灵机；本卡判某个具体问题在这台机器上是否值得算
- 与 `approximation-heuristics`（v16）的区别: 本卡只到「必须近似」这句结论为止；近似算法的设计与质量评估归 v16
- 与 `problem-definition-troubleshooting`（v21）的区别: v21 处理「问题定义错了」；本卡处理「问题定义对了但仍然可能算不出来」

## E — 可执行步骤 (Execution)

1. **固定问题与规模变量**
   - 完成标准: 用一句话写清输入、输出与规模参数 n（如「给定 n 个城市的成本矩阵，输出最短回路」），并标明要求的输出形式
   - 输入契约: 必需字段 = 问题陈述、输入对象类型、规模参数 n 的定义、要求的输出形式（精确最优 / 可行近似 / 只要判定真伪）；缺失任一项先问，不许静默猜值
   - 判停条件: 若连输入/输出都写不定 → 转 `problem-definition-troubleshooting`（v21），本卡不代做问题定义
2. **第一级：判可计算性**
   - 完成标准: 给出「可计算 / 不可计算 / 未知」三选一，并写明依据是「存在有穷步骤内终止的过程」还是「与停机问题等已知不可判定问题等价」
   - 判停条件: 若判定为不可计算（或与已知不可判定问题等价）→ 停在此步，输出「不必再投入算力」的结论（L527 口径），不再进入第二级
3. **第二级：估代价**
   - 完成标准: 写出增长阶（多项式 / 指数级 / 阶乘级）并给一个可与书内阈值对照的量级（L527「以超级计算机为基准要几亿年或几百亿年」即对现实没有意义；阶乘级见 L5305 的 21! 与 L5309「超过宇宙的寿命」）
   - 输入契约: 规模 n 的取值或范围 + 可接受的时限；缺时限先问
   - 判停条件: 若增长阶仍在多项式级且量级可接受 → 结束本卡（后续属算法与工程优化，不在本卡范围）
4. **第三级：归复杂度类**
   - 完成标准: 判定是否属 NP 完全（书内口径：所有 NP 问题中最难、任何 NP 问题都可归约到它，L529）；判不定时明确写「未定」，并写明需要哪条归约论证
   - 判停条件: 需要完整的类定位或归约证明 → 转 `complexity-class-locating`（v14）/ `reduction-argument`（v15）
5. **出判定书并分流**
   - 输出契约: 一张三级判定表，字段固定为「问题与规模 n｜可计算性（可算/不可算/未知 + 依据行号）｜代价（增长阶 + 量级对照 + 是否超阈值）｜复杂度类（P/NP/NP 完全/未定）｜下一步动作（直接实现 / 转 v14 / 转 v16 近似）」；末行写结论段
   - 完成标准: 五行字段齐全，每格带依据（书内行号或明确标「未定」）；凡出现「必须近似」的结论，须按 L5991 同时标注该结论依赖 P≠NP 这一未证明假设

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 问题本身还没定义清楚：要的是 `problem-definition-troubleshooting`（v21）
- 已确认需要解法层面的手段（近似、启发式、并行、专用硬件）：分别转 v16 / v17 / v18
- 只是想知道某系统或语言是否图灵完备：转 `turing-completeness`（v13）

### 作者在书中警告的失败模式

- ce172 穷举暴力求解（L5403）：「因此，采用穷举法来暴力计算所有的可能性，很容易陷入指数级增长的计算任务」；量级证据见 L5309「一旦城市达到100个，遍历完所有路线的计算时间会超过宇宙的寿命！」与 L5375「即便它是可计算的，很可能我们在有生之年也看不到计算结果」
- ce03 能力边界的错误直觉（导论 L433）：「今天的计算机看起来无所不能，但事实上许多人不知道的是，计算机有其能力边界，有许多题是今天的计算机永远算不出来的」——用「等算力上来」解释原理性失败
- ce166 把停机问题误读成「图灵机一定会停机」（L5021）：忽略「不停机」本身就是计算模型的一部分，于是把「可计算」当成「一定算得出结果」
- ce147 孔德式的不可解断言（L4279）：「在探查构成宇宙天体的化学成分的秘密时，绝不会成功。几年后，问题却被解」——「不可解」的断言需要形式化判定（不可判定性证明），不能凭现有技术与直觉

### 作者的盲点 / 时代局限（含阶段 1.5 登记的待核查项）

- 阶段 1.5 note（本单元登记为「（无）」）：未登记单元特有风险，以下为全局清单中与本单元相关的条目
- **依赖未证明假设（第三级）**：本卡「NP 难解问题转近似」的实践推论建立在 P≠NP 的**信念**上——作者原句即「由于大多数人相信P丰NP」（L5991），而 P 是否等于 NP 在书内明写为「未知问题」（L529）。凡输出含「必须近似」的结论，必须同时标注「依赖 P≠NP 这一未证明假设」
- **依赖未证明假设（第一级）**：把「不可计算」等同于「图灵机不可计算」，依托的是丘奇-图灵论题；作者自陈「这个论题无法从数学上证明，它不是一个定理」（L643）
- **术语口径（NR-02）**：NP 不是「非多项式 / 很难的问题」；书中正解是「非确定性多项式时间过程」，指「能在多项式时间内验证答案是否正确的问题」（L5491-5493）。引用时不得用常识误读替代作者口径
- **NR-06 上标丢失**：本单元相关复杂度记号在 OCR 稿中上标降级（如 L5419 的「2"」「O(2")」、L5375 的「远远大于2"」、L5409 的「n10n-1」）。引用含指数处一律标**待核查**，不得当准确数字使用
- **候选 spillover**：本单元候选池含主题不相关条目（如 f190 过完备空间搜索、f264 意识的三层科学定义、f90 集合的两种定义方式，属 task_ids 宽泛标注所致），**不作为本卡主张**
- 书中没有端到端的三级筛选演练与判定书样例；A1 案例 3 是本卡标记的合成演练，仅按书内口径归类，不复算数值

### 容易混淆的邻近方法论

- `complexity-class-locating`（v14）: 两者都以「这是哪一类问题」收尾，容易混。区分在**深度与契约**——本卡输出五行判定书（快筛，可短时完成），v14 输出带论证链的完整分类；本卡是 v14 的入口筛子
- `turing-completeness`（v13）: v13 检查机器（表达力上限），本卡检查问题（可行性与代价）
- 「跑得慢」不是本卡的判据: 复杂度结论是「没人能在多项式时间内算出」的结构性陈述，与当前机器快慢无关；把性能调优问题当成本卡会得到错误的「转近似」结论
