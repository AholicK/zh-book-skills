# 问题复杂度类定位（七步流程）

## R — 原文 (Reading)

> 可以将计算分成几个层次：在第8章提到的“忙碌的海狸函数”是一个快速增长函数，其增长速度超过了一般的指数级时间（即2"级别）的计算问题，可以良定义，但是无法求解、计算；一般的O(2")或O(n!)级别的计算问题，可以求解或计算，但是无法“高效计算”；
>
> — 第9章 计算复杂性（L5419）

> 简单来说，NP问题指的是能在多项式时间内验证答案是否正确的问题……NP问题的特点是结果比较容易检验，而求解过程可能很难。
>
> — 第9章 计算复杂性（L5491、L5499）

> 在NP问题中存在一些特别难的问题，使得所有的NP问题都可以“归约”到这类问题，从而只要解决了这些最难的问题，那么所有的NP问题就都解决了。
>
> — 第9章 计算复杂性（L5535）

## I — 方法论骨架 (Interpretation)

这一步做的是给一个具体问题"定类"，并留下可追溯的依据链。它不是难度打分，而是一条逐级收紧的检查链，每一级都可能判停或改道：

1. **可计算性**（第 8 章已终结的一级）：能不能给整类问题找到一组确定的规则、按规则机械执行、在有限步骤内出结果（L4677）。不可计算的问题没有"类"可定，只有"边界"可记。
2. **增长阶**：不问某次跑多久，而问规模扩大时所需资源怎么涨——复杂度是"规模增长数百、数千、数万、数亿倍时的增长速度"（L5413），因此小规模时意义不大。尺度写作 O(2^n) / O(n^k)，书中上标残缺处只记结构（L5415）。
3. **求解 / 验证不对称**：这是全流程的枢轴。把"求解"与"给一个候选解再验证"分开算账——求解可能指数级，验证却在多项式内（22 城 TSP 有 21! 种路线，但任一条路线都能很快验算长度，L5495）。能验证、不能（已知）求解，就落到 NP 一侧（L5491）；顺带做一个便宜的自洽检查：把"是 / 否"互换，P 类通常仍多项式可解，NP 类通常不对称（L5497）。
4. **归约**：把本问题与已知最难的问题接上——在多项式时间内把 A 的任意实例构造成 B 的实例，使 A 与 B 的答案完全相同（要么都为是、要么都为否），且规模不过分膨胀（L5537）。
5. **NP 完全判定**：两条同时成立才算——① 本问题 ∈ NP（第 3 步的验证流程）；② 所有 NP 问题都可归约到它（L5535）。判成 NPC 后，正确的动作是停止找精确快速算法，转向近似与启发式。
6. **中间问题**：若"不在 NPC"有证据、"在 P"看不出，就落进 P 与 NPC 之间的中间地带（因数分解、图同构，L5785）；这条不是例外状态，若 P≠NP，拉德纳尔定理保证 NP 中间问题的存在（L5771）。
7. **可近似性**：最后判"这个问题要最优解还是要可行解"——搜索问题可以通过设定下界转化为判定问题（L5589），转化为近似/启发式路线（归 `approximation-heuristics`）。

一条全程约束贯穿七步：**所有复杂度类结论都建立在"假定 P≠NP"之上**（L5655），作者自陈"尽管没有任何证据"（L5653）。每一步都要显式登记自己踩在哪个未证前提上。

## A1 — 书中的应用 (Past Application)

### 案例 1: 因数分解与图同构——落在"中间地带"的问题怎么处置
- **类型**: 原书案例
- **问题**: 素数判定与线性规划先后被划入 P 类，那因数分解与图同构该归到哪一类
- **方法论的使用**: 按七步走——① 可计算性：两者显然可计算（因数分解要"做大量计算"但仍在有限步骤内，L5499）；② 增长阶：目前最快的整数分解算法是亚指数级（L5793，公式区 OCR 残缺，只记结构），图同构 2015 年被推进到拟多项式时间，仍不是多项式时间（L5813）；③ 求解 / 验证不对称：给出两个因数后一次乘法即可验证（L5499），求解方向却没有任何高效算法（L5787）；④ 归约：已有明确证据证明它们**不**属于 NP 完全问题（L5785）；⑤ 因此既不能判 P、也不能判 NPC
- **结论**: 显式记为"未分类 / 中间地带"，不做二选一——"虽然已有明确证据证明它们不属于NP完全问题，但这两个问题看起来又比P类问题要难很多，似乎属于P与NP的中间地带"（L5785）
- **结果**: 书中给出两个"曾未分类、后被划入 P"的先例（素数判定与线性规划），并指出若 P≠NP，拉德纳尔定理保证 NP 中间问题必然存在（L5771）；图同构的进展用城市比喻收尾——"如果P类问题处在城市的中心，图同构这样的问题可能位于城市的郊区"（L5813）

### 案例 2: 椭球算法——多项式时间却不实用（书中反例）
- **类型**: 原书案例
- **问题**: 线性规划被椭球算法划入 P 类之后，是否就该选它做工程实现
- **方法论的使用**: 第 2 步只判增长阶（椭球算法是多项式时间算法，L5781），第 7 步追问实践口径——分类刻画的是增长阶与最坏情况，不含常数项与真实数据分布
- **结论**: 归入 P 类不等于实用；"椭球算法并不实用，实践中的耗时比单纯形法要多得多，因此人们还是更偏爱单纯形法"（L5781）
- **结果**: 书中给出反向对照——单纯形法最坏情况是指数级，却"依然有着重要的应用，因为大多数时候我们都不会遇到最坏的情况"（L5779）；另记 1984 年卡马卡的内点法"理论和实践上的效果都很好，而且这是一种多项式时间算法"（L5781）

### 案例 3: "每秒运算 10 次的计算机在不同条件下的运行时间"对照表
- **类型**: 原书教学表格
- **问题**: 怎样把抽象的复杂度阶换算成工程师能感知的时间量级
- **方法论的使用**: 固定机器速度，让复杂度函数与规模 n 变化——前文说明计算 TSP 的全部路线要遍历 n! 种，"这个数已经远远大于2"[上标残缺，原文如此]，指数级规模的任务"即便它是可计算的，很可能我们在有生之年也看不到计算结果"（L5375）
- **结论**: 同一台机器在不同复杂度函数下，运行时间从百万分之一秒量级跳到十几天、乃至几十万亿年
- **结果**: 表格在 OCR 稿中结构残缺（表头与表体散落为 20 余个独立行，L5377-5401），只能读出量级数字，**对应关系不可复原、不作数值复算**；表标题中的"每秒运算10次"缺上标 [原文如此]，标待核查

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 手上有一个具体问题（排班、路径规划、资源分配、约束求解、密码相关），要判"它到底难在哪一类、我该找精确算法还是换路子"
2. 有人给出"这是 NP 完全问题，所以没戏"这类结论，需要复核它的依据链是否成立、前提是否被偷偷当成了定理
3. 面对一个长期没有人解决的多项式算法的问题，要判断该记为"未分类"还是"NPC"
4. 方案评审里要回答"为什么我们要上近似 / 启发式 / 松弛"——需要一份带出处的分类依据，而不是一句"这个问题很难"
5. 要读一份算法或优化方案的宣传材料，检查它的复杂度论断是否标了前提

### 语言信号

- 「这个问题是 P 还是 NP？」「它是不是 NP 完全？」
- 「为什么说这个问题没有高效算法？」
- 「我们该做精确算法还是上近似？」
- 「这个优化问题是 NP 难吧，那就不用想了」
- 「因数分解到底算哪一类？」
- 英文: "Is this NP-complete?", "Can this problem be solved in polynomial time?", "Why can't we find an efficient algorithm for this?", "should we go for approximation or exact?"

### 与相邻 skill 的区分（阶段 3 定稿）

- 与 `three-tier-screening` 的区别: **这是同一链条的完整版对快筛版**。v03 只做三级粗筛（可计算性 → 代价 → NP 完全），输出"该不该用计算机做这件事"的判定书，不追依据；本卡跑满七步，逐步给出增长阶、验证/求解不对称、归约来源、NPC 判定、中间问题、可近似性，输出"分类结论 + 依据链"。只要三级结论 → v03；要"到底哪一类、依据是什么、下一步找算法还是找近似" → 本卡
- 与 `reduction-argument` 的区别: 本卡第 4 步只**用**归约给本问题定位；归约本身的构造（A 变换为 B、答案一致、规模不爆炸）归 v15
- 与 `approximation-heuristics` 的区别: 本卡第 7 步只判"可不可近似、走哪条路线"；近似因子判定与启发式四问设计归 v16
- 与 `quantum-credibility` 的区别: 涉及 BPP / BQP 等类时，量子宣传的可信度判定归 v18；本卡只在定类时保留"未证分离"的限定（ce225）
- 与 `turing-completeness` 的区别: v13 判"能不能算"（能力），本卡判"要算多久、答案好不好验证"（代价）

## E — 可执行步骤 (Execution)

1. **判可计算性（第 1 级筛子）**
   - 完成标准: 明确回答"该问题是否存在一组确定的规则，能机械地在有限步骤内求出任一实例的结果"（L4677），并给出"是 / 否 + 依据"
   - 输入契约: 问题的完整陈述——输入集合、输出形式、问题规模测度 n 的定义。缺规模测度必须回问，**不许静默假定**
   - 判停条件: 若判为"不可计算"（与停机问题等价，如忙碌的海狸函数类，L5421），停止分类，转 `three-tier-screening` / `self-reference-limits`，本卡不产出复杂度类结论

2. **测增长阶（时间与空间）**
   - 完成标准: 分别写出时间复杂度（计算步骤数的规模）与空间复杂度（写入纸带的格子数规模，**不含输入输出占用格子**，L5413）的增长阶；用 n 表示规模
   - 输入契约: 算法/流程的步骤数表达式与格子数表达式。书中上标 OCR 残缺处（O(2")、O(n)、CXn*、O(2n)）只记结构、标"待核查"，不得按常识补符号
   - 判停条件: 若增长阶已明确落在多项式以内 → 直接判 P 侧并跳至第 6 步做自洽复核；若只能给实测耗时、给不出表达式 → 记为"未定阶"，不得跳过继续往下判

3. **测求解 / 验证不对称**
   - 完成标准: 写出"给定候选解即验证真伪"的验证流程，并给出验证步骤量的阶；与求解方向的阶并列对比
   - 输入契约: 候选解的形式（一条路线 / 一组因子 / 一个赋值）+ 判定条件或界限
   - 判停条件: 若验证方向本身就在多项式以外（如 TSP 的补问题要检查所有路线，L5497），标记为"补问题侧不对称"，跳到第 6 步按中间问题处理，不要直接判 NP

4. **做归约定位**
   - 完成标准: 给出一条从已知 NP 完全问题（SAT / 3SAT，L5539、L5593）到本问题的多项式时间归约，或给出"不存在此类归约"的明确证据
   - 输入契约: 基准 NPC 问题 + 本问题的实例构造规则；归约须同时满足"答案相同（同为是 / 同为否）"与"规模不过分膨胀"（L5537）
   - 判停条件: 若两个方向都拿不出证据 → 跳第 6 步判"未分类"；需要把归约写完整时转 `reduction-argument`

5. **判 NP 完全**
   - 完成标准: 两条同时成立——① 本问题 ∈ NP（第 3 步的验证流程）；② 所有 NP 问题可归约到它（第 4 步，或在已证明的 NPC 问题基础上继承完全性，L5535）
   - 输出契约: 结论段"该问题为 NPC / 非 NPC / 未定"，附归约来源与判定依据
   - 判停条件: 判为 NPC 后停止寻找精确快速算法，直接跳第 7 步并转 `approximation-heuristics`

6. **处置中间问题与未分类**
   - 完成标准: 对"不在 NPC 有证据、在 P 看不出"的问题，显式记为未分类，并分别列出两个方向的证据（口径见因数分解与图同构，L5785）；注明"若 P≠NP，则中间问题必然存在"（拉德纳尔定理，L5771）
   - 输出契约: 未分类条目，字段为"不在 NPC 的证据 / 不在 P 的证据 / 当前最好的算法进展"
   - 判停条件: 出现"必须二选一"的压力时按 ce190 判停——保留"未分类"这一类别，不做二分，不得因"未见多项式算法"就判 NPC

7. **判可近似性并收口**
   - 完成标准: 判定本问题是判定型还是搜索型（搜索问题可设下界化为判定问题，L5589）、可接受的近似口径、可用的启发式路线；若只能得到"多项式时间可解"的理论保证而实践性能未知，按 ce175 补基准测试
   - 输出契约: 一页定位书，字段固定为——问题陈述与规模测度 n / 第 1 级可计算性结论 / 时间与空间增长阶 / 验证流程与验证阶 / 归约来源 / 复杂度类结论（P·NP·NPC·未分类）/ **未决项与假设登记（逐条写明是否依赖 P≠NP 等未证前提）/ 下一步动作（找算法·做归约·转近似·转并行）**
   - 完成标准: 每一栏都有内容或显式写"未说明"；所有引用带章节 + 行号；OCR 残缺处只写结构描述，不给数值复算

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 只需要"该不该用计算机做这件事"的三级粗筛结论：走 `three-tier-screening`，本卡的开销不必要
- 问题定义本身还没稳定（现象与问题未分离）：先走 `problem-definition-troubleshooting`（附录 B），否则会把错的问题定错类
- 要拿本卡给密码体系的安全性下结论：本卡只能回答"它押注在哪个未证前提上"，不能判"安全 / 不安全"（相关口径见 v18 与单向函数条目）
- 要评估并行化收益、加速比上限：那是 `parallelization-speedup` 的判据，与复杂度类不是同一把尺子

### 作者在书中警告的失败模式

- **ce15（L529、L547）**：把 **P≠NP 当已证前提**，用它推演复杂度类结论、给系统定性（如"这个优化问题必然没有高效算法，所以不必找"）。作者原话是"但比较悲观的是，直到今天，我们依然没有一个较好的思路"——它至今是千禧年七大问题之一
- **ce183（L5683）**：把 **NP=coNP 的未知状态当结论**。"至今，我们也不知道NP=coNP是否成立"；由"NP 的是 / 否不对称"直接推出补问题一定难，是把直觉当结论（素数判定长期属 NP∩coNP 而不知是否在 P，直到 2002 年才确定在 P——说明直觉判断在类归属上会长期出错）
- **ce225（L6425）**：把 **BPP≠BQP 当已证分离结论**。作者原句自带限定"尽管还没证明，但人们倾向于相信BPP≠BQP"；同类还有"目前人们猜测BPP=P，但这尚未得到证明"（L6411）
- **ce181（L5655、L5653）**：整套推论的前提被遗忘。"我们需要记住，这些结论都是在假定P≠NP的前提下产生的"；作者自陈"大多数计算机科学家都相信P≠NP，我也如此。尽管没有任何证据"（L5653）
- **ce179（L5645）**：把"NP 问题超出人类直觉能力"当无条件结论——作者自己给它加了前提："但是，前提条件是P≠NP"
- **ce180（L5649）**：把"补充信息变成神谕"推广为通用解法。它只缩小搜索集合、不改变复杂度类，换一个实例即失效（作者自陈"我至今无法理解他的大脑中发生了什么"）
- **ce175（L5781）**：以"这是多项式时间算法"作为选型理由，忽略常数项与真实数据分布（椭球算法 vs 单纯形法）
- **ce184（L5691）**：把复杂度类包含关系当已证事实——已证的只有"上述包含关系中至少有一个是真包含"，"我们强烈怀疑这些包含关系都是真包含，但没有任何证据"
- **ce190（L5785）**：把因数分解 / 图同构硬塞进 P 或 NPC 两个抽屉，忽略"未分类"这一现实类别
- **ce191（L5787）**：以为素数判定的突破会顺带解决因数分解——判定与分解是两个问题，"即便是AKS算法，现在也只能告诉我们一个数是否为素数，却并不能提供关于因数分解的任何帮助"
