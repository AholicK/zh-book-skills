# 编码—符号变换三步设计法

## R — 原文 (Reading)

> 计算的过程可视作通过算术关系来模拟自然界的事物，先通过数字化完成编码，再通过算术关系来驱动编码后的数字符号的变形，来表达状态间的转化。…只要给出定义和初始状态，执行计算规则就能得出结果。
>
> — 导论（L645-647）

## I — 方法论骨架 (Interpretation)

这段方法把「建一个可计算模型」拆成三个有先后的动作，缺一个都跑不起来：

1. **编码**：把目标对象表示为符号/数字串。这一步的本质是抽象，判据是「将所有不必要的细节剔除，而只保留最关键的信息」（L5581）；本书用奥卡姆剃刀给动作定名，用柯尔莫哥洛夫复杂度给好坏定口径——描述越短、后续运算越省，编码越好（L5571 一带）。
2. **规则**：用算术关系去驱动编码后符号的变形，让「状态 A 变成状态 B」落成「符号串 A 变换为符号串 B」的可执行步骤。判据是计算系统的两项共同特征——有符号表征、有变换规则；两者齐备，这套东西才具备交给机器驱动的条件（L1465）。
3. **初始状态与定义**：给出定义与初值，规则才有起跑线；三者合成一个可执行的计算模型。

适用范围比直觉宽：目标对象不必真实存在。只存在于人脑构想中的大楼草图、电子游戏，同样「只要给出定义和初始状态」就能算（L647）——作者给的依据是丘奇-图灵论题的心理形式（属论题假设，见 B 段）。

次序不可颠倒，也不可跳过第一步：编码的形状决定了规则能怎么动作，规则只在自己编码出的符号空间里作业，初值是唯一入口。工程上最常见的返工来自「先写规则、再回头发现编码丢掉了必须保留的信息」。

## A1 — 书中的应用 (Past Application)

### 案例 1: 元胞自动机——「方格编码 + 局部规则 + 初始配置」
- **类型**: 原书案例
- **问题**: 冯·诺依曼受乌拉姆启发，想研究一种可再生的自动机（能自复制的计算模型），需要一套能表达平面空间连续演化的可计算形式（L6701）。
- **方法论的使用**:
  1. 编码：以均匀的方格分割平面空间，每一格代表一个细胞，每个细胞用有限个状态来对应（如空格、已占或染色）；
  2. 规则：每个细胞只与周边方格的细胞构成关联，单体细胞的互变只取决于它自身与相邻细胞——本地规则，不含全局信息；
  3. 初始状态：给定初始的格点配置，按规则迭代下去；
  4. 用同一个三步骨架再检验它的计算能力。
- **结论**: 元胞自动机；书中记它「可以通过规则，完美复制任意元胞自动机的初始状态，因此是一种自复制的计算模型」（L6703）。
- **结果**: 书内给出等价性结论——「冯·诺依曼同样证明了元胞自动机和通用图灵机是等价的，因此所有可以由图灵机完成的计算，也可以由元胞自动机完成」（L6705）；未说明元件级实现细节。

### 案例 2: 线性规划被质疑「世界不是线性的」——建模前提该核什么
- **类型**: 原书案例
- **问题**: 1948 年威斯康星大学会议上，丹齐格报告线性规划，一位数学家质疑「可是我们都知道世界不是线性的」，丹齐格一时不知如何回复（L5861）。
- **方法论的使用**: 第一步编码就把问题内在的结构复杂性换成了「空间规模大但结构简单」的线性形式（决策变量 + 线性约束 + 线性目标）；面对质疑，不辩论世界是否线性，而是把核对对象收缩到「应用是否满足模型原理」这一条上逐项检查。
- **结论**: 冯·诺依曼解围的口径是——「你的应用要是满足他的原理，那就用他的模型；要是不满足，那就不用」（L5861）。
- **结果**: 会上分歧就此落地为一条前提核对规则；书中未说明该次会议的后续裁定（本书用它说明编码三步法的正当性来自「应用是否满足前提」，而与世界本身的线性与否无关）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 要把一个非数值的东西（审批流、评级规则、合同条款、评分细则）改写成程序或可计算模型，得先决定编码成什么。
2. 手里有一大堆输入数据，但状态怎么表示、字段怎么归一还没定，方案卡在建模第一步。
3. 想判断某个「规则体系」到底算不算一个计算系统、能不能交给机器执行（流程规范、评定规则、成套表单）。
4. 建模之前需要登记前提（线性/可加/对称/有限精度），担心模型结论被外推到不适用的场景。

### 语言信号

- 「这套流程能不能写成程序？先怎么编码？」
- 「我有一堆数据，但状态该怎么表示才对？」
- 「这个规则表算不算一个计算系统？能不能让机器执行？」
- 「先把哪些细节砍掉、留哪些？」
- 英文: "How do I encode this process into a computable model?" / "What's the initial state and the transition rules?"

### 与相邻 skill 的区分（阶段 3 定稿）

- 与 `turing-completeness` 的区别: v13 检查一台机器/形式系统是否五元组齐备、是否图灵完备；本卡只产出「编码表 + 变换规则 + 初始状态」这套建模骨架，不判定计算能力的上限。
- 与 `godel-encoding` 的区别: v12 处理的是面向自指的符号→码→公式码编码与良恶性判定；本卡的编码是为外部现实过程或虚构构想建模型，不引入自指。
- 与 `complexity-class-locating` 的区别: v14 在模型已定之后定位问题的复杂度类；本卡是它的建模前置（编码与规则未定，复杂度类无从谈起）。
- 与 `symbolic-logic-calculus` 的区别: v26 讲符号化与逻辑演算的史论与原则（莱布尼茨→布尔），本卡是可执行的三步操作与交付物。
- 与 `problem-definition-troubleshooting` 的区别: v21 先定义问题、划清输入输出关系与故障面；本卡在问题定义之后做形式化编码。

## E — 可执行步骤 (Execution)

1. **登记目标对象与建模前提**
   - 完成标准: 写出一段清单，含「对象描述 / 必须保留的信息 / 可丢弃的信息 / 已登记前提（线性、可加、对称、有限精度等）」四栏，四栏都有内容。
   - 输入契约: 目标对象（现实过程或只存在于构想中的事物）+ 要算出的东西 + 可接受精度 + 前提清单；任一项缺失先向用户追问，不许静默猜值。
   - 判停条件: 若连「要算的是什么」都说不清 → 转 `problem-definition-troubleshooting`，不要先编码。
2. **编码（数字化／符号化）**
   - 完成标准: 产出编码表，列出每个对象的符号表示、状态集合，并逐条注明哪些细节被剔除及理由（理由须能对应到「保留与问题相关的信息」）。
   - 输入契约: 第 1 步的四栏清单。
   - 判停条件: 若同一对象在两套编码下无法比较优劣 → 回第 1 步补全前提与目标口径，再选编码。
3. **定义变换规则**
   - 完成标准: 每条规则写成「前提条件 → 符号变换」形式，逐条可机械执行，且同一输入不产生两个不同输出。
   - 判停条件: 若某条规则需要外部判断（人眼识别、额外资料、口头经验）→ 回第 2 步，把该判断本身也编码进去。
4. **给出定义与初始状态**
   - 完成标准: 模型能从初值出发至少跑出一步，且该步结果与人工核算一致。
   - 判停条件: 若初值无法指定或对象在本编码下不可判定 → 输出「该对象在本编码下不可计算」，转 `inherent-constraints` 登记约束，不硬凑。
5. **交付计算模型**
   - 输出契约: 结构化交付 = ①编码表（对象/符号/状态集/被剔除细节及理由）②变换规则表（前提 → 变换）③初始状态与定义 ④已登记前提清单与适用条件 ⑤未解决问题清单。完成标准：第三方仅按此三件套即可独立复现第一步结果，且能指出结论依赖哪些前提。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 目标对象还没有定义清楚「要算出什么」时——先做问题定义与排障。
- 需要判自指系统的界限（可证性、停机、不可判定）时——编码 + 对角线 + 归谬是 v08 的活。
- 需要给出「做不到」的结论时——转 `reductio-proof`。
- 只是要给一个已定模型定位复杂度类时——转 `complexity-class-locating`。

### 作者在书中警告的失败模式

- **两种方向都错的建模边界（ce195，L5861）**: 一是因「世界不是线性的」而否定线性建模的价值，二是把线性模型的结果无条件外推到非线性现实。作者给的边界口径是「你的应用要是满足他的原理，那就用他的模型；要是不满足，那就不用」。
- **数据到手 ≠ 机制到手（ce253，L6863）**: 2003 年人类基因组计划发布了完整序列（约 25000 个基因），「解开原本被寄予厚望的生命密码本之后，其并没能够解释人的所有复杂性和缺陷」——完整编码并不等于解释机制，这正是还原论的缺口。
- **编码标准的路径依赖（ce36，L863、L875）**: 「事实上，十进制除了方便屈指计数，怎么看都不应该是数学家们的首选…10既非素数，又不含足够多的因数，在数学上不是最佳的选择。但10 个手指是人类天生的计算工具，我们早已习惯了10的存在」（两处引文分置 L863 与 L875，中段为布冯提议十二进制、拉格朗日主张素数基底的引述）——不最优的进制被制度化为默认标准，后世为绕开默认值到处添加辅助单位（如「一打」、分数的多种等价写法）。
- **为符号强行指派物理意义会锁死运算自由度（ce49，L1461）**: 古希腊要求每个代数式都对应几何量，因为空间只有三维而「不能把3个以上的数相乘」，还要同行同类量相加，于是现代意义的代数运算几乎无法实现。

### 作者的盲点 / 时代局限（含阶段 1.5 登记的待核查项）

- **依赖未证明假设**: 本卡第 3 步的宽适用范围（构想中的事物也可计算）建立于丘奇-图灵论题的「心理形式」（L647）；同源的 f11 物理形式更进一步推出「只要有足够的算力，甚至可以用一台机器模拟出我们所在的这个宇宙」（L631）。后者属「宇宙是图灵机」类未证明假设，只能作为作者的推论引用，**不得写成学科结论**。
- **NR-02 术语与 OCR 口径**: 全书一律写「哥德尔数/编码」，0 次「哥德尔编码」；OCR 错形（入演算＝λ演算、悖论作「悸论/湟论」、熵作「炳/摘」）照抄，可加 `[原文如此]`，不得更正。
- **NR-04 OCR 公式残缺**: 本单元候选 p168 的「直言命题 → 布尔代数方程映射表」括号内公式在 OCR 中残缺（主语与常数 0 丢失），只记结构、**不提供数值复算**，引用须标待核查。
- **NR-06 上标丢失**: 凡引文含指数处（如压缩概率上界 2^-k 在源文作 `2*`）上标已降级，一律标待核查，不得当准确数字。
- **候选 spillover**: 本单元全量 69 条中含 c278/c279（柯尔莫哥洛夫复杂度）、f156（七桥问题图论建模）、f134（映射方法）等偏「抽象/复杂度」的条目，其 `task_ids` 标注宽泛而落入本单元。写卡按各单元**主属**候选立论，不把 spillover 条目当作本单元主张。

### 容易混淆的邻近方法论

- `turing-completeness`: 都谈「机器能不能做」，但检查对象不同——本卡查模型骨架（编码/规则/初值）是否齐备，v13 查机器本体是否完备。
- `godel-encoding`: 都叫「编码」，区别在编码的目的——一个是自指与可证性，一个是给外部过程建模型。
- `complexity-class-locating`: 一个在建模之前（编码），一个在建模之后（定位）。
