# 问题定义与排障流程（附录 B）

## R — 原文 (Reading)

> 数学是人类最重要的工具。…数学的目的是对模式和结构的洞察与发现，在数学的思维活动中，提出正确的问题是极其关键的，它决定了求解的方向。…尤其在计算机发明后，求解的效率大大提升了，因此复杂的难点落在了如何定义关键问题上。
>
> — 附录B·提问与求解的艺术·提问的方法（L8321）

> 在工作中，我发现许多人经常会混淆“现象”和“问题”。现象是我们所观察和感知到的。…而问题则是我们根据现象定义出来的，是洞察了现象的模式与结构后，尝试进行控制的关键点。一旦改变了这个关键点，就能改变现象或结论。
>
> — 附录B·提问与求解的艺术·提问的方法（L8339）

> “第一条是：凡是我没有明确认识到的东西，我决不把它当成真的接受。…最后一条是：在任何情况之下，都要尽量全面地考察，尽量普遍地复查，做到确信毫无遗漏。”
>
> — 附录B·提问与求解的艺术·提问的方法（L8325、L8331，转引笛卡儿《谈谈方法》）

## I — 方法论骨架 (Interpretation)

这是一条「先把问题定义清楚，再谈求解」的前置流程，它假设求解能力已经便宜（计算机发明后求解效率大大提升），因此瓶颈前移到「问什么」。

第一环是把观察和定义拆开：把观察到的东西原样列成现象（不可控、只是数据），再单列「我据此定义的问题」。合格的问题必须含一个可改变的关键点，并且能回答「动这个点会改变哪个现象」；答不出来就说明还没定义清楚，只是把现象复述成了问题。

第二环是给思考定次序：只接受无法怀疑的东西（排除先入之见）；把难题按可能与必要的程度拆成若干部分；从最简单、最容易认识的对象起步，逐步上升到最复杂的对象，本来没有先后关系的也设定一个次序；最后尽量全面复查。作者把它读成逐次逼近，从计算上看是递归或启发式——这正是它为什么总能逼近关键问题的原因。

第三环是判边界与改写：先分清哪些问题是不可计算的、哪些是可计算但无法高效计算的；对算不动的那一类，动作是改变问题本身的定义、把它改写成近似问题以获得高效求解，而不是硬扛精度。

第四环是挖根因：分析与挖根因环节调用直觉——猜想、联想、类比、归纳、顿悟，共同前提是观察与长期持续思考；直觉产生的假设要放回经验里验证（直接经验经直觉上升为公理体系，演绎出命题后再回到直接经验验证的闭环）。

关键约束有三：现象与问题一旦混在一起，后面每一步都会偏；直觉不是免责条款，未被验证的只能记为猜想；笛卡儿四步的「清楚分明」原书没有给操作标准，遇到判不动的对象要显式说明而不是自行判定。

## A1 — 书中的应用 (Past Application)

### 案例 1: 四色问题——现象与问题的分离，以及「关键点」的迁移
- **类型**: 原书案例（数学史案例）
- **问题**: 1852 年格斯里发现给英国地图的不同区块着色时最多只需 4 种颜色（两两相邻必不同色），由此提出猜想；此后百年无人能证（L2465）。
- **方法论的使用**: ①现象=「最多只需 4 种颜色」这一观察（L2465）；②问题=从现象里定义出的关键点：肯普提出构形与可约性两个概念，并指明「寻找可约构形的不可避免组成是证明四色问题的关键」（L2467）——这就是「一旦改变它就能改变结论」的那个点；③判边界：验证大构形可约「需要极其庞大的计算量，数学家们再次陷入泥潭」（L2467）——属可计算但人力无法完成；④改用机器求解：阿佩尔与哈肯用 4 年、几台计算机运算超过 1200 小时、检验超过 2000 个构形、做了超过 100 亿次判断、证明了 1482 个不可避免构形的可约性（L2469）；⑤复查环节暴露新问题：如此庞大的计算量已无人能逐步验证，而计算机又无法解释其中的逻辑（L2471）。
- **结论**: 关键问题被重新定义为「可约构形的不可避免集」，求解方向随之从人工推演改为机器穷举 + 事后复查。
- **结果**: 四色猜想成为四色定理；蒂莫兹科的质疑与阿佩尔、哈肯的回应使「不可人工验证的证明是否算证明」成为长期争论，此后数学家日益习惯计算机辅助证明（L2471）。

### 案例 2: 钉绳法——先造一个能快速打分的廉价模型
- **类型**: 原书案例（丹齐格小组 1954 年的验证装置）
- **问题**: 手算时代求解 42 城市的旅行商问题，算法给出的路线好不好、有没有优化空间，缺少快速判据。
- **方法论的使用**: ①把问题铺成物理副本：42 个城市的简化地图（采用欧几里得距离）铺在板上，每个城市位置钉一颗钉子（L5889）；②让物理约束自动满足可行性：从起点出发用一根绳子依次绕过所有钉子，绷紧后即得一条可行路线（L5889）；③直接测量代价来验证算法结果——量绳子长度（L5889）。这是「先把评价函数做便宜，再去做昂贵推演」的动作。
- **结论**: 得到一条可行路线与一个可测量的代价（699 单位）。
- **结果**: 699 单位后来被证明就是最优解，与割平面法的结论一致（L5889）。

### 案例 3: 一次现象/问题分离的演练（合成演练）
- **类型**: 合成演练（原书未提供该场景的案例；仅按书内规则演示第 2、3 步）
- **问题**: 某服务上线后「用户投诉变多，同时机器负载曲线出现周期性尖峰」，团队准备直接扩容。
- **方法论的使用**: ①现象清单（原样列）：投诉工单文本与数量时间序列、负载曲线的周期与幅度、发布记录；②问题定义：从现象里找一个可改变的关键点，并写出「动它会改变哪个现象」——例如把关键点定义为「尖峰期间的排队时长」，其判据是缩短排队时长后投诉量应随之下降；③边界判定：先判它是否属「可计算但无法高效计算」——本例可用日志重放逐步逼近，属可算类，不必改写；④复查：把「扩容」作为候选根因而非结论，写明若扩容后尖峰与投诉不同步下降，则该根因被否。
- **结论**: 输出的不是「扩容方案」，而是一份含关键点与可检验预测的问题定义。
- **结果**: 未说明（演练本身不产生书内结果；此处只校验第 2、4 步的动作可复算）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 排障/复盘时，手里的「问题描述」其实是现象复述（一堆报表、日志、投诉原话），改了几轮都改不动现象。
2. 复杂难题无从下手：不知道该先拆哪一块、先做哪一步，需要一套思考次序（怀疑→分解→由易到难→复查）。
3. 问题已经定义但算不动（不可计算或无法高效计算），要判断该放弃还是该把它改写成近似问题。
4. 根因分析停在一堆猜测上，需要把直觉产生的候选根因放回观察里验证、并区分「已验证」与「仍是猜想」。

### 语言信号

- 「帮我定义一下到底要解决什么问题」
- 「我们一直在改，但指标没动」
- 「这个需求说不清楚，帮我把现象和问题分开」
- 「这个问题的根因到底是什么，怎么验证」
- 英文: "help me frame the actual problem, not the symptom", "root cause analysis with a verifiable hypothesis"

### 与相邻 skill 的区分（阶段 3 定稿）

- 与 `concept-positioning` 的区别: 概念定位卡处理的是「计算／智能／信息这类词到底指什么」，输出术语口径；本卡处理的是「一个具体困惑的问题陈述是否定义清楚」，输出问题定义书与根因链。
- 与 `complexity-class-locating` 的区别: 定类卡接手的是**已经定义清楚**的问题，输出复杂度类结论与依据链；本卡是它前面的那一环——问题还没定义清楚时，任何定类都是在给错误的对象分类。本卡第 3 步只做粗判（可计算／不可计算／可计算但难以高效计算），细判转定类卡。
- 与 `approximation-heuristics` 的区别: 本卡只负责把问题改写成近似问题（改定义、给精度口径）；近似因子判定与启发式四问设计由近似卡负责。
- 与 `systematic-debugging`（通用排障）的区别: 本卡不提供日志取证、二分定位等具体手段，只提供「现象/问题分离 + 次序 + 改写 + 根因验证」的定义层流程。

## E — 可执行步骤 (Execution)

1. **列现象清单**
   - 完成标准: 清单里只有「观察到的」条目（数据、记录、原话），任何解释性措辞都被移出并另存为「解释候选」。
   - 输入契约: 现象描述或数据原文（工单、日志、指标序列、访谈原话）、已有的问题陈述、可用的观察手段与时间窗。缺数据原文只有转述时先问，不许把转述当现象。
   - 判停条件: 若连稳定的观察都拿不到（每次观察结果互相矛盾且无法归因），先补观察手段，不进入第 2 步。
2. **现象/问题分离**
   - 完成标准: 写出一句问题陈述，其中含一个明确的关键点，并写出「动这个关键点 → 预期改变哪个现象」。写不出这条因果预期即判为未定义清楚，退回重写。
   - 判停条件: 若反复无法给出关键点，说明缺领域知识——转 `concept-positioning` 澄清概念或补材料，不硬写。
3. **粗判边界**
   - 完成标准: 每个问题被归入三档之一——① 不可计算；② 可计算但无法高效计算；③ 可算且可高效求解，并各写一句依据。
   - 判停条件: 归入①→停止并输出「在现有模型下不可判定」，转 `three-tier-screening` 讨论是否换模型；归入②→进入第 4 步；归入③→跳到第 5 步。
4. **近似化改写**
   - 完成标准: 改写后的问题明确给出精度口径或规模上限，以及由此引入的代价与误差会被谁看到。
   - 判停条件: 若改写后的近似问题其误差无法被任何现有观察手段分辨，判为「改写失效」，退回第 2 步重定义关键点；若改写只是换用启发式求解则转 `approximation-heuristics`。
5. **给思考定次序（笛卡儿四步）**
   - 完成标准: 产出子问题序列，且每条子问题能标出「为什么它比其他条更容易认识」；无先后关系者已显式设定次序；末尾有「复查项」清单。
   - 判停条件: 若某条子问题依赖尚未确立的前提，把它标为「先决项」并提到序列最前。
6. **挖根因并验证**
   - 完成标准: 每条根因候选标为「已验证」或「仍是猜想」；已验证者必须能指回第 1 步的现象清单；用到的直觉方式（猜想/联想/类比/归纳/顿悟）被显式标注。
   - 判停条件: 若所有候选都未被验证，输出「根因未定位」并列出下一步观察设计，不得给出处置方案。
7. **出交付物**
   - 完成标准: 六段结构完整，且「问题陈述」与「根因链」之间能逐条对应。
   - 输出契约: 问题定义书（现象清单 / 问题陈述+关键点 / 边界判定 / 近似改写（如有）/ 子问题序列 / 根因链与验证状态）+ 明确标注的判据强度（哪些结论是笛卡儿原文、哪些是作者的转译与经验判断）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 问题已经定义清楚、只是需要分类或算法选择时——直接转 `complexity-class-locating` 或 `approximation-heuristics`，本卡会白跑一轮。
- 需要的是统计推断、因果识别、实验设计等实证方法时（本卡不提供抽样、检验、对照组设计）。
- 纯执行类任务（目标与验收标准都已给定），此时定义环节没有可改动的空间。
- 面对注定无法用事实仲裁的终极争论时：作者的处置是「因为没有答案，所以不存在对错……只能依靠心中的信仰做出自已的选择」（p33，L543，[原文如此]）——这是作者立场引文，不是可执行方法。

### 作者在书中警告的失败模式

- ce335 / g108（L8339）: 核心陷阱——「在工作中，我发现许多人经常会混淆“现象”和“问题”」；把现象当问题后，改进举措全都针对现象，问题定义里没有「改变哪个关键点」。
- ce238（L6607）: 问题层次选择失当——维纳早期「试图解决费马大定理、四色问题、黎曼猜想等大问题，以他可怜的数学水平当然没有任何结果」；缺少可逐步累积的中间成果。
- ce188（L5769）: 把已被堵死的方法当既定路线——「有人发现，通过现有的自然证明方法不可能证得P≠NP」。
- ce276（L7197）: 把长期经验当最优解来源——「人类几千年的经验积累也没能抵得过不知疲倦的机器搜寻出的更优解，由此可见经验并不可靠」。
- ce331（L8295）: 跨领域类比当本体——以「以太」解释新领域现象，最后「不得不放弃这些以太模型」。
- ce332（L8299）: 以「算得足够快就能预测一切」作为方案前提——「量子理论表明微观粒子是充满不确定性的，因此拉普拉斯期望的神圣计算者永远都不可能存在」。
- c134（L2467）: 反面示范——作者自述小学时手工证明四色猜想「以那时的认知水平自然是毫无进展」；超出人力上限的问题不该靠人力硬解。

### 作者的盲点 / 时代局限（含阶段 1.5 登记的待核查项）

- **阶段 1.5 note（必须继承）**: 附录 B 的部分结论为**作者个人经验**，本卡中「提问决定求解方向」「按这种思考框架，总能发现和定义关键问题」（L8337）均应标注为作者判断，不得当作方法效力的证明。
- 附录 B 为两篇文章合编（书内注明内容相对独立、无法插入正文），**书中并未把上述流程写成一张统一流程图**；本卡第 3–5 步的顺序由行文合读得出，标「待核查」（f287 missing_conditions）。
- f288 missing_conditions: 笛卡儿四条在书内为**节选**（原文更完整），且作者未给「如何判定某物清楚分明」的操作标准——本卡 E 段第 1、2 步因此只要求可指回的观察证据，不假装有严格判据。
- f286（L8315）: 「成功理论成为思想包袱」处的「包」为 OCR 疑脱字（对照同段语境应为「包袱」），[原文如此]。
- 作者对范式变化的判断属**预测**：「在过去，人们解决问题主要靠自己的思维活动，而在计算机发明后，未来应当主要靠机器模拟人的思维与心理活动来求解」（L8341）。
- **NR-06**: 全局 OCR 折行与上标丢失，引用含指数处一律标待核查。
- 本卡不依赖 P≠NP 等未证明假设——ce188 只作「路线已被堵死」的举例，不作为判据。

### 容易混淆的邻近方法论

- `complexity-class-locating`: 最容易混。分辨：本卡输出「问题陈述 + 关键点 + 根因链」，输入是模糊困惑；定类卡输入是已定义清楚的问题，输出复杂度类与依据链。
- `concept-positioning`: 容易混，因为都在「澄清」阶段。分辨：定位卡澄清的是词义与混淆类型；本卡澄清的是问题陈述的结构（现象 vs 问题 vs 关键点）。
- `approximation-heuristics`: 容易混，因为都涉及「近似」。分辨：本卡只改问题的定义与精度口径；近似卡判近似因子、设计启发式。
- `three-tier-screening`: 本卡第 3 步只做粗判，筛子（可计算性→代价→NP 完全）由它执行。
