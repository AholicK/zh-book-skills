# 观察与评论的区分（含面对批评时的澄清序列）

## R — 原文 (Reading)

> 非暴力沟通并不要求我们保持完全的客观而不作任何评论。它只是强调区分观察和评论的重要性。将观察和评论混为一谈，人们将倾向于听到批评，甚至会产生逆反心理。
>
> — 第三章 · 区分观察和评论

## I — 方法论骨架 (Interpretation)

同一句话里往往同时装着两样东西：**发生了什么**（观察）与**我如何定性它**（评论）。听者无法反驳事实，却一定会反击定性——所以混淆发生的那一刻，对话的议题就从「事情」变成了「你凭什么这么说我」。

判据是可操作的：观察能被摄像机复现（在什么时间、什么场合、对方具体做了/说了什么），评论则是对人的整体判断、推测或预测。书里给出五类典型混淆：把评论当事实（「你太大方了」）、把推测当唯一可能（「她无法完成工作」）、把预测当事实（「你这样下去健康一定会出问题」）、评价能力（「欧文是个差劲的前锋」）、用形容词副词下定性（「索菲长得很丑」）。

标记词是最快的筛子：**「每次」「曾」多为观察；「总是」「从不」几乎必是评论；「经常」「很少」介于两者之间，需要落到具体事例上再判。**

要提醒两点：作者并不要求完全客观，情绪与评价本身不是错，错的是把两者焊死在同一句里；正面标签（「他是个好厨师」）同样妨碍全面了解一个人，只是方向不同。

## A1 — 书中的应用 (Past Application)

### 案例 1: 小学咨询——四位教师给出的全是评论
- **类型**: 作者亲历（第三章）
- **问题**: 一所小学教师与校长沟通困难，作者受邀做咨询
- **方法论的使用**: 作者问「校长的哪些行为不符合你们的需要？」，四位教师依次回答「他是个大嘴巴」「话太多了」「他认为只有他的话有价值」「他希望所有的人都一直听他讲话」——没有一条是观察；作者与教师一起把它转成具体行为（校长在全体教员会议中讲童年和战时经历，有时导致会议超时 20 分钟）
- **结论**: 教师与校长对谈时仍只敢用无声抗议（转眼珠、打哈欠、看表），一位教师又喊出「你是个大嘴巴！」
- **结果**: 校长听后抱怨「为什么从没有人提醒我呢？」并承认自己有讲故事的习惯——说明具体的观察此前从未到达他那里

### 案例 2: 「区分观察和评论」对照表
- **类型**: 原书教学表格（第三章）
- **问题**: 如何判断一句日常表达属于观察还是评论
- **方法论的使用**: 成对例句对照——「米奇花钱大手大脚」（评论）vs「米奇上周买书花了一千元」（观察）；「欧文是个差劲的前锋」（评论）vs 具体的上场表现记录（观察）
- **结果**: 未说明（表格为演示材料，非事件）

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 说了自认为是事实的话，对方却反应激烈、觉得被指责
2. 想指出别人的问题又不想吵起来，想知道话该怎么说
3. 听到批评就本能防卫或反击，想先弄清对方到底在说什么
4. 被问「他具体做了什么」时，发现自己答上来的全是形容词

### 语言信号

- 「我只是陈述事实，他怎么就炸了」
- 「他一开口就说我总是……／你从来……」
- 「我就是觉得他这个人很（懒／自私／不靠谱）」
- 「你总是……」「你从不……」这类句子出现在抱怨里
- 英文: "you always / you never…", "I was just stating facts", "I didn't mean it as an attack"

### 与相邻 skill 的区分

- 与 `feelings-vs-thoughts` 的区别: 两者都会出现「对方听到的是指责」。本 skill 检查**行为层**——句子里是行为还是评价；`feelings-vs-thoughts` 检查**感受层**——句子里是感受还是判断
- 与 `alienating-self-check` 的区别: 那条是所有四类异化语言模式的全局体检；本 skill 只处理「观察/评论」这一对，并给出改写动作

## E — 可执行步骤 (Execution)

1. **取原句**
   - 完成标准: 拿到引发问题的那句话（用户自己说的、或听到的那句抱怨），逐字写下来
   - 判停条件: 用户只描述情绪而无原句时，先请其还原原话；确实无法还原则按「听到的那句抱怨」处理并在结论中标注

2. **判定类型**
   - 完成标准: 对照五类混淆（当事实 / 推测 / 预测 / 评价能力 / 形容词定性），指出原句命中了哪一类或哪几类
   - 输入契约: 一句自然语言；无需其他字段

3. **改写为观察**
   - 完成标准: 改写后的句子满足「摄像机可复现」——只有看得到、听得到的具体行为、时间、场合；用标记词扫尾（「总是/从不」必须被替换）
   - 输出契约: 给出①原句 ②命中类型 ③改写后的观察句；改写句不含对人的整体定性

4. **校准（必要时）**
   - 完成标准: 依 `requests-vs-demands` 的反馈机制请对方复述，确认他听到的版本与你的观察一致
   - 判停条件: 若用户其实想表达感受或提出请求，转入 `feelings-to-needs` / `requests-vs-demands`，本卡只负责把观察剥出来

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 纯事实汇报或信息同步场景（不需要剥离评价时，剥离反而降低效率）
- 评价本身就是目的且合法（如绩效评定中必须下结论）——此时应明确声明「以下是评价不是观察」，而不是假装在做观察

### 作者在书中警告的失败模式

- 混为一谈的代价是双向的：「将观察和评论混为一谈，人们将倾向于听到批评，甚至会产生逆反心理」（ce49）——愿望更难实现，即使对方让步也带着敌意
- 正面标签同样有害：称一个人「厨师」会妨碍我们全面了解他（作者原例）
- 评论一旦被当成事实，对方只会辩解「我没有」或沉默，而不会回应需要

### 作者的盲点 / 时代局限

- 自然语言的灰色地带没有解决：像「他很少主动联系我」这类频率描述，作者承认「经常、很少」可能混淆，但未给出灰度情况下的裁定规则
- 「摄像机可复现」标准对内心状态（态度、意图）无解——而多数冲突正发生在对意图的解读上
- 未讨论中文语用中特有的隐式评价（如「你也不看看别人」「就你事多」），这类无形容词的评价句也需先转写才能套用

### 容易混淆的邻近方法论

- `feelings-vs-thoughts`: 「我觉得被忽视了」既是伪感受也是评论，两卡可先后配合使用——先剥离行为层评论，再修正感受层表述
