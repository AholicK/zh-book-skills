# 感受反推需要（含听到不中听的话时的四种选择）

## R — 原文 (Reading)

> 听到不中听的话的四种选择：1. 责备自己 2. 指责他人 3. 体会自己的感受和需要 4. 体会他人的感受和需要
>
> — 第五章 · 听到不中听的话：四种选择

## I — 方法论骨架 (Interpretation)

被一句话刺痛时，人只有四条路可走：①**自责**（内疚、惭愧、厌恶自己）②**指责对方**（恼怒、争吵）③**体会自己的感受和需要**（承认感受源于自身）④**体会他人的感受和需要**（「他伤心可能是因为他需要体贴和支持」）。前两条是异化路径——一条向内攻击，一条向外攻击，都不解决问题；后两条是同一套机制的两个方向。

这条路可以走通的前提是一个反直觉的判断：**感受的根源在于我们自身，而不在他人的行为。**他人的话是扳机，需要才是子弹。所以「你让我很伤心」把因果说颠倒了——正确的表述是「我很伤心，因为我需要被重视」。

核心操作是往下再问一层：**「这个感受背后，我哪个需要没有被满足？」**批评、抱怨、指责往往是需要的悲剧性表达——对方在说自己缺什么，只是用了一种让人听不见的方式。

还要区分**需要与策略**：需要是抽象的（尊重、理解、支持、安全、自主），策略是具体的（让他道歉、每天打电话）。同一需要可以有很多策略；把策略当成需要，就会为了一个方案而战。

## A1 — 书中的应用 (Past Application)

### 案例 1: 母亲站起来说「36 年来，我一直在生你父亲的气」
- **类型**: 作者亲历（第五章，家庭故事）
- **问题**: 一次研讨班讨论「表达个人需要的畏惧」，作者的妈妈突然起身离开房间，很久没回来，回来时脸色苍白
- **方法论的使用**: 她说想起一件事心里极为难受——36 年来一直生丈夫的气，认为他不在乎自己的感受；直到此刻才意识到「我从没有和他说我想要什么」
- **结论**: 感受的根源是未说出的需要，而不是丈夫的行为
- **结果**: 未说明（书中未交代回家后的后续）

### 案例 2: 母亲 14 岁时的珠子钱包
- **类型**: 作者转述（第五章）
- **问题**: 作者的妈妈 14 岁时妹妹做阑尾手术得到一只漂亮的小珠子钱包，她极想要却不敢说
- **方法论的使用**: 她假装病痛，隐瞒家人，被带去看几位医生后做了手术探查（对她来说太冒险），终于如愿得到同样的钱包；护士误以为她要送人，收下了，她不知所措无法索回
- **结论**: 说不出需要的代价——作者说「这个不幸的故事告诉我们，一个人如果无法说出自己的需要，会是多么的痛苦」
- **结果**: 得到钱包又失去它，需要始终未被好好满足

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 只知道自己难受，说不出究竟想要什么
2. 同一种情绪反复出现，找不到原因
3. 听到难听的话之后无法自处，在反刍「他凭什么这么说」
4. 总觉得委屈，想倾诉但一开口就变成指责对方

### 语言信号

- 「我很烦 / 很难受，但不知道烦什么」
- 「他让我很失望 / 你怎么能这样对我」
- 「我为你付出了这么多（你却……）」
- 「我不知道自己想要什么」
- 英文: "you made me feel…", "I'm upset but I don't know why", "I feel terrible and I can't explain it"

### 与相邻 skill 的区分

- 与 `feelings-vs-thoughts` 的区别: 那条负责**找到**真感受词（把「我觉得他不尊重我」修正为情绪词）；本 skill 从感受**追到需要**。找不到感受先用那条，找到后接本卡
- 与 `self-empathy` 的区别: 自责、自我攻击方向的用法归 `self-empathy`；本 skill 处理向外归因与一般情绪定位
- 与 `expressing-anger` 的区别: 愤怒的完整四步流程（含停下来、表达）归 `expressing-anger`；本 skill 是它第 3 步「体会自己的需要」的完整机制

## E — 可执行步骤 (Execution)

1. **定位感受**
   - 完成标准: 写出一个具体情绪词（不允许「好 / 不好 / 还行」；说不出时先做身体扫描再映射）
   - 输入契约: 一个情绪事件 + 至少一个情绪词；情绪词缺失时先转 `feelings-vs-thoughts`

2. **检查归因句式**
   - 完成标准: 识别当前表述是否含「你 / 他让我……」的外包结构，并把归因从他人行为移回自身需要
   - 判停条件: 若真实情形涉及人身侵犯等外部事实，先如实承认事实，再处理需要（不得用「归因于自身」替对方开脱）

3. **反推需要**
   - 完成标准: 回答「这个感受背后，我哪个需要没有被满足？」，从需要清单（尊重、理解、支持、安全、自主、信任、意义……）中圈出 1–3 个，并说明推断依据

4. **需要与策略分层**
   - 完成标准: 把「让他道歉 / 让他改变」识别为策略，写出它服务的抽象需要；同一需要至少给出 2 个可选策略
   - 输出契约: 给出①情绪事件 ②情绪词 ③未满足的需要（抽象名词）④（可选）可回应该需要的具体策略
   - 判停条件: 用户目标若是让对方改变行为 → 转 `requests-vs-demands`；若是自我攻击 → 转 `self-empathy`

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 需要即时处置的冲突现场（先降温与安全，再谈需要）
- 纯事实判断场景（需要做的是决策而非情绪梳理时）

### 作者在书中警告的失败模式

- 「你让我……」把情绪外包给他人，是内疚控制的语法基础：家长对孩子说「你成绩不好让爸爸妈妈伤透了心」——孩子可能因此调整行为，但「这种调整只是为了避免内疚，而非出自对学习的热爱」（ce06）
- 把感受全归因于他人，等于宣布自己无力——因为对方不改变，情绪就无解

### 作者的盲点 / 时代局限

- 需要清单（尊重、理解、支持……）源自英语文化的分类，中文语境下的需要层级与表达方式书中未系统讨论
- 「需要 vs 策略」的边界在实际操作中常有争议：有些需求（如「道歉」）到底算策略还是需要，书中没有裁定标准
- 在对方确有侵害行为时，「感受源于自身」可能被误读为容忍——作者未讨论「归因于自己」与「追责于对方」在现实层面的边界

### 容易混淆的邻近方法论

- `self-empathy`: 都问「我什么需要没被满足」，但对象不同——自责时用自我同理，别的情绪用本卡
