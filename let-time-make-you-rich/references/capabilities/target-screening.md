# 标的属性检验与排除清单（「长期不断看涨」是唯一准入属性）

## R — 原文 (Reading)

> 「定投是长期持续投入的行为，所以，投资标的必须满足“长期不断看涨”的属性。于是，若是在这个属性上极度严格，那么结论也非常显而易见。债券、黄金、房产——更不用提潮牌运动鞋了——都不是合格的定投标的，因为它们根本没办法满足这个必须满足的属性。」
>
> 「这里有个隐秘的重点：没有只涨不跌的标的，只有长期来看只涨不跌的标的。」
>
> — 第3章 · 究竟有没有只涨不跌的投资标的（L333-339、L307-309）

## I — 方法论骨架 (Interpretation)

**定投的第一道闸门，只有一条属性要求：标的能否「长期不断看涨」。** 逻辑很简单——定投是长期持续投入的行为，持有得越久，选错的代价越大，所以筛选只能无比严格（f28 的倒推链）；而「严格」的落点不是收益率、不是波动率、不是「公司强不强」，而是这一条属性。

**必须带上的自我限定（作者原话）**：「没有只涨不跌的标的，只有长期来看只涨不跌的标的」——任何「不跌」都必须带「长期来看」的限定，下游引用时不得简化为「存在只涨不跌的标的」。

**排除清单是这条属性的直接推论**：债券、黄金、房产、潮牌运动鞋——因为它们根本没办法满足该属性。判据不是「是否抗通胀」「是否保值」这类流行标准，而是「能否长期不断看涨」。

**这条属性的关键代价（必写）**：它本质上**只能事后观察**；书中的事前判据只有「市场上所有人最看好」（`target-spotting`），两者构成循环关系。事前可执行的只有「倒推自检」：我能持有它至少两个大周期以上吗？说不出这个答案的，参照 ce28/ce27 的失败模式——那正是「定投了，但选错了」的常态。

## A1 — 书中的应用 (Past Application)

### 案例 1（判定演示）: 巴菲特的选股偏好
- **类型**: 转述案例（reported_case，作者用来说明属性应用）
- **问题**: 为什么巴菲特对科技股异常小心，却对可口可乐异常放心？
- **方法论的使用**: 作者把这一组偏好归因于同一条属性——可口可乐满足「长期不断看涨」而科技股在当时不满足
- **结论**: 属性应用的一致性是选股偏好的来源
- **结果**: 书中未给出进一步数据（作者的解释性引用，非严格验证）

### 案例 2（判定演示）: 四类资产的排除
- **类型**: 教学示例（原书判定示例，非事件）
- **问题**: 债券、黄金、房产、潮牌运动鞋为什么不能定投？
- **方法论的使用**: 逐个套用「长期不断看涨」属性，全部不满足
- **结论**: 排除清单成立；判据唯一
- **结果**: 未说明（演示材料）；房产的排除与第 1 章「房贷即定投」并存，注意两处的讨论对象不同（第 1 章讨论的是「大众已在定投」的事实，第 3 章讨论的是「什么标的合格」）

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 有人推荐了一个项目（黄金抗通胀、房产保值、某只基金），问「这个能不能定投」
2. 想给「什么能定投、什么不能」找一个可判定的标准
3. 已经定投了某标的，但说不出它为什么合格（ce28 的征兆）
4. 面对「看不懂价格的标的」，想先判断该不该碰

### 语言信号

- 「有人让我定投黄金，说能抗通胀，行吗？」
- 「房子不是一直在涨吗，怎么就不能定投？」
- 「这只基金在推销定投，值得投吗？」
- 「我说不出为什么选它，就是感觉不错」
- 英文: "can I DCA into gold / real estate", "is X a good DCA target", "why is my fund not qualified"

### 与相邻 skill 的区分

- 与 `target-spotting` 的区别: 那条给候选（市场共识），本条做判定（属性闸门）——注意两者是循环的一体两面：拿候选靠共识，判属性只能事后，需同时携带边界
- 与 `opportunity-cost-dilution` 的区别: 本条判「单个标的合不合格」；载体替换（一个 → 一系列）是另一张卡的动作
- 与 `half-baked-check` 的区别: 「定投却把钱交给主动管理者」（ce21）在行为链上表现为半吊子，在标的层面表现为不合格——两卡从不同侧面处理同一批场景，先做本条

## E — 可执行步骤 (Execution)

1. **取标的**
   - 完成标准: 拿到待检验标的的名称与类型（个股 / 基金 / 其他）；类型不明的先确认
   - 输入契约: 标的名称 + 用户了解到的信息（用途：判定依据要落到属性的表述上）

2. **属性检验**
   - 完成标准: 回答「它是否满足『长期不断看涨』」并给出判据来源；回答中不得把「抗通胀」「稳定」「大公司」当作通过理由（替换标准即判不合格）
   - 判停条件: 若标的在排除清单（债券/黄金/房产/潮鞋）→ 直接判不合格并给出去排除理由

3. **倒推自检**
   - 完成标准: 让用户回答「我能持有它两个大周期以上吗」；答不出或不打算持有的，按 f28 倒推链判为不合格（筛选强度必须与持有期限匹配）
   - 输出契约: 判定（合格 / 不合格 / 待定）+ 判据 + 未闭合项

4. **边界标注（不可省略）**
   - 完成标准: 输出必须包含「该属性只能事后观察；事前判据（市场共识）与它是循环关系」这一说明；不得把「长期不断看涨」写成可用历史涨幅判定的规则

5. **转交**
   - 完成标准: 合格 → 转 `opportunity-cost-dilution` 处理载体；不合格 → 说明可从排除清单外重新选，并要求走 `target-spotting` 的流程

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 用户询问估值、买卖点、仓位——全部超出本书范围
- 已经发生永久性损失风险的场景（个股暴雷、标的停牌）——此时先做事实核查而非属性辩论
- 把本卡当「黑名单生成器」：排除清单的判据是属性不满足，不是「这些资产不好」的价值判断

### 作者在书中警告的失败模式

- **「最优秀的企业」幻觉（ce05）**：柯达、诺基亚、乃至可口可乐与茅台都可能遇黑天鹅——「没有任何有效方法规避黑天鹅事件」；单点失效是拉长持有期的暴露面
- **把亏损归因于「贪」（ce26）**：真正的根源是买了看不懂、无法判断合理价格的标的——道德词替换能力词，错误不可修复
- **跟着感觉走（ce27）**：无判据出手，「随机漫步的傻瓜」的结局是慢慢沉沦
- **未倒推筛选标准（ce28）**：用着定投的形式，却没过定投的筛——「定投」于是变成放大错误持续时间的机制

### 作者的盲点 / 时代局限

- **结构性缺口（不可在书内闭合）**：属性只能事后观察，事前判据与它循环；「最被看好」与「估值是否合理」的关系书中完全未讨论（BOOK_OVERVIEW §3）
- p10「长期来看，风险竟然可以被稀释殆尽」未区分波动风险与永久性损失风险——引用时必须保留这一限度
- 「不理解标的就不该投」的批评同样适用于作者自己的核心建议（他没给合理价格的判定方法）

### 容易混淆的邻近方法论

- `target-spotting`: 两条合起来才是完整的选标路径；分开使用时各自带着同一根循环性边界
- `half-baked-check` / ce21: 「宣传定投、实际主动管理」的产品在这个层面是本卡的不合格案例，在行为层面是半吊子案例——引用时别只讲一半
