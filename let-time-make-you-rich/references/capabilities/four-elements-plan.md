# 定投方案的四要素设定与启动条件（含第五问「意外」）

## R — 原文 (Reading)

> 「所谓定投，指的是投资者长期定期定额地持续投资某个投资标的。……直接说答案吧：标的是定投策略四个要素之中最为重要的，因为标的决定结果，被投资的标的的未来表现决定了投资结果的成败。」
>
> 「定投这个策略，包括以下几个要点：标的究竟是什么？长期究竟是多久？定期究竟是多长的间隔？每次投入至少多少金额？当然还有另外一个因素需要考虑：出现意外的时候怎么办？」
>
> — 前言（L61-77）；第1章 · 几乎所有人都有定投的资格和能力（L169-181）

## I — 方法论骨架 (Interpretation)

**定投是一份要填四个槽位的方案，不是一句决心。** 四个槽位是：标的是什么、长期是多久、定期是多长间隔、每次投入至少多少；再加一个补充必答项——出现意外的时候怎么办。

这份框架的重心与常识相反：作者把「标的」的权重拉到最高（标的决定结果），而「长期」「定期」「定额」三个槽位在他看来「反向倒过来算就是了」——先定标的，再倒推其余三项。常识把「坚持」当第一难题，本书把「选什么」当第一难题。

两个容易漏掉的判断点：①「降均价」不是定投的确定好处（同样的机制也会抬高均价，p12），定投的价值在于它反向塑造人（p13），所以不能用「反正能摊薄成本」当启动理由；② 第五问「意外」不答等于没有方案——大众对前四问有被社会化的答案（房贷），唯独把第五问无限期推迟（「到时候再说吧」）。

完成形态是一张可被逐栏否证的四栏表：每栏要么有落点，要么显式标为待填；标的栏交给属性检验（见 `target-screening`），长期栏以两个大周期为准（见 `long-term-cycle`）。

## A1 — 书中的应用 (Past Application)

**原书未提供本单元的正例案例。** 以下为按原书规则构造的**合成演练**（明确标记为非书中案例）。

### 合成演练: 一份四处不合格的定投方案
- **类型**: 合成演练（依据 f01/f02 与 p09/g04 的规则构造，非原书材料）
- **问题**: 「我打算每月投入 800 元做定投，标的是朋友推荐的一只债券基金，打算投 3 年。这是不是一份合格的定投方案？」
- **方法论的使用**: 按四栏逐项落位——标的→债券（在排除清单内，不满足「长期不断看涨」）；长期→3 年不是本书口径（应为两个大周期）；定期（每月）/定额（800 元）→形式上合规，但需补两项自查（不借钱、不省投资的钱，p46）。
- **结论**: 方案不合格；第五问（意外）未作答，按 f02 判定「不算完成」。
- **结果**: 四处判定全部有原文落点，无悬空项（演练结论，非实测）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 准备开始定投，想写出一份可执行的方案（「我每月投多少、投多久、投什么」）
2. 已经有一份定投计划，想知道它合不合格、缺什么栏
3. 被问「出现意外怎么办」时答不上来，想知道这一栏该怎么处理
4. 用「反正能摊薄成本」当启动理由，需要一面镜子检查这个理由成不成立

### 语言信号

- 「我想开始定投，怎么定？」
- 「每月投 1000 块，投 3 年，这样行吗？」
- 「出现意外怎么办……到时候再说吧」
- 「定投不就是跌了就多买点、摊薄成本吗？」
- 英文: "how do I start DCA / dollar-cost averaging", "is my DCA plan ok", "what if something unexpected happens"

### 与相邻 skill 的区分

- 与 `qualification-check` 的区别: 那条回答「能不能开始」（资金属性与资格），本条回答「开始之后这份方案长什么样」——先过资格，再填方案
- 与 `target-screening` 的区别: 本条只指出「标的栏必须过筛」，不执行筛选动作；标的合格/不合格的判定归 `target-screening`
- 与 `long-term-cycle` 的区别: 本条要求「长期栏按两个大周期填」，周期定位本身（我度过一个周期了吗）归 `long-term-cycle`

## E — 可执行步骤 (Execution)

1. **取四栏 + 第五问**
   - 完成标准: 四个槽位（标的 / 长期 / 定期 / 定额）与第五问（意外）逐一列出；用户已有的填上，没有的显式标「待填」
   - 输入契约: 用户的方案描述或意图；金额单位、时间单位要明确（未给的先问，不猜值）
   - 判停条件: 若用户还没过资格判定且存在借钱/杠杆 → 转入 `qualification-check`

2. **标的栏落位**
   - 完成标准: 该栏给出「合格 / 不合格 / 待检验」，且判定有判据引用（「长期不断看涨」属性 + 排除清单）；任一项判定的依据必须能指向原文
   - 判停条件: 判定需要属性检验细节时转 `target-screening`，本卡只记录落点

3. **长期 / 定期 / 定额三栏落位**
   - 完成标准: 每栏给出取值或明确的待填标记；长期栏不得写「七年/永远」，须按「至少两个大周期」口径（转 `long-term-cycle` 取得定位结论）；定期须为固定间隔；定额须通过两项自查——不借钱（p02）、不省下投资的钱（p46）
   - 输出契约: 三栏含「用户现值 → 口径修正 → 修正后取值」

4. **第五问（意外）**
   - 完成标准: 给出「意外发生时这份计划怎么办」的明确回答；未作答时把方案整体判为「未完成」，并说明这是方案的必答项而不是情绪问题

5. **出具方案表**
   - 完成标准: 输出一张四栏 + 意外栏的表，逐栏标注状态（合格 / 修正 / 待填）与依据；结论**不得含收益承诺**，不得给出「一定赚钱」类表述
   - 输出契约: 表列 = 栏位 | 用户取值 | 判定 | 依据；附「未闭合项」清单

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 把本卡当产品推荐或方案代写工具：本卡只能检查与修正结构，不能替代投资顾问，也不推荐任何具体产品
- 用户处于债务危机、应急现金告罄状态时——先处理现金流与负债，不做方案美化
- 用户想用它做「收益率测算」——那是 `dca-return-calc` 的职责

### 作者在书中警告的失败模式

- **降均价误读（ce03）**：把「摊薄成本」当定投的确定好处，一旦均价被抬高立刻失去继续的理由
- **第五问悬置（ce02）**：对「意外」的回答是「到时候再说吧」——作者用房贷定投说明这正是惨案的温床（借来的钱 + 没有意外预案）
- **筛选倒推缺失（ce28）**：会背定投定义，却说不清标的为什么合格

### 作者的盲点 / 时代局限

- 除标的外，其余三要素的取值规则书中只给「反向倒过来算」的思路，没有具体规则——本卡据此把它们写成待填项，不虚构规则
- 作者对「意外」栏只给了要求（必须作答），未给正解与判据
- 「定额」的两条自查（不借钱、不省钱）出自作者对无管理费产品的推论（p44），带产品语境，非普适财务规划

### 容易混淆的邻近方法论

- `qualification-check`: 资格论处理「凭什么能投」，本卡处理「投的话方案长什么样」——顺序在前，不要合并
- `half-baked-check`: 半吊子诊断是行为链检查（做活不做全套），本卡是方案结构检查，两者可先后使用
